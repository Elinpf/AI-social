## 1. 实验目标与定位

### 1.1 目标
用货币系统把 50 个 LLM Agent 的「成长与协作」变成**可度量、可激励、可结算**的闭环：Agent 相互沟通、扮演角色，货币经济激励成长，**账户净值归零在连续判死后即「死亡」**；实验产出一套**可复现、可审计、不依赖 LLM 主观判断**的统计结论。

### 1.2 研究定位与核心问题
本实验关注的**核心问题**（本文全篇围绕其组织）：
1. **经济闭环**：货币如何发行、流转、回收，形成可自持的循环？
2. **死亡触发**：以什么量、什么规则判定「死亡」才稳定不抖动？
3. **死后（可续命）处理**：死亡后允许借贷/负资产如何续命，配套什么惩罚？
4. **确定性统计程序**：如何得到可复现、可审计、不依赖 LLM 判断的指标？
5. **10→50 放量**：如何先在小规模沙盒验证稳定性，再安全扩展到 50？

## 2. 总体架构

### 2.1 分层总览（确定性内核 + LLM 决策外挂）
```
                       Simulation Kernel（确定性、非 LLM）
  Clock/Round Scheduler → Event Queue → World State Store(+snapshot cache)
                     │                        ▲
                     ▼                        │
        Central Rule Arbiter（纯函数 hook 链，唯一写账入口）
         4.1 settle_market → 4.2 settle_obligations → 4.3 apply_tax
         → 4.4 apply_metabolism → 4.5 apply_penalty
         → 4.6 check_lifecycle → 4.7 resolve_revival → 4.8 check_death
                     ▲                        │
     intents         │                        ▼ events
  Decision Layer（T0 规则/T1 小模型/T2 LLM）  Ledger（append-only + SHA-256 哈希链）
  Communication（3 通道）                      │
  RNG Streams（层级化确定性）                  ▼ 只读
                                        Stats/Metrics（确定性统计程序）
```
（架构图对应 03 §1.1；经济四层闭环对应 01 §1。】

### 2.2 回合六阶段与 Phase 4 hook 链（已定，全引擎统一）
每回合严格按 6 阶段：`Phase0 ROUTE → 1 PERCEIVE → 2 DECIDE → 3 COMMUNICATE → 4 ARBITRATE → 5 LIFECYCLE → 6 COMMIT`；**Phase 4 前不产生任何状态突变**（03 §1.2）。

Phase 4 内 hook 链**固定顺序**（01 §1.2 / 02 §1.3 / 03 §1.3 三方对齐）：
| 序 | hook | 归属 | 说明 |
|---|---|---|---|
| 4.1 | `settle_market` | 经济 | 撮合、清算、原子转账、扣市场手续费（固定种子洗牌） |
| 4.2 | `settle_obligations` | 经济 | 计息、到期债务、强制还本（含续命贷） |
| 4.3 | `apply_tax` | 经济 | 子序：**铸币判定 → 收入税 → 财富税 → UBI** |
| 4.4 | `apply_metabolism` | 生命周期 | 每回合代谢消耗（销毁） |
| 4.5 | `apply_penalty` | 生命周期 | 负资产 / 作弊惩罚结算 |
| 4.6 | `check_lifecycle` | 生命周期 | 状态机（计数更新 + 状态迁移） |
| 4.7 | `resolve_revival` | 生命周期 | DECEASED→REVIVING 复活判定 |
| 4.8 | `check_death` | 生命周期 | 最终死亡判定（本回合终局） |

- **已裁决**：采用 `apply_tax`(4.3) 在 `apply_metabolism`(4.4) 之前（**先税后代谢**，03 D1-1），濒死判定统一在「同回合扣完税与代谢后的 `E_eff`」上做（回写 01 §5.4，见 §12-C03）。
- **已裁决**：`I_eff`（含 `flags` 剔除）须在 `4.1+4.2` 结算后、`4.3` 之前计算，经 `ctx` 传入（见 §12-C04）。
- **确定性随机源**：层级化 `stream_id`，抽样由 `(global_seed, stream_id, round, seq)` 唯一确定；PRNG 用整数运算（SplitMix64），禁浮点（03 §1.4）。
- **硬约束**：世界引擎/裁决器必须是确定性代码（非 LLM）；统计程序只读日志、纯函数、逐位一致。

### 2.3 数据与事件契约（与 01/02 对齐）
- 金额一律整数 `mu`（`1 CR = 100 mu`），比例量用基点 `bp`；单笔上限 `2^53−1`。
- 事件类型表以 03 §2.3 为唯一权威；01/02 的 `tx_type` 做映射（见 §12-C08）。
- `TRANSFER`/`MARKET_TRADE` **必带** `counterparty_id` 与 `flags{wash,cycle,self,mule}`，否则反作弊与死亡判定失效。

## 3. 经济闭环

### 3.1 四层闭环
经济系统按数据流分四层，构成闭环：**L1 生产 → L2 交易 → L3 财税/信贷 → L4 结算**（01 §1）。
| 层 | 职责 | 关键观测量 |
|---|---|---|
| L1 资源/生产 | 有限资源、生产函数、劳动→商品 | 人均产出、资源枯竭率、库存周转 |
| L2 货币交易 | 订单、撮合、成交、原子转账 | 成交量额、价差、深度、转账分布 |
| L3 税收/借贷 | 征税、UBI、借贷/计息/坏账、铸币 | 税基/税额、信贷规模、坏账率、杠杆 |
| L4 市场结算 | 逐笔清算、手续费、销毁、写账本 | 结算笔数、手续费、销毁、余额分布 |

**方向性**：税/UBI 是货币**再分配**（不改总量）；借贷是**时空调配**（不改总量）；**只有铸币/销毁改变总量**——这是防通胀/通缩的抓手。

### 3.2 货币体系
- **初始分配**：每 Agent `E0 = 100 CR`（=10000 mu），世界初始总量 `M0_total = N × E0`（50 人 = 5000 CR；沙盒 10 人 = 1000 CR），等额分配。
- **发行**：初始注入 + 铸币（`issue_max = 0.5·N·m`，入税池供 UBI）。
- **回收（销毁）**：代谢 `m = 2 CR/回合/人`（主出口）；交易手续费 50% 销毁；惩罚性销毁（坏账核销等额销毁）。
- **防通胀/通缩**：锚 `M_target = N × E0`，目标 `P ∈ [0.9,1.1]`；阈值 + 计数器确定性触发（`M < 0.9·M_target` 连续 5 回合 → 铸币；`> 1.1·M_target` 连续 5 回合 → 提代谢/停铸币），不由 LLM 决定（01 §2.3）。
- **流速控制**：`V = 每回合成交总额 / M_supply`，目标 `[0.3,1.5]`；手段：手续费、代谢、挂单深度上限、转账上限。

### 3.3 市场机制（确定性撮合与清算）
- **LLM 只提交意图**（限价/市价/标价/直接转账）；中央裁决器做全部撮合与清算。
- 机制：**连续双向拍卖（CDA）订单簿**；成交优先级 = **价格优先 → 时间优先 → 同价同时按固定种子随机**；成交价 = 挂单方 price（maker price）。
- 每笔成交原子清算：买方扣款 + 卖方交货 + 双方各扣手续费（`fee_market = 1%`，50% 税池 / 50% 销毁）。
- 撮合层**确定性拒绝自成交**（`buyer == seller`）；熔断器：单回合价波 >50% 暂停该商品撮合 1 回合。

### 3.4 税收与再分配
| 税种 | 税基 | 默认税率 |
|---|---|---|
| 收入税 `τ_income` | `max(0, I_eff)`（**与反作弊同口径**） | 10% |
| 财富税 `τ_wealth` | 超 `2×E0` 的净值部分 | 1%/回合 |
| 交易税（=市场手续费） | 成交额 | 1%（50% 税池 / 50% 销毁） |
| UBI | 税池发放 | 1 CR/回合/存活 Agent（**< 代谢 m=2**，仍需劳动） |

- **系统项不计入 `I_eff`**：UBI、铸币、税、手续费、贷款本金、利息、罚息、复活费一律不计入 `I_eff`（否则 UBI 会永远吊住濒死 Agent，死亡机制失效）——01 §1.4 与 02 §5.2 一致。
- **税基与 `I_eff` 同口径**：对倒环路刷量既不产生 `I_eff` 也不被误缴税。

### 3.5 借贷与负资产（续命主手段）
准入由**确定性信贷规则**审批（非 LLM），与 02 §3.1 完全一致：仅 `E < θ_warn` 可申请；须抵押（`LTV=0.6`）；单笔 ≤ `L_max=50 CR`；总负债 ≤ `D_max=100 CR`；利率随负资产深度上升（`r = r_base + k_pen·max(0,−E)/E0`）；逾期罚息 `r_overdue=5%`；`W_refi=3` 回合禁借新还旧。
- **放贷方**：v1 采用**世界银行（World Bank）单一放贷方**（确定性），Agent 间私人借贷列入开放问题（EQ3）。
- **坏账**：逾期 `N_overdue=3` 回合未清 → 没收抵押物 → 不足则核销差额（等额销毁）；最终 `terminated` 时账户清零、债务核销销毁。

### 3.6 闭环守恒不变量（核心）
每回合末必须校验（01 §1.3 / 03 §5.9(1)）：
```
Σ(所有账户 B) + 销毁额 + 沉淀手续费 + 税池余额
  = M0_total + 累计铸币 − 累计销毁（含代谢） − 累计坏账核销
```
不成立 → 该回合经济事件全部回滚，写 `ECONOMY_INVARIANT_VIOLATION`/`SYSTEM_ERROR` 并暂停世界（防静默通胀）。**税池作为 SYSTEM 账户是否计入 `M` 的口径见 §12-C05（高优先级，待用户拍板）。**

## 4. 死亡触发与可续命处理

### 4.1 判定基准：净值 `E`（非现金 `B`）
死亡判定基准是**净值 `E`**（00 §2.1）。理由：允许负资产与借贷后，「余额归零即死」失去意义；现金可被瞬时转账抖动，净值综合资产与负债才是真正清偿能力，且与 Sugarscape「代谢→耗尽→补充」一脉相承。

### 4.2 组合式死亡判定（防抖动三重机制）
1. **不用瞬时归零**：单回合 `E < θ_floor` 只是 `near_death`，给自救/借贷窗口；
2. **连续计数**：`c ≥ N_death` 才判死（默认 3，**沙盒档 5**）；回升到 `θ_recover` 以上清零；
3. **滞回带**：`θ_floor < E < θ_recover` 之间只递减计数、不清零，抬高「贴线横跳」成本；
4. **死亡冻结宽限**：判死后进入 `K_exit`（默认 6）回合冻结窗口，期间可被外部有效净流入救回，超窗才 `terminated`。

**判定用 `E_eff`**（扣除已标记作弊流入的净值）——§1.2 状态机与阈值中的 `E` 一律读作 `E_eff`（02 §5.2）。

### 4.3 生命周期 6 态状态机
`alive → warning → near_death → dead → revived → alive`，任意态可 → `terminated`；非法转换记 `SYSTEM_ERROR`（03 §5.9(5)）。迁移在每回合末、`计息→净值计算→I_eff 统计`之后确定性评估（02 §1.2）。

### 4.4 可续命路线（用户已拍板约束的落地）
- 死亡**不是终局**：默认走「死亡冻结 → 外部救助/借贷 → 复活」的续命闭环；`dead` 期间仍留在社交/经济图（可被谈判、被救助），只丧失主动行动权。
- **复活条件**（须同时满足）：`dead` 且 `now − freeze_start < K_exit`；`E ≥ θ_recover`；若靠借贷救回须满足全部信贷准入。
- **复活成本**：`fee_revive = 10 CR` + 冻结期累计罚息；复活后进入 `revived`，持续 `C_cool=5` 回合权利冻结。
- **最终退出**（`terminated`，避免僵尸账户）：`dead` 且超 `K_exit` 且期间无有效净流入且无法新增借贷，三者同时成立。

### 4.5 负资产/复活的惩罚措施（≥3 类，全部可量化）
主惩罚 = **经济权利冻结**（确定性、可审计）；行为惩罚叠加；生命惩罚默认关闭。
| # | 惩罚 | 规则 | 默认 |
|---|---|---|---|
| P1 | 利率惩罚 | 随负资产深度上升 + 逾期罚息 | 见 §3.5 |
| P2 | 交易权限限制 | `near_death`/`dead` 禁主动转出、禁发新单/新贷/拍卖 | 允许转入 |
| P3 | 行动力削减 | 每回合动作数分档 | `alive:5 / near_death:3 / E<-20:1` |
| P4 | 通信权削减 | 每回合通信配额分档（直接决定 LLM 预算） | 见 §5.3 |
| P5 | 抵押物没收 | 逾期 `N_overdue` 回合 → 抵押物划转债权人 | 3 回合 |
| P6 | 复活冷却 | 复活后禁新增借贷/发起交易/投票 | `C_cool=5` |
| P7 | UBI 抵扣 | 负资产期 UBI 全额抵债，不产生净流入 | 已定 |
| P8（可选，默认关） | 代谢加速 | 复活期 `m×1.5` | off（防连锁全灭） |

### 4.6 防全灭安全阀
世界级确定性安全阀（02 §4.3）：存活率 < `ρ_min=60%` → 一次性 UBI + 代谢减半持续 `W_rescue=5` 回合；单回合死亡 ≥ `D_burst`（10 人档 3 / 50 人档 10）→ 暂停判死 `W_pause=3` 回合；货币萎缩 > `ρ_shrink=30%` → 触发增发/再分配。
> ⚠️ **安全阀与验收下界冲突**（04 C-16，高优先级）：`ρ_min=60%` 会即刻介入并自动满足沙盒存活率下界 60%，掩盖稳定性观测 → 采用 **自然模式/干预模式两轮制** 化解（见 §7.3 / §14-Q3）。

### 4.7 死后计息/代谢/征税口径
**待明确（04 C-13）**：`dead` 期间各 hook 是否条件化。本方案建议（见 §14-Q7）：**计息照常**（02 已定）、**代谢继续计**（否则死亡冻结=免费避风港）、UBI 抵扣债务；作为开放问题交用户确认。

## 6. 确定性统计程序

> 总原则：**只读事件日志与 `turn_seal`，不读 LLM 输出，不做主观判断**；所有指标 `= f(EventLog, snapshot_round)`，纯函数、确定性、可重放；金额整数 `mu`，除法先通分再整除，浮点仅在最终格式化（`round(x,6)`）使用（03 §5）。

### 6.1 指标清单（口径统一，以 03 §5 为准）
| 指标 | 口径/公式 | 来源 |
|---|---|---|
| 货币总量 `M(t)` | `Σcash + Σdeposits`（+税池口径见 §12-C05） | `WorldState` / `turn_seal` |
| 流速 `V` | 仅计 `TRANSFER + MARKET_TRADE`（不含手续费、系统项单列） | 事件日志 |
| Gini | **主指标 `gini_shifted`**（负值平移法），另出 `gini_nonneg` | 净值序列 |
| 破产率 | 存量 `bankrupt(t)` + 流量 `flow_bankrupt(t)` | `net_worth`/`STATE_CHANGE` |
| 死亡率 | `mortality_rate(t) = deaths(t)/alive_count(t−1)`；`cum_mortality(T)` | `AGENT_DIED`/`STATE_CHANGE` |
| 存活时长分布 | `lifetime_i`（仅已死者）+ 直方图 + 生存函数 `S(k)` | `AGENT_DIED` |
| 坏账率 | **主指标 `default_rate_outstanding = overdue_total/outstanding_total`** | `LOAN_*` |
| 交易额分布 | 分位数 + 对数直方图 + Hill 幂律指数 | `TRANSFER`/`MARKET_TRADE` |
| 关系网络 | 度/密度/聚类/介数/模块度/连通分量（金钱图 + 沟通图，全序 tie-break） | `TRANSFER`/`MSG_*` |
| 守恒校验 | §3.6 不变量 + 交易原子性 + 台账一致 + 状态合法性 | 日志 |

### 6.2 不可篡改日志与复现
- **只追加 + SHA-256 哈希链**：`hash = H(canonical_json(去 hash 字段))`，`prev_hash` 链式；每回合末 `turn_seal`（含末哈希、存活数、货币总量、seed）。
- **复现**：`State = reduce(apply, EventLog, InitialState(seed))`；重放只折叠日志事件、不重跑 hook，保证首跑=重放逐位一致（03 §6.2）。
- **逐位一致保证**：整数运算 + 规范 JSON（键排序、浮点固定 6 位）+ 全序 tie-break + 无墙钟/环境依赖；CI 中两次 `metrics()` 断言字节相等。
- **异常检测**：哈希链断裂/seq 非单调/守恒破坏/交易不原子/状态非法转换/复现不一致 → 硬失败或 `SYSTEM_ERROR`。
- 日志字段（`tx`/`state_event`/`turn_seal`）与统计指标一一对应，缺任一强制字段即无法计算（02 §6）。

## 7. 10-Agent 沙盒验证

### 7.1 定位与角色
10-Agent 沙盒是 50-Agent 正式实验的**前置门禁（gate）**：验证世界引擎、经济机制、生命周期与反作弊、统计程序在**小规模**下自洽、稳定、成本可控、可复现；**不追求涌现现象与实验结论**。全部成功判据通过且冲突已裁决，才允许放量（04 §0）。

### 7.2 待验证假设与最脆弱机制
- 要验证 H1–H8（见 §1.3）。
- **最脆弱机制排序**：① 死亡阈值抖动（H2，10 Agent 样本极小，**最先崩**）；② 借贷滚雪球（H3）；③ 消息爆炸（H5）；④ 成本超支（H6）；⑤ 基尼漂移（次要）。
- **沙盒第一优先级**：确认 H2 与 H3 不崩；若 10 Agent 下即不稳定，禁止放量。

### 7.3 两轮制（化解安全阀冲突，确认 T4 设计）
- **轮次 1 · 自然模式**：**关闭安全阀**，验证 H2 真实死亡动态；存活率观察窗口 **R ≥ 100 回合**。
- **轮次 2 · 干预模式**：**开启安全阀**（`ρ_min=60%`），验证防全灭；救助打 `flag=rescue` 便于统计剔除。
- 两轮判据分别套用；本方案**确认采纳**该两轮制设计（回应 04 C-16）。

### 7.4 成功判据（沙盒"通过" = 全部满足）
| 判据 | 阈值 | 口径来源 |
|---|---|---|
| 存活率（自然模式，R=100） | 60% ≤ 存活率 ≤ 90% | 03 §5.3（含 `dead` 与否见 §14-Q2） |
| 基尼 `gini_shifted` | ≤ 0.60 且连续 5 回合变化 < 0.05 | 03 §5.1 |
| 坏账率 `default_rate_outstanding` | ≤ 5% | 03 §5.5 |
| 通胀 `M(t)/M_target` | ∈ [0.90, 1.10] | 01 §2.3 |
| 单回合 LLM 调用数 | ≤ 8 次/回合（N=10） | 03 §3.3 |
| 消息配额触顶率 | ≤ 20% | 03 §4.2 |
| 可复现性 | 首跑 vs `replay` 状态哈希一致；`metrics()` 两次字节相等 | 03 §6.3 |
| 反作弊 | C1–C10 注入用例 100% 被标记且不计入 `I_eff` | 02 §5.1 |

| 稳定性 | R 回合内无 `SYSTEM_ERROR`、无哈希链断裂、无回滚 | 03 §6.4 |

### 7.5 失败判据与回滚
| 失败信号 | 阈值 | 首要怀疑 |
|---|---|---|
| 人口崩溃 | 存活率 < 50% 或 = 100%（无人死亡） | H2 / 窗口（C-15） |

## 9. 风险与反作弊

### 9.1 可预见的作弊路径与确定性封堵（C1–C10）
| # | 作弊路径 | 封堵规则（确定性） |
|---|---|---|
| C1 | 串通刷单/对倒 | 滑窗 `W_wash=4` 检测双向流水，净额对消比 ≥ `ρ_wash=0.8` → 标 `wash`，不计 `I_eff` |
| C2 | 空转资金互相续命 | 转账图环路检测（最大环长 `L_cycle=5`），环路内转账不计 `I_eff` |
| C3 | 绕开死亡判定（临判定瞬时回正） | 计数连续且基于 `E_eff`；濒死/冻结期禁主动转出；滞回带抬高成本 |
| C4 | 借贷套利/庞氏续命 | `W_refi=3` 禁借新还旧；`D_max` 硬上限；利率随负资产深度上升；复活冷却禁增贷 |
| C5 | 女巫/多账户输血 | 同主体内转账不计 `I_eff`；新账户须唯一身份 |
| C6 | 自成交 | 撮合层拒绝 `buyer==seller` |
| C7 | 抵押物重复质押 | 全局抵押登记表（资产 ID 唯一、原子占用） |
| C8 | 拆分转账规避监控 | 滑窗 `W_split=4` 累计笔数/金额超阈 → 合并审计标记 |
| C9 | 结算顺序套利 | 撮合/结算用固定种子洗牌，hook 全序对所有 Agent 一致 |
| C10 | 洗钱/资产藏匿 | 中转跳数 > `L_hop=3` 且最终受益人同源 → 标 `mule`，不计 `I_eff` |

### 9.2 核心机制：有效净流入 `I_eff` 过滤
```
I_eff(agent,t) = Σ Inflow − Σ Outflow，仅计入满足：
  ① from ≠ to；② 非同一主体；③ 不在 wash/环路/mule 链；
  ④ 未被标记 flags∈{wash,cycle,self,mule}；
  ⑤ tx_type ∉ {ubi, mint, tax, fee, interest, penalty, revive_fee}
E_eff(t) = E(t) − Σ 当回合流入中被标记作弊的金额
```
死亡判定与收入税均以 `I_eff`/`E_eff` 为准（02 §5.2）。

### 9.3 其他风险
- **误杀真实互惠**：`I_eff` 过滤可能误伤真实救助/互惠交易——边界见 §14-Q8。
- **安全阀干预实验自然演化**：须打 `flag=rescue` 并在统计中剔除/单列（02 Q2）。
- **日志伪造**：v1 只用哈希链；是否引入密钥签名见 §14-Q9。
- **连锁全灭**：P8 代谢加速默认关闭以避免（02 §3.3）。

## 10. 成本

### 10.1 分层决策成本模型
```
E[Calls_T2] ≈ N_near · min(q_near,1) · p2        # 濒死求助，配额硬钳制
E[Calls_T1] ≈ (N − N_near) · a · p_t1             # 主动决策走 T1
E[Tokens]   ≈ E[Calls_T1]·tok1 + E[Calls_T2]·tok2
```
符号口径（**统一，消除 w/配额混淆**，见 §12-C20）：`a` = 主动决策率（默认 0.6），`p2` = 濒死求助率（默认 0.70），`p_t1` = 主动决策走 T1 比例（0.9），`q_near=1`、`q_alive=3`（通信配额）。

### 10.2 单轮沙盒预算（N=10，R=100，濒死占比 ~10%）
| 项 | 计算 | 次数 |
|---|---|---|
| T2 | `1×1×0.7` | 0.7/回合 → 70/轮 |
| T1 | `9×0.6×0.9` | 4.86/回合 → 486/轮 |
| 合计 | — | ≈ 5.6 次 LLM/回合 → ≈ 556/轮 |
| 硬预算闸 | ≤ 8/回合 | ≤ 800/轮 |

- **T2 天然有界**：`q_near=1` ⟹ `E[Calls_T2] ≤ N_near/回合`；即使濒死率 40% 也 ≤ 0.4N。
- **分层节省**：不分层基线 = 1000 次/轮；分层 ≈ 556 次/轮 → **调用数节省 ≈ 44%**，token 层面节省更大（须实测）。
- 成本闸门：每回合 `LLM_BUDGET`，超限按优先级（濒死 > 投资 > 结盟 > 常规）降级 T2→T1→T0，写 `LLM_CALL(degraded=true)` 可审计。

## 14. 待用户拍板的开放问题清单

> 每题给出 2–3 个候选方案 + 推荐意见。**覆盖 04 冲突清单全部高优先级项**（C-05/C-15/C-16 直接涉及用户拍板）。推荐仅为本团队综合建议，最终以用户裁决为准。

### Q1【C-05，高】货币总量 `M` 的口径：税池是否计入、负现金如何处理
- **背景**：01 用 `M_supply = Σmax(B_i,0) + 税池`（排除负现金、含税池）；03 用 `M(t) = Σcash + Σdeposits`（未含税池，且含负现金）。守恒式与通胀判据都依赖此口径。
- **候选**：
  - **A（推荐）**：`M = Σmax(B_i,0) + Σdeposits + 税池(SYSTEM 账户)`，负现金单列「负债」科目不进供应。同时明确税池为 SYSTEM 账户、计入 `M`；守恒式相应纳入税池项。理由：负资产不是货币，把负值计入供应会低估 `M`、扭曲通胀判定；税池是真实沉淀货币，应计入总量。
  - **B**：`M = Σcash + Σdeposits + 税池`（含负现金）。优点：与账本逐账户加总一致、实现最简；缺点：负资产会抵消货币供应，通胀指标失真。
  - **C**：`M = Σcash + Σdeposits`（03 原式，不含税池，含负现金）。缺点：与 01 守恒式不自洽，税池成「账外货币」。
- **推荐**：**A**。需同步修订 03 §5.6/§5.9 把税池纳入守恒式。

### Q2【C-11，中】存活率定义：`dead` 是否计入存活、是否置 `death_round`
- **背景**：02「存活率 = 非 TERMINATED 占比」（含 `dead` 冻结中）；03「存活 = 未死亡即算」并用 `death_round` 计死亡率。直接影响沙盒存活率阈值与安全阀触发。
- **候选**：
  - **A（推荐）**：**双指标并存**——① 结构存活率（用于安全阀）= 非 `terminated` 占比（含 `dead`/`revived`），与 02 一致；② 死亡事件死亡率（用于 H2 验证）= `AGENT_DIED` 计数 / 初始 N，与 03 `death_round` 一致。`dead` **置** `death_round`（判死回合）以便计死亡率，但 `alive_count`（结构）仍计入 `dead`。
  - **B**：存活 = `alive/warning/near_death`（不含 `dead`），`dead` 计死亡。缺点：把「可复活的冻结」当死亡，低估续命路线的存活含义。
  - **C**：沿用 02 单一「非 TERMINATED 占比」。缺点：H2 只看得见 `terminated`，死亡动态被稀释。
- **推荐**：**A**（双指标），兼顾稳定性观测与死亡可观测性。

### Q3【C-15，高】默认参数下沙盒窗口内观测不到死亡
- **背景**：默认 `E0=100`、`m=2`，被动 Agent 每回合仅降 2 CR，从 100 到 −20 需 60 回合，叠加 `N_death=5` → **约 65 回合**才可能首个自然死亡；若窗口仅 50 回合，H2 与存活率判据失去意义。
- **候选**：
  - **A（推荐）**：**窗口 R ≥ 100 回合**（自然模式），保证至少 1 个判死周期完整发生；同时**设「死亡压力档」**（`m`=5 CR 或 `E0`=50 CR）专测 H2 边界，两档对照。
  - **B**：只延长窗口 R ≥ 130，不设压力档。优点：更接近自然演化；缺点：成本翻倍、死亡样本仍少。
  - **C**：只设死亡压力档、保持 R=50。优点：省成本；缺点：偏离默认参数，H2 结论外推性弱。
- **推荐**：**A**（主用 R≥100，压力档作 H2 专项）。

### Q4【C-16，高】安全阀 `ρ_min=60%` 与验收下界 60% 冲突
- **背景**：安全阀在存活率 60% 即介入，会自动满足沙盒验收下界 60%，掩盖「机制本身是否稳定」的观测。
- **候选**：
  - **A（推荐）**：**两轮制**——轮次 1 自然模式（**关安全阀**，验证 H2 真实死亡动态）；轮次 2 干预模式（开安全阀，验证防全灭），救助打 `flag=rescue`，统计时剔除/单列。**本方案确认采纳 04 的该设计。**
  - **B**：降低安全阀阈值到 `ρ_min=40%`，使自然模式在 40–60% 区间可观测。缺点：与「防全灭」目标冲突，风险更高。
  - **C**：安全阀始终开启但只在统计口径上剔除救助回合。缺点：无法观测「无干预下机制是否稳」。
- **推荐**：**A**（两轮制，已在 §7.3 确认）。

### Q5【EQ2/02-Q4，中】UBI 是否足够维生、沙盒 `N_death` 取 3 还是 5
- **背景**：UBI 1 CR < 代谢 2 CR（需劳动维生）；`N_death` 沙盒档 5 / 全量 3。
- **候选**：A（推荐）保持 UBI 1<代谢 2，`N_death` 沙盒 5、全量 3，靠安全阀兜底；B UBI 提到 2（=代谢）→ 无生存压力、H2 消失；C `N_death` 全档 3 → 死亡率更高、张力更强但可能崩。
- **推荐**：**A**（保持生存压力，用安全阀与压力档控风险）。

### Q6【EQ1/EQ3/EQ5/EQ7，中】经济机制细节：转账费/私人借贷/资本利得税/利息流向
- **候选**：A（推荐）内部转账费 v1=0、仅世界银行放贷、资本利得税关闭、利息入税池；B 开转账费抑制对倒但增摩擦；C 引入 Agent 间信用市场（作弊面扩大）。
- **推荐**：**A**（v1 保守，沙盒扫描后定）。

### Q7【C-13，中】`dead` 冻结期是否继续代谢/计息/征税
- **候选**：A（推荐）**计息照常、代谢继续计、UBI 抵扣债务**（避免死亡冻结成为免费避风港导致「假死续命」套利）；B 冻结期全部暂停（简单，但可被滥用）；C 计息照常、代谢暂停（折中，仍留套利口）。
- **推荐**：**A**。

### Q8【02-Q8/D5-1，中】`I_eff` 过滤与「真实救助」的边界；Gini 负值口径
- **候选**：A（推荐）以「非环路、非同主体、非自成交」为过滤准则，Gini 主用 `gini_shifted` 并另出 `gini_nonneg`；B 放宽过滤（误伤真实互惠风险降低但作弊面扩大）；C 只用 `gini_nonneg`（丢失负资产信息）。
- **推荐**：**A**；真实互惠边界需经济学复核（沙盒日志回放校准 `ρ_wash/L_cycle`）。

### Q9【02-Q3，低】日志是否引入密钥签名防伪
- **候选**：A（推荐）v1 仅用 SHA-256 哈希链（成本低、够防篡改）；B 每 Agent 一对密钥签名（更强，成本高）；C 哈希链 + Merkle 根外部锚定（折中）。
- **推荐**：**A**（v1），后续按需升级。

### Q10【03 D3-1/D4-1，中】T2 触发阈值与消息配额具体数值
- **候选**：A（推荐）先用符号参数跑沙盒，`LLM_CALL` 日志回放标定 `a/p2/p_t1` 与阈值；B 先按经验值硬编码后微调。
- **推荐**：**A**（标定驱动）。

### Q11【03 D4-3，低】是否为「求救消息」设免配额白名单通道
- **候选**：A（推荐）为 `distress` 标签设免配额私聊通道（由 T0 分类），保证濒死求生路径可达；B 不设，用 near_death 的 1 条配额兜底。
- **推荐**：**A**（增强续命路径可达性）。

### Q12【03 D5-4/D5-5，低】网络指标：时间窗版本、是否剔除作弊边
- **候选**：A（推荐）v1 累计版 + 作弊边双版本输出（含/剔）；B 只累计版不剔作弊边。
- **推荐**：**A**。

### Q13【03 D0-2，低】是否引入回合内子 tick
- **候选**：A（推荐）v1 纯离散回合（降复杂度与复现难度）；B 引入子 tick（更接近连续时间，成本与不确定性上升）。
- **推荐**：**A**。
