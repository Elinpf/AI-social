> 领域：经济机制设计 | 作者：econ-mechanism-designer | 版本：v1 draft
> 适用对象：「50 个 LLM Agent 社会实验」（先 10-Agent 沙盒，后扩展至 50）
> 关联文档：`02-lifecycle-anticheat.md`（生命周期与反作弊，已对齐口径）、`03-engine-stats.md`（引擎与统计）、`04-sandbox-plan.md`（沙盒验收）
> 记账单位：CR（Credit）；每个 Agent 初始净值 `E0 = 100 CR`

## 0. 设计目标、约束与总原则

### 0.1 设计目标
1. 用货币系统把 Agent 的「成长」变成**可度量、可激励、可结算**的闭环。
2. 让 Agent 之间的沟通与协作产生**真实的经济后果**（赚钱/破产/负债），而非纯文本游戏。
3. 经济必须**逐层可观测**：每层产出确定的观测量，可直接喂给确定性统计程序。
4. 经济机制**确定性可复现**：给定相同决策序列与随机种子，结算结果逐比特一致。

### 0.2 必须继承的既有约束（不可推翻）
- **确定性代码定市场，LLM 只定个体决策**：撮合、清算、税收、利息、结算全部由确定性代码执行；LLM 绝不参与计算市场均衡或账户余额。
- **死亡机制参考 Sugarscape**：「代谢消耗 → 归零 → 补充」；货币化的「代谢消耗」是本世界能量的回收出口。
- **世界引擎/裁决器不是 LLM**：所有状态变更（转账、成交、纳税、放贷）必须经中央裁决器校验。
- **内建防作弊 + 不可篡改交易日志**：每笔经济事件写入 append-only 哈希链日志，规则校验前置。
- **分层决策 + 事件驱动**：经济事件只在有事件时驱动 LLM 思考，控制 token 成本。
- **死亡后走「可续命」路线**：原生支持借贷与负资产，配套明确惩罚（惩罚细则与 `02` 对齐）。

## 1. 四层闭环：架构总览

经济系统按数据流向分四层，构成闭环：**生产 → 交易 → 财税/信贷 → 结算**。每层是中央裁决器的一个子模块，只通过事件与账本交互。

```
┌──────────────────────────────────────────────────────────────┐
│                世界引擎 (确定性, 非 LLM)                        │
│                                                                │
│  L1 资源/生产层              L2 货币交易层                       │
│  Resource/Production         Monetary Exchange                 │
│  ─ 资源产出/衰减             ─ 订单簿撮合/标价成交               │
│  ─ 劳动→商品                 ─ 原子性转账                       │
│         │                            │                          │
│         └────────────┬───────────────┘                          │
│                      ▼                                          │
│  L4 市场结算层               L3 税收/借贷层                      │
│  Settlement                  Tax & Credit                       │
│  ─ 逐笔清算/余额更新          ─ 税/转移支付/UBI                  │
│  ─ 手续费/销毁               ─ 借贷/利息/坏账/铸币              │
│         │                            │                          │
│         └────────────┬───────────────┘                          │
│                      ▼                                          │
│           账本 Ledger (append-only, SHA-256 哈希链)              │
│                      │                                          │
│                      ▼                                          │
│           确定性统计程序 (离线, 可复现, 不依赖 LLM)              │
└──────────────────────────────────────────────────────────────┘
        ▲                                        │
        │ 事件驱动唤醒                            │ 每回合宏观指标
        │                                        ▼
  LLM Agent 决策 (只读世界状态快照, 只提交意图)   观测/埋点
```

### 1.1 分层职责、输入、输出、观测量

#### L1 资源/生产层 (Resource & Production)
| 项 | 内容 |
|---|---|
| 职责 | 定义有限资源、生产函数、资源再生与衰减；把「劳动/技能」转化为可交易商品/服务 |
| 输入 | Agent 生产意图、世界资源存量、Agent 技能等级、投入品 |
| 输出 | 商品/服务增量（入库存）、资源存量变化 |
| 观测量 | 人均产出、产出种类分布、资源枯竭率、库存周转率 |
| 确定性 | 生产为纯函数 `output = f(技能, 投入, 资源丰度)`；随机项用固定种子 PRNG |

#### L2 货币交易层 (Monetary Exchange)
| 项 | 内容 |
|---|---|
| 职责 | 承载订单、撮合、成交；货币在 Agent 间转移（含原子性转账） |
| 输入 | LLM 提交的买/卖单、标价单、直接转账意图 |
| 输出 | 成交记录（价/量/买卖双方）、转账事件 |
| 观测量 | 成交量/额、成交价、买卖价差、挂单深度、转账频次与金额分布 |
| 原子性 | 一笔转账/成交要么全部生效（扣款+交货+手续费）要么全部回滚 |

#### L3 税收/借贷层 (Tax & Credit)
| 项 | 内容 |
|---|---|
| 职责 | 征税、发放转移支付/UBI；办理借贷、计息、催收、坏账标记；铸币调节货币总量 |
| 输入 | Agent 余额/净值、收入流、借贷申请、债务状态、货币总量 |
| 输出 | 税额、UBI 额、贷款发放/利息/本金回收/坏账/铸币事件 |
| 观测量 | 税基、税率、税收总额、UBI 发放额、信贷规模、坏账率、杠杆率、铸币量 |
| 方向性 | 税/UBI 是货币的**再分配**（不改变总量）；借贷是**时空调配**（不改变总量）；铸币/销毁才是**总量调节** |

#### L4 市场结算层 (Settlement)
| 项 | 内容 |
|---|---|
| 职责 | 逐笔清算：扣款、交货、扣手续费、计算销毁、更新受影响账户；写账本 |
| 输入 | L2/L3 产生的待结算事件列表 |
| 输出 | 新余额、手续费收入、销毁额、`tx_type`/`counterparty_id`/余额与净值快照、账本记录 |
| 观测量 | 每回合结算笔数、手续费总额、销毁总额、余额分布（Gini 输入） |
| 一致性 | 结算后必须满足守恒等式（§2.5），否则整回合回滚并告警 |

### 1.2 回合内固定执行顺序（与 `02 §1.3`、`03 Phase4` 一致，防顺序套利）
```
回合 t（确定性、全局统一；与引擎 `03 §2.2 Phase4` 全序对齐）：
  ① 广播各 Agent 当前 state（冻结语义生效）
  ② 收集行动：LLM 已在下线阶段产出结构化意图（此步不解 LLM）
  ③ Phase4.1 settle_market：撮合、清算、原子转账、扣市场手续费（固定种子洗牌）
  ④ Phase4.2 settle_obligations：计息、到期债务、强制还本（含续命贷）
  ⑤ Phase4.3 apply_tax：铸币判定 → 收入税 → 财富税 → UBI（§5.4 子顺序）
  ⑥ Phase4.4 apply_metabolism：每回合代谢消耗（销毁）
  ⑦ Phase4.5 apply_penalty：负资产/惩罚扣减（与 02 协同）
  ⑧ Phase4.6–4.8 check_lifecycle / resolve_revival / check_death（02 §1.2）
  ⑨ 计算 E(t) → 统计 I_eff(t) → append-only 写日志 + turn_seal
```
> 关键：`③` 顺序对全体 Agent 用**同一随机种子洗牌**；`Phase4` 内 hook 全序对所有 Agent 一致，消除「抢跑结算顺序」套利。
> 顺序口径：**先税后代谢**（4.3 在 4.4 前），濒死判定基于扣税/代谢后的余额，与 `02`/`03` 统一。

### 1.3 闭环守恒关系（核心不变量）
每回合末必须校验：
```
Σ(所有账户 B) + 销毁额 + 沉淀手续费 + 税池余额
  = M0_total + 累计铸币 − 累计销毁（含代谢） − 累计坏账核销
```
不成立 → 该回合经济事件全部回滚，写 `ECONOMY_INVARIANT_VIOLATION` 事件并暂停世界（防静默通胀）。

### 1.4 系统项与 `I_eff` 的口径（与 `02 §5.2` 对齐，要害约定）
- **系统项不计入 `I_eff`**：UBI、铸币、税款、手续费、贷款本金、利息、罚息、复活费 一律**不计入**「有效净流入 `I_eff`」。
  - 理由：`I_eff` 是死亡/复活判定的基准；若常规 UBI 计入，濒死 Agent 会被 1 CR/回合兜底资金永远吊住，死亡机制直接失效。
- **税基与 `I_eff` 同口径**：收入税 `= τ_income × max(0, I_eff)`。对倒/环路刷量既不产生 `I_eff`、也不被误缴税，无法用虚假流水洗白税负。
- **世界干预不走 `I_eff`**：全局安全阀救助（`02 §4.3`）及任何世界级救济直接调整 `E` 并打 `flag=rescue` 日志，便于统计剔除，不计入 `I_eff`。

### 1.5 与引擎/统计层的事件与单位契约（对齐 `03-engine-stats.md`）
- **货币单位**：金额以整数最小单位 `mu` 存储，**`1 CR = 100 mu`**（采纳引擎 D0-1=100）；禁止浮点入账。换算见 §6.6。
- **事件类型映射**（经济侧 `tx_type` → 引擎事件）：
  | 经济侧 tx_type | 引擎事件 | 触发层 |
  |---|---|---|
  | trade | `MARKET_TRADE` | 4.1 |
  | transfer | `TRANSFER` | 4.1 |
  | fee_burn | `MONEY_BURNED`(reason=fee) | 4.1 |
  | fee_pool | `TRANSFER`(to=tax_pool, reason=fee) | 4.1 |
  | loan | `LOAN_ISSUED` | 4.2 |
  | repay | `LOAN_REPAY` | 4.2 |
  | interest | `INTEREST_CHARGED`（borrower→税池） | 4.2 |
  | default | `LOAN_DEFAULT` | 4.2 |
  | tax | `TAX_LEVIED` | 4.3 |
  | ubi | `UBI_PAID` | 4.3 |
  | mint | `MONEY_MINTED` | 4.3 |
  | metabolism | `METABOLISM`(→MONEY_BURNED) | 4.4 |
  | penalty | `PENALTY_APPLIED` | 4.5 |
  | revive_fee | `REVIVE_FEE_PAID`（独立事件，agent→税池） | 4.7 |
- **已与引擎确认补充事件类型**（已加入 `03`）：`INTEREST_CHARGED`（4.2，利息/税基复算锚点）、`REVIVE_FEE_PAID`（4.7，独立事件，供审计与坏账/成本分析）。
- **剔除项**：所有系统项（`TAX_LEVIED/UBI_PAID/MONEY_*/METABOLISM/LOAN_*`/利息/罚息/复活费）不计入 `I_eff`（§1.4），也不计入基础流速（§8）。

## 2. 货币体系

### 2.1 初始分配
| 参数 | 默认值 | 可调范围 | 说明 |
|---|---|---|---|
| `E0`（初始净值/资金） | **100 CR** | 50–200 | 每 Agent 出生资金（与 `02` 一致） |
| `M0_total` | **N × E0**（50 人 = 5000 CR；沙盒 10 人 = 1000 CR） | — | 世界初始货币总量 |
| 初始分配方式 | 等额 | 等额 / 按角色加权 | v1 等额，避免出生即不平等 |
| `endowment_goods` | 每人 10 单位基础投入品 | 5–20 | 出生自带生产投入品 |

### 2.2 货币发行与回收渠道

**发行渠道（增发，改变总量）**
| 渠道 | 默认 | 说明 |
|---|---|---|
| 初始分配 | 一次性注入 `M0_total` | 世界启动 |
| 铸币 (Seigniorage) | 每回合，上限 `issue_max` | 确定性按货币总量缺口增发，入税池（见 §2.3） |
| 公共项目支出 | v1 关闭 | 世界引擎发起公共采购时启用（预留） |

**回收渠道（销毁，改变总量）**
| 渠道 | 默认 | 说明 |
|---|---|---|
| 代谢消耗 `m` | **2 CR/回合/人** | Sugarscape 式生存成本，**货币回收主出口** |
| 交易手续费销毁 | 手续费 **50%** | 手续费另 50% 入税池 |
| 惩罚性销毁 | 事件触发 | 坏账核销时对应销毁等额货币（§4.5） |

> **迁移说明**：税收、UBI、借贷属于「账户间转移 / 债权转移」，**不改变货币总量**，只是再分配；真正改变总量的只有 `铸币 − 销毁`。这是防通胀/通缩的抓手。

### 2.3 防通胀与防通缩（确定性货币政策）
以货币总量锚 `M_target = N × E0`（恒定）。物价水平近似 `P ≈ M / Y`（Y = 总产出价值），目标 `P ∈ [0.9, 1.1]`。

| 情形 | 触发条件（连续计数） | 默认调节手段（确定性规则） | 参数 |
|---|---|---|---|
| 通缩（货币不足） | `M(t) < 0.9·M_target` 连续 5 回合 | **铸币**：`issue = min(issue_max, M_target − M(t))` 入税池供 UBI | `issue_max = 0.5·N·m`（=50 CR/回合@50人） |
| 温和缺口 | `0.9·M_target ≤ M(t) < M_target` | 铸币补足至 `M_target`，不超 `issue_max` | 同上 |
| 通胀（货币过多） | `M(t) > 1.1·M_target` 连续 5 回合 | 提高代谢消耗 & 销毁比例；暂停铸币 | `m += 5%`（每 5 回合一次，上限 2×基准） |
| 稳定 | `0.9·M_target ≤ M(t) ≤ 1.1·M_target` | 不干预 | — |

- 调节由**阈值 + 计数器**的确定性规则触发，**不由 LLM 决定**；每次调节写 `MONETARY_POLICY_ADJUST` 事件，保证可复现。
- 铸币与销毁同时记录在 `turn_seal`，审计可逐回合核对总量。

### 2.4 货币流速控制
- **流速定义**：`V = 每回合成交总额 / M_supply`。目标 `V ∈ [0.3, 1.5]`。
- 控制手段：手续费（提高则降速）、代谢（提高则增速）、挂单深度上限（§3.4）、转账上限（§6）。
- 观测量：逐回合 `V`、`M`、`Y`、`P`，由统计程序绘制。

### 2.5 货币总量观测（供统计程序）
| 指标 | 口径 | 频率 |
|---|---|---|
| `M_supply` | `Σ max(B_i, 0)` + 税池余额（负余额不计入供应） | 每回合 |
| `liabilities_total` | `Σ max(-B_i, 0)`（含债务利息） | 每回合 |
| `M_target` | `N × E0`（恒定锚） | 常量 |
| `issue_amt` / `burn_amt` | 本回合铸币 / 销毁额 | 每回合 |
| `tax_pool` | 税池余额 | 每回合 |
| `gini` | 净值分布的基尼系数 | 每回合 |
| `velocity` | `V` | 每回合 |

> 注：负余额在会计上计入「负债」科目，与「货币供应」分列，避免把负余额当货币。

## 3. 市场机制（确定性撮合与清算）

### 3.1 原则
- **LLM 只提交意图**：买单（限价/市价）、卖单、标价出售、直接转账。LLM 不计算成交价、不读取对手方余额、不撮合。
- **中央裁决器做全部撮合与清算**：采用**连续双向拍卖（Continuous Double Auction, CDA）订单簿**，这是经济学上价格发现效率高、且完全确定性的机制。
- **确定性撮合顺序**：同一时间戳的订单用「价格优先 → 时间优先 → 同价同时按固定种子随机」三级排序。

### 3.2 订单类型与成交优先级
| 订单类型 | 语义 | 成交规则 |
|---|---|---|
| 限价单 (Limit) | 指定最高买价 / 最低卖价 | 与对手簿最优价交叉即成交 |
| 市价单 (Market) | 立即以对手簿最优价成交 | 逐档吃到深度耗尽或金额耗尽 |
| 标价单 (Ask/Bid listing) | 挂单等待 | 入订单簿，按优先级排队 |

**成交优先级（确定性）**：
1. **价格优先**：买单出价高者优先；卖单要价低者优先。
2. **时间优先**：同价按挂单 `seq` 升序成交。
3. **同价同时**：以 `seed = hash(turn, good_id)` 的固定种子随机排序（同实验种子可复现）。

### 3.3 成交价与清算
- 成交价 = 被撮合**被动方（挂单方）的价格**（标准 CDA 规则，maker price）。
- 每笔成交生成一笔原子清算：`买方扣款` + `卖方交货` + `双方各扣手续费`，要么全成要么全回滚。
- 手续费 `fee_market = 1% × 成交额`（向下取整，min 0）；其中 50% 入税池、50% 销毁。
- 每笔成交必须输出（供 `02` 反作弊检测）：`tx_type=trade`、`buyer`、`seller`、`counterparty_id`、`price`、`qty`、`turn`、`seq`。
- **自成交拒绝**：撮合层确定性拒绝 `buyer == seller`（`02` C6）。

### 3.4 市场约束
| 参数 | 默认 | 范围 | 说明 |
|---|---|---|---|
| `price_unit` | 1 CR/单位（整数） | — | 最小价格单位，保证确定性 |
| `max_open_orders_per_agent` | 5 | 1–20 | 挂单深度上限，防刷单 |
| `max_order_qty` | 20 单位 | 1–100 | 单笔挂单量上限 |
| `fee_market` | 1% | 0–5% | 市场手续费 |
| `circuit_breaker` | 单回合价波 >50% 暂停该商品撮合 1 回合 | — | 防价格操纵 |

## 4. 借贷与负资产（可与续命路线；与 `02` 对齐）

### 4.1 借贷是「续命」的主要手段
借贷由**确定性信贷规则**审批，不靠 LLM。准入条件（与 `02 §3.1` 完全一致）：

| 条件 | 规则 | 默认 |
|---|---|---|
| 触发门槛 | 仅当 `E < θ_warn`（`WARNING/DISTRESSED/DECEASED`）可申请 | 已定 |
| 抵押要求 | 新增借贷必须提供抵押物，`贷款额 ≤ LTV × 抵押物折价` | `LTV = 0.6` |
| 单次上限 | 单笔贷款额 ≤ `L_max` | **50 CR** |
| 总负债上限 | 债务余额（本金+利息）≤ `D_max` | **100 CR**（=1.0·E0） |
| 利率 | `r = r_base + k_pen × max(0, −E) / E0`（随负资产深度上升） | `r_base=2%`、`k_pen=0.5` |
| 逾期罚息 | 逾期未还按 `r_overdue` 计息 | **5%/回合** |
| 借新还旧禁止 | `W_refi` 回合内不得用新贷偿还旧贷（防庞氏） | `W_refi = 3` 回合 |

**利率示例**：`E = −20` 时 `r = 2% + 0.5 × (20/100) = 12%/回合`——越深越贵，构成自愈激励。

### 4.2 资产估值细则（供净值 `E` 计算；本文件回填 `02 Q1`）
`E = B + Σ资产估值 − (债务本金 + 已计利息)`，各项估值口径：
| 资产类别 | 估值口径 |
|---|---|
| 现金 `B` | 面值 1:1（**负债单列**，不进资产项） |
| 可交易商品/库存 | 按最近一次市场成交价；无成交按账面成本；连续 **>20 回合**无成交则按账面 ×**0.5** 流动性折价 |
| 抵押物 | 按评估价 × **LTV(0.6)** 折价计入（防虚高估值骗过判死） |
| 应收账款/债权 | 若对手方已逾期或已计提坏账，**按 0** 计 |

> 该口径已回填给 `02`，`02 §8.2 Q1` 可据此关闭。

### 4.3 负资产状态下的经济权利限制（经济侧执行）
主惩罚 = **经济权利冻结**（确定性、可审计）；行为惩罚叠加；生命惩罚默认关闭（与 `02 §3.3` 一致）。

| # | 经济侧限制 | 规则 | 默认 |
|---|---|---|---|
| E1 | 禁止主动转出 | `DISTRESSED`/`DECEASED` 仅允许**转入**（复活通道） | 已定 |
| E2 | 禁止发起新订单/拍卖 | 濒死与冻结期不可挂单、不可参与拍卖 | 已定 |
| E3 | 禁止新增借贷 | 触及 `D_max` 或复活冷却 `C_cool` 内不可借 | `C_cool=5` |
| E4 | 强制还债 | 每回合净收入优先偿还利息 + 最低本金摊还 | 本金摊还 10%/回合 |
| E5 | 手续费上浮 | 濒死期交易手续费 | ×2 |
| E6 | UBI 抵扣 | 负资产期 UBI 全额抵扣债务，不产生净流入 | 已定 |
| E7 | 抵押没收 | 逾期 `N_overdue` 回合未清 → 抵押物划转债权人 | `N_overdue=3` |
| E8（可选，默认关） | 代谢加速 | 高强档 `m×1.5`，默认 off | off |

### 4.4 借贷实现细节
- **贷款事件**：放贷方? v1 采用**世界银行（World Bank）单一放贷方**（确定性，非 LLM），避免信用市场复杂化；Agent 间私人借贷列入待讨论。
- **抵押登记表**：全局资产 ID → 抵押状态（`02` C7 防重复质押）；抵押时原子占用，未解除不可再抵押。
- **计息**：每回合 `④` 阶段对未偿债务计息，写 `tx_type=interest` 事件（`from=借款人, to=WorldBank`）。
- **利息流向**：入税池（即利息是货币再分配，不销毁）。

### 4.5 坏账处理（与 `02 §4.2` 对齐）
- 逾期 `N_overdue = 3` 回合未清偿 → 标记坏账：`没收抵押物` → 仍不足则核销差额。
- 核销差额 = 等额销毁（货币回收出口），写 `tx_type=penalty` 事件与 `LIQUIDATION` 记录。
- 坏账后债务人进入更严惩罚（`02` 后果状态），经济侧冻结其全部主动权利。
- `Agent` 最终 `TERMINATED` 时，账户清零、债务全部核销销毁（`02 §4.2`）。

## 5. 税收与再分配

### 5.1 税种与税率（v1 默认）
| 税种 | 税基 | 默认税率 | 范围 | 说明 |
|---|---|---|---|---|
| 收入税 `τ_income` | `max(0, I_eff)`（同口径，见 §1.4） | **10%** | 0–30% | 对真实劳动/经营所得征，排除作弊转账与系统项 |
| 财富税 `τ_wealth` | 超出 `2×E0` 的净值部分 | **1%/回合** | 0–5% | 抑制赢家通吃，仅对富人征 |
| 交易税（=市场手续费） | 成交额 | **1%** | 0–5% | 50% 税池 / 50% 销毁 |
| 资本利得税 | v1 关闭 | 0 | 0–20% | 待讨论（资产增值变现时征） |

### 5.2 转移支付与 UBI
| 项 | 默认 | 说明 |
|---|---|---|
| UBI 额度 | **1 CR/回合/存活 Agent** | 由税池发放；**< 代谢 `m=2`**，即 UBI 不足以单独维生，仍需劳动 |
| UBI 资金来源 | 税池（收入税+财富税+手续费50%+利息） | 不足时**按比例缩放**（确定性），不铸币补 UBI |
| UBI 资格 | `ALIVE`/`WARNING` 全额；`DISTRESSED`/`DECEASED`/`REVIVING` 抵扣债务（E6） | — |
| UBI 与 I_eff | UBI 属系统项，**不计入 `I_eff`**（§1.4） | — |
| 转移支付（定向） | v1 仅 UBI；定向救助走 Agent 间自愿转账 | — |

### 5.3 对基尼系数的影响假设（供统计验证）
- **税制设计假设**：收入税（10%）+ 财富税（1%/回合 on >2E0）+ 等额 UBI，预期使**基尼系数稳态落在 0.35–0.5**（无税情形预期 >0.6）。
- **可检验假设 H1**：加入税收再分配后，10-Agent 沙盒 100 回合的 Gini 显著低于关闭税收的对照组。
- **可检验假设 H2**：财富税阈值 `2×E0` 越低，Gini 越低但经济活力（产出/成交额）也下降——存在最优阈值，由沙盒扫描确定。
- 观测量：逐回合 Gini、Top-1 净值占比、税收前/后 Gini 差、各组对比。

### 5.4 税收的确定性
- 每回合 `Phase4.3 apply_tax` 内部固定子顺序：**铸币判定 → 收入税 → 财富税 → UBI 发放**（对齐引擎 `03 §2.2`，且先税后代谢）。
- 每笔税/UBI 写 `TAX_LEVIED` / `UBI_PAID` 事件（`tx_type=tax|ubi`），含税基与税率快照，供审计复算。

## 7. 经济侧激励相容与防作弊要点（交由 `02` 统一收敛）

> 原则：经济层面用**机制设计**堵住套利（提高作弊成本、让作弊无利可图），具体检测规则由 `02` 反作弊执行。经济侧负责**输出检测所需字段**与**封堵接口**。

| # | 经济层漏洞 | 经济侧封堵建议 | 与 02 的接口 |
|---|---|---|---|
| W1 | 刷单/对倒（wash）制造虚假收入刷信用 | 手续费使对倒有成本；转账额度上限；收入税只对 `I_eff⁺` 征 | 清算输出 `tx_type`/`counterparty_id`，供 `02` C1 检测 |
| W2 | 空转资金互相续命 | `T_turn_max` 限制单回合搬款；濒死期禁主动转出 | 供 `02` C2 环路检测 |
| W3 | 借贷套利/庞氏续命 | `D_max` 硬上限、`W_refi` 禁借新还旧、利率随负资产深度上升 | 与 `02` C4 一致 |
| W4 | 女巫/多账户输血 | 同一主体内转账不计 `I_eff`；身份唯一 | 供 `02` C5 |
| W5 | 自成交操纵价格 | 撮合层拒绝 `buyer==seller` | 供 `02` C6 |
| W6 | 抵押重复质押 | 全局抵押登记表，资产 ID 唯一，原子占用 | 与 `02` C7 一致 |
| W7 | 拆分转账规避阈值 | 滑窗累计审计 | 供 `02` C8 |
| W8 | 结算顺序套利 | 固定种子洗牌撮合/结算顺序 | 与 `02` C9 一致 |
| W9 | 洗钱/资产藏匿 | 净值估值用折价口径，藏匿资产估值缩水 | 供 `02` C10 |
| W10 | 低买高卖瞬时套利 | 手续费 + 熔断器；同回合限价单不可撤销（防抢跑） | 经济侧独立 |

## 8. 观测量与统计映射（供 `03-engine-stats.md` 直接引用）

> 统计程序 **确定性、可复现、不依赖 LLM**：只读账本事件与 `turn_seal`，纯函数计算。

| 统计指标 | 口径 / 公式 | 数据来源 |
|---|---|---|
| 货币总量 `M_supply` | `Σ max(B_i,0) + tax_pool` | 账本逐笔 / `turn_seal` |
| 货币流速 `V` | `(Σ TRANSFER + Σ MARKET_TRADE.amount) / M_supply`；系统项单列不入基础流速 | 事件日志 |
| 基尼系数 `Gini` | 对各 Agent 净值 `E_i` 的标准 Gini | `turn_seal.equity[]` |
| Top-1 净值占比 | `max(E_i) / ΣE_i` | 同上 |
| 收入税总额 | `Σ tx(amount) where tx_type=tax & kind=income` | `tx` |
| 财富税总额 | `Σ tx where tx_type=tax & kind=wealth` | `tx` |
| UBI 发放总额 | `Σ tx where tx_type=ubi` | `tx` |
| 信贷规模 / 杠杆 | `Σ debt` / `Σ debt / Σ equity` | `tx.liabilities` |
| 平均利率 / 逾期率 | `Σ interest / Σ debt`；逾期笔数占比 | `tx_type=interest` |
| 坏账率 | `Σ liquidated / Σ loaned` | `tx_type=penalty` |
| 死亡率 / 存活率 | `deceased_count / N`；`alive_count / N` | `state_event` / `turn_seal` |
| 复现校验 | 重放哈希链与 `turn_seal.last_hash` 比对 | 账本 |

**每个指标必须能由「账本事件 + turn_seal」纯函数复算**——这是验收标准之一。
