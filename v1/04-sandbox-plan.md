## 0. 目的、范围与使用方式

- **沙盒的角色**：10-Agent 沙盒是 50-Agent 正式实验的**前置门禁（gate）**。全部成功判据（§3.1）通过、且冲突清单（§6）已裁决，才允许沿放量阶梯（§5）扩展。
- **验证什么**：验证世界引擎（03）、经济机制（01）、生命周期与反作弊（02）、统计程序（03）在**小规模**下自洽、稳定、成本可控、可复现。不追求涌现现象与实验结论。
- **使用方式**：每一条判据都给出可量化阈值与判定动作；观测点给出字段级清单；失败按 §3.4 回滚。测试用例直接引用 01 §9（ET1–ET17）与 02 §5.1（C1–C10）。
- **复现入口（引用 03 §7）**：`run(seed, config, rounds)`、`replay(log)`、`metrics(log, T)`。

## 1. 沙盒目标与待验证假设清单

### 1.1 待验证假设（H1–H8）

| 假设 | 陈述 | 验证方式 | 对应观测点（03 事件/字段） | 脆弱度 |
|---|---|---|---|---|
| **H1 确定性可复现** | 同 seed 重跑与 `replay(log)` 得到逐位一致的状态与指标快照 | 首跑 vs 重放状态哈希比对；`metrics()` 跑两次断言字节相等（03 §6.3） | `log.last_hash`、`turn_seal`、metrics snapshot | 低 |
| **H2 死亡阈值不抖动** | 连续 `N_death` 回合净值低于 `θ_floor` 的判定稳定，不因单回合波动误杀/漏杀 | 统计濒死→死亡转化率、误判率；自然死亡是否发生 | `STATE_CHANGE`、`AGENT_DIED(net_worth,cause)` | **高（最先崩）** |
| **H3 借贷不滚雪球** | 带惩罚的借贷/负资产不让少数 Agent 无限续命，坏账不扩散 | 坏账率、单账户最大负债、续命次数分布 | `LOAN_*`、`AGENT_REVIVED`、`PENALTY_APPLIED` | **高** |
| **H4 市场与货币收敛** | 撮合价/量不发散，M 围绕锚 M_target，流速稳定 | `M(t)/M_target`、`V`、未成交率 | `MARKET_TRADE`、`MONEY_MINTED/BURNED` | 中 |
| **H5 消息量有界** | 通信不爆炸（03 已用配额硬封顶），配额不被频繁触顶 | `DROPPED` 事件率、每回合消息数 | `MSG_PUBLIC/DM/GROUP`、`DROPPED` | **高** |
| **H6 成本可预测** | 单回合 LLM 调用在预算内，分层决策带来显著节省 | 实测 `LLM_CALL` 计数 vs 预算模型（03 §3.3） | `LLM_CALL(tier,tokens,degraded)` | 中-高 |
| **H7 反作弊有效** | C1–C10 路径被封堵，违规交易被标记且不计入 `I_eff` | 注入违规用例命中率、拦截率 | `TRANSFER/MARKET_TRADE.flags`、`PENALTY_APPLIED` | 中 |
| **H8 统计程序确定** | 指标可从日志纯函数重算，人人可复现 | 独立重算 vs 运行期报告比对 | 全部只读日志 | 低 |

### 1.2 最脆弱机制排序（预期最先崩）

1. **死亡阈值抖动（H2）** —— 10 Agent 样本极小；且**受 §6-C15 制约：默认参数下约 65 回合才可能出现首个自然死亡**，窗口设置不当会让 H2 完全无法观测。
2. **借贷滚雪球（H3）** —— 可续命路线下若无强惩罚/额度约束，坏账与隐性续命会滚雪球。
3. **消息爆炸（H5）** —— 03 §4.2 已用配额硬封顶（公开 20/回合、私聊 3/Agent/回合、群组 10/群/回合），"爆炸"风险转为"配额触顶率"，见 §3。
4. **成本超支（H6）** —— 03 §3.3 揭示 T2 由 `q_near=1` 硬钳制、T1 由主动决策率 `a` 决定；若 `a` 或唤醒集失控则成本上升。实测标定 `a/p2/p_t1`。
5. （次要）基尼漂移（H4 派生）。

> **沙盒第一优先级**：确认 H2 与 H3 不崩。若在 10 Agent 下即不稳定，禁止放量。

## 2. 观测点与埋点清单（对齐 03 §2.3 事件 schema）

### 2.1 设计原则

- **一切判据经日志确定性重算**（支撑 H8）：只读 03 §2.3 事件 + `turn_seal`，不读 LLM 输出。
- **现金/净值变动必须有对应事件**（03 §2.3 对齐要求）：无事件即 bug，由守恒校验暴露。
- **字段名以 03 为唯一权威**；01/02 的字段/枚举映射到 03（映射见 §6-C08）。

### 2.3 派生指标（口径以 03 §5 为准）

- **存活率**：`alive_count/N_initial`（口径待 §6-C11 裁决是否含 `dead`）

## 3. 成功判据与失败判据（含数值阈值）

> 阈值来源可追溯：数值取自 01/02 的具体默认值；口径取自 03。`[C-xx]` 指向 §6 需先裁决的冲突。

### 3.1 成功判据（沙盒"通过"= 全部满足）

| 判据 | 阈值 | 来源/口径 | 备注 |
|---|---|---|---|
| 存活率（自然模式，R=100 回合） | **60% ≤ 存活率 ≤ 90%** | 03 §5.3 | >90%=死亡机制近乎未触发（H2 未验证）；<60%=过狠。见 [C-11] |
| 基尼系数 `gini_shifted` | **≤ 0.60** 且连续 5 回合变化 < 0.05 | 03 §5.1；01 §5.3 预期稳态 0.35–0.5 | 不发散即可 |
| 坏账率 `default_rate_outstanding` | **≤ 5%** | 03 §5.5 | 可续命安全边界 |
| 通胀 `M(t)/M_target` | **∈ [0.90, 1.10]** | 01 §2.3 | 币值稳定 |
| 单回合 LLM 调用数 | **≤ 8 次/回合**（N=10；≈ 03 模型 5.6 ×1.4 余量） | 03 §3.3 | 成本可控 |
| 消息配额触顶率 | **≤ 20%**（`DROPPED`/总消息） | 03 §4.2 | 触顶过高=配额过紧或刷屏 |
| 可复现性 | 首跑 vs `replay` 状态哈希一致；`metrics()` 两次字节相等 | 03 §6.3 | H1 硬门禁 |
| 反作弊 | 注入 C1–C10 用例 **100% 被标记且不计入 `I_eff`** | 02 §5.1 | H7 |
| 守恒 | 03 §5.9 五条不变量全部成立 | 03 §5.9 | 硬门禁 |
| 稳定性 | R 回合内无 `SYSTEM_ERROR`、无哈希链断裂、无回滚 | 03 §6.4 | — |

### 3.2 失败判据（触发即判失败 / 暂停复盘）

| 失败信号 | 阈值 | 首要怀疑 |
|---|---|---|
| 人口崩溃 | 存活率 < 50%，或 = 100%（无人死亡） | H2 死亡阈值 / 窗口 [C-15] |
| 过狠全灭 | 存活率 < 40%（安全阀关闭的自然模式） | H2 |
| 财富极化 | `gini_shifted` > 0.75 或单调上升 | H4 |
| 坏账扩散 | `default_rate_outstanding` > 10% | H3 |
| 恶性通胀/通缩 | `M(t)/M_target` 越出 [0.8,1.2] 且政策 10 回合内未拉回 | H4 |
| 成本超支 | 单回合 LLM 调用 > 10（预算 8 ×1.2） | H6 |
| 续命滥用 | 单账户续命 > 3 次，或 `D_burst=3` 个 Agent 同回合判死且无复活 | H3/H2 |
| 消息失控 | 配额触顶率 > 50% 连续 3 回合 | H5 |
| 复现失败 | 首跑 vs 重放哈希不一致 | H1 |
| 守恒破坏 | 任一不变量不成立 | 引擎/经济 |

### 3.3 判定执行方式（确定性、可审计）

- 每回合由 `metrics(log, T)`（03 §5）离线重算，与运行期报告比对；差异即 bug。
- 失败判据命中 → 引擎暂停并冻结现场（保留该回合完整日志 + 快照 + `state_hash`），进入 §3.4。
- **沙盒两轮制**（解 [C-16]）：① 自然模式（关安全阀，验证 H2 真实死亡动态）；② 干预模式（开安全阀 `ρ_min=60%`，验证防全灭，救助打 `flag=rescue`）。两轮判据分别套用。

### 3.4 失败后的回滚 / 调参动作（模板）

| 失败模式 | 回滚动作 | 调参（单变量，一次只改一个） |
|---|---|---|
| 死亡阈值抖动 | 回滚到上一稳定参数集 | `N_death`↑、`θ_floor` 缓冲带、代谢平滑窗口；见 02 §2.1 滞回带 |
| 死亡不可观测 [C-15] | 切"死亡压力档" | 提高 `m`（如 2→5 CR）或降低 `E0`，或延长窗口 R≥130 |
| 借贷滚雪球 | 禁用借贷模块回基线 | 收紧 `D_max/L_max`、提高 `k_pen/r_overdue`、降 `W_refi`、缩短 `K_exit` |
| 消息触顶过高 | 放宽配额回基线 | 调 `CAP_PUBLIC/CAP_DM`（03 §4.2），或加冷却 |
| 成本超支 | 降级到 T0/高层低频 | 提高 T2 触发阈值、降主动决策率 `a`、增 `cadence`、启用 `LLM_BUDGET` 硬闸（03 §3.3） |
| 基尼漂移 | 回滚再分配参数 | 调 `τ_wealth`/阈值 `2×E0`/UBI（01 §5） |
| 复现失败 | **立即停止放量** | 排查非确定性源（浮点、哈希表迭代、并发，03 P4/P5） |

## 4. 成本估算

### 4.1 分层决策模型（引用 03 §3.1/§3.3）

**T0 纯规则（0 成本）→ T1 廉价小模型 → T2 昂贵 LLM**；Agent 默认休眠，事件驱动唤醒。

> **符号口径（03 §3.3 澄清，重要）**：lifecycle 早期符号 `w=3` 实为**通信配额 `q_alive`**，**不是唤醒率**。本文采用 03 的 `a`（主动决策率）与 `p2`（濒死求助率），避免成本与配额混淆。

```
E[Calls_T2] ≈ N_near · min(q_near, 1) · p2      # 濒死求助，配额硬钳制
E[Calls_T1] ≈ (N − N_near) · a · p_t1           # 主动决策走 T1
E[Tokens]   ≈ E[Calls_T1]·tok1 + E[Calls_T2]·tok2
```
默认初值（03 §3.3，待沙盒回放标定）：`a=0.6`（0.4–0.8）、`p2=0.70`（0.5–0.9）、`p_t1=0.9`、`q_near=1`。

### 4.2 单轮沙盒预算（N=10，R=100，濒死占比 ~10% → `N_near≈1`）

| 项 | 计算 | 次数 |
|---|---|---|
| T2 调用 | `N_near·q_near·p2` = 1×1×0.7 | ≈ 0.7/回合 → **70/轮** |
| T1 调用 | `(N−N_near)·a·p_t1` = 9×0.6×0.9 | ≈ 4.86/回合 → **486/轮** |
| 合计 | — | **≈ 5.6 次 LLM/回合 → ≈ 556/轮** |
| 硬预算闸 | ≤ 8/回合（含余量） | ≤ 800/轮 |

- 单次 token：T1 短（约 200–500），T2 长（约 600–1200，含工具）。`[待对齐：模型单价]`
- **总成本区间** = `Σ(tier 调用数 × 平均 token × 单价)`，选定模型后填入具体金额。
- **T2 天然有界**：`q_near=1` ⟹ `E[Calls_T2] ≤ N_near/回合`；即使濒死率飙到 40%，T2 也 ≤ `0.4N`（03 §3.3）。故濒死求助白名单不会炸成本。

### 4.3 分层决策的节省

- **不分层基线**：每存活 Agent 每回合 1 次 LLM = `N/回合` = **1000 次/轮**（N=10，R=100）。
- **分层**：≈ 5.6 次/回合 → **556 次/轮**。
- **调用数节省 ≈ 44%**；且约 40% Agent-回合不唤醒（走 T0）、T1 短上下文替代 T2 长上下文，**token 层面节省更大**（须实测，H6）。
- 沙盒以回放标定 `a/p2/p_t1` 替换预测值。

### 4.4 成本可控手段

1. 提高 T2 触发阈值（`INVEST_THRESHOLD`、`SURVIVAL_THRESHOLD`，03 D3-1）
2. 请求批处理 / 结果缓存
3. 本地规则兜底（低价值决策走 T0）
4. 降低主动决策率 `a` / 提高唤醒周期 `cadence`
5. `LLM_BUDGET` 硬闸 + 降级（T2→T1→T0，按濒死>投资>结盟优先级，03 §3.3）

## 5. 放量阶梯：10 → 20 → 35 → 50

每级为**门禁**；上一级全通过才进下一级，触发回滚条件即退回上一级。

| 级 | 规模 | 放行条件（全部满足） | 回滚条件 | 观测重点 |
|---|---|---|---|---|
| L0 | **10** | §3.1 全部成功判据通过；H1 复现一致；H2/H3 不崩（自然模式观测到死亡且不抖动） | 命中任一 §3.2 | 死亡阈值、借贷、反作弊、守恒 |
| L1 | **20** | L0 通过 + 无新崩溃模式 + 单回合 LLM 调用 ≤ 2.2×(L0 值)（近似线性） | 成本超线性增长或消息触顶激增 | 成本线性度、消息 |
| L2 | **35** | L1 通过 + 压力测试（消息/坏账/人口）稳定 + `metrics()` 与离线重算一致 | 任一派生指标发散 | 系统性压力、审计一致性 |
| L3 | **50** | L2 通过 + 全部判据在目标规模成立 + 成本在预算内 + 复现与审计通过 | 任何失败判据 | 目标规模终验 |

- **单变量推进**：每级只改规模，不同时改机制，确保归因清晰。
- **每级至少 2 个 seed** 验证 H1 稳健性，避免对单 seed 过拟合。
- 规模放大时注意 [C-11]（存活率口径）与 [C-16]（安全阀）在大 N 下的判定一致性。

**[C-04][中] `I_eff` 计算时点未在 hook 链显式落点**

**[C-05][高] 货币总量 `M` 是否含税池 / 排除负现金**

**[C-06][低 / 基本解决] 负现金 / 透支口径**

- 建议：01/02 补"负现金须借贷背书、`|B|≤D_max`"约束，与 03 一致即可。

**[C-07][低 / 基本解决] 手续费去向与守恒式**

**[C-10][低] 通信配额分档命名**

**[C-11][中] 存活率定义（是否含 `dead`/`terminated`）**

- 建议：明确 `dead` 是否置 `death_round`、是否计入存活；统一 02/03 与 04 判据。

**[C-15][高 / 设计不自洽] 默认参数下死亡在沙盒窗口内几乎不可观测**
- 出处：01 §6.1（`E0=100 CR`、`m=2 CR/回合`）；01 §5.2（UBI=1 CR/回合且受税池约束，初期税池近空）；02 §2.3（`θ_floor=-20`、`N_death` 沙盒档 5）。
- 描述：**被动 Agent 在无收入时 `E` 每回合仅降 `m`=2**，从 100 到 -20 需 **60 回合**，再加 `N_death=5` → **约 65 回合**才可能判死；若沙盒只跑 50 回合，将**观测不到任何死亡**，H2（死亡阈值抖动）与存活率判据失去意义。
- 建议：① 沙盒自然模式观测窗口 **R ≥ 100 回合**；② 或设"死亡压力档"（`m` 提高至 5 CR 或 `E0` 降至 50 CR）专测 H2；③ 明确沙盒初期 UBI 是否发放及其对 E 的兜底。

- 描述：安全阀在 60% 即介入，会**自动满足**验收下界并掩盖"机制本身是否稳定"的观测。
- 建议：采用 §3.3 两轮制——自然模式（关阀）验证 H2、干预模式（开阀、打 `flag=rescue`）验证防全灭；判定分别套用。

**[C-20][中] 成本模型符号口径（`w` vs `a`/`q_alive`）**
