# 02 · 死亡与生命周期机制 + 反作弊体系 v1

> 归属：生命周期与反作弊设计专家（lifecycle-anticheat-designer）
> 状态：v1 初稿，供 Leader 汇总进正式方案
> 上游约束：用户已拍板「可续命」路线（允许借贷与负资产，但必须配套明确惩罚）
> 设计原则：**所有判定由确定性规则完成，不依赖 LLM**；引擎可作为状态机直接执行

## 0. 阅读约定与口径（术语表）

| 术语 | 符号 | 定义 | 口径来源 |
|---|---|---|---|
| 现金余额 | `B` | 账户可动用的货币余额，可为负 | 经济层 |
| 净值 / 清偿能力 | `E` | `E = B + Σ资产估值 - (债务本金 + 已计提利息)` | **本文件定义**，需经济层对齐 |
| 有效净流入 | `I_eff` | 一回合内，来自**不同经济主体、非同环路、非自成交**的净收入 | **本文件定义**，需经济层在清算输出中支持 |
| 回合 | `t` | 全局确定性时钟的一拍（回合制） | 引擎层 |
| 初始资金 | `E0` | 每个 Agent 起始净值 | 经济层 |
| 货币单位 | `CR` | Credit，实验记账单位；实现以整数 `mu` 计账（建议 `1 CR = 100 mu`，禁浮点） | 经济层 / 引擎层 |

**核心口径决策（已定）**：死亡判定的基准量是**净值 `E`，不是现金 `B`**。

理由：
1. 既然允许负资产与借贷，「余额归零即死」失去意义——借到钱余额仍是负的，但未必该判死；
2. 现金 `B` 可被瞬时的疑似作弊转账拉回正数，产生抖动与绕过；净值 `E` 综合了资产与负债，才是真正的清偿能力；
3. `E` 与 Sugarscape 的「代谢→耗尽→补充」一脉相承：代谢消耗使 `E` 下滑，经济行为使 `E` 回升，耗尽则判死。

> ⚠️ 待对齐：`E` 中「资产估值」的口径（按市价 / 按账面 / 抵押物折价）由经济层确定。本文件默认**抵押物按 LTV 折价后计入**，其余资产按最近一次市场成交价，无成交则按账面。

## 1. 生命周期状态机

### 1.1 状态定义

| 状态 | 英文 | 含义 | 权利 |
|---|---|---|---|
| 正常存活 | `ALIVE` | `E ≥ θ_recover`，健康 | 全部权利 |
| 预警 | `WARNING` | `θ_floor ≤ E < θ_warn`，接近红线 | 全部权利 + 系统预警提示 |
| 濒死 | `DISTRESSED` | `E < θ_floor` 但连续计数 `c < N_death` | **禁止主动转出**，可接收；可申请借贷 |
| 死亡冻结 | `DECEASED` | `c ≥ N_death` 触发判死 | 仅可接收救助；结算与计息照常 |
| 复活惩罚期 | `REVIVING` | 冻结期内被救回 `E ≥ θ_recover` | 权利受限（见 §3.3），有冷却 |
| 永久退出 | `TERMINATED` | 冻结期内未被救回且超过退出窗口 | 无（移出经济与社交图） |

### 1.2 迁移条件（引擎每回合末确定性评估）

```
每回合末（在 计息 → 净值计算 → 有效净流入统计 之后）执行：

# 注：本伪代码中的 E 指 E_eff（扣除已标记作弊流入的净值，见 §5.2）
输入: E(t), c(t-1), state(t-1)
输出: state(t), c(t)

# 1) 计数更新（滞回 + 递减，防止抖动）
if E >= θ_recover:
    c = 0
elif E >= θ_floor:
    c = max(0, c - 1)          # 回升不立即清零，只递减
else:                           # E < θ_floor
    c = c + 1

# 2) 状态迁移
if state == DECEASED:
    if E >= θ_recover:          # 被外部救助救活
        state = REVIVING
        cool_left = C_cool
    elif (now - freeze_start) >= K_exit:
        state = TERMINATED      # 超过退出窗口，永久退出
    # 否则保持 DECEASED
elif state == REVIVING:
    cool_left -= 1
    if cool_left <= 0 and E >= θ_recover:
        state = ALIVE
elif c >= N_death:              # 触发判死
    state = DECEASED
    freeze_start = now
    snapshot_balance(agent)     # 冻结瞬间余额快照，供审计
elif E >= θ_warn:
    state = ALIVE
else:
    state = WARNING if E >= θ_floor else DISTRESSED
```

### 1.3 触发时机（回合内固定顺序）

生命周期评估必须发生在**一个固定位置**，否则会被利用结算顺序套利：

```
回合 t 的执行顺序（确定性、全局统一）：
  ① 回合开始：广播各 Agent 当前 state（冻结语义生效）
  ② 行动收集：LLM 已在下线阶段产出结构化意图（此步不解 LLM）
  ③ 市场撮合 / 清算（经济层，固定种子随机化撮合顺序）
  ④ 计息 / 代谢扣减 / 手续费（经济层）
  ⑤ 计算 E(t)
  ⑥ 统计 I_eff(t)（有效净流入）
  ⑦ **生命周期状态机评估**（本文件 §1.2）
  ⑧ 只追加写交易与状态日志（本文件 §5）
```

**与引擎 Phase4 挂载的映射（已与 sim-engine-stats-architect 对齐）**：

```
引擎 Phase4 顺序                           本文件对应
  4.1 settle_market      ┐
  4.2 settle_obligations ├─ 本文 §1.3 的 ③④（撮合/结算/计息/手续费）
  4.3 apply_tax          ┘   （先税后代谢，与引擎一致）
  4.4 apply_metabolism   ── 本文 §1.3 的 ④（基础代谢扣减）
  4.5 apply_penalty      ── 本文 §3.3 P1–P8 惩罚结算
  4.6 check_lifecycle    ── 本文 §1.2 状态机（计数更新 + 状态迁移）
  4.7 resolve_revival    ── 本文 §3.4（DECEASED→REVIVING 复活判定）
  4.8 check_death        ── 本文 §1.2/§4.2（触发 DECEASED / TERMINATED）
```

`apply_metabolism→apply_penalty→check_lifecycle→resolve_revival→check_death` 的顺序与本文 §1.2 完全一致；**税在代谢之前**（先结算收入税，再扣基础代谢），保证濒死判定口径全引擎统一。

**生命周期挂载对引擎的硬性要求**：
1. 死亡判定必须落 `AGENT_DIED` / `STATE_CHANGE` 事件，字段含 `death_round, cause, net_worth, status`；
2. `TRANSFER` / `MARKET_TRADE` 事件必须携带 `counterparty_id` 与 `flags`（wash/cycle/self/mule），否则本文件 §5.2 的 `I_eff`/`E_eff` 无法计算、反作弊与死亡判定全部失效；
3. `status` 字段白名单见 §1.4。

**已定**：判定冻结（`DECEASED`）在评估当回合即生效，下一回合 `②` 阶段其主动转出/交易意图被引擎拒绝。

### 1.4 状态白名单与金额精度（与引擎对齐）

**`status` 字段白名单（6 态，写入日志与事件）**：

| 本文件状态 | 日志 `status` 值 | 引擎口径 |
|---|---|---|
| `ALIVE` | `alive` | 一致 |
| `WARNING` | `warning` | 引擎原提议 `near_death` 的「非禁转」区，独立命名 |
| `DISTRESSED` | `near_death` | 采纳引擎命名；**语义 = 禁止主动转出** |
| `DECEASED` | `dead` | 一致（死亡冻结） |
| `REVIVING` | `revived` | 一致（复活惩罚期） |
| `TERMINATED` | `terminated` | **引擎原 4 态白名单缺失，必须补上** |

> ⚠️ 引擎原提议白名单 `alive/near_death/dead/revived` **不够用**：①缺 `terminated`，而存活率/安全阀需要区分「死亡冻结中」与「已永久退出」；②若把 `WARNING` 与 `DISTRESSED` 合并，则「禁主动转出」的触发边界无法表达（`warning` 区允许转出，`near_death` 区禁止）。故白名单为 6 值。

**金额精度**：引擎以整数最小单位 **`mu`** 记账（建议 `1 CR = 100 mu`），**禁止浮点入账**。本文件所有以 `CR` 表述的阈值需在实现时换算为 `mu`：

```
θ_floor = -20 CR = -2000 mu    E0 = 100 CR = 10000 mu
θ_recover = +5 CR = 500 mu     θ_warn = 20 CR = 2000 mu
L_max = 50 CR = 5000 mu        D_max = 100 CR = 10000 mu
fee_revive = 10 CR = 1000 mu   T_large = 30 CR = 3000 mu
```

利率/税率等比例量以**整数分数或万分比**表示（如 `r_base = 2% = 200‱`），避免浮点。

## 2. 死亡阈值定义

### 2.1 组合式判定（已定）

采用「**连续 N 回合净值低于硬地板**」为主判据 + 「**滞回带**」+ 「**死亡冻结宽限**」三重防抖动：

1. **不用瞬时归零**：单回合 `E < θ_floor` 不判死，只是 `DISTRESSED`，给 Agent 自救/借贷窗口；
2. **连续计数**：`c ≥ N_death` 才判死（默认 `N_death = 3`）；回升到 `θ_recover` 以上清零；
3. **滞回带**：`θ_floor < E < θ_recover` 之间只递减计数，不给清零，避免「贴线反复横跳」刷生存；
4. **死亡冻结宽限**：判死后进入 `K_exit` 回合的冻结窗口，期间允许被外部有效净流入救回（复活），超窗才永久退出。

### 2.2 为什么这样定（设计理由）

- **抗抖动**：经济系统每回合波动正常，瞬时判死会把正常波动误杀，实验信息量崩塌；
- **保留自救窗口**：可续命路线要求给 Agent 借贷/求助的时间，连续计数天然提供了多拍窗口；
- **可确定性执行**：整条规则只用整数比较和计数器，引擎一行不依赖 LLM；
- **可调保守档**：沙盒阶段可把 `N_death` 提到 5（与经济侧建议一致），全量阶段调到 3 提高死亡率、制造张力。

### 2.3 默认阈值

| 参数 | 符号 | 默认值 | 可调范围 | 说明 |
|---|---|---|---|---|
| 初始净值 | `E0` | 100 CR | 50–200 | 由经济层定（已确认） |
| 基础代谢（销毁出口） | `m` | 2 CR/回合（=2%·E0） | 1–20 | 经济层；代谢使 E 下滑 |
| 收入税率 | `tax_rate` | 10% · max(0, I_eff) | 0–30% | 经济层 |
| 预警线 | `θ_warn` | 20 CR | 0.05–0.3 × E0 | 触发系统提示 |
| 死亡硬地板 | `θ_floor` | **-20 CR**（=-0.2 × E0） | -0.5×E0 – 0 | 低于此值开始计死 |
| 恢复线（滞回上沿） | `θ_recover` | **+5 CR** | 0 – θ_warn | 回升到此才回正 |
| 判死连续回合数 | `N_death` | **3**（沙盒档 5） | 2–5 | 连续低于 θ_floor 的回合数 |
| 死亡冻结/退出窗口 | `K_exit` | **6 回合** | 3–10 | 判死后允许被救的窗口 |

> 说明：`θ_floor` 为负，意味着「资不抵债但负债未超 0.2×E0」还不算死，符合可续命路线的容错设计。

## 3. 续命 / 复活机制

### 3.1 借贷续命准入条件（确定性信贷规则）

借贷是「续命」的主要手段，但审批**不靠 LLM**，由引擎按固定规则执行：

| 条件 | 规则 | 默认 |
|---|---|---|
| 触发门槛 | 仅当 `E < θ_warn`（即 `WARNING/DISTRESSED/DECEASED`）可申请 | 已定 |
| 抵押要求 | 新增借贷必须提供抵押物，`贷款额 ≤ LTV × 抵押物折价` | `LTV = 0.6` |
| 单次上限 | 单笔贷款额 ≤ `L_max` | 50 CR |
| 总负债上限 | 债务余额（本金+利息）≤ `D_max` | 1.0 × E0 = 100 CR |
| 利率 | `r = r_base + k_pen × max(0, -E) / E0`，随负资产深度惩罚性上升 | `r_base=2%`，`k_pen=0.5` |
| 逾期罚息 | 逾期未还按 `r_overdue` 计息 | 5% / 回合 |
| 借新还旧限制 | 同一 Agent 在 `W_refi=3` 回合内不得用新贷偿还旧贷（防庞氏续命） | 已定 |

**利率示例**：`E = -20` 时 `r = 2% + 0.5 × (20/100) = 2% + 10% = 12%/回合`——越深越贵，构成自愈激励。

### 3.2 无效续命封堵（与经济层共担）

只有「有效净流入 `I_eff`」能推动 `E` 回升到 `θ_recover` 并复活。**疑似作弊的转账（wash 对倒、环路、自成交）不计入 `I_eff`**，详见 §4。

### 3.3 负资产 / 复活的惩罚措施（≥3 类，全部可量化）

> 主惩罚 = **经济权利冻结**（确定性、可审计）；行为惩罚叠加；生命惩罚默认关闭。

| # | 惩罚类别 | 规则（确定性） | 默认数值 |
|---|---|---|---|
| P1 | **利率惩罚** | `r = r_base + k_pen·max(0,-E)/E0`，逾期再加 `r_overdue` | 见 §3.1 |
| P2 | **交易权限限制** | `DISTRESSED`/`DECEASED`：禁止**主动转出**；禁止发起新订单/新增借贷/参与拍卖 | 允许收款 |
| P3 | **行动力削减** | 每回合可执行动作数随负资产深度分档 | `ALIVE:5 / 濒死:3 / E<-20:1` |
| P4 | **发言/通信权削减** | 每回合通信配额按状态分档，**直接决定 T2 的 LLM 调用预算** | 见下方分档表 |
| P5 | **抵押物没收** | 逾期 `N_overdue` 回合未清偿 → 抵押物划转债权人 | `N_overdue = 3` |
| P6 | **复活冷却** | 复活后 `C_cool` 回合内：禁止新增借贷、禁止发起交易、不可投票 | `C_cool = 5` |
| P7 | **UBI 抵扣** | 复活惩罚期内 UBI（若有）全额抵扣债务，不产生净流入 | 已定 |
| P8（可选，默认关） | **代谢加速** | 复活期内每回合代谢 `m` 上浮系数 | `m × 1.5`，默认 `off` |

> 说明：P8 默认关闭，理由是代谢加速会放大死亡概率，可能引发连锁全灭，与沙盒稳定性目标冲突。仅作为「高强度档」保留，`K_exit` 相应放宽。

**P4 通信配额分档（按状态，直接映射 LLM 成本预算）**：

| 状态 | 每回合通信配额 | 白名单说明 |
|---|---|---|
| `alive` | 3 条 | 公开/私聊均可 |
| `warning` | 3 条 | 同上 |
| `near_death`（=DISTRESSED） | **1 条** | **白名单：仅限私聊求助**——保证「濒死求生」可被触发 |
| `dead`（=DECEASED） | 0 条（主动） | 冻结期不可主动发言，但**可接收**外部救助/谈判 |
| `revived`（=REVIVING） | 1 条 | 冷却期，限私聊 |
| `terminated` | 0 条 | 已退出 |

> 说明：`near_death` 必须保留 1 条私聊求助配额，否则濒死 Agent 无法发起求生协商、T2 濒死求生路径不可达。此配额与仿真引擎的成本模型 `E[Calls_T2]≈N·w·p2` 直接挂钩，`w/p2` 由沙盒阶段标定。

### 3.4 复活条件与成本

- **复活条件（必须同时满足）**：
  1. 处于 `DECEASED` 且 `now - freeze_start < K_exit`；
  2. `E ≥ θ_recover`（由有效净流入或有效外部救助实现）；
  3. 若通过新增借贷救回，须满足 §3.1 全部准入条件。
- **复活成本**：`fee_revive = 固定复活费 + 冻结期累计罚息`。
  - 默认 `fee_revive = 10 CR`（可调 5–30）；
  - 冻结期利息照计（`r_overdue`），复活时并入债务。
- **复活后状态**：进入 `REVIVING`，持续 `C_cool = 5` 回合的 P6 权利冻结，冷却结束且 `E ≥ θ_recover` 才回到 `ALIVE`。

## 4. 死后处理与「防全灭」安全阀

### 4.1 默认路径（已定）

死亡**不是终局**，默认走「死亡冻结 → 外部救助/借贷 → 复活」的续命闭环。Agent 在 `DECEASED` 期间仍留在社交图与经济图中（可被谈判、可被救助），只是丧失主动行动权。

### 4.2 最终退出规则（极端情况）

当且仅当以下条件**同时**成立，才转入 `TERMINATED`（永久退出，避免无意义僵尸账户）：

1. 处于 `DECEASED` 且 `now - freeze_start ≥ K_exit`（默认 6 回合）；
2. 期间无任何有效净流入使其 `E ≥ θ_recover`；
3. 无法新增借贷（触及 `D_max` 或无可抵押资产或借贷被拒）。

退出处理：账户清零、债务作坏账核销（债权人计提损失，见经济层坏账口径 M=3）、从社交图移除、状态日志标注 `terminated`。

### 4.3 全局安全阀（防几十回合内全灭）

实验最怕「雪崩式全灭」导致失去信息量。设**世界级确定性安全阀**：

| 触发器 | 条件 | 动作（确定性） |
|---|---|---|
| 存活率低水位 | 存活率（非 `TERMINATED` 占比）`< ρ_min` | 触发世界救助：全体发放一次性 UBI、代谢 `m` 下调 50%，持续 `W_rescue` 回合 |
| 死亡速率告警 | 单回合死亡数 `≥ D_burst` | 暂停判死 `W_pause` 回合（仅计数冻结，不判死），人工/Leader 复核 |
| 经济冻结 | 死亡计数榜触顶且货币总量萎缩 `> ρ_shrink` | 触发货币增发/再分配（经济层配合） |

默认：`ρ_min = 60%`，`D_burst = 3`（10-Agent 沙盒）/ `10`（50-Agent），`W_rescue = 5`，`W_pause = 3`，`ρ_shrink = 30%`。

> 待讨论：安全阀是否算「干预实验自然演化」，需 Leader 与沙盒验收方确认触发后是否在统计中打标（建议打标，便于事后剔除/单独分析）。

## 5. 反作弊约束（确定性与封堵规则）

> 原则：**所有封堵都由引擎的确定性规则完成**，LLM 不参与判定；规则可参数化、可审计、可复现。

### 5.1 可预见的作弊路径与封堵

| # | 作弊路径 | 手法 | 确定性封堵规则 |
|---|---|---|---|
| C1 | **串通刷单 / 对倒（wash trading）** | A→B 转账，B 立即 A→回，制造「收入」假象、刷流水与信用分 | 在滑窗 `W_wash` 内检测同一对 `(A,B)` 的双向流水；若 `min(ΣA→B, ΣB→A) / max(...) ≥ ρ_wash`（净额接近对消）→ 该组转账标记 `wash`，**不计入 `I_eff` 与信用分** |
| C2 | **空转资金互相续命** | 多个濒死 Agent 循环转账，让每人在判定回合前「恰好」回正 | 转账图环路检测（DFS/Jonson，最大环长 `L_cycle`）；落在环路内的转账**不计入 `I_eff`**；且计数 `c` 只认 `I_eff` |
| C3 | **绕开死亡判定（临判定瞬时回正）** | 在 `c = N_death - 1` 的临界回合突然转入大额资金 | ①计数需连续且基于 `E`；②濒死/冻结期禁止主动转出，仅允许外部有效流入；③`θ_floor<E<θ_recover` 只递减不清零（滞回），垫高「瞬时回正」成本 |
| C4 | **借贷套利 / 庞氏续命** | 借新还旧无限滚动、利用利率结构套利，永不进入退出 | ①`W_refi` 回合内禁止借新还旧；②总负债硬上限 `D_max`；③利率随负资产深度上升（`r_base + k_pen·(-E)/E0`），滚动成本递增；④复活冷却 `C_cool` 期间禁止新增借贷 |
| C5 | **女巫 / 多账户（Sybil）** | 一个 Agent 操控多个账户互相输血 | 账户关联检测：同 `agent_key`/同 `owner_id` 的账户视为同一主体，**同一主体内转账不计入 `I_eff`**；新账户创建需唯一身份凭证 |
| C6 | **自成交（self-trade）** | 同一主体既是买单又是卖单，制造虚假成交价影响净值估值 | 撮合层确定性拒绝 `buyer == seller`；撮合输出 `tx_type` 供日志审计 |
| C7 | **抵押物重复质押（double-pledge）** | 同一资产抵押给多方骗取多笔贷款 | 全局**抵押登记表**（资产 ID 唯一），抵押时原子占用，未解除不可再抵押 |
| C8 | **拆分转账规避监控** | 把大额拆成多笔小额，绕过 `T_large` 阈值 | 滑窗 `W_split` 内，同一 `(from,to)` 对累计笔数 `≥ K_split` 或累计额 `> T_large` → 合并审计并标记 |
| C9 | **结算顺序套利** | 利用确定性结算顺序抢在计息/判死前转移资产 | 撮合与结算顺序由**固定随机种子**洗牌（同一实验种子可复现）；`③④⑤⑥⑦` 的先后对所有 Agent 一致 |
| C10 | **洗钱 / 资产藏匿** | 通过多层中转账户洗白资金以满足净值阈值 | 转账深度检测：超过 `L_hop` 跳中转且最终受益人同源的链路标记 `mule`，不计入 `I_eff` |

### 5.2 「有效净流入 `I_eff`」判定公式（引擎实现口径）

```
I_eff(agent, t) = Σ_{tx ∈ Inflow(agent,t)} amount(tx)
                − Σ_{tx ∈ Outflow(agent,t)} amount(tx)
其中 Inflow/Outflow 仅计入满足以下全部条件的 tx：
  ① tx.from ≠ tx.to                                    # 排除自成交
  ② tx.from 与 tx.to 不属于同一主体                      # 排除 Sybil/同主体
  ③ tx 不在 wash 组 / 环路 / mule 链中                   # 排除对倒、循环、洗钱
  ④ tx 未被标记 flag ∈ {wash, cycle, self, mule}        # 引擎最终裁决
  ⑤ tx_type ∉ {ubi, mint, tax, fee, interest, penalty, revive_fee}
     # 系统项（再分配/铸币/税/费/息/罚/复活费）不计入 I_eff——它们是对 E 的直接调整，
     # 不是「赚来的收入」；否则常规 UBI 会永远吊住濒死 Agent、使死亡机制失效
```

**判定用有效净值 `E_eff`（死亡判定的实际基准）**：

```
E_eff(t) = E(t) − Σ_{tx ∈ 当回合流入(agent,t), flag(tx)∈{wash,cycle,self,mule}} amount(tx)
```

- §1.2 状态机与 §2 阈值中的 `E` 一律读作 **`E_eff`**；
- 效果：对倒/循环/自成交「转来又转走」的钱不再能重置死亡计数 `c` 或触发复活；
- 标记在 `W_wash` 窗口内由引擎**确定性**判定；实验可回放，标签一旦确定即固定，保证可复现；
- **系统项例外**：安全阀触发的一次性世界救助（§4.3）是**显式干预**，直接调整 `E`（而非计入 `I_eff`），并在日志打 `flag=rescue`，便于统计时剔除/单独分析。

**税基口径（与经济层对齐）**：收入税 = `tax_rate × max(0, I_eff)`，与反作弊同口径——刷量不产生 `I_eff`，故不会被用于洗白税负，也不会因对倒而误缴税。

> 口径对齐需求（给经济层）：清算模块须为每笔 tx 输出 `tx_type`（trade / transfer / loan / interest / tax / ubi / penalty / revive_fee）与 `counterparty_id`，否则 §5 检测无法落地。

## 6. 不可篡改交易日志

### 6.1 写入约束（已定）

1. **只追加（append-only）**：任何记录不可修改、不可删除；纠错以「反向记录（reversal）+ 新记录」表达。
2. **哈希链（hash chain）**：每条记录含 `prev_hash`，`hash = SHA256(prev_hash || canonical_payload)`；创世记录 `prev_hash = 0×64`。
3. **规范化序列化**：`canonical_payload` 用固定字段顺序 + UTF-8 + 无空格 JSON（确定性序列化），保证跨语言重算一致。
4. **每回合锚点**：每回合末写一条 `turn_seal` 记录，含本回合末哈希、存活数、总货币量，作为检查点。
5. **可复现重放**：给定初始种子 + 日志，引擎可重放出完全一致的最终状态（供审计）。
6. ~~签名~~（待讨论）：是否引入密钥签名（每 Agent 一对密钥对）以防伪造，取决于引擎实现成本。

### 6.3 日志字段 ↔ 统计指标映射（一一对应）

| 统计指标 | 计算来源 |
|---|---|
| 存活率 / 死亡率 | `state_event.to_state` + `turn_seal.alive_count` |
| 死亡数 / 复活数 / 退出数 | `state_event` 按 `to_state` 分组计数 |
| 基尼系数 Gini | `tx` 聚合后的各 Agent 净值序列（`turn_seal` 快照） |
| 货币流速 V | `Σ tx.amount / money_supply`（按 `turn`） |
| 负债率 / 杠杆 | `tx.liabilities` |
| 借贷规模与利率 | `tx_type = loan/interest` |
| 作弊事件率 | `tx.flags` 非空计数 |
| 破产分布 / 濒死时长 | `state_event` 中 `DISTRESSED→DECEASED` 的回合差 |
| 复现校验 | 重放 `hash` 链与 `turn_seal.last_hash` 比对 |

**已定**：缺失上述任一字段，统计层的对应指标即无法计算，故字段为**强制**。

### 6.4 审计与回溯要求

- 允许**只读**审计工具按 `agent_id` / `turn` / `tx_type` / `flags` 检索；
- 支持「从 `turn_seal` 任意检查点重放至目标回合」验证哈希链连续性；
- 任何 `hash` 断裂即判定日志被篡改，实验数据作废。

## 8. 已定 / 待讨论

### 8.1 已定（v1 生效）

1. 死亡判定基准 = **净值 `E`**（非现金 `B`）；
2. 组合式判定 = **连续 `N` 回合低于硬地板 + 滞回带 + 死亡冻结宽限**，默认 `θ_floor=-20`、`N_death=3`、`θ_recover=+5`；
3. 生命周期 6 态状态机（ALIVE/WARNING/DISTRESSED/DECEASED/REVIVING/TERMINATED）及迁移条件；
4. 借贷续命准入：低于预警线 + 抵押（LTV=0.6）+ 负债上限 1.0·E0 + 利率随负资产深度上升；
5. 惩罚 ≥3 类可量化：利率惩罚、交易/发言/行动权限冻结、抵押没收、复活冷却；生命惩罚默认关闭；
6. 反作弊 10 类路径 C1–C10 及确定性封堵，核心机制 = **`I_eff` 有效净流入过滤**；
7. 不可篡改日志：只追加 + SHA-256 哈希链 + 每回合锚点 + 字段与统计指标一一对应；
8. 全局安全阀防全灭。
