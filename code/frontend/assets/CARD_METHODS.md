## 0. 手段结论：本机**无可用图像生成**（故插画卡只能"画"）

| 探测项 | 结果（证据） | 结论 |
|---|---|---|
| 内网端点 `/v1/models` | 仅返回 `DeepSeek-Flash`（vllm-frontend-rs，文本模型） | 只有文本模型 |
| `POST /v1/images/generations` | **HTTP 404**（空 body） | **无图像生成接口** |
| `/v1/chat/completions` | 正常返回（文本） | 文本可用、图像不可用 |
| 本地 `baoyu-image-gen`（codex-cli） | 挂起超时（endpoint 不可达） | 不可用 |

**若要走"生成式插画"，需用户提供其一**：① 一个可用的图像生成 API（OpenAI `images` / Stability / 国内文生图 等，含 base_url + key + 可用模型名）；② 或本机可用的 codex-cli/本地文生图运行时；③ 或授权使用某在线服务并给出凭据。
在拿到之前，采用"我方绘制"的可交付替代（下述三法）。

## 1. 三种画法（本次样例：导师指导 / 稀缺抢购）

- **① 像素场景卡**：复用 `assets/peeps.png` 真实像素角色摆位 + 道具/图标徽章 + 中文标签 + 统一边框。**与小镇同源、零新素材**。
- **② 矢量扁平插画卡**：SVG 几何化角色/场景（非像素）、扁平渐变底 + 情绪/语义符号 + 标签。**观感最接近"插画"**。
- **③ 混合卡**：像素角色场景 + 矢量粗边框/标签条/图标徽章。**像素味 + 插画清爽 + UI 感**。

---

## 2. 对比表（供用户勾选）

| 维度 | ① 像素场景卡 | ② 矢量扁平插画卡 | ③ 混合卡 |
|---|---|---|---|
| 观感 | 像素游戏感，与小镇画面统一 | 扁平插画感，干净、偏"图释" | 像素角色 + 矢量 UI 框，介于两者 |
| 制作成本 | **低**（脚本确定性生成，复用现有 peeps/图标） | 中（每卡需手写/生成 SVG，角色与场景需美术设计） | 中低（在①之上叠矢量框/标签） |
| 可扩展性 | **高**（20/50 事件批量、模板复用、缺图退化） | 中（几何模板可复用，但差异化需逐卡设计） | 高（批量 + 统一 UI） |
| 中文标签 | 支持（Noto CJK） | 支持 | 支持 |
| 与 Agentopia 插画差距 | 大（像素≠插画；无手绘光影/表情细节） | **较小**（同为扁平/插画语义；但几何化、无精细人物） | 中（角色仍像素） |
| 与现有前端一致性 | **最高**（同素材同调色板） | 低（新视觉语言） | 中高 |

**建议**：若用户追求"像 Agentopia 插画"→ 选 **②**（后续可用图像生成进一步升级）；若求"快、稳、与小镇统一"→ 选 **①**；折中 **③**。

---

## 3. 与 Agentopia 插画的差距（诚实说明）

Agentopia 参考卡是**手绘/生成式动漫插画**：有完整人物五官表情、动态姿势、环境光影、道具细节（如"倦怠"卡的躺床、"评分分歧"的对话气泡 UI）。我方三法**都无法等价复现**：
- ① 像素卡：**风格不同层级**（像素 vs 插画），信息表达到位但"插画感"弱；
- ② 矢量扁平：**语义与构图接近**，但角色几何化、无精细表情/光影，属"图示插画"而非"叙事插画"；
- ③ 混合：像素角色限制了插画感。
**要真正接近 Agentopia**，唯一路径是**图像生成通道**（见 §0 需用户提供项）。

---

## 4. 接入方案（选定画法后）

- **事件流**：每条事件（`audit.js` 事件流）已有像素图标徽章；可在**事件详情抽屉**里，把该事件类型的卡作为头图（`<img src="assets/generated/event_cards/<id>.png">`），点击展开。低频、不阻塞列表。
- **角色卡**：角色详情面板的"最近事件"区，用对应事件卡做缩略图墙（按 `EVENT_STYLE[type].icon ↔ 卡 id`）。
- **小镇日报**（叙事层周报）：每条故事/事件用卡作配图；卡清单 `assets/generated/event_cards.json` 提供 `id/title/icon/file` 供渲染。
- **协同**：卡片资产在 `assets/generated/`（与 T72 资产库同区，`pixel-asset-artist` 维护）；审计台/详情/日报的**挂载点**由 `frontend-dev` 负责。约定：卡通过 `id`（= 事件英文 slug）索引，`icon` 键与 `EVENT_STYLE[].icon` 一致。
