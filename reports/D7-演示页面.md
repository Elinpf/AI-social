# D7 · 小镇对话观看页面：线程化聊天视图 + 回放

> 交付人：frontend-demo-dev ｜ 用途：让用户**亲眼看到**居民对话——谁跟谁、几轮、什么时候、在哪儿、为什么这么聊；
> 以及「生活气息」能不能被看见（一天的时间轴、谁在串门、闲话怎么传开）。
> 页面：`code/frontend/dialogue.html`（原生 JS，无构建链，可离线打开，600px 可读）。

页面已经能**从真源 run.jsonl 派生出可逐条核对的对话流**，并且每个展示字段都能回指日志 `seq`；

## 4. 页面能看什么

| 区域 | 内容 | 数据来源（可回指） |
|---|---|---|
| 线程卡 | 参与者像素头像 + 姓名 + 角色、渠道（私聊/公开说/群聊）、地点、模拟时间、`thread_id`、轮次数、旧格式标记 | `threads[].*` |
| 消息气泡 | 「第 n 轮 · 说话人」+ 正文 + `#seq`（点击复制） | `messages[].seq/body/turn_index` |
| 为什么这么聊（可展开） | 生成时语境快照（`payload.ctx`）、关系证据（before→after + cause + seq）、当时需求（NEED_UPDATE）、在场/群组证据、本条溯源（seq/msg_id/reply_to/turn_index/refs） | `messages[].context`（均取「本条之前」最近一条真实事件） |
| 顶部时间轴（常驻） | 一天一行 × 四个时段格：对话条数、走动次数（🚶）、私聊/公开/群聊比例色条；点格跳到该时段第一条对话 | `rhythm[]`（日志 day/slot 字段） |
| 节律 · 串门 | ①一天里什么时候在说话（按时段，分子/分母写清）②谁在串门（每人每天场所轨迹 `住宅→农场→市场`，悬停看 seq/时段）③话都发生在哪儿 | `rhythm[]` / `travel[]` / `messages[].place` |
| 闲话怎么传开 | ①转述链 `msg.refs`（**真源**，本批全空 → 明确空态）②同一句话被第二个人说出（**派生口径**：去标点空白后逐字相同、长度≥8、说话人不同；附 seq 列表） | `spread.ref_edges` / `spread.echoes` |
| 回放 | 播放/暂停/上下一条/跳最新、滑杆、0.5x–4x；按模拟时间逐条浮现（同线程 280ms、跨线程 900ms ÷ 速度）；空格=播放暂停，←/→=步进 | `messages[].seq` |
| 筛选 | 只看多轮（一键）、按人物、按地点、线程长度 ≥N、正文搜索；URL 参数可分享（`thread/person/place/min/multi/q`） | 全部来自数据文件 |

## 5. 「生活气息」在这批数据里是什么样（改造前基线读数）

以下全部由 `threads.json` 直接统计（脚本可复算，不是主观描述）：

| 维度 | 读数 | 口径 |
|---|---|---|
| 对话总量 | **187** 条 | `stats.messages` |
| 渠道分布 | 私聊 132 / 公开 48 / 群聊 7 | 按 `msg.type` |
| 覆盖天数 × 时段格 | **7 天 / 28 格** | 日志 `day`+`slot` |
| 带地点的对话 | **139** 条 | `messages[].place` |
| 走动（串门） | **406** 次，**16/16** 位居民都动过 | `PLACE_MOVE` |
| 线程结构 | 187 条线程、**多轮 0**、最长 1 轮 | 改造前 `thread_schema=legacy` |
| 转述引用 | `refs` 全空（0 条可匹配边） | 日志真源，页面显示空态 |

**这就是「改造前的证据」**：一天里有人在说话、有人在串门，但**没有一句话是接着上一个人说的**——
页面把它显示成「每条消息一条线程 + 旧格式标记」，与评测侧的「多轮 0.0%」互为证据。

## 8. 空态与「不伪造」纪律（逐条对应实现）

| 场景 | 页面行为 | 实现位置 |
|---|---|---|
| 旧格式日志（无 `thread_id`） | 橙色提示 + 每条单发 + 标「旧格式·单发」，**自动关掉**「只看多轮」（否则空白） | `src/dialogue.js::prepare/render` |
| `turn_index`/`reply_to`/`ctx` 缺失 | 显示「未记录」，不补值 | `renderCtx` |
| 正文缺失（`body_ref` 侧存储） | 显示 `（正文未写入日志：body_ref=…）` | `renderThread` |
| 关系/需求/在场证据缺失 | 卡片显示「日志未记录（本条之前没有 … 事件）」 | `renderCtx` |
| `refs` 全空 | 「真源没有记录，不用相似度硬凑」 | `renderSpreadPanel` |
| 数据源路径不存在 | **报错并停止加载**，不渲染任何消息，**不回退内置样例** | `loadDefault`（显式 `?data=` 分支） |
| 无对话事件的日志 | 空态提示 + 换日志建议，不白屏 | `render` |

## 10. 复现边界（重要）

产出 `threads.json` 的**复现单元**是：

```
(gen_threads.py 字节 sha + run.jsonl 字节 sha + personas.json 字节 sha + places.json 字节 sha + 参数)
   → 产出 threads.json 字节
```

`threads.json.source` 里已绑定：`generator_sha256`、`run_sha256`、`inputs.personas.sha256`、
`inputs.places.sha256`、`inputs.params`。**换脚本（哪怕只改注释）或换人格文件都会产出不同字节**，
这是特性不是缺陷——报告引用时必须把这几项一起带上。

另外一条实测事实（决定了必须用 `seq` 而不是 `msg_id` 定位）：
改造前日志（`run_d2_before_n16_seed42`，187 条消息）里只有 **74** 个不同 `msg_id`：
**19** 个 id 被复用，最严重的 `D-6-0` / `D-42-0` 各被 **12** 条不同消息复用。
因此页面一律用**全序 `seq`** 作唯一键，报告引用也用 `#seq`（按 `msg_id` 引用会产生歧义）。
复算一条命令：
```bash
python3 -c "import json,collections;\
c=collections.Counter((r['type'],r['payload'].get('msg_id')) for r in map(json.loads,open('v2/evidence/run_d2_before_n16_seed42/run.jsonl')) if r.get('type','').startswith('MSG_'));\
print('msgs',sum(c.values()),'unique',len(c),'dup_ids',sum(1 for v in c.values() if v>1),'worst',c.most_common(2))"
# → msgs 187 unique 74 dup_ids 19 worst [(('MSG_DM','D-6-0'),12), (('MSG_DM','D-42-0'),12)]
```

## 11. 已知边界 / 未做

- 页面只吃 `threads.json`（不直接解析 `run.jsonl`）：解析与聚合口径只保留在 `gen_threads.py` 一处，避免两套口径分叉。
  拖入 `.jsonl` 会提示先跑生成脚本。
- 头像像素立绘按 `agent_id` 哈希选取，**纯展示**，不参与任何语义字段。
- 「同句复现」是**脚本派生**信号（不是日志字段），页面已显式标注口径与 seq，引用时不得当成日志事实。
- 「转述链」当前无数据（改造前 `refs` 全空）；若 A0 之后 `refs` 仍全空，该视图会如实显示空态，不会用相似度凑。
- 未做的：跨批次并按人聚合的「习惯/偏好」视图（属评测侧指标，避免前端重复造口径）。
