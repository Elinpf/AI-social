**⚠️ 读者必读：判断"聊了几轮"看 `turn_index` 分布，不看 `reply_to` 链长**

- A0 的指针语义是「**回指上一轮**」，不是「**逐句串成链**」；
- `turn_index` 在同一轮内**可以有多条**（群聊里多人并发回复）——这是**并发发言的合理形态，不是缺链**；
- 实例 `TH-P009-Gplace-hall-67`：`turn_index` 分布 `0×1 / 1×1 / 2×7 / 3×1 / 4×7 / 5×1` ⇒ **去重 6 个回合、18 条消息**；`turn_index=2` 的 7 条**全部 `reply_to=42:125169`**（同一上轮），彼此不互指；
- **若用 `reply_to` 链长当轮数，会把这段 18 条 / 6 轮的群聊误读成 6 轮不到**，进而错误地得出「多轮效果没那么强」。
> 因此本报告统一口径：**轮数 = `turn_index` 去重后的个数（S-1C）**；`chain_by_pointer` 只作"指针可解析性"辅助，不用于计轮。A0 实测：**206 线程，轮数 p50=2 / p90=6 / max=6**（不是 18）。S-1A「说话人交替段数」max=18 是**交替密度**，与轮数无关。

**指针粒度问题（A0 特有，需解释，不判 FAIL）**：A0 中同一 `turn_index` 可对应多条消息（同轮多人先后发言）。实测 **9/206 条线程存在 `turn_index` 重复**，重复出现 **67 次**；典型 `TH-P009-Gplace-hall-67`：`turn_index=2` 有 **7 条**消息，**全部 `reply_to` 指向 turn 1 的那一条**（`42:125169`），彼此之间不相互指向。
⇒ 这解释了「交替链 18 vs 指针链 6」的差：**不是装配错误**（480/480 指针全部可解析、`ptr_dangling=0`），而是**指针语义为「回指上一轮」而非「串成链」**。D6 作为设计观察项记录，不判失败；如需链式指针，需在下一轮改装配规则。

> **A0 判据提醒**：这一对的比率分子/分母定义随 `thread_id` 落地而改变，**不得套 B2**。结构是否改善，看「指针完整率是否接近 100%」「是否出现多轮线程」这类**阈值型**事实。

**L-13 的成因（强证据，归属 prompt-linguist 的定位 + 我的读数复核）**：
> 泄漏**不是模型幻觉，是提示词层把内部 token 当人话喂了**。A0 的 `_reply_prompt` 把 `ctx.topic` 原样写进提示（形如`你正在和{who}聊「{topic}」`），而 `topic` 就是模板 id；模型于是把 `contest / whisper` 当名词复述。
> 硬证据：**同一模型在 v0（无 `ctx.topic`）泄漏率 0.0%，A0 一引入 topic 立刻 3.94%，且 27 条全部是把模板 id 当名词用**（样本：`（摆摆手）不饿。秀娘，你说那 mentorship 是啥？`）。
> ⇒ 结论写法：**「L-13 是多轮上下文引入的提示词层泄漏，不是模型行为漂移」**，比"模型爱说英文"这类猜测更硬。

**A1-措辞 反向检查项（判据写死，防"掩盖式修复"）**：
1. `L-13 = 0`；
2. **且不靠禁词实现**：若 A1-措辞 通过「主体不得出现这些字符串」这类硬规则达标，判为**掩盖而非修复**；
3. 验收需同时满足：正文不出现内部标识 **且** 该话题仍能被**自然表达**（抽样人读 5 条 + judge 判「是否仍在谈该话题」）。
> 理由：把 token 换成"那个事/那档子事"也能让 L-13 归零，但那不是修复。

**反绿规则**：景物描写 ≠ 生活气息（旁白升则不算改善）；每句塞「昨天」= 套路（须查 L-6/L-7）；编造未发生事件 = 世界观污染（优先级高于任何好看读数）。

## 7.5 窗口效应（会翻转"代价"结论，必须单列）

同一份 A1-措辞（284 条 / 34 回合）与**两种 A0 基线**相比，代价幅度不同：

| 指标 | A0 **整批**（686 条）→ A1-措辞 | A0 **同窗口**（284 条）→ A1-措辞 | 差异含义 |
|---|---|---|---|
| 长度 p50（本报告口径：字数中位数，含标点、去首尾空白） | 54 → 28.5 = **−47.2%** | 48 → 28.5 = **−40.6%** | 整批口径把代价**夸大 6.6pp** |
| 长度 p90 | 97.5 → 53 | 92 → 53 | 同上 |
| 具体性密度（**prompt-linguist 口径，本报告未复算**） | **−12.7pp（破 10pp 线）** | **−9.5pp（差 0.5pp 未破线）** | 整批口径下"破线"，同窗口下"未破线" |

**判读纪律（写死）**
1. **判定一律用同窗口那组**（284 vs 284、94 线程 vs 94 线程、34 回合，分母可对）；**整批口径只作描述**，用于说明"如果拿整批比会得到什么数"。
2. **窗口效应单列为局限**，不得混进"措辞改造的代价"里：本轮可确认的措辞代价是**同窗口口径下的长度 −40.6%（p50）**；`−47.2%` 中有约 6.6pp 来自窗口差异。
3. 口径差异要标：本报告的长度是**字数 p50**；prompt-linguist 的具体性密度是**另一种聚合**（其 −12.7/−9.5pp 我**未复算**，按引用处理，不冒充我的读数）。
4. 因此结论写：**「同窗口下长度显著变短（−40.6% p50），具体性在 10pp 容差边缘（−9.5pp，未破线）」**，不写"长度掉了近一半"。
5. **摘要/结论统一引「同窗口 长度 p50 48 → 28.5 字（−40.6%），口径 = 字数 p50」**；prompt-linguist 的「具体性密度 −9.5pp」作为**另一维度**单列（衡量"具体物/数/由头"覆盖，不是长度）。
6. **全文禁止把 −40.6% 与 −28.8% / −30.5% 混用或互译** —— 三者来自不同聚合方式（字数 p50 / 均值 / 具体性密度），混一次就再也说不清。

## 8. 局限与读数陷阱

1. **同 seed ≠ 同文本**：t300/t355 逐条一致仅 21.3%（收发对/说话人 100% 一致）⇒ 禁止逐条配对比较，一切比较为分布级。
2. **噪声带只有一对批**（t300/t355，自由度 1），不可外推到新规模/新模型/新提示词版本；跨规模用**同分母档**。
3. **B2 退化**：两臂恒 0/恒 1 时 B2=0 不是零噪声，改用 rule-of-three（3/n）。
4. **F-3/F-4 分母 <68**：只能写事件数，不得写率、不得进摘要。
5. **`tokens_out==0` 且 `cached==false` 才是可疑空输出**（v0 实测 0 例；`tokens_out==0` 全为 cache 命中）。
6. **`PromptCapture` 默认 `compress=True`** 会把记录压成 `{"z":...}`，外部读不到 system/user 原文 ⇒ 必须 `compress=False`。
7. **口径纠错记录**：L-8b 曾因实现 bug 得 18.3%，按定义重做后为 0.0%（裸 ID 100% 在台词本体）——见 `D5-评测方法.md` §9.5。
8. **judge 成本**：v0-anchor 中 judge 占 output token **81.3%**（241,528/297,145）；关 thinking 可省约 185k–199k（**估算**，非实测）。
