## 0. 摘要

**【判断】** 本轮最有研究价值的设计不是"改完更好"，而是**能把"好在哪一层"分开**。我们有三条臂，每条只差一个变量：

| 臂 | 结构 | 提示词 | 作用 |
|---|---|---|---|
| **v0-anchor** | 旧（单发消息，无会话对象） | **原提示词** | 起点（唯一历史锚点） |
| **A0** | **新（线程化）** | **必要适配**（显示名/称谓注入、熟悉度/好感、情绪与最紧需求两行、`_reply_prompt` 承接装配） | 同时含"结构改造"与"为多轮成立所必需的提示词适配" |
| **A1** | 新（线程化，同 A0） | **A0 + 措辞层优化**（禁旁白、禁寒暄起句、具体性锚点、口语节奏、情绪呼应、生活气息项） | 单独看**措辞层**贡献（相对 A0） |

于是：
- **结构臂效应** = A0 − v0-anchor（结构改造 **+ 必要适配**，二者在实现上不可分离——多轮承接本身需要提示词装配）
- **措辞层效应** = A1 − A0（结构完全相同，只换措辞）
- **总效应** = A1 − v0-anchor

**【事实 · 限定】** A0 与 v0-anchor 的差**主体是结构效应**（线程化 + 为其成立所需的上下文装配），但**含一处引用方式替换**（`P0xx` → 名字，必要时带熟悉度/好感），属**实现必要项、非措辞优化**；D2 不包含任何「让话更好听」的指令（措辞重写曾短暂写入并**已回退**，见 §2.0 B4/B4′ 记录）。

⛔ **A0 不是"只改结构"**：显示名注入与 `_reply_prompt` 承接装配是让多轮得以成立的必要条件，撤掉它们 A0 就没有多轮。因此 `prompt_sha(v0-anchor) ≠ prompt_sha(A0)` 是**预期且必须**的。

**【判断 · 边界】** 「结构改造 + 必要适配」在本轮**拆不开**：名字注入与承接装配是多轮成立的前提，撤掉即不成多轮，因此无法在保持多轮的同时单独测「只加名字注入」的效果。若将来要拆，需要**额外一臂 A0′ = A0 关掉显示名注入**（`dialogue.names_enabled=false`，其余不变，该开关在 `code/life/agent.py` 已实现），那是下一轮工作；本轮报告不会声称能分开这两部分贡献。

**【判断】** 这比"改造前 vs 改造后"强得多：后者只能给一个混在一起的差值，读者无法知道是"结构让对话变长所以看起来自然"还是"措辞本身变好了"。三方消融把这两个来源拆开，即使最终结论是"其中一层没带来改善"，也是有信息量的结论。

**【事实 · 口径】** 三臂必须同 `n`、同 `rounds`、同 `seed`、同 `provider`、同 `model`；**A1 与 A0 的差别只能落在措辞层提示词**（`prompt_sha` 前后值必须给出，diff 范围必须能一句话说清）。

## 2. 消融设计（这一节是本报告的方法核心）

### 2.0 臂身份表（每臂的代码版本，**不写 master HEAD**）

**【事实 · 待填】** 三臂的 `code_sha` 一律取该臂 `meta.json.code_sha`（复现要用"那批数据当时的代码"，不是当前主分支）：

| 臂 | 结构 / 提示词 | `code_sha`（臂 commit） | `prompt_sha` | `run.jsonl` sha256（sha8） | `provider` / `model` | `admission.verdict` |
|---|---|---|---|---|---|---|
| v0-anchor | 旧结构 / 原提示词 | 待填 | 待填 | 待填 | 待填 | 待填 |
| A0 | 新结构 / **必要适配提示词** | 待填 | 待填（**须 ≠ v0-anchor**，差异须逐项落在成分边界表内） | 待填 | 待填 | 待填 |
| A1 | A0 + 措辞层优化 | 待填 | 待填（**须 ≠ A0**，diff 仅落在 `_dialogue_prompt`/`_reply_prompt`） | 待填 | 待填 | 待填 |

> **跑批树未被报告提交影响（可复算断言，非口头保证）**：`git diff --stat aeb3243..HEAD -- code/life code/orchestration code/config code/engine` **输出为空**。核对时刻 `2026-10-20 18:03–18:04`，核对时 HEAD = `3de31eb`（此后 HEAD 继续前进不影响本断言的可复算性——按上式重跑即可复核）。**归属**：核验方独立核对（首次），撰写方于 `3de31eb` 处复跑一次结果一致。⇒ **A0 实际执行代码 == landing commit `aeb3243`**。

> **更新约定（追加式，不覆盖）**：本断言按时间序列维护——若日后复跑结果为空，**追加新的时刻与 HEAD sha 与空结果，保留旧的时刻**；若某次不为空，同样追加该次记录并说明是哪次改动导致。**不得用新结果覆盖旧记录**，否则读者无法判断哪一句对应哪一版代码。

> 填表纪律：`code_sha` 与 `prompt_sha` 从该臂 `meta.json` 读取；填表时重新 `sha256sum` 校验，不沿用骨架旧值。
>
> **判据（三条硬验，别按旧定义校验）**：① `prompt_sha(v0-anchor) ≠ prompt_sha(A0)`，差异须逐项落在「消融成分边界表」的 D2 提示词改动上（**表外差异 ⇒ 未声明改动 ⇒ 降级**）
   - **依据 = 消融成分边界表** `v2/evidence/d2_ablation_components.md` (**f75454b3**，随 `aeb3243` 入库)：逐项列出结构层 A1–A8 与提示词层 B1–B5（文件 / 函数 / 行范围 / 改动内容 / 意图 / 影响指标 / 开关）。**表外差异一律算「未声明改动」⇒ 降级**。
   - **B4 已回退（必须写明，否则会被当成我们藏了改动）**：`_dialogue_prompt` 曾短暂写入「口语化的家常话 / 不要解释、不要旁白式总结」等措辞指令，**已删除**，当前与基线**逐字相同**；B4 现仅剩「对象由 `P0xx` → 名字（熟悉度/好感）」这一处**引用方式替换**。该表把它单列为 **B4′（已知成分重叠，本轮无法剥离）**，注明「曾写过、已删除」。同理 `_reply_prompt` 也削成中性（「…刚才的对话：{最近≤3轮，按名字}。请接着说一句。」），不含任何「口语化/防旁白/防重复」指令。
   - 相关但**不在本轮**的改动已由该表 §C 明确排除（配额未改、`max_messages_per_slot` 2→4 未进本轮、经济/生命周期/世界层零改动），避免归因串线。；② `prompt_sha(A1) ≠ prompt_sha(A0)`，diff 行范围只落在 `_dialogue_prompt`/`_reply_prompt`；③ `code_sha` 三臂各不相同、`run.jsonl sha8` 各不相同。「对照作废」仅用于差异**无法归因**的情形；能归因的臂称「结构臂（含必要适配）」，正常出结论。

### 2.1 三条臂的身份与差量

- **A0 与 v0-anchor 的差**：结构（线程化）**+ 必要适配**。`prompt_sha` 必须**不相等**，且差异须**逐项落在「消融成分边界表」**列出的 D2 提示词改动上；**表外差异 = 未声明改动 ⇒ 该臂必须降级**。
- **A1 与 A0 的差**：**只有措辞层**。结构、规模、seed、provider 相同；`prompt_sha` 必须不同，且 diff 行范围**只能落在** `_dialogue_prompt` / `_reply_prompt` 区间（逐字 diff 落 `v2/evidence/d4_prompt_diff.txt`）。
- **A1 与 v0-anchor 的差**：总效应，**不能**用它推断"哪一层起作用"。
- **三臂各自一个 commit**：`code_sha` 互不相同，`run.jsonl` sha8 互不相同。

### 2.2 为什么必须做消融而不能只做前后对比

**【判断】** 措辞层指标（旁白率、裸 ID、承接率）会被结构间接影响：一旦消息有了回复对象，模型自然会带人称、少写舞台指示。所以"改造后旁白率下降"既可能来自新提示词，也可能来自"现在有上一句可回了"。**只做前后对比，会把结构红利记在提示词头上**（或反之），从而误导下一轮该往哪投入。

### 2.3 判定规则（先写死，防事后找补）

**【事实】** 每项指标必须给三行：`A0−v0`、`A1−A0`、`A1−v0`，每行都要带**同一分母**与**对应 B2 上界**。判定取值只有三档：

| 情形 | 写法 |
|---|---|
| `\|Δ\| >` 同分母 B2 上界 **且** `> 合并 CI` | 「带外（结构性）」——可写"在本配置/本规模/本 seed 下观测到…" |
| `\|Δ\| >` B2 上界 **但** `≤ 合并 CI` | 「**不足以下结论**」 |
| `\|Δ\| ≤` B2 上界 或 **无可用带** | 「带内，仅印象」/「本规模下无法判定」 |

**【事实】** 三条补充纪律：
1. **不许在三个差量里挑最好看的那个**作为结论——三行都要报，即使某一层没效果；
2. 两臂恒 0 / 恒 1 时 B2 退化为 0 **不是零噪声**，改 `rule-of-three(3/n)`；表中 `band_source` 列必填；
3. 分母 <68 一律标 `probe`；分母 <30 **只报事件数，不报比率**。

## 3. 措辞层方法边界（三条，影响怎么读结果）

**【事实】** ① **mock 不可测措辞**：mock 生成器按输入字符串哈希从词池取句、不读语义 ⇒ 在 mock 上改提示词既不能证明变好也不能证明变坏。**措辞层结论只能来自真 LLM 臂**；`provider` 为空或含 `mock` 的读数表不进对照。
**【事实】** ② **措辞不可逐条复现**：`temperature=0.0` 下，同 seed 同提示词两批日志的台词逐字节一致率仅 **21.30%**（49/230）⇒ 只能做**分布级**比较，不能逐条配对；措辞证据是"冻结快照 + sha"。
**【事实】** ③ **单变量纪律**：真 LLM 迭代必须用副本并登记副本 sha；改提示词会改变缓存键，**不得与旧基线混比**（须重建同配置对照臂）。

| 去重唯一 prompt 数 | 1,207 | 按缓存键去重后的不同请求 |
| **真实网络调用数** | **1,207**（= `count(cached==false)`） | **报成本乘单价只能用这个** |

**【判断】** **调用数虚高 2.41 倍**（`2,905 / 1,207 = 2.41`）；**这不是金额倍数**——金额倍数取决于分 purpose 单价（`judge` 是否开 thinking、`importance` 是否命中缓存的计价规则不同），本报告**未按金额核算**，只给调用数与网络调用数两个口径。乘单价必须用 **1,207**，用 2,905 属口径漂移。v0-anchor 缓存命中率约 **58.5%**（`1 − 1207/2905`）。

**【判断 · 三条可执行的结论】** ① **去重杠杆在 `importance`**（调用多但几乎全缓存）；② **网络调用与输出 token 两个杠杆都在 `judge`**（零缓存 + 输出最长，占输出量 81.3%）；③ 因此降本先动 `judge` 的输出长度与调用频次，而不是压缩 `importance` 的调用数——后者已经被缓存摊薄到近乎免费。

**【判断】** 两条用处：① `narrate` 0 条说明"叙事层"在本轮数据里是空转的，报告不能拿它解释任何现象；② `judge` 占输出 token 八成以上，是后续降本的第一目标——这与"提升对话自然度"无关，但会影响下一轮还能跑多大。

## 6. 可持续核验性（对外）

**【事实】** judge 原始输出为 `judge_raw.jsonl`，体积大、默认不入库。为让外部读者能核验"判分是否被挑过样本"，公开**抽样版** `v2/evidence/judge_raw_sample_n24x2.jsonl`（每臂 24 线程），并满足三条：
1. 抽样文件必须是全量文件**前缀子集**，同一记录**逐字节一致**，不做改写或精简字段；
2. 报告给出全量 sha256、记录条数、抽样条数、抽样规则（seed）；
3. **抽样不含任何未出现在全量中的记录**。

（`.gitignore` 已为此加显式负向规则放行抽样版；全量仍不入库。）

### 6.1 每条 judge 记录必须自带"可回溯到日志"的绑定字段

**【事实】** 每条 judge 记录除判分本身外，还写入：`source_log`（来源日志相对路径）、`source_log_sha256`、`source_log_sha8`、`thread_key`、`msg_ids`（该线程被评消息的 id 列表）、`thread_input_sha256`（送评 transcript 的哈希）。

**【判断】** 这让核验方可以走完一条**不依赖我们口述**的路径：

```
取 source_log（用 source_log_sha256 校验文件没被换）
 → 按 thread_key / msg_ids 从日志中重放该线程
 → 重新拼装送评 transcript → 算 sha256
 → 与 thread_input_sha256 比对
 → 一致 ⇒ 判分对象就是日志里那段对话，没有被替换或改写
```

**只写"已记录"没有意义**——必须能让第三方重算出同一个哈希。这也是本报告族"口径漂移"最容易被抓的地方：同目录里有多份文件名相近、读数接近的真实日志，仅凭文件名无法确定引用的是哪一份，所以 R1/README 另有硬规则：引用日志必须写「文件名 + sha8」。

## 6.5 读数陷阱（两条，核验方会问）

**【事实】** 陷阱一：**`tokens_out = 0` 的调用 100% 是缓存命中**（同批实测 247/247 均带 `cached=true`）。因此判断"空输出/降级"的正确判据是 **`tokens_out == 0` 且 `cached == false`**；只看 `tokens_out == 0` 会把缓存命中误报成"模型没输出"。

**【事实】** 陷阱二：judge 的输入捕获必须 **`compress=False`**。否则记录会被压成单键结构（如 `{"z": ...}`），外部读者读不到 system/user 原文，"可核验"当场失效——这是真实发生过的可复现性陷阱，不是理论风险。

**【判断】** 两条都不影响结果数字，但都会让**核验链断掉**。本报告族宁可多写两段，也不让读者花时间怀疑我们在隐藏什么。

## 7. 限制

1. **措辞不可逐条复现**（21.30% 一致率）：所有措辞结论都是分布级观测，不是"可重跑复现"。
2. **mock 不能验证措辞**：mock 臂只用于行为面回归与规模预估。
3. **单 seed、单批次、单一模拟周**：跨配置外推无证据。
4. **judge 自评偏差 + 样本量仍小**（每臂 24 线程 / ≤72 条），只能作旁证。
5. **三臂的规模必须一致**：若任一臂规模不同，该对比降级为"仅描述"，不进摘要。
6. **"措辞变好"不等于"生活气息"**：后者是另一组指标（R4），两者不可互相代替。
