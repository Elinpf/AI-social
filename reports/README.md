> **三臂命名（全族唯一口径，禁止都叫「baseline」）**：
> - **`v0-anchor`** = **旧结构 + 原提示词**，唯一历史锚点 `run_d2_before_n16_seed42`
> - **`A0`** = **新结构 + 必要适配提示词**（结构：线程字段/msg_uid 等；提示词层必要适配：显示名/称谓注入（`青溪镇·老周`→`老周`）、熟悉度/好感、情绪与最紧需求两行、`_reply_prompt` 的承接上下文装配）
> - **`A1`** = **A0 + 措辞层优化**（禁旁白、禁寒暄起句、具体性锚点、口语节奏、情绪呼应、生活气息项）
>
> ⛔ **不许把 A0 写成"只改结构"**——A0 是「结构改造 + 必要适配」，`prompt_sha(v0-anchor) ≠ prompt_sha(A0)` 是**预期且必须发生**的；若两者相等，说明必要适配没做，A0 反而没有多轮承接。旧版"新结构+旧提示词"的说法已作废。
>
> **三条硬验判据（可机械核验）**
> 1. `prompt_sha(v0-anchor) ≠ prompt_sha(A0)`，且差异**逐项落在「消融成分边界表」列出的 D2 提示词改动上**；表外差异 ⇒ 未声明改动 ⇒ 必须降级。

## 三条通用纪律（全族适用）

1. **每条结论绑来源文件 + sha256**；探针级读数一律原样标 `probe`。
2. **判定三件套**：`|Δ|` / 同分母噪声带上界或 CI / 分母条数——三者未同表出现时，该表必附表注。
3. **截图三件套**：来源 run 目录 + 渲染命令 + 日志 sha256；文件名 `<batch_id>-<视图>-<sha8>.png`。禁止拼图与跨批混拼；拿不到图就写「无图 + 渲染命令」，不替代。
4. **分母 < 30 只报事件数，不报比率**。分母过小时比率会被读者误读为"总体率"，因此只写"6 次张力事件中观察到 0 次修复"这类事件级事实，不写"修复闭环率为 0%"。分母 < 68 的指标一律标 `probe` / 「本规模下无法判定」。
5. **阈值来源单列**：每张读数表带一列 `band_source`，取值 `B2(m=…)` / `rule-of-three(3/n)` / `无可用带`，让读者一眼看出该阈值怎么来的；两臂恒 0/恒 1 时 B2 退化为 0 **不是零噪声**，改用精确二项上界（0 事件时 95% 上界 ≈ 3/n）。
6. **引用日志/证据一律写「文件名 + sha8」**，不允许只写文件名、口头简称或"n20 真日志"这类描述。
   - 写法示例：`run_p1_final_n20_llm.jsonl (fb832372)`、`D3-null-pair-t300-t355.md (79d9ea19)`；`sha8` = 文件 sha256 前 8 位。
   - 为什么必须：仓库里存在**文件名相近、读数几乎相同、sha 不同**的真 LLM 日志——例如 `run_p1_final_n20_llm.jsonl (fb832372)` 与 `run_t136_real_llm_canon_n20.jsonl (7049c272)`，两者 MSG 数只差 1（231 vs 232）、事件数差 1732，事后光看名字分不清引用的是哪一份，"每个数字可复算"会当场对不上。
   - **已声明例外（Leader 批准）**：`数据 / 日志 / 读数 / 证据` 文件 ⇒ 文件名 + sha8（必须）；`源码 / 配置` ⇒ 「**该臂的 commit sha** + 文件:行号」，`sha8` 列写 `TODO（源码随提交变动）`。
   - **跑批相关的源码引用，写「该臂的 commit」而不是 master 的 commit**：读者要复现的是「那一批数据是用哪版代码跑的」。三臂各自的 `code_sha` 取该臂 `meta.json.code_sha`，登记在 R2 §2.1 / R3 §2 的臂身份表；**master HEAD 不能替代臂 commit**。
   - **填数时重算 sha**：骨架里的 sha 是写作当时的当前值；D2/A1 出来后相关文件内容会变，填数时必须**重新 `sha256sum` 再填**，不得沿用骨架旧值（引用过期 sha 是最容易被核验抓到的低级错误）。
   - 证据索引表固定列：`# | 结论 | 层级 | 来源 | sha256 | sha8 | 复现`；无 sha 可填的行，`sha8` 列写 `TODO` + 原因。
