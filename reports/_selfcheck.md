# 口径漂移自检（命令 + 分类 + 每次结果）

> 本文件**只放自检**，不参与报告正文。检查命令一律带 `--exclude=_selfcheck.md`。
> 目的：让"命中数"稳定、可被两个人跑出同一个数——即对拍成立。

## 1. 三组命令（在 `reports/` 下执行）

```bash
cd reports

# G1 旧表述残留（结论性用法应为 0；允许作为规则/机制说明出现）
grep -rn "v0 基线\|baseline\|12 线程\|n12x2\|旧提示词" *.md --exclude=_selfcheck.md

# G2 A0 不得被写成"只改结构"（命中只应是禁止性规则句本身）
grep -rn "A0.*只改结构\|只改结构.*A0" *.md --exclude=_selfcheck.md

# G3 历史日志不得被当作本轮读数来源（只可出现在"近名日志易混"的反例说明里）
grep -rn "fb832372\|7049c272" *.md --exclude=_selfcheck.md
```

## 2. 为什么本文件必须独立存在（自指污染，实测）

第一版把「命令 + 结果说明」写在 `README.md` 里，结果**下一次检查会被自己命中**：
- 撰写方（HEAD `ac7982f`）测得 **4 / 2 / 3**；
- 核验方（HEAD `69ce67c`）复跑测得 **6 / 5 / 4**；
- 差额 2 / 3 / 1 全部来自 README 里的**命令原文行**与**结果说明段**（它们复述了关键词）。

⇒ 同一份文档里放"检查命令 + 结果说明"，会让命中数随文档自身增长而漂移，**最终没人能说清"命中数为什么变"**。
修法：把自检段移出被检查的正文（本文件），命令加 `--exclude=_selfcheck.md`。迁移后两侧均测得 **4 / 2 / 3**。

## 4. 每处命中的"为什么必须在这里"

**G1 的 4 处（均非结论性用法）**
1. `R1-method-and-reproducibility.md`：`obs gate --baseline auto` —— 这是**命令行参数名**，不是"基线"概念；
2. `R3-dialogue-quality.md`：「不同规模批**不可互作基线**」——这是一条**警告**；
3. `README.md`：「三臂命名（全族唯一口径，**禁止都叫 baseline**）」——**规则本身**；
4. `README.md`：「⛔ **不许把 A0 写成"只改结构"**」——**规则本身**。

**G2 的 2 处**：均为 ⛔ 禁止性规则句（`R3` 的「A0 不是"只改结构"」与 `README` 的同义规则），**不是我们在声称 A0 只改结构**。

**G3 的 3 处**：
1. `README.md`：近名日志**反例**（`run_p1_final_n20_llm.jsonl (fb832372)` 与另一份对比），用于说明"为什么引用必须带 sha8"；
2–3. `R5`/`README` 中历史文件的**溯源字段**与实际读数引用无关。

## 5. 判据

- **判据不是"计数为 0"**，而是"**每一处命中都能说明为什么必须在这里**"；把规则句删掉以凑 0 属于拆防线，不接受。
- 两人用同一组命令跑出**同一计数 + 同一分类** ⇒ 对拍成立。
