   - **判据（全族口径，可直接照抄）**：**`payload` 无 `from` 键 ≠ 无线程归属**。C 臂 `MSG_*` 中不含 `from` 键的消息 **55 条**（类型全部为 `MSG_PUBLIC`，发送人写在 `payload.author`；`thread_id` 两两互异 ⇒ **55 个单条线程，全部计入 169 分母**）；B 臂同口径 **53 条 / 170 分母**。
   - **排查三步**：**先数消息 → 再线程去重 → 最后与 `dialogue_metrics` 的 `n_threads` 对账**。
   - **反例（错口径会让 C 反而更高，故全量口径不是偏向任一臂的选择）**：若把这 55/53 条剔除（DM-only 分母），`ge6` 变成 C `52/114 = 45.61%`（虚高 +14.84pp）、B `50/117 = 42.74%`（虚高 +13.32pp）⇒ **C 反高于 B**。全量口径下为 C **52/169 = 30.77%**、B **50/170 = 29.41%**（`metrics_recompute.json` 的两个字段 `n_threads_without_from_key` / `ge6_rate_pct_excluding_no_from_threads` 已复算落盘）。
   - **历史教训（同一对象的另一种误读）**：D2.5a 曾把 55/169 个单条线程**从分母剔除**，使 `ge6` 从 30.77% 虚高到 45.61%，差 8.60pp 的失败差点被写成「差 0.61pp 惜败」（`fa58a93` + runbook §3.119 `5f73676`）。
