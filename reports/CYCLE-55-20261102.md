### 0.4 回放为什么必须钉 `--code-sha`，以及它带来什么边界

`emit_run_meta.py` 默认用**现场** `git rev-parse HEAD` 当 `code_sha`。若直接对 R53 的 run 目录重跑，会把 `code_sha` 写成 `4aaf794`——那是**今天**的树，不是 R53 跑批当时的树，会让「`git diff <code_sha> -- 冻结区`」这一路证据指向错误的比较基线。

故回放一律带 `--code-sha 9f592bfaf6f2bf86f5c79731b82193cd9334ceea`（该 sha 来自两臂 `env_manifest.txt` 的 `code_sha=` 行，见 §① 1.2），输出用 `--out /tmp/...`，**不覆盖原 `meta.json`**：

```bash
python3 tools/d2/emit_run_meta.py --run-dir <R53 臂目录> --out /tmp/meta_<arm>.json \
  --code-sha 9f592bfaf6f2bf86f5c79731b82193cd9334ceea
# → meta.code_sha_source = "arg:--code-sha（事后回放钉住那次跑批的 sha，非现场 HEAD）"
```

**边界**：因此本报告引用的两份新 meta（`/tmp/meta_off.json`、`/tmp/meta_on.json`）是**临时产物**，不是仓内证据文件；仓内可复现的是「跑同一条命令得到同样取值」。原 R53 目录下的 `meta.json` **仍是被旧提取器写的那一份**（`switch_effective` 只有 4 键、`code_unchanged_during_run = null`），本报告把它当作**改动前对照**（§① 1.2 的 BEFORE 列），而不是缺陷未修的现态。
