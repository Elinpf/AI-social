## ③ 仍有问题（含失败 / 不可判 / 已知缺陷）

### 3.1 **尺子口径缺口**：官方出数器认不出 `reply_to`（本轮最重要的一条）

**现象**：对 ON 臂跑官方 `tools/public_talk/public_talk_metrics.py`，得 `msg_graph_degree.pub_in_degree_total = 0`、`reply_to_forms.real_message_id = 0`、`reply_to_forms.other = 7`——**与「7 条真接话」直接矛盾**。

**根因（已定位到代码行）**：尺子用 `msg_ids = {pl["msg_id"] ...}` 建索引（`tools/public_talk/public_talk_metrics.py:422`），而接话的 `reply_to` 里存的是 **`msg_uid`**（形如 `"42:189"`），不是 `msg_id`（形如 `"P-0-0"`）。

**复算（本作者已跑，输出 7 / 0 / 7）**：见 §附录 A-C3b。

> ⇒ **`pub_in_degree_total = 0` 在本轮的读法是「尺子没认出来」，不是「没接话」。** 任何引用该字段的下游文档必须带这句限定，否则会把「机制已生效」误读成「零接话」。

**正面变化（同一份尺子给的）**：`place_adjacency` 由基线的 `UNVERIFIED` 变为 **`MEASURED`**（ON 臂 `nonnull_place_records=30/30`、`numerator_same_place_pairs=11`、`denominator_pairs=29`；`ratio_same_place=null` 因分母 <68 仍 `probe`）。⇒ CYCLE-41 想解开的第 4 组可判性缺口，在 ON 臂上已解开。

**本轮为什么不修**：改 `tools/` 虽不在冻结区，但会让既有历史批次读数失去可比性（同一脚本两套口径），须单独立项 + 重跑历史批次，**不能顺手塞进本周期的 commit**。

### 3.2 `participants` 一致性：ON 臂出现违规（**新发现，本节由本作者首次实测**）

`meta.assertions` 在两臂的差异：

| 断言 | OFF | ON |
|---|---|---|
| `participants_consistent` | **True**（`participants_violations=0`） | **False**（`participants_violations=4`） |
| `msg_uid_unique` | True | True |
| `reply_to_same_thread` | True | True |
| `turn_index_dense` | True | True（`turn_index_gap_threads=0`） |
| `ptr_dangling` / `ptr_cross_thread` | 0 / 0 | 0 / 0 |

本作者用更严的口径复核（`participants` 是否等于该 thread 最终作者集合）：ON 臂 30 条公开消息里 **10 条**不满足（OFF 臂 0 条）。逐条现象：`TH-P013-PUB-0-0` 的 turn0 消息 `participants=["P013"]`，而该 thread 最终有 `P006/P012/P013` 三人。⇒ **`participants` 是「发言当时」的快照，不是 thread 最终参与者集合**；接话把新参与者加进 thread 后，旧消息的 `participants` 未回填。

**影响**：不影响本报告任何判据（PR-1…PR-4 都不读 `participants`），但会让**页面按 thread 展示「N 人参与」时偏小**（这也是为什么 ON 截图里仍能看到若干「1 人参与」的卡片）。**属机制侧遗留缺陷，须下一轮登记处理**，本轮**不修**（改 `code/life` 属冻结区、且会改变已入库机制的行为面）。
