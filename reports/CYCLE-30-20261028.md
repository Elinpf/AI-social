## §二 · 北极星对应：这个读数如何回答「居民对话更有生活气息」

**必须先说清定位**：套话 / 模板化命中率是「生活气息」的**可测量代理之一，不是生活气息本身**。生活气息是一个复合观感（有人味、有具体细节、有来回承接、有跨天记忆），套话率只覆盖其中「措辞是否可替换成任意人说」这一条窄面。

因此本轮只能回答一个**子问题**：

> 把「去量化词 / 回指模板化」这条 prompt 约束叠加上去之后，**居民台词里的套话词与骨架重复是否被压低**？

本轮的答案是：**点估计向下，但不足以声称效果**（数字见 §三、强度自评见 §五）。三条硬限定：

1. **单 seed、无重跑**：只有 `seed=42` 的一次读数，无跨 seed 方差、无置信区间可比性 ⇒ 不构成对北极星的总体结论。
2. **基座已贴地板**：OFF 臂本身就在低位（14 词消息级并集 7.06%、骨架重复 0/510），可压缩空间本来就小 ⇒ 本轮测的是**边际效应**，不是「把套话从高位压下来」。
3. **套话率下降 ≠ 生活气息上升**：即使读数真的向下，也只能说「更少出现这几类套话词」，不能反推「更像真实小镇生活」——后者需要 judge 维度 / 人工盲评等另一套证据，本轮零跑批、没有这套证据。

**为什么这一轮仍值得做**：因为「套话是否被压低」是**可复算、可被第三方重跑**的（脚本 + 日志 + 命令全在盘），而「生活气息」本身暂时没有这个性质。把可测的子问题钉死，才有资格谈不可测的总体。

## §六 · 已知局限与风险

1. **单 seed（最硬的一条）**：两臂仅 `seed = 42`，各一次读数，**无重复、无跨 seed 方差**。所有率类数字都是「这一份日志」的描述性读数，**不得外推为总体效果**。任何「提升 / 改善」表述都必须带「点估计 + 口径 + 限定」，禁用「显著 / 明显」。
2. **`cached_ratio = 0.4951` 必须与「dialogue cached = 0」一起披露**：两臂 `cached=1425 / calls=2878`（`cached_ratio 0.4951`）完全相同，但 **dialogue 段 `cached=0`** ⇒ 1425 次命中全部落在 importance(1387) / negotiation(34) / reflect(4)，**台词层无缓存回放、读数未被缓存污染**。只披露 `cached_ratio 0.4951` 而不说 dialogue cached=0，读者会误以为近半台词是回放；只说 dialogue cached=0 而不说 0.4951，则是隐瞒。两者必须并列。
3. **`n8r16` 与 `n16r60` 尺度不可比（并附 CYCLE-28 论证的更正）**：两批的**分母与轮次都不同**（n8r16：16 agent × 16 rounds、`n_msg=67`；n16r60：16 × 60、`n_msg=510`），样本落在不同轮次区间，**不得把两批 pp 放进同一张表做对比结论**，只能并列「不同尺度的历史读数」。
   ⚠ **同时必须更正 CYCLE-28 §八.3**：该段用「`n8r16` OFF 6.0% vs `n16r60` 79.8%，差一个量级」论证尺度差异，**这一论证不成立**——79.8% 的归属是错的（见下条）。**同 code（`71a6d74`）下**实测：`n8r16` OFF `上回` 4/67 = 6.0% vs `n16r60` OFF `上回` 18/510 = 3.5%，**只差 2.5 pp，不是「一个量级」**。⇒ 该段需重新表述；「跨尺度不可比」这一**纪律**仍成立，但**理由要换成「分母 / 轮次不同」，不能再拿 79.8% 当证据**。
4. **79.8% 的归属更正（本轮真实附加价值之一）**：`v2/evidence/dequant_probe_baseline_71a6d74.json` **文件名误导**——名字带 OFF 臂 sha `71a6d74`，内容实为 `v2/evidence/run_d12d_on_n16r60_seed42` 的读数（`log_sha256 ad0c939f…44ca0`，`code_sha 5ca515d`，`arm_state_check.txt` 原文 `arm=T2 (D12-C ON + D12-D ON)`，env 含 `LIFE_PROMPT_D12C_DEDUP=1` / `LIFE_PROMPT_D12C_SPECIFIC=1`）。其数值**可复现**（`上回` 407/510 = 79.8%、`第三格` 152/510 = 29.8%、`半指` 121/510 = 23.7%、骨架重复 113/510），但**归属错误**：它是**另外两个 prompt 开关全开的实验臂**，不是「基线」，也不是本轮 OFF 臂；且 `5ca515d` 与 `71a6d74` **无祖先关系**（`git merge-base --is-ancestor` → NOT ancestor），属另一条开发线。⇒ 禁止写「79.8% → 1.8%」「套话从高位压下来」「套话已消除」。
5. **OFF 臂 `llmcost_raw.txt` 的形态（对等，但要说清来路）**：该文件本轮才落盘（1161 B / `409fa34f…`），是**事后离线重跑**生成，不是跑批当时 `--out` 的产物；其可信度由「与跑批当时 `stdout_batch.log` 第 13 行 JSON 语义相等、补行尾换行后字节相同」保证。**不标注降级**，但也不得写成「跑批当时就落盘了」。侦察员转述的「1124 B」**复现不出来**，不作依据。
6. **`meta.code_sha` 语义陷阱（工具字段缺陷，延续 R21 登记）**：`meta.json.code_sha` 是「**生成 meta 那一刻的 HEAD**」，不是起跑时钉住的 sha，也不是 `code/` 子树指纹。⇒ 引用代码身份时不要只信它；本报告引用两臂代码身份时同时给出可验证的东西：两臂 `code/` 差异仅 3 个文件（`code/life/agent.py` +151/−5、`code/tests/test_dequant_prompt.py` +150、`code/frontend/README.md` +18），且 `71a6d74` 是 `3888957` 的祖先。
7. **两臂不是同一 sha 的严格 A/B**：严格说是「父提交 + 默认 OFF」对「子提交 + `env=1`」，不是同一二进制翻转环境变量。可认为「代码差异 ≈ 被测特性」，但不等于理想 A/B。
8. **`events` 不等量（116366 vs 116335，Δ=31）**：未做逐条对齐，无法保证事件流一一对应；台词层 `n_msg=510` 同基成立。
9. **「模型遵守指令」未验证**：`prompt_hash` 交集 0 只证「提示词变了」；`provider_guard.ok=true` 只证「调用是真的」。两者都不能替代「模型照做了」——后者本轮无人工判读 / 无 judge 维度证据。
10. **M-0 同日对照不为 0（18.85%）**：M-1 指标捕获了一部分模板复现，解释力打折，已在 §3.4 披露。
11. **基座下移未归因（本轮最大未解）**：套话从 `5ca515d` 的 79.8%（407/510）降到 `71a6d74` 的 3.5%（18/510），**发生在去量化之前、跨分支、本轮未做也未验证任何归因**。⇒ 本轮测的是「在一个已经低套话的基座上再叠一层去量化」的边际效应；「大效果已在别处实现」这一可能性必须承认。
12. **本轮零跑批**：所有读数来自 2026-10-28 20:03–21:20 已完成的既有日志，本轮只做离线读数 / 渲染 / 核验。**新增达标效果项不适用**（本窗口未新起任何实验臂）。
