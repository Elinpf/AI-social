## 0. 一页摘要

**本报告能证明的三件事**
1. 【事实】世界层状态与事件流是**可逐位重放**的（哈希链 + 回合封印 + `replay = reduce(apply_event, …)`），同一日志重放两次状态哈希相等。
2. 【事实】对话的**结构**（谁在何时对谁说、一条消息回复哪条）以事件字段形式落盘，因而线程切分、轮次分布、指针完整率**可被任何人从日志复算**，不依赖作者口述。
3. 【事实】措辞层（台词文本）**不可逐条复现**，但可以被**冻结成快照**并以 sha256 固定；因此措辞结论的形态是"某份具体日志里的观测"，不是"重跑会得到同一句话"。

**本报告不能证明的三件事**
1. 【判断】不能证明"在任何配置下都如此"——本轮只有单 seed、单规模、单批次，跨配置外推没有证据。
2. 【判断】不能证明"措辞变好"可被重跑复现；`temperature=0.0` 下两批同配置日志的台词逐字节一致率仅 **21.30%**（49/230）。
3. 【判断】不能证明 mock 环境下的任何措辞改动有效——mock 生成器**不读语义**（详见 §3 边界 2）。

> 读法建议：只想判断"能不能信"，读 §3；想复算，读 §6 与 §7；想知道我们踩过哪些"看起来跑通了其实没跑"的坑，读 §4。

## 1. 目标与判据

### 1.1 两个阶段的目标

**【事实】** 项目底座是「确定性内核 + 生活层 + 观测层 + 前端」四层，内核按固定六阶段编排：`P0 ROUTE → P1 PERCEIVE → P2 DECIDE → P3 COMMUNICATE → P3.5 LIFE → P4 ARBITRATE → P5 LIFECYCLE → P6 COMMIT`；所有状态变更只经中央裁决器，事件以哈希链追加，每回合末追加回合封印 `TURN_SEAL`（`code/README.md` §3.1–§3.2）。

第一阶段的目标是让居民对话**流畅自然**；第二阶段（现行北极星）升级为让小镇更有**生活气息**——日常节律、闲话与八卦、误会与和解、习惯与偏好、关系张力、跨天记忆引用。两阶段的关系是：**流畅自然是必要不充分条件**，它解决"句子像不像人说的"，生活气息解决"这些句子像不像有人在过日子"。

**【判断】** 本报告只负责"方法可不可信"，不负责"效果好不好"——效果在 R2–R4。之所以先发 R1，是因为读者在读到任何数字之前，应当先知道这些数字的边界在哪。

### 1.2 判据从哪来（不靠形容词）

**【事实】** 指标体系统一编号并固定统计单位：结构层 **per-thread**（S 系列）、话题层（K 系列）、措辞层 **per-message**（L 系列）、效率层 **per-agent-round**（E 系列）、judge 单列 J 系列；**禁止**把 per-message 均值冒充 per-thread，**禁止合成单一"自然度总分"**（内部口径文档 `D5-指标定义-定稿v1.0`；对外引用一律使用其编号）。

**【判断】** "禁止合成总分"不是洁癖：一个 0–100 的"自然度"分数会立刻掩盖"旁白化严重但话题连贯"这类结构性冲突。本报告族宁可给四组互不换算的数，也不给一个好看的总分。

## 2. 系统与方法

### 2.1 确定性内核与重放

**【事实】** 重放语义为 `replay(log) = reduce(apply_event, EventLog, InitialState(seed))`，**不重跑 hook**；未知事件类型立即报错（禁止静默忽略）；门禁要求同一日志重放两次 `state_hash` 相等（`code/README.md` §3.4）。

**【事实】** 随机数由 `SHA-256(canonical_json([seed, stream_id, round, seq]))` 派生子种子，PRNG 为纯整数 SplitMix64；无隐式随机、无墙钟依赖，各随机流相互隔离（`code/README.md` §3.3）。

### 2.2 分工原则：世界确定、措辞非确定

**【事实】** 设计原则为"LLM 只填已定分支的内容，不决定世界随机"——`code/life/llm.py` 文件头原文：*"the life layer never decides world randomness from LLM output; it only fills already-determined branches with content"*。

**【事实】** LLM 输出一次生成后被冻结，重放链路不再调用模型（`code/life/llm.py` 头注释 + 冻结层设计）。

**【判断】** 这条原则直接决定了本报告族的证据形态分裂为两种：
- **结构证据**：可复算、可重放、可被第三方从日志重算 ⇒ 报告可给完整读数与分母；
- **措辞证据**：只能给"某个冻结快照里的观测" + provider/model/温度 + sha256 ⇒ 报告必须同时给出不可复现声明。

**【读数 · 实测印证】** `B1 ≪ B2`（见 §3 边界 3）本身是这条原则的印证：两批同配置真 LLM 日志之间，**说话人序列、渠道序列逐位一致（230/230）**，而**台词的逐字节一致率只有 49/230**。即：结构完全同步，文本大面积不同。

### 2.3 线程化与复算规则

**【事实】** 改造前，每条 `MSG_*` 是**独立单发消息**，消息层没有"会话"对象：`reply_to` / `in_reply_to` / `thread_id` 在代码与文档中无定义；`MSG_PUBLIC.payload.topic` 键存在但恒为空（生成侧从不设置）；`refs`（唯一可能的"指向另一条消息"通道）恒为空数组（`code/life/agent.py:729-767`、`code/orchestration/integration.py:739-841`）。

**【事实】** 改造后采用**只追加字段、不新增事件类型**的方式，在 `MSG_DM` / `MSG_PUBLIC` / `MSG_GROUP` 的 payload 上增加线程字段（`thread_id`、`turn_index`、`reply_to`、`participants`、`ctx`），并在生成侧保证 `thread_id` 唯一。

**【判断】** 方法上最要紧的一处设计是**把"边界规则"与"复算规则"分开**：
- **边界规则**（一条线程何时开始、何时封口）只约束**新生成的世界**；
- **复算规则**（按 `thread_id` 分组、按 `(round, seq)` 升序排序即得线程）对所有日志一致。
这样即使将来调整边界规则，也不会让旧日志的线程切分数字发生变化——读者按复算规则重算，必然得到与报告一致的切分。

**【未完成】** 线程字段的完整契约与回退开关以 R2 为准（R2 发布后此处改为引用）。

### 2.4 评测口径

**【事实】** 前后对照的**主口径**是"说话人交替轮次"：`turns_A = 1 + #{i : speaker(m_i) ≠ speaker(m_{i-1})}`，不依赖 `reply_to`，故改造前后都能算；"往复对数"（依赖 `reply_to`）**只报改造后一侧，不参与前后差**（改造前无该字段，报 0 并标"字段缺失，非缺陷"）。

**【事实】** 碎片化的核心判据是"单条线程占比"，且裁决为**长度 1 的线程不剔除、进入分母**，只单列比例。

**【判断】** 剔除长度 1 的线程会让结果人为好看——这是最容易发生的自欺，所以在方法层直接禁掉。

### 2.5 判据三件套：分母 / CI / 噪声带

**【事实】** 分母门槛（现行口径）：基线臂与对照臂一律 **`MSG ≥ 150` 且 `MSG_DM ≥ 100`**，且需覆盖 ≥12 条不同的 `(day, {from,to})` DM 会话线；低于门槛的批次**只做原文抽查并标 `probe`，不出比率结论**。

**【事实】** 比率 p 在分母 m 下的 95% CI 半宽 ≈ `1.96·√(p(1−p)/m)`；p≈0.5 时 m=100 → ±9.8pp、m=150 → ±8.0pp、m=230 → ±6.5pp。

**【事实】** 噪声带采用**两级口径**（`v2/evidence/D3-noiseband-two-level.md` (12416374)）：
- **B1 观测对差**：同 seed、同提示词、同规模的两批真 LLM 实测差（旁白 0.87pp / 裸 ID 0.87pp / 无人称 1.75pp）。**这是一次观测，不是带**，只作**量级参照**，**不作阈值**；
- **B2 抽样噪声带**：对两批消息级重采样 2000 次（seed 固定），取比率差的 2.5–97.5 分位：**n=230 ±8.7pp；n=170 ±10.6pp；n=100 ±13–14pp；n=68 ±16pp**。**判定阈值用 B2 的同分母上界**。
- **规模适用**：B2 依赖分母；本轮各臂 n=16×84（≈188 条 `MSG`，扣除群消息后有效分母约 170）⇒ 采 **n=170 档**；跨规模（如更大或更小的批）**不适用**，需重估。若某指标未做规模敏感性检验，一律在局限中说明。

**【判断】** 判定表述固定为三档，不给模糊空间：

| 情形（三件同引） | 写法 |
|---|---|
| `\|Δ\| >` 同分母 B2 上界 **且** `> 合并 CI` | 可写「在本配置/本规模/本 seed 下观测到 X 由 A 到 B」 |
| `\|Δ\| >` B2 上界 **但** `≤ 合并 CI` | 必须写「**不足以下结论**」 |
| `\|Δ\| ≤` B2 上界 | 只能写「带内，仅印象」，**不得称改善** |

**【判断】** **B1 是观测、B2 是阈值**——这点必须写死。若用 B1 的 0.87pp 当阈值，任何微小抖动都会被当成"结构性改善"；两次跑差异小只说明那次运气好，不说明分布窄。

**【判断】全族单一阈值纪律（本报告族硬性规定）**：
1. **判定阈值只有 B2**（消息级重采样、同分母上界）。B1、任何"经验阈值"（如曾用过的 `|Δ| > 2pp`）**一律不得作阈值**，只可作量级参照。
2. **不许两种阈值并列后挑好看的那个用**。每张读数表只能有一个阈值来源，且必须写明"该分母 n=… 对应 B2 上界 ±…pp"。
3. **若某指标的 B2 上界宽到无法区分"改善"与"未变"**，一律写「**本规模下无法判定**」，不得改写为"趋势向好"或"初步有效"。
4. 分母与上界必须**同分母匹配**：用 n=170 档的上界去判 n=68 的指标，视为口径错误（应重新抽样估计该分母的上界）。

**【判断】** 这条纪律会砍掉一批原本想宣称的改善。这是有意的：**承认"我们的样本只支持这么大的结论"，比声称一堆 2pp 改善可信得多**。读者据此判断的不仅是我们做得好不好，还有我们是否懂得自己的证据有多薄。

## 3. 可信边界清单（权威版，共 14 条）

> 这是全族唯一的权威版。R2–R5 只写一句"边界见 R1 §3"并列出各自最相关的 2–3 条。

**边界 1 · 措辞不可逐条复现。**
世界状态可逐位重放，但重新生成不会得到同一句话。`temperature=0.0` 下，同 seed、同 provider、同提示词、同规模的两批日志，台词逐字节一致率仅 **49/230 = 21.30%**；`strip` 后与归一化后同为 49/230 ⇒ 差异不是空白或标点造成。同位置说话人 230/230 相同、渠道序列 230 位一致 ⇒ 位置对齐有效；同位置 `seq` 相同仅 28/230 ⇒ **禁止按 seq 对齐**。因此：措辞证据只能以"冻结快照 + provider/model/温度 + sha256"形式引用，比较只能做**分布级**，不能逐条配对。
（来源 `v2/evidence/D3-null-pair-t300-t355.md` (79d9ea19)，在该文内给出的复算脚本为 `v2/evidence/d3_null_pair.py` (bb983b6e)）
**两条不得越界的读法**：① 上例两批树并不完全相同（提示词未变），属**"近似"同配置对**，只能当**噪声下界**，不是"零差异应然值"；② **不得**把 21.30% 当作"复现率下限"去要求别人复现到 21%。

**边界 2 · mock 不可测措辞。**
mock 生成器按输入字符串的哈希从词池取句、**不读语义**。因此在 mock 上：改提示词既不能证明变好，也不能证明变坏——"改了没变好"不构成反证。推论三条：① 措辞层结论**只能来自真 LLM 臂**；② `provider` 为空或含 `mock` 的读数表**不进对照**；③ mock 臂只用于**行为面回归**与**规模预估**（零成本预估 `MSG ≈ 0.14 × n × rounds`）。

**边界 3 · 单批 + 噪声带，不做显著性主张。**
单 seed、单批次。两臂差值须**同时**超过同分母噪声带上界与合并 CI 才可称结论；仅超噪声带而落在合并 CI 内，必须写"不足以下结论"。噪声带用 B2（抽样带），不用 B1（观测差）。

**边界 4 · 冻结与受控解冻（改动范围必须公开）。**
世界层（内核、生活层、冻结层、配置、观测层、契约层、组合根）默认**禁改**；本轮仅对**对话路径**做受控解冻，且必须满足四条前提：① 只追加字段不改既有语义；② 每处改动配回退开关；③ 单变量对照 + 向后兼容不破；④ 交付说明写清"改什么/为何必须/如何回退/影响面"。经济结算、生命周期、世界层数值参数**不在解冻范围**。详见 §5。

**边界 5 · 规模豁免（一次性，不推广）。**
本轮跑批规模纪律原为 `n ≤ 12`、回合 `≤ 24`。因需观测**跨时段的线程延续**，本轮各对比批次经批准豁免至 **84 回合 = 1 个模拟周**（时间结构：3 回合/时段 × 4 时段/天 × 7 天/周，来源 `code/config/default.json` (a94fba10) 与 `code/engine/time.py` 文件头）；批次实际 `n=16`、`seed=42`。豁免理由：24 回合仅覆盖 2 个模拟日，跨时段线程延续几乎不可观测，比率型指标分母也会过小。代价与范围：成本约为常规批 3.5 倍、单批墙钟约 55–90 分钟；**仅适用于本轮对比批次，不推广为通用规模**。

**边界 6 · 副本结论需标副本 sha。**
任何在副本树（非主树）上得到的结论，必须标明副本 sha 并注明"落地需复核"。主树与副本的差异哪怕是无关改动，也可能改变上下文从而改变措辞。

**边界 7 · 所有计数均为事件级，不是人次级。**
本报告族的 `MSG_*` 计数、`LLM_CALL` 计数、指标分母全部以**日志事件条数**为单位，不是"多少人说/说了几次"。凡出现 per-agent-round / per-thread 等统计单位，一律按各自定义使用，**不与事件条数换算**；同一名称在不同层的含义不互相替代（例如"话题"在消息 payload、活动标签、议题统计三处含义不同，不可互引）。

**边界 8 · `meta` 里的 `code_sha` 可能是「meta 写入时刻的 HEAD」，不等于跑批代码。**
已实测发生：A0 臂运行期树是 landing **`3ec85a0`**，但 `meta.code_sha` 写的是 `884f4541`（事后重生成 meta 时的 HEAD）。因此确定「这批数据是哪版代码跑的」必须**三件共同确定**：① `code_sha_start`（跑批开始时记录）；② landing 记录（分支/提交）；③ 期间无改动（`assertions.code_unchanged_during_run` 或等价的起止校验）。**只用 `meta.code_sha` 是错的**；同理，凡引用 `prompt_sha` 必须绑定**运行期树**，而不是 meta 写入时的 HEAD。
> **口径说明（本轮实测补充）**：本仓库当前两批（`run_d2_after_n16_seed42`、`run_g1_b0_n16r60_seed42`）的 `meta.json` **并没有 `code_sha_start` 字段**。可复算的替代证据是：① landing 记录 `v2/evidence/d5_s0a_a0.json` 的 `batch_landing.batch_landing_sha`（= `3ec85a0`）；② `meta.git_status_start_source`（文本，记录"起跑前 code/ 无未提交改动"及其来源）。**引用时须写这两个真实字段，不得写成 `code_sha_start`——那会指向一个不存在的键，读者无法复算。**

**边界 9 · 「指标算了但没变行为」的差值，是定义产物，不是证据。**
已实测：`expired_unanswered_inbound` 两臂分别算出 **38 vs 22**，但**行为逐项相同** ⇒ 该差值是**定义/窗口口径造成的产物**，**不构成"行为差异"的证据**。因此凡出现「某个计数器两臂不同、但行为指标逐项相同」时，必须**单独标注为定义产物**，不得计入结论、不得用于解释机制。
（推论：`config_digest`/日志字节 sha 变化同理——**能变的东西不等于变了的东西**。）

> **判定口径（与发布包一致）**：**判定一律看「行为指标是否逐项相同」**；行为指标逐项相同而计数器/sha 不同时，记「定义产物」，不计入结论。

**边界 10 · 指标与阈值必须同时冻结。**
任何用于判定阈值的指标，必须以**唯一实现（函数源码 + `sha256`）**入预登记；**两种实现并存时，判定值取更保守者**，另一版只能作注。
事故实例：同一 `DETAIL_WORDS` 两个实现使 OFF 相差 **1.04pp**，把 Δ 从 **+3.14pp** 翻成 **+2.09pp**，而阈值恰为 **+3pp** ⇒ **同一份数据得出相反判定**。
（推论：「达标与否」在实现未冻结前不是事实，是可被实现的写法翻转的结论。）

**边界 11 · A0 展示素材须先过 L-13 筛查（词汇层历史 bug 会污染案例）。**
A0 臂（`run_d2_after_n16_seed42`，日志 `643f13a5`，686 条消息）的运行树**早于 L-13 修复**，`ctx.topic` 的内部英文 token 直接进入了台词本体。按「正文含 ≥3 位连续英文词」计数（脚本口径：正则 `[A-Za-z]{3,}`，**不加 `\b`**——中文字符在 Unicode 下算词字符，加了边界会漏计中文夹英文的情形），实测 **27/686 = 3.94%** 命中：`contest` 18、`whisper` 8、`combat` 2、`training` 2、`mentorship` 1。

事故实例：原定对外展示案例 `TH-P009-Gplace-hall-67`（**18 条 / `turn_index` 去重 6 回合**、`group_id` 恒为 `place:hall`、round 67–72、跨 3 个时段）**18 条中 14 条命中**（token 全为 `contest`）⇒ 判定**不合格**，改用零泄漏线程 `TH-P016-Gplace-town_hall-76`（**15 条 / 6 回合 / `group_id` 恒为 `place:town_hall` / 跨 3 个时段 / 命中 0**）。**替换必须写在正文里（"原定案例因 L-13 不合格，改用零泄漏线程"），不许悄悄换**——悄悄换等于让读者以为 A0 没有这个问题。

**边界 12 · 「会话地点」认 `group_id`，`msg.place` 是发言人位置——两者不可混用。**
一条线程的地点应看 **`group_id`**（形如 `place:<place>`，`TH-P009-Gplace-hall-67` 的 `hall` 与 `TH-P016-Gplace-town_hall-76` 的 `town_hall` 都在这里）；而 `MSG` 的 **`msg.place` 是"该发言人此刻所在地"**，可以与会话地点不同（人可以在家/公园插话）。实测（A0 批 `643f13a5`，686 条消息 / 206 线程）：
- 带 `place:*` group 的 **126** 条消息中，`msg.place` 与 group 地点相同的只有 **13/126 = 10.3%**；
- **没有任何线程跨 >1 个 `group`（0/206）**；
- 反例形态：`TH-P009`（`place:hall`，18 条）的 `msg.place` 出现 `hall / park / residence / workshop` 四种；`TH-P016`（`place:town_hall`，15 条）出现 `cafe / park / plaza / residence / town_hall` 五种——**这两种"多值"是同一类东西：发言时刻各人在哪**。

因此：① 凡「同一地点群聊」「跨地点」等叙述，**一律以 `group_id` 判定**；② **不得把 `msg.place` 的去重个数当作线程地点数**（这正是边界 11 初稿的口径错误来源）；③ 若确实要谈"发言位置与会话地点不一致"，那是**另一个议题**（本轮观测到 89.7% 的 `place:*` 群消息由不在该地点的居民发出），不与线程地点混算。

**边界 13 · 同一指标族的多批不可合并计数（"三次结果" ≠ "反复验证了三次"）。**
同一指标族（本项目为 D12-C 人读档位）已跑过 **3 批**，但这 3 批**不是同一把尺子的三次重复**——**抽样框、刻度、判据版本、判读者四项各不相同**：

| 批 | 抽样框 | 判读者 | 判据版本 | 结果与判定档 |
|---|---|---|---|---|
| batch1 | A5 臂 12 条（4–6 轮 8 + 2–3 轮 4，分层） | 双评（两人盲评） | V0/V2 澄清后同批重判（**非盲评**那次数值更高） | 三档 `κ=0.5862`、二值 `κ=0.6250`；**档位只作描述** |
| batch2 | **新样本** 12 条（真双盲） | 核验方 × 新评 | V2 | 三档 `κ3=0.1818`、二值 `κ=0` **退化** ⇒ **`不可判（判据未定型）`** |
| batch3 | 同臂 4–6 轮层 **12 条**（与 batch1/2 零重合；**无 2–3 轮样本**） | 设计者侧 × 独立第三方（**核验方主动弃权**） | v3（**已知漏「骨架复现 ≥3 ⇒ C」**） | 计数格 77/84 = **0.9167**、档位 8/12 = **0.6667**，**均为上界**、**不报 κ** ⇒ **`不可判（无干净第二读者 + 判据已知有缺口）`** |

因此三条硬规则：
1. **不得合并计数**：不能写「三批合计 n=36」「三次里两次不可判」——分母不同框、判据不同版，合起来的分母没有意义。
2. **不得把跨批数字并列成"上升/下降"**：`0.1818`（batch2，κ）与 `0.9167`（batch3，上界一致率）**不是同一刻度**（前者是 κ 点估计、后者是口径可复现性上界，且后者明令不报 κ）；并列比较等于把两种量当一种。若要对比，只能**在同一批内取同一子集重算**并明写"子集重算"。
3. **判定档必须逐批各自引用**：batch2 的 `不可判（判据未定型）` 与 batch3 的 `不可判（无干净第二读者 + 判据已知有缺口）` **理由不同**，不得写成"D12-C 第二次不可判"这类合并叙述（那会把两个不同病因说成同一个病）。
> **附带两条同源纪律**：① **同批重判会把 κ 抬高，不得替代盲评**（batch1 的"澄清后重判"数值高于其盲评数值，即为例证）；② **判据版本升级不等于效力已验证**——v4 已落盘（改 D1 末轮提问 / D2 补回骨架复现项 / D3 词表），但**从未被盲评验证**，且设计者写 v4 前已看过 batch3 原文与自己的判读 ⇒ **v4 ≠ 中性设计**，只能在新批次上验证。

**边界 14 · 尾截断线程不得计入短线程层，也不得作为缺陷类型的证据。**
跑批有轮数上限，**靠近上限才开始的线程在物理上没有足够回合把话说完**——它的"没接上/没回答"是**截断**造成的，不是生成缺陷。判定式（本臂实例：`maxround=41`、`max_turns=6`）：

```
尾截断 ⟺ min_round + T − 1 ≥ maxround        # T = 该线程【实际】轮数（唯一 turn_index 个数）
# r42 算例：maxround=41、max_turns=6 ⇒ 自 min_round=36 起即截断（36+5=41 ≥ 41）；本文件此前写作
#   `min(round) > maxround − (max_turns−1)`，该式用【配置上限】而非实际轮数，会把"起始贴尾但已自然结束"的
#   线程误判为截断（例 min=37、T=2 ⇒ 实际未截断，旧式判截断）。2026-10-29 更正为此式。
# ⇒ 判据与配置无关；「36」只是 r42 的算例，换配置须按该臂 maxround 重算。
```
本臂实测：2–3 轮层共 **8 条**，其中 **4 条为尾截断**（`min(round)` = 39/39/40/40，全部贴着上限）；**有效供给只有 4 条**。批次构成：batch1 = 1 自然 + 3 截断；batch2 = 3 自然 + 1 截断。
三条硬规则：
1. **截断件不计入短线程层的有效分母**——谈"短线程有几条、缺陷率多少"时，分母是**自然短线程**，不是含截断件的总数。
2. **截断件的"未接上 / 未回答"不得判为生成缺陷**。已发生的错例：Q6「回合失接」的旗舰判例 `TH-P015-P011-40`（`min(round)=40`）正是截断件 ⇒ 该判例**不足以支撑该缺陷类型存在**；Q6 的**干净实证支撑为 1 例**（`TH-P001-P009-18`），"2 条样本"一说作废。
3. **"计数"与"证据"分开陈述**：同一批里"判读者判了 2 条 C"是**计数事实**（成立），"该缺陷类型有 2 条证据"是**强度主张**（不成立，只有 1 条干净）。**不得合并成"证据充分"，也不得反向写成"证据为零"。**
> **取数说明（本项目实测的两个坑，别踩）**：`round` 必须从 **`msg_id` 的次末段**取（`G-place:hall-67-1` → **67**；DM 形如 `D-12-1` → **12**）。
> ① **不得取 `msg_id` 末段**——那是 `turn_index`，本臂 8 条短线程的末段**全为 `0`**，会把 `min(round)` 全部算成 0 ⇒ 误判「**0 条截断**」（本文档第一版即如此，已修正）。
> ② **`thread_id` 末段也不能当数据源**（有实测证据，不是推测）：本臂 **113/140 线程**的 `thread_id` 末段恰等于 `min(round)`，**27/140 不等**——**全部是 `-PUB-` 线程**（其 `thread_id` 末段恒为 `0`，而真实 `min(round)` 为 1–3）。关键在于**本批 8 条短线程全是 DM，因而错误取法在这 8 条上 8/8"看起来对"**。⇒ **"错误方法在局部样本上恰好给出正确答案"是最危险的形态：局部对拍会骗人，取法必须按字段语义判定**（`round` 只能从 `msg_id` 次末段取）。
> **来源**：`v2/evidence/d12c_short_thread_tail_truncation.md`（`max_turns=6`、`round 0–41`、523 条消息；`d68ba78`）；该核查由 `batch4-short-thread-spec` 的"DM 且非尾截断"口径触发，属口径修正，不是新实验。

## 4. 静默降级与假跑（本报告最实用的一节）

**【判断】** 这一类问题比"效果好不好"更要紧：一个看起来跑通的批，如果是静默降级到 mock，那么后续所有读数都是假的，而且**不会报错**。

### 4.1 真跑判据（四层，现行）

**【事实】** 配置错误静默、网络错误响亮 ⇒ **"跑批没崩"不能证明跑的是真 LLM**；`meta.json.provider` 是人填的声明，**本身不作为真跑证据**，只作"作者声明"；唯一硬证据是**运行期写入日志的 `LLM_CALL.payload.provider/model`**。硬门禁命令（rc 即判决）：

```bash
cd code && python3 -m obs llm-cost --log <RUN_DIR>/run.jsonl --require-provider openai_compat
# rc=0 且 provider_guard.ok=true  → 通过
# rc!=0 或 problems 非空          → 混入 mock，整批作废（不得进对照）
```

特征值判读：0 条 `LLM_CALL` ⇒ 规则兜底（非真 LLM）；`provider=mock` ⇒ mock 跑；`provider=openai_compat` 且 `model` 为预期模型 ⇒ 真跑（仍需其余三层）。

**【事实】** 三个实际踩过的静默坑：
1. **副本不携带凭据文件** ⇒ 静默回落到 mock，看起来在跑；
2. **`LLM_ENDPOINT` 设成空串**不会回落配置文件，而是直接失败/降级（取决于路径）；
3. **`provider` 写法大小写不匹配**会被判为非真 provider。

### 4.2 另两个"看起来像死了"的坑

**【事实】** ① `--flush-every N` 会把落盘推迟，前 N 回合（可能十几到二十几分钟）日志不增长，据此判"跑完了/挂了"会误判；② `LLM_CALL` **条数 ≠ 实际调用次数**——命中缓存的调用也会各记一条，故"条数 ≥ 实际调用"，报成本必须说明口径。

**【事实】** 转引的两个"同名不同义"陷阱（本项目历史遗留，引用时必须区分）：① 沟通图的边：定向私信 1 条消息 = 1 条边，群消息 1 条消息 = N−1 条边，公开消息在当前实现里**不产生边** ⇒ 不能拿"沟通图密度"论证"公开讨论活跃"；② "哈希链变"与"状态哈希变"是两件事——只追加日志字段会让链变而状态哈希不变，**不得把链变说成行为变**。

## 5. 受控解冻：改了什么、为什么必须、怎么回退

**【事实】** 对话链路的两个靶心（提示词函数、给消息追加线程字段）都位于世界层的冻结区内。本轮的处理是**受控解冻**：只放开对话路径，其余冻结不动。

| 项 | 内容 |
|---|---|
| **允许改** | 生活层的对话生成与提示词、`MSG_*` 追加线程字段、角色显示名注入、对话开关注入 |
| **仍然禁止** | 经济结算、生命周期、世界层数值参数、世界导演的双事件缺陷修复、其他收口事项 |
| **四条前提** | ① 只追加字段不改既有语义；② 每处改动配回退开关；③ 单变量对照 + 向后兼容不破；④ 交付说明写「受控偏离」小节（改什么/为何必须/如何回退/影响面） |

**【未完成】** 四条前提是否逐条满足（尤其②回退开关与③向后兼容）以 R2 的「受控偏离」小节为准；本报告不复述未核实的部分。

## 8. 局限（本报告自身的）

1. **单 seed、单规模、单批次**：所有读数限定在本配置内，不做跨配置外推。
