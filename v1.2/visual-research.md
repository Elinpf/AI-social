## 0. 摘要（TL;DR）

用户抱怨「前端非常丑、和 AI Town 完全不可比」。经无头浏览器实地取证与在线参考调研，结论是：

**当前「青溪镇」的问题不在于「没有素材」（它已经在用 AI Town 同一套 tileset/角色表），而在于「素材的使用方式」——装饰密度、瓦片过渡、角色比例、建筑同质化、配色分层、构图取景这六件事没有做，导致画面呈现为「一片高饱和绿色的噪点地毯 + 一堆同款色块房子」。**

- 素材来源是对的（AI Town `gentle-obj.png` tileset + `peeps.png` 立绘），**不是换素材的问题**。
- 最大单项收益是 **P0-1 降低植被密度并做簇状分布 + 留白**：当前草地上装饰瓦片铺得过密，直接淹没建筑与角色，是「丑」的第一观感来源。
- 其次 **P0-2 统一描边/阴影、P0-3 角色比例与标签、P0-4 中央广场去「灰盘」**。
- 参考已核对：AI Town 仓库、其 README 列出的原始 tileset 出处、像素画可读性禁忌（Pixel Joint 教程）、配色 ramp 方法（Slynyrd）、以及公开 tileset 库（OpenGameArt / Kenney）——**每条附 URL**（见 §3）。

> ⚠️ 重要背景：取证期间前端正被 art-director **高频迭代**（14:39–14:42 连续变更，`sprites.js` 一度存在致命语法错误 `[{ -26 }, { 26 }]`，已在 14:39 修复）。因此本报告的「现状」锚定在 **14:44:06 的冻结版本**（文件哈希见 §1.2），部分 P0/P1 项可能已被 art-director 的后续提交覆盖；本清单仍可作为**验收 checklist** 使用。

## 2. 现状客观描述（基于截图）

### 2.1 「重构前」基线（`baseline_prerefactor_browser.png`）——用户抱怨的那个版本
- **地形/道路**：草地上铺出一条 **深蓝色** 的道路网络（近乎水色），与真正的水塘同色，**路与水不可区分**（疑似 `dirt` 瓦片索引误取到水面 tile）。这是最刺眼的硬伤。
- **装饰**：树/灌木/花/石以 **~1/3 的草地格** 随机散落，画面呈高频「马赛克噪点」，无疏密。
- **建筑**：程序化几何房子（矩形墙 + 阶梯屋顶 + 两个纯色窗 + 门），全部同款剪影，只靠类别底色区分；无描边统一、无投影一致。
- **构图**：建筑集中在中部，四周大片空地无处理，中心以十字形道路连接，缺少焦点与框景。
- **UI**：顶栏 + 右侧固定「审计观测台」+ 底部控制条，通用深色面板。

### 2.2 「当前」冻结版（`demo_run.png` / `engine_run_r20.png`）——art-director 重构中
已明显改善：道路**改为棕色土路**（与水分离）、建筑**换上了带像素屋顶的立绘**、中央**新增圆形广场 + 喷泉**焦点、引入了**审计抽屉**（默认收起，点「审计」按钮打开——属**设计**而非缺陷）、缩放控件、时间条。

仍存在的问题（逐项，均为截图可见）：

**A. 装饰密度过高 → 噪点地毯（最突出）**
- 大量深绿树丛/灌木以极高密度铺满草地（顶部、右侧、底部成片），画面呈「西兰花地毯」；高频斑点与建筑/角色争抢注意力。
- 缺少「留白 + 疏密对比」：建筑周边没有净空带，树直接贴到墙根。

**B. 角色可辨性差 + 比例失调**
- `peeps` 立绘被放大到**接近建筑高度**，人/房比例失真（见 `crop_top_buildings.png`：角色几乎和房子一样高）。
- 角色名标签（`P003` 等）与建筑标签（如「工坊」）**直接叠压**，文字互相盖住。
- 密集树丛中角色**几乎被淹没**，无高亮/描边/落脚阴影来「弹出」。

**C. 建筑同质化**
- 所有建筑仍是同一套「屋顶 + 两窗 + 门」剪影，仅靠**类别底色**区分；窗户是**纯色矩形**（无窗框/反光），屋顶无明暗分级，整体偏「色块」而非「像素道具」。缺招牌/图标/烟囱/遮棚等辨识细节。

**D. 中央广场「灰盘」割裂**
- 广场是一整块**中性灰/白**的圆形铺装 + 灰白喷泉，与周围**高饱和绿**形成突兀的冷灰对撞，像一个「灰色飞盘/陨石坑」贴在地上，与小镇暖调不融合。

**E. 瓦片过渡生硬**
- 草↔路、草↔水、路↔水之间是**直角硬切边**，无过渡瓦/角瓦/边缘不规则瓦；道路为等宽直带，水面为矩形块，缺岸线与波纹。

**F. 配色缺少层次**
- 整体以中高饱和绿为主，缺少明度/冷暖分层；草地、树丛、建筑亮度接近，画面「平」；`app.css` 里已备 `.lighting` 昼夜覆盖层，但观感上**氛围色基本未启用**。

**G. 构图/取景**
- 宽屏（1920）下地图被 `object-fit: contain` 居中，**两侧留大片纯黑边**（见 `demo_run_wide1920.png`），未做「放大填充」或「像素相框」处理；左上图例/时钟**压在画面上**，信息层与地图比例失衡。

**H. UI 质感与美术风格不统一**
- 面板是通用**深色玻璃拟态**（圆角、模糊），与像素地图是两种语言；按钮/滑条为现代扁平《无像素边框/点阵字体》。时间条色块与地图无视觉关联。

### 2.3 一处口径提示
`render_svg.py` 导出的 `baseline_render_svg_preview.png`（棕路 + 稀疏树 + 干净草地）已经接近「目标方向」，但它与**在线 PixiJS 页面曾出现观感不一致**（历史上在线版出现蓝路/密植）。→ 建议把 SVG 导出与在线渲染**对齐到同一份视觉 spec**，避免「导出图好看、在线图丑」的双口径（供 frontend-dev 核对）。

## 5. 可执行改进项（按收益排序，供 art-director / frontend-dev 直接执行）

> 编号含「收益/成本」直觉标注；每项都落到**具体动作 + 建议参数 + 验收点**。

### P0 — 立刻改变第一观感（高收益）
**P0-1　降植被密度 + 簇状分布 + 留白（最高收益）**
- 动作：把 `town.js` 装饰摆放的阈值概率从当前 **≈0.34 下调到 0.12–0.18**；把「逐格随机」改为「**成簇**」——以 3×3~5×5 为簇种子，簇内密度高、簇间留空。
- 加「净空带」：建筑/道路/广场**周边 1–2 格强制无装饰**（现有 `placeRadius` 避让可加大）。
- 增加**留白区**：让每块功能区之间至少保留一条 1–2 格纯草地走廊。
- 验收：截图缩小到 25% 时仍能一眼看清道路骨架与建筑轮廓，不再是均匀噪点。
- 来源：R1 / R4（避免 Noise）。

**P0-2　统一描边 + 落脚阴影 + 单一光源**
- 动作：建筑、角色、装饰一律加 **1px 深色描边**（建议 `#1c2817~#241a12` 量级）与**椭圆落脚影**（角色已有，扩展到建筑/树）；光源统一为**左上前**（受光面亮、右下暗）。
- 来源：R4 / R6。

**P0-3　角色比例与标签可辨性**
- 动作：将角色显示缩放从当前 ~0.95 **回落到 0.7–0.8**，使**角色高 ≈ 建筑的 1/2 以内**；名字标签固定放在**脚下槽位并对建筑标签做避让**（同格冲突时错行）；给「正在说话/移动」的角色加**高亮圆环或描边变色**。
- 来源：R1 / R9。

**P0-4　中央广场去「灰盘」**
- 动作：把广场铺装由中性灰改为**暖石色（偏赭/米）+ 地砖纹理**，灰白喷泉改为**暖石喷泉**；或**缩小圆盘半径**并在圆盘内嵌入绿化岛/花坛，削弱「飞盘感」。
- 来源：R8 / R10。

### P1 — 显著提升精致度（中收益）
**P1-1　建筑差异化**：为 10 个类别各做 **2–3 种剪影变体**（宽宅/窄宅/带烟囱/带遮棚），窗加**窗框 + 反光**，屋顶分**亮/暗两级**，必要时按类别加**招牌图标**（面包房=面包、诊所=十字、学校=书）。
来源：R3 / R7 / R10。

**P1-2　瓦片过渡**：为 草↔路、草↔水、路↔水 补**过渡瓦与角瓦**；道路边缘用**不规则边缘瓦**；水面补**岸线 + 波纹**。缺件可从 Kenney/OpenGameArt CC0 包取（注意许可证登记）。
来源：R2 / R3 / R7。

**P1-3　配色分层（hue-shift ramp）**：给地形/建筑/角色**各建 3–4 阶色阶**；草地整体**压饱和、抬明度**，建筑**提高明度对比**，用整条 ramp 的 hue 偏移保证协调。
来源：R5 / R8。

**P1-4　构图/取景**：宽屏下让地图**放大填充**（必要时允许超过 100% 或用固定放大级）或加**像素风相框/暗角**消除黑边；把**图例/时钟/HUD 收纳到画面外的边栏或半透明收纳条**，减少对地图的遮挡。
来源：R6 / R10。
