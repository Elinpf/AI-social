# D9u 判据 3 核对：**字面表述会误杀，本意完全满足**（旧词 21 个归族计数零变化）

> 用新旧两组快照对跑：**旧 = `narration_family.py` `3dbca76f` + `lexicon` `01e55338`（21 词）；新 = `ba645ea6` + `c9e8924c`（43 词）**。

## 1. 判据 3 的原文与实际结果

**预登记 §4 判据 3**：
> 新词**追加在末尾**前后，历史臂的 `max_v` 变化 **≤1**。
> （理由：R2 是"按表序取首个命中"，插在中间会改变已有片段的归族。）

**实测**：

| 臂 | `max_v` 旧 | `max_v` 新 | 差 |
|---|---|---|---|
| OFF_run1 | 15（`挪`） | **32（`搁`）** | **+17** |
| ON2 | 3（`伸`） | **31（`压`）** | **+28** |

⇒ **按字面，判据 3 严重不通过（+17 / +28 ≫ 1）。**

## 2. 但本意完全满足

**判据 3 要防的是"新词抢了旧词的首次命中位置"** —— 那么应该看的是**旧词自己的归族计数有没有变**：

| 臂 | **旧词 21 个中，归族计数发生变化的个数** |
|---|---|
| OFF_run1 | **0 个** |
| ON2 | **0 个** |

⇒ **21 个旧词，逐个比对，一个都没变。** 追加在末尾完全成功。

**`max_v` 从 15→32 的原因是**：新词成为新的最高频——
- OFF_run1：`搁 32`、推 10、蹲 9、压 6
- ON2：`压 31`、搁 18、翻 14、敲 12、按 11

⇒ **这不是"抢位置"，是"新来的人比原来最活跃的人更活跃"。**

## 3. 结论：判据 3 表述有缺陷（今天第 10 次判据问题）

| 项 | 判 |
|---|---|
| **判据 3 本意**（旧词不动） | ✅ **满足**（0/21 变化） |
| **判据 3 字面**（`max_v` 变化 ≤1） | ❌ 不满足（+17 / +28） |

**⇒ 字面表述会误杀一个正确的改动。** 如果照字面判，D9u 会被判"不合格"，而实际上扩表**完全正确**。

**正确判据（建议替换）**：
> **建成校验：扩表前后，`V_judge` 原有词的归族计数必须逐词零变化**（`{k: old.get(k)==new.get(k) for k in old_set}`）。
> 若某项变化 >0，说明新词插到了旧词之前，违反"追加末尾"。

**为什么不看 `max_v`**：`max_v` 的语义是"最高频动作是谁、多高"，**扩表必然改变它**（新词带来新高频）——它是**结果指标**，不能当**校验指标**。

## 4. 连带两个必须声明的后果

1. **`(d2)` 从 12 → 31（OFF）/ 3 → 31（ON2）** —— 远超门槛 10 ⇒ **`(d2)≥10` 这条护栏在扩表后几乎自动满足**，**失去区分力**（与 `③≥10%` 那次同型）。⇒ **下游若继续用 `(d2)≥10`，必须重新标定**；
2. **`max_v` 换主角**（预登记 §5 已写"不是退步"）：OFF 从 `蹭 15` 变成 `搁 32`；ON2 从 `蹭 3` 变成 `压 31`。⇒ **`(d) max_v ≤5` 这类绝对阈值全部作废**，需按新表重定。

## 4.5 判据 4（六类指标新旧差 ≤15pp）：**天然满足，但有前提**

**先查代码**：`tools/d9s/syntax_shape.py:203-206`
```python
lex = v = parts = objs = None
if split_family:                    # ← 仅 --split-family 时才加载
    lex = nf.load_lexicon(DEFAULT_LEXICON)
    v = nf.v_judge(lex)
```
⇒ **六类分类（`classify`）与 `classify_h4` 都不读 lexicon**；lexicon **只用于 `--split-family` 的 assigned/unassigned 侧别统计**。

**⇒ 因此**：
| 情形 | 判据 4 结果 |
|---|---|
| **不加 `--split-family`**（判据 4 的正常跑法） | **差 0**，天然满足 ✅ |
| **加 `--split-family`** | `fam6`/`fam_old` 的 assigned/unassigned 分布**会随 lexicon 变**（因 `assign_family` 依赖 `V_judge`）⇒ **不可比** |

**实测（ON2，不加 `--split-family`）**：`c1 12.07 / c2 0 / c3 70.11 / c4 6.32 / c5 7.47 / c6 4.02`，`H/log₂6 = 0.5591`，`blocks 174` —— **与扩表前逐位相同** ✅

**⇒ 结论：判据 4 满足；但任何引用 `--split-family` 侧别统计的件，扩表前后不可比。**
