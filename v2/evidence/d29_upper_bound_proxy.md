# D2.9 预估：**骨架多样化最多能把 L-7 降约 10pp（−58%）** —— 但"归一化"会更糟

> 日期：2026-10-24。**离线代理，不是真跑**。B 臂（D2.7，502 条）文本改写后重算，用于判断 D2.9 值不值得跑。
> ⚠ **口径警示**：本件用的是**简化 L-7**（去标点空格后 8-gram、逐条判"是否与已见 8-gram 相交"），
> 与官方 `tools/d5/dialogue_metrics.py` 的 `L-7_dup_ngram8_rate` **不同口径**（官方 B 臂 = 28.49%，本件同批 = 17.73%）。
> **只能读相对变化，绝对值不得与官方数混用**（§3.113）。

## 1. 四种改写下的 L-7（相对变化才是信息）

| 改写 | L-7（简化口径） | 相对原始 |
|---|---|---|
| B 原始 | **17.73%** | — |
| **代理A：只把 `把…{往/在/向/回}…` 骨架旁白归一为占位** | **7.37%** | **−10.36pp（−58.4%）** |
| 代理B：把**所有**旁白归一为同一个占位（上界假设） | 9.38% | −8.35pp（−47.1%） |
| 代理C：剥掉全部旁白（= 台词层） | **3.82%** | −13.91pp（−78.5%） |

## 2. 三条结论

1. **D2.9（句式多样性）收益上限可观**：只动 46.6% 那批"把…往/在…"骨架，就能让简化 L-7 降约 **10pp / −58%**。
   这与"骨架是重复真源"的判定一致（`d27_syntax_skeleton_concentration.md`）。
2. **⚠ 但"归一化"会更糟**：代理B（所有旁白换成同一个占位）**9.38% > 代理A 的 7.37%** ——
   因为把多样文本压成同一串，**反而制造了新的高频 8-gram**。
   ⇒ **D2.9 必须是"真正多样化"（多种句式轮转），不是"统一成一种新句式"**。这是本件最重要的警示。
3. **台词层本身很干净**（3.82%）⇒ 重复问题**几乎全在旁白层**，动旁白是对的。

## 3. 对 D2.9 设计的直接含义

- 方案应是**给 N 种句式骨架按确定性哈希轮转**（如 4–6 种：`把N往P一V` / `V着N说` / `N在手里转了转` / `抬头看了X一眼` …），
  **不是**"禁止'把'字"（禁用会把分布推向另一个单一骨架，重演代理B 的退化）；
- 判据应用**「`把` 开头占比 ≤25%」+「TOP1 骨架占比 ≤30%」**这类**分布指标**，而不是"换了新句式"；
- 并必须设**反向闸**：若改用后 `L-7` 不降反升（像代理B）⇒ 判「无效（同质化）」。

## 4. 局限

- 代理改写是**人工正则替换**，不是模型重新生成；真实效果取决于模型能否真的产出多样句式（可能只会换几个动词）；
- 简化口径与官方口径不同，故只报相对幅度；
- 单 seed 单批；D2.8 正在跑（B:42），本件不占用其结论。
