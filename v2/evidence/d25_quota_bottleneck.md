# D2.5 离线定位：**真正的瓶颈是"每时段 2 条"配额，不是 `max_turns`**

> 日期：2026-10-24。只读分析，OFF 基线 `run_d12c_off_n16r60_seed42`（510 MSG / 16 人 / 60 轮 / 114 线程）。
> 前情：`d24_flow_limits.md` 已测得 `max_messages_per_slot=2` 饱和 **77.7%**、`max_turns=6` 封顶 **45.6%**。
> 本件回答：**这两个上限里，哪一个是"对话被掐断"的真因？** ⇒ 决定下一臂测哪个（单变量只能测一个）。

## 1. 方法（可复算）

对 52 个"恰好 6 条封顶"的线程，检查**最后一条的接收者**在**同一 slot** 里是否还有配额余量：

```
per (agent, slot) 已用配额 used[(agent, slotkey(round))]++      # slotkey = (round//12, (round%12)//3)
封顶线程的最后一条为 A→B：
    used[(B, slot)] < 2  ⇒ 对端本可回，是 max_turns 掐的
    used[(B, slot) == 2 ⇒ 对端配额用光，即使放开 max_turns 也回不了
```

## 2. 读数

| 情形（52 个封顶线程） | 条数 | 占比 |
|---|---|---|
| 对端同 slot **仍有余量** ⇒ 是 **`max_turns=6`** 掐的 | 22 | 42.3% |
| 对端同 slot **配额已用满** ⇒ 是 **`max_messages_per_slot=2`** 掐的 | **30** | **57.7%** |
| 若 `max_messages_per_slot` 放到 **3**：**可解锁** | **52** | **100.0%** |

## 3. 反例检查（这一步决定结论强度）

63? 不 —— 62 个"**没到 6 条就停**"的线程里：

| 情形 | 条数 |
|---|---|
| 最后一条对端 slot **仍有余量**（说明不是配额造成的停） | **2 / 62** |

⇒ **96.8% 的"短线程"也是被配额停住的，而不是自然收尾。**
这两条证据合起来：**`max_messages_per_slot=2` 是主约束，`max_turns=6` 是从约束。**

## 4. 结论（对北极星的直接含义）

- 居民**每时段固定 2 句**，无论聊到哪儿都停 ⇒ 对话必然是"短、齐、机械"。
- 单独把 `max_turns` 6→8 只能解锁 **42.3%** 的封顶线程（其余被配额挡住）；
- 单独把 `max_messages_per_slot` 2→3 可解锁 **100%** 的封顶线程。
⇒ **下一臂应测 `max_messages_per_slot` 2→3`（D2.5a），而不是 `max_turns`（D2.5b）。**

## 5. 局限（如实写）

- 这是**上界估计**：配额有余量 ≠ 对端一定回（还受 `max_turns_per_round`、可见性、"已接过"等约束，以及 LLM 侧是否愿意接）；
- 配额放宽后**总消息量上升**，可能触发新的瓶颈（如 `max_turns_per_round=2` 变成主约束）——真跑必须观察；
- 不能证明"更长 = 更好"：可能只是更啰嗦、更重复。**故预登记必须设复述/重复质量闸**（见 D2.5a 预登记）。
