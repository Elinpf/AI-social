# D2.3 裁决：**「不可测（规模不匹配）」—— 不跑批**，并附两处事实更正

> 日期：2026-10-24。依据：执行方 mock 五项（`c2512ce`，`v2/evidence/d23_mock_verification.md`）+ 本 Leader 复核。
> 预登记：`v2/refs/D23-prereg-place-affinity.md`（`ac82a21`）。**本件在跑批之前作出，未改任何阈值。**

## 1. 阻断项（采纳，且是本件的核心结论）

**一周 = 7 天 × 4 时段 × 3 轮 = 84 轮**；基线 n16r60 只有 **60 轮 ⇒ 不足一周**。
计划（`_weekly_slots`）**一次 run 只在 round=0 做一次**，那一刻**尚无任何消息历史** ⇒
`place_peer_counts = {}` ⇒ **`w ≡ 1`** ⇒ **ON ≡ OFF**（mock 两趟 events 均 33,556、`n_msgs 190 / n_init 45 / same_place 35.56% / repeat 44.44%` 逐项相同，实证 no-op）。

⇒ **本臂在 60 轮规模下不是"效果不足"，而是"数学上恒等于零"**。

## 2. 三条出路的裁决

| 选项 | 裁决 | 理由 |
|---|---|---|
| (a) 规模 ≥85 轮 | **不足**，且否 | 85 轮只到第 2 周的**第 1 轮**，生效期数据近乎为零；要得到"一整周生效期"需 **≥144 轮（2 周）**，成本 **≈2.4×/臂 ⇒ 两臂 ≈4–5h** |
| (b) 改历史取点（周内刷新） | **否** | 属设计变更，动单变量；应单独立项 |
| (c) 承认 no-op、不跑 | **采纳** | 见 §4 |

## 3. 判定词：**「不可测（规模不匹配）」**

不是「无效」，也不是「机制未生效」——机制在**更大规模上**未验证过，此处只是**测不到**。
按 runbook 判定纪律，这一档必须与"无效"分开写，**不得**表述为"近因/地点亲和这条路走不通"。

## 4. 真正的结构性发现（比这个臂本身更值钱）

**当前架构每个 run 只在 round=0 规划一次，周内不重算对端** ⇒
**任何依赖"周内累积状态"（历史共现、近因、记忆）的对端机制，在本项目的跑批规模（≤84 轮）下都不可生效。**
这解释了为什么 D2.2（近因加权）离线为正/为负都无从实测——它同样受此限制。

⇒ **真正该改的不是权重，而是"何时算"**：让 `plan_slot` 只定 `tid`/`place`，把 **`participants` 推迟到发起时刻**按当时历史抽。
这是一次**架构级改动**（会改 `thread_id` 生成时机与计划可复现性），须单独立项、单独预登记，不能塞进现有臂。
