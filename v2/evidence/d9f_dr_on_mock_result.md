## 3. 两组分开证据（预登记 §3 要求，决定"为什么 0"）

### ① 语料局限（主因）
`NEG_WORDS`（18 词）在 H1 的 **929 条 MSG** 上**逐词全 0 命中**。

mock 的 `body` 来自**固定模板池**，池子里没有"你这说的不对"这类冲突句 ⇒ **rift 从未产生，prune/退出机制根本没机会跑** ⇒ amendment 1 的必报量 10–12（`prune` 分类 / `c1·c2a·c2b·c3` 分档 / `has_repair` 命中）**整档不适用，全部 0**。

### ② 合成输入下行为符合预期（**不等于生产路径走到了**）
微测（**未改码**，只调模块函数）：

| 注入 | 结果 |
|---|---|
| 合成负向话 | rift 记 **1 条**（`R\|TH-T1\|u1`，`with=P002`） |
| 同线程再注入和解词 | **注销为 0** |
| `enabled=False` 下注入同句 | **0**（开关真的在起作用） |
| 静态检查 | `agent.py:899 DR.ingest(...)` 位于 `if dr.get("enabled")` 内 |

⇒ **模块在合成输入下能记、能注销、受开关控制**。

⚠ **严格限定（2026-10-29 采纳 `dialogue-core-dev` 的更正）**：这只证明**手段可达**，**不**证明"生产路径真的走到了 `agent.py:899`"——本臂从未产生 rift ⇒ 生产路径是否执行过无日志证据。正确表述是：

> **「合成输入下 `DR.ingest` 行为符合预期」**，而不是「接线正常」。

一般化：**手段的可达性 ≠ 对象的实际发生**（"微测能通" ≠ "生产路径走过了" ≠ "事件发生了"）。与"N 级不许写『未生效』"同族。

0 事件可由"语料无负向词"解释，但**该解释本身也只是候选之一**，不能排除"生产路径未执行"。

## 4. 两处必须写清的更正

1. **`config_digest` 不能归因于 DR**：两臂 digest 不同（H0 `4755a6e6…` / H1 `58485c06…`），但 `dialogue_repair.json` **不在** `FINGERPRINT_FILES`（12 项）⇒ 该差异只可能来自"`window=4` 的表达方式"（H0 用 override、H1 用默认值）。**按分级件，`config_digest` 本就不能当开关证据。**
2. **`T-不可判` 与 `N` 不是一回事**：`T` = 机制跑了但没触达（如 D9b）；`N` = **日志层面无法区分跑没跑**。本批属后者，判词不得混用。

## 5. 这次"失败"真正回答了什么

它把问题从「**DR 机制有没有用**」换成了「**在什么语料上才有负向话**」：

- **mock 永远测不了误会与和解**——不是机制问题，是**语料种类不对**；
- 因此 D9F 的**唯一出路是真 LLM 臂**：只有真模型会生成"我可没答应""你这话不对"这类话，才可能命中 `NEG_WORDS`；
- 这条与六维评估 ③ 的 `CANNOT-VERIFY` 是**两条独立路径的同一结论**。

**与 `D5-01/04/05` 的区别**：那三条是"**语料规模**不够"（多跑几臂可解），本条是"**语料种类**不对"（mock 再多跑也无解）。

## 6. 局限

1. 单臂、单 seed、mock；真 LLM 下 `NEG_WORDS` 命中率**未知**（本件不作任何估计）。
2. 微测用的是合成句，**不代表**真 LLM 会用 `NEG_WORDS` 里的词——词表本身是上游的子集镜像，**可能系统性漏检**（已知保守方向）。
3. 本件**不判** "误会与和解能否发生"，也不判"DR 是否改善生活气息"——两者都需要真 LLM 臂 + 人工读样本。
