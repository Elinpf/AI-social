## 0. 一句话结论（先给判定）

**【判断】主因是样本量，不是词表；词表是二阶放大项（+35% 分母、接住率 +2.8pp）；另有一个必须先排除的第三因素——mock 批（占语料 43% 消息、分母结构性恒 0）。**

三条支撑（全部可复算）：

1. **同一套 18 词表在大批次上接住率非零**：分母 ≥30 的 10 批共 **135/648 = 20.83%**（逐批 9.68%–26.09%，**无一批为 0**）⇒ **尺子是活的**，n16r24 的「四档分子全 0」不是尺子死，是样本不够。
2. **换 v2 词表救不了小规格**：在 n16×r24（191 条消息）参考批上，现行词表分母 **4**、v2 候选词表分母 **8**，**两版分子都为 0**；要在 191 条消息上拿到分母 ≥30，需要机会密度 ≥ **0.1571**，而 n16r24 规模的 28 批里只有 1 批达到（0.1623），中位仅 **0.0288**。
3. **「四档分子全 0」是抽样正常，不是机制失效**：按实测接住率 20.83% 算，`P(分子=0 | 分母=4) = (1−0.2083)^4 ≈ 39%`、`P(分子=0 | 分母=3) ≈ 50%`；而分母 30 时 `P(分子=0) < 0.1%`。⇒ 在 n16r24 上连续观察到 0 命中，**约有一半概率纯属运气**，不构成「尺子死」的证据。
4. **"0.0157 是普遍密度"不成立**：全库逐批密度 p50 **0.0306**、p90 **0.0794**、max **0.1669**；且密度随批次规模单调上升（n16r24 规模 0.0309 → 中批 0.0424 → 分母≥30 批 0.1147）。exp-runner 的 0.0157 落在 n16r24 这一族的**下沿**，不是全库常态。

## 3. 问题 2：要分母 ≥30，需要多大跑批规格（算术链）

**【读数】** 实测换算基准：**msgs / agent-round = 0.559211**（p10 0.529 / p90 0.705，108 批中位）。

**算术链（写进下轮验收标准用）**：
```
期望分母 ≈ MSG数 × 机会密度          ⇔  MSG数 ≈ 目标分母 / 机会密度
agent-round ≈ MSG数 / 0.5592         ⇔  16 agents 时 rounds ≈ agent-round / 16
```

| 用哪个密度 | 密度 | 所需 MSG | 所需 agent-round | 换算规格（16 / 24 / 32 agents） |
|---|---|---|---|---|
| exp-runner 实测 0.0157 | 0.0157 | **1,911** | **3,418** | 16×**r214** / 24×r143 / 32×r107 |
| n16r24 族 p50 | 0.0288 | **1,042** | **1,864** | 16×**r117** / 24×r78 / 32×r59 |
| **全库 p50（推荐基准）** | 0.030612 | **980** | **1,753** | 16×**r110** / 24×r73 / 32×r55 |
| 非 mock 加权 | 0.050631 | **593** | **1,060** | 16×**r67** / 24×r45 / 32×r34 |
| v2 词表 + 全库 | 0.038932 | 771 | 1,378 | 16×r87 / 24×r58 / 32×r44 |
| v2 词表 + 非 mock | 0.068295 | 439 | 785 | 16×r50 / 24×r33 / 32×r25 |

**【判断】** 以「n16 为固定 agent 数、密度用全库 p50」为准，**分母 ≥30 的最小可行规格是 `n16 × r110`（约 980 条消息）**；要留安全边际（密度取 p10 一侧），取 **`n16 × r150`（≈1,340 条消息，期望分母 ≈41）**。当前 n16×r24 只产 **191 条消息 / 分母中位 6.5**，差 **5–7 倍**。

**【判断 · 关于分子】** 分母 30 时若接住率取实测 20.83%，**期望分子 ≈ 6.2**（P(分子=0) < 0.1%）；而分母 4 时 P(分子=0) = (1−0.2083)^4 ≈ **39%**，分母 3 时 ≈ 50% ⇒ **n16r24 上「四档分子全 0」在统计上完全正常，不构成尺子失效的证据。**

**【判断】** 报给用户的数应按**边际率外推**给区间、把线性值当**上界**标注：

**【纪律 · 从本轮两次纠错提炼，可复用】** **凡跨规格外推，必须用边际率（Δtoken/ΔAR），不得用 per-单位均值直接乘倍数。** 本轮有两个同源的坑：① F-3 机会密度被当成"常数 0.0157"，实际是**规模的函数**（0.0309 → 0.0424 → 0.1147）；② token 成本被当成"每 AR 常数 903.8"，实际也是**规模的函数**（903.8 → 449.6–623.7，启动开销摊薄所致）。二者的共同形态是「看起来是常数、其实是规模函数」，故凡外推先问一句：**这个 per-单位量在小样本上是否含未摊薄的固定成本/结构性截断？**

**【未验证】** 边际率由 3 份 r60/r84 批反算，样本仅 3 组、且 `dialogue` 的输入 token 随线程历史变长（in/call 147–373 跨度大），故区间保留得较宽；实际成本还会随并发/重试（`cached`/`degraded`）波动。

## 5. 问题 4：判定与下轮建议

**【判断】归因（按贡献排序）**
1. **样本量是主因（决定性）**：n16×r24 只给 191 条消息、分母中位 6.5；要 ≥30 需 ≈980 条消息（`n16×r110`）。**在 191 条消息这个规模上，"任何合理词表都救不了"成立**——算术上需要密度 ≥0.1571，而 v2 词表在该规模只给到 0.0419（分母 8）。
2. **词表是二阶放大项（真实但不够用）**：v2 让分母 +34.9%、接住率 +2.8pp、可判批数 10→24；**不是**当前不可判的原因，但升级后能把所需规格从 `16×r110` 降到 `16×r87`。
3. **语料族/版本差异是并列需排查项**：同一 n16r24 规模下逐批分母 0–31（10 倍跨度），`run_d12b_off_seed7_n16r24` 在 191 条消息上就拿到 31；原因**未验证**（无 meta.json）。
4. **mock 批是必须先剔除的噪声源**：占 43% 消息、分母结构性为 0。

**【判断 · 下轮最小可行建议】**
- **主要动作：只扩规格，不动尺子。** 取 `n16 × r110`（下限）或 `n16 × r150`（安全边际），跑在**非 mock、真 LLM** 上，分母目标 ≥30（期望 ≈41）。
- **不要**以「改词表」作为本轮主要动作：v2 能让分母 +35%，但**单独换词表在现规格下仍然是分母 8 < 30，仍然不可判**。
- **验收标准建议写成**：`Σden_reply_path ≥ 30` 且排除 mock 批；同时报 `den_all` 作对照；若 `den ≥ 30` 而分子仍为 0，才可判「尺子失效」并启动 v2。
- **顺带必做**：把 `mock|synth` 批从 F-3 统计里永久剔除，并把「强呼应 vs 仅共情词」两列并列报（本轮已证明二者占比约 2:1，混报会夸大"共情"）。

## 7. 限制与分层

1. **行为层读数**：本报告只陈述「词表在这些历史日志上能看见什么、多快能看见」，**不含任何效果层结论**（本轮无 OFF/ON 对照、无干预、无显著性检验）。

4. **`reply_path` 口径在部分批上等于 `all_messages`**（三份对拍批次二者相等），但该等价性未在全库逐批验证；本报告凡用主口径处均同时给了 `den_all`。
5. **v2 词表未生效**：候选件仅作敏感性对照，本报告**不主张**换词表。
