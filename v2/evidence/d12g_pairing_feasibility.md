## Q1 两臂在同一 slot 上逐字相同的比例

slot 定义 = `(thread_id, turn_index, from)`；共 **510** 个 slot 两臂都有。

| 指标 | 值 |
|---|---|
| 逐字完全相同 | **14 / 510 = 2.74%** |

⇒ 两臂**几乎没有任何共同文本**：所谓"配对"只是**位置对齐**（同一世界、同一 slot 编号），**不共享同一句话**。

## Q2 该比例是否随轮次衰减

| 轮次区间 | 相同 / slot | 比例 |
|---|---|---|
| 0–9 | 2 / 91 | 2.20% |
| 10–19 | 1 / 83 | 1.20% |
| 20–29 | 2 / 72 | 2.78% |
| 30–39 | 2 / 86 | 2.33% |
| 40–49 | 3 / 95 | 3.16% |
| 50–59 | 4 / 83 | 4.82% |

⇒ **不衰减**（全程 1–5%，后段甚至略升）。原因不是"轨迹逐步分叉"，而是**从第 1 轮起就分叉**：只要改动候选池，每条消息都不同，随后上下文累积使差异持续存在。⇒ **不存在"前期配对有效、后期失效"的窗口**，整段都只有位置对齐。

## Q3 配对 bootstrap 真实压缩了多少方差

按 slot 对齐、有放回重采样 slot（B=2000 / seed=42）：

| 口径 | Δ | 配对 CI（slot） | 半宽 | 独立 CI（消息级，D12-G 主报告） | 半宽 | 压缩 |
|---|---|---|---|---|---|---|
| `L-7` norm8 | −3.92pp | **[−9.41, +1.37]** | 5.39pp | [−10.20, +2.35] | 6.28pp | **0.89pp（≈14% 相对）** |
| `L-7` raw8 | −4.51pp | **[−10.00, +0.98]** | 5.49pp | [−10.59, +1.37] | 5.98pp | **0.49pp（≈8% 相对）** |

⇒ 配对**没有把 CI 压到能分辨 −4pp 的程度**（仍含 0）。按半宽 ∝ 1/√n 折算：

- 若坚持"跨 run 配对 + 消息级"路线，要把 norm8 半宽从 **6.28pp** 压到 **4pp**，需 **n ≈ 510 × (6.28/4)² ≈ 1,260 条**（且这是**乐观值**，未计线程聚簇，见 `d12g_result.md` ⑦-2）；
- 即"配对 + n"叠加也只是把 n×4 降到 n×2.5 左右，**不改变"必须放大样本"的事实**。

## 建议的三种走法（按可行性排序）

1. **run 内配对（真配对，推荐）**：在同一条消息的**同一上下文**下，同时生成"该结构位 ON 的候选集"与"OFF 的候选集"，在同一轮内比较被选候选的交集数。这样共模噪声（同上下文、同世界状态）被**完全**抵掉——这是本引擎唯一能实现的真配对。代价：`dialogue` 调用翻倍（510 → 约 1,020），但仍**一个 run、同一场景**，不改测量口径。可复算性最好（`scores` 已有 on/off 成对结构即可）。
2. **放大样本**：n ≈ 1,260（消息级乐观）或按线程级 bootstrap 再上浮；**须同时重定窗口/分母**（rounds 变化会改 `L-7` 基线，见 `d12g_result.md` ⑦ 与 leader 预登记禁区）。
3. **放弃效果层显著性判定**：效果层只报点估计 + "不可分辨"，**判定改由机制层指标承担**（`picked` 分布、选中候选的交集均值、`scores` 分布）。**最省且最诚实**，但需预登记明确"本设计不判效果显著性"。

## 边界

- 本实测只覆盖 **1 对臂（T4/T5）、单 seed、60 轮**；不同臂对（如 T1/D12-E）的相同率可能不同，结论"跨 run 配对收益≈0"**在机制上**由"候选池改动 ⇒ 所有文本变"保证，不依赖具体臂对，但仍属**单点实测**；
- 2.74% 的相同率**不作为"两臂太像/太不像"的优劣判断**，只用于说明配对的信息共享量；
- 本文件不产出判定词。
