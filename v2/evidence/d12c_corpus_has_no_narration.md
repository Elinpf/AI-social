# 受测语料本身被剥掉了旁白：A5 臂 `paren = 0.00%` vs A0 臂 `86.01%`

> 核查人：`team-leader`｜2026-10-29｜独立复算，不采信任何口述
> 数据源：`v2/evidence/run_a5_real_n16r42_seed42/run.jsonl`（523 条）｜`v2/evidence/run_d2_after_n16_seed42/run.jsonl`（686 条）
> 起因：在核 batch4 规格的层占比时，顺手核了"台词形态"，结果发现 **D12-C 三批盲评所用的语料（A5 臂）根本没有任何旁白**。

## 1. 事实（同一口径，两条臂并列）

| 指标 | A5 `n16r42`（D12-C 用此臂） | A0 `n16` |
|---|---|---|
| 消息数 / 线程数 | 523 / 140 | 686 / 206 |
| **含括号旁白**（`（…）` 出现在 body 任意位置） | **0 / 523 = 0.00%** | **590 / 686 = 86.01%** |
| 旁白**起句**（body 以 `（…）` 开头） | 0 / 523 = 0.00% | 557 / 686 = 81.20% |

| 开场公式（我这…都…了…先歇） | 2 / 523 = 0.38% | 0 / 686 = 0.00% |

## 2. 这意味着什么（这是本条唯一有价值的结论）

**D12-C 的判据（v3/v4）全部是在"纯台词流"上被设计与检验的**：A5 臂台词**没有动作、没有神态、没有心理旁白，也没有角色名标注**，读者看到的每一行都只有话本身。

因此：
1. **判读者反复报出的"槽位填装""机械开场""句尾硬贴状态尾巴"，在结构上被放大了**——因为生活气息的另一半载体（人一边说一边在做什么）被整条剥掉，所有负担压到台词一句上。
2. **"生活气息"这件事在这批语料上是不可完整测量的**：判据判的是"剩下的台词像不像人话"，不是"这段交流像不像过日子"。**两者不是同一件事，而报告里一直在用前者的分数谈后者。**
3. A0 臂 86% 旁白、A5 臂 0% 旁白，说明"旁白有无"是**臂与臂之间的巨大差异**，**跨臂比"生活气息"档位或文本指标时，必须先声明这一项**——否则等于拿"有动作描写的小说"和"纯对白剧本"比谁更像生活。

## 3. 边界（必须与结论并列，不得省略）

- **这两条臂不是同规模**：A5 是 `n=16 × r=42`（`reply_window_rounds=2`、`HITT_REPLY_BUDGET=1`、`HITT_INIT_PREFER_UNREPLIED=1`，见 `switch_proof.txt`），A0 是 `n=16` 另一批；**规模/参数不同 ⇒ 上表的比率不可当作"改造前后对比"**，只能作"两批语料的形态描述"。
- **旁白 0% 是机制结果，不是随机波动**：523 条里 0 条含括号，不是抽样偏差。
- **本核查未触及"旁白该不该有"的判断**：D2.7 曾判「作废（台词被旁白挤短）」，D2.8/D2.9 又分别判「无效（重复恶化）」「机制未生效」。**本条不重开那个判断**，只登记"当前受测语料没有旁白"这一事实及其对判读的影响。
- 收束套话在 A5（6.88%）**高于** A0（1.75%），但两臂规模不同、且 A5 为纯台词流，**不得据此说"改造后套话变多"**——这同样只能作形态描述。

## 4. 对下游的影响（逐条，不推论）

1. **D12-C 的档位读数**（batch1/2/3）**只在"纯台词流"这一条件下成立**；报告中引用时必须带这句限定，否则读者会以为判的是完整对话。
2. **v4 的判据**（Q2 悬空、Q3 收束、Q5 槽位填装、Q6 回合失接）在 A0 那种"带旁白"语料上**是否仍适用，未经检验**——旁白可能承载"回答"的语义（例：`（低头拨算盘）账要平` 里的动作就是一种回应）。**这是一个未验证的适用性问题，不得默认成立。**
3. **batch4 若起跑**，须在预登记里写死：**本批语料是否含旁白**，因为它直接决定判据的适用范围，比样本量更影响可比性。

## 6. 追加核查（2026-10-29，用于检验"旁白承载回答语义"这一假设）

**先前的猜测**：A0 那种带旁白的语料里，旁白可能承载"回答"的语义（`（低头拨算盘）账要平` 里的动作本身就是一种回应），因此 v4 的 Q2/Q6 在带旁白语料上可能误判。

**实测（A0 臂 590 条含旁白消息）**：

| 指标 | 值 |
|---|---|
| 旁白字数 > 台词字数（旁白是主内容） | **13 / 590 = 2.20%** |
| 去掉旁白后台词 ≤8 字（台词近乎空壳） | **6 / 590 = 1.02%** |
| A5 臂台词长度中位数 / ≤8 字占比 | **42 字 / 0.00%** |

**结论（对先前猜测的修正）**：**旁白在绝大多数消息里不是内容载体，而是伴随动作/神态的装饰**——只有 **2.2%** 的消息里旁白比台词更长。⇒ 「旁白承载回答语义 ⇒ 判据会系统性误判」这一担忧，**证据支持很弱**，不能作为"恢复旁白前必须先重做判据"的理由。

**仍然成立的部分**：那 2.2%（13 条）里确实可能存在"用动作作答"的情形，**这是一个小规模的、边界性的风险，而非系统性风险**；若要核查，范围应限定在这 13 条，而不是全批。

## 7. 方法学提醒（由本节自身产生）

我先前那句「旁白可能承载回答语义」是**未测量的推断**，本节把它量成了 2.2% ⇒ **推断与读数差了一个数量级时，必须以读数为准，并把推断降级为"边界性风险"**。这条与"反推数不得当读数"是同一族纪律，区别只在于：前者是**推断冒充事实**，后者是**减法冒充查询**。
## 8. 口径拆分：81.92% 与 86.01% 都不是错，是两个不同定义

本节由 `dialogue-core-dev` 指出，已复核：

| 口径 | 数 | 占比 |
|---|---|---|
| **起首括号块**（body 以 `（` 开头） | 562 / 686 | **81.92%** |
| **任意位置含括号**（`（…）` 出现在 body 任一处） | 590 / 686 | **86.01%** |

差 28 条 = 旁白**不在起首**的消息（如 `钱，早备好了（递过去）`）。⇒ 引用"旁白率"时必须带口径后缀，**"86.01%"与"81.92%"不得互换、不得取中、不得简写为"约 84%"**。这与 §1 表中"旁白起句 81.20%"也不是同一个量（那一条用的是另一条臂 A0 与"起句"定义，已在本节统一说明）。
