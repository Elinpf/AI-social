# 台词首句的跨线程重复率：A5 3.6% / d1_f6off 5.5%（模板痕迹集中在少数固定句）

> 核查：`team-leader`｜2026-10-29｜只读，未跑批、未改 `code/`
> 目的：给"对话机械不机械"一个**可复算的数**，而不是靠观感。此前"开场模板化"的印象来自个别句（如 `你这会儿练得还顺当吧…`），本文件检验它是否普遍。

## 1. 口径

```
取 MSG 的 body，去掉括号旁白；
按第一个分句切（，。！？；：）；
只留长度 ≥6 字的首句（滤掉「哎」「哟」这类语气词）；
统计：① 同首句重复次数 ② 同一首句出现在几个不同 thread_id（跨线程重复）
```

## 2. 结果

| 臂 | 首句(≥6字) | 不同首句 | 重复首句(≥2次) | **跨线程重复** |
|---|---|---|---|---|
| A5（r42，D12-C 语料） | 280 | **273** | 5 种 / 12 条 = **4.3%** | 4 种 / 10 条 = **3.6%** |
| d1_f6off（r84，batch5 语料） | 380 | **363** | 8 种 / 25 条 = **6.6%** | 6 种 / 21 条 = **5.5%** |

**跨线程重复 TOP（A5）**：`这日子过得真快` 4 线程／`这炉桃酥刚出炉` 2／`日子过得真快` 2／`赵家锄头刚回完火` 2
**跨线程重复 TOP（d1_f6off）**：`这日子过得真快` 7／`日子过得真快` 4／`这炉桃酥刚出炉` 3／`这雨下得人心慌` 3

## 3. 结论（两条，方向相反，必须并列）

1. **开场层基本不模板化**：273/280（A5）、363/380（d1_f6off）的首句**互不相同**；跨线程重复只覆盖 **3.6% / 5.5%**。
   ⇒ 此前"开场模板化"的**印象被数据否掉**：真实的模板句只有少数几条（`这日子过得真快` 系、`这炉桃酥刚出炉`），**反复出现拉高观感，但占比小**。

2. **但语气词高频**：若把"哎/哟/唉"这类单字首句也算进来，重复覆盖跳到 **41.5% / 41.7%**（A5 里 `哎` 单字首句 47/523）。
   ⇒ **这一项不应算作"机械"**：真人说话也高频用语气词。**把 41.5% 当机械度会严重高估**。

## 4. 这条对判据的影响（重要）

- `Q3b`（句尾标签复现）与 `Q7`（骨架复现）**依赖"重复"来判机械**，而本文件显示：**重复在开场层只有 3.6%–5.5%**。
- ⇒ 若某批判出"骨架复现率高"，**必须先排除"是否只是那几条固定模板句被反复抽到"**（`这日子过得真快` 一条就能贡献 4–7 次）。
- ⇒ 与 `D5-02`（Q5 误伤）同族：**判据把"自然语言的高频形式"误当"机械痕迹"**。

## 5. 边界

- 只测**首句**，不测全篇；句中/句尾的复现（Q3b 关心句尾）未测。
- 只测"字符串完全相等"，**不测换皮复现**（Q7 关心的 `钉` vs `钉完`）。
- 两臂配置不同（r42 / r84），**不得据此做"改造前后"对比**，只能作两个语料的形态描述。
- 未做显著性检验，不写"显著"。

## 8. 追加：复现类判据应带"跨线程基线分母"（由 prompt-linguist 提出，采纳为 v5 设计输入）

**问题**：`Q3b` / `Q7` 只看"本线程内复现次数"，不看"该形式在本臂里本来就多常见"。于是两种东西会被混为一谈：

- `哎` 这类**正常高频**（A5 47/523）——在短样本里很容易"看起来复现"；
- `这日子过得真快` 这类**跨线程模板**（A5 4 线程 / r84 7 线程）——它的"复现"来自**跨批次共用开场**，不是本线程内部生成。

**做法（v5 待实现，本文件只登记）**：

```
对任一候选短语/骨架 s：
  base(s) = 本臂全库中"出现 s 的线程数" / 本臂线程总数      ← 跨线程基线
  in(s)   = 本线程内 s 的出现次数
  判据    ：只有当 in(s) 相对 base(s) 显著偏高（且剥离语气词后仍成立）才计复现
```

**不做的**：本文不给显著性阈值（那需要预登记），也不改 v4/v5 任何条文。

**实例（已发生）**：batch5 #12 `TH-P007-P002-51` —— 唯一 3 回合线程 + 最高频模板 `这日子过得真快`（7 线程）+ 前置语气词 `唉`，**三重危险形态叠加**。本批未误判仅因 `Q7` 阈值是 `n≥3`；**若 v5 把阈值降到 `n≥2`，此条立刻成为误判源**。

## 9. `n≥3` 是"临时护栏"，不是校准过的阈值（由 prompt-linguist 指出，采纳）

**关键区分**：`Q7` 现在用 `n≥3`，**不是因为 3 被校准过**，而是因为**"跨线程基线分母"这个补丁缺位**——严阈值在替代它。

```
n≥3：'这日子过得真快' 在本线程只 1 次 ⇒ 不触发 ⇒ 正确（#12 未被误判）
n≥2：若把"跨线程共用开场模板"与"本线程内部复现"合并计数 ⇒ 立刻满足 ⇒ 误判为复读
```

⇒ **降阈值的真正代价不是"更敏感"，而是"必须先把跨线程基线剥离出去"，否则敏感度提升的全是假阳性。**

**两条必须一起引的结论**：

1. `n≥3` 是**补丁缺位时的临时护栏**，不是经过校准的选择；**不得以"n≥3 太严、样本凑不齐"为由单方面降阈值**；
2. 若确要降，**前置条件是 §8 的基线分母先落地并生效**——否则 `#12` 这类"唯一 3 回合 + 最高频模板 + 语气词前置"的线程会立刻变成误判源。
