## 4. 分母自证（必须先自证，再谈比例）

1. **线程分母与官方读数器对账**（`dialogue_metrics` 的 meta 是另一套分组：`T:<thread_id>` / legacy `L:day|channel|pair`）：

   - 两臂 `thread_schema` 均为 `explicit`（无 legacy 兜底参与计数）。
2. **发送人字段缺 `from` 的线程（runbook §3.119 的"匿名"侧）——已逐条确认纳入分母**：
   - `MSG_PUBLIC` 的 `payload` **没有 `from` 键**，发送人取自 `payload.author`；"`from` 与 `author` 都为空"的消息数两臂**均为 0**。
     ⚠ **这个 0 只说明「发送人彻底缺失」不存在**，**不得**据此推「匿名/缺 from 线程数 = 0」——匿名侧的真实量是上一行的 **C 55 / B 53 个单条线程**。
   - 缺 `from` 的消息：**C = 55 条（全部 `MSG_PUBLIC`）/ B = 53 条**；其 `thread_id` **两两互异**，线程规模分布 **C = {len1:55} / B = {len1:53}** ⇒ 即 **C 55 / B 53 个单条线程，且这两批线程已全部在 169 / 170 分母内**（与 runbook §3.119「55/169」一致）。
   - **剔除反例（证明"纳入"不是把比例做高）**：把这 55/53 个单条线程从分母剔除后，`ge6` 变为 **C 52/114 = 45.61% vs B 50/117 = 42.74%** ——
     剔除反而使 **C 更高、B 更低**，C−B 差从 −1.36pp 扩大到 −2.87pp。⇒ 纳入这些线程**不改变方向、也不是为了让 B 好看**，分母口径必须保持"全量 thread_id 去重"。
   - 另注：D2.7 的"旁白"是**写在正文括号里**（`（…）台词`），不是独立消息 ⇒ 旁白本身不产生额外线程；这里说的 55/53 是 `MSG_PUBLIC` 的 `from` 键缺失，**与旁白无关**，不得混为一谈。
3. **`ge6` 分母**：`ge6_rate = 消息数≥6 的线程数 ÷ 该臂全部 thread_id 去重数`，即 C 52/169、B 50/170；两臂分母口径相同（均为 169/170 全量），可直接比。
