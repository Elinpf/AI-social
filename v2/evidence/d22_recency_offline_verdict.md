# D2.2 预登记前离线裁决：**近因加权对端选择 —— 不值得跑批**（+ 一个可复用的零成本模拟器）

> 日期：2026-10-24。工具：`tools/d21/d22_recency_feasibility.py`。
> 目的：在写 D2.2 预登记、花一次 ~52 分钟跑批之前，用**离线模拟器**判定"近因加权选对端"是否可能有效。
> 结论先说：**16 组参数全部为负或零 ⇒ 不写预登记、不跑批**；但顺手拿到两件更有用的东西（§1、§3）。

## 1. 意外收获：对端选择可**精确离线复现**（114/114 = 100%）

```
master 代码：planner._participants → _pick(f"{agent}|{slot_id}|{tid}|p{i}", rem)
            _pick(seed, opts) = opts[int(sha256(seed)[:8],16) % len(opts)]
            slot_id = f"day{dow}-{slot}"，rem = 全部 peers（sorted，15 人）
离线反推：  dow = round // 12；si = (round % 12) // 3；slot = SLOTS[si]
            （default.json: ROUNDS_PER_SLOT=3，SLOTS_PER_DAY=[morning,afternoon,evening,night]）
```
⇒ 用该式在 OFF 日志上重放 114 次发起，**命中 114 次（`self_check_orig_matches_actual_rate = 100.0%`）**。
**意义**：任何"改对端选择"的臂，都能在**零 LLM 调用、零跑批**的前提下预估换人率与指标变化。
此后凡涉及 `_participants` 的候选，先跑模拟器，再决定要不要开跑批。

## 2. 三方对照（这一步是本件的方法论核心）

只比较"新策略 vs 现状"会把**换抽样函数**带来的伪影当成机制效果，故设三档：

| 档 | 定义 | 作用 |
|---|---|---|
| **A** | 原 `_pick`（`% len`） | 复现现状（自检 100%） |
| **C** | **等权**加权抽（w≡1，走累积权重轴） | 只保留**映射差异**，机制为零 |
| **B** | 近因加权抽（w=1+α·exp(−Δ/τ)） | 映射 + 权重 |

读数（OFF 基线，`repeat_pair_rate`）：

| 档 | repeat_pair_rate |
|---|---|
| A 现状 | **42.98%** |
| C 等权（纯映射） | **48.25%**（**+5.27pp，纯伪影**） |
| B 加权 | 42.11%–48.25%（随参数） |

⇒ **仅"把 `%len` 换成累积权重轴"就能把重复率抬高 5.27pp，与机制无关。**
若不设 C 档，会用 B−A = +3.51pp 报"机制有效"，**而机制真实效应是负的**。

## 3. 网格扫描：16 组 (α, τ)，**无一为正**

`α ∈ {0.5,1,2,4}` × `τ ∈ {5,10,20,40}`，全部读数在 `v2/evidence/d22_recency_grid_16.json`：

| α \ τ | 5 | 10 | 20 | 40 |
|---|---|---|---|---|
| **0.5** | −4.39 | −4.39 | −4.39 | −4.39 |
| **1** | −1.76 | −1.76 | −2.64 | −1.76 |
| **2** | **0.00** | **0.00** | −1.76 | −1.76 |
| **4** | −4.39 | −6.14 | **0.00** | −5.27 |

（单位 pp，= `repeat_pair_rate_weighted_B − repeat_pair_rate_equalweight_C`，即**权重净效应**）

**12 组为负、4 组恰为零，最好也不过 0.0pp。** 加大 α 反而更负（α=4 最差 −6.14pp）。

## 4. 为什么是负的（机理，如实写）

"最近聊过的人更可能再被抽到"听起来必然抬高 `repeat_pair_rate`，但这里有反作用：
权重把质量**集中到少数近期对端**后，`repeat_pair_rate` 的分子（"这对此前出现过"）与分母（本次选中落到的对）**同时重排**——
被挤出去的那些"此前出现过的一对"不再命中，而被集中进来的少数对端本身名额有限、很快被"用完"。
在 16 人 / 114 次发起 / 5 天的规模上，**集中 ≠ 重复**：集中减少的是"不同对端数"，重复率取决于序列结构。
⇒ 这与此前 D12 系列的核心发现同型：**动一个旋钮，另一个指标反向**。

## 5. 裁决与后续

**裁决：D2.2（近因加权对端选择）不上预登记、不跑批。** 依据是本件的 16 组网格（可复算），不是"感觉"。

**留档的两条通用规则**（已写入 runbook）：
1. §3.115：**凡改抽样函数的臂，必须加"等权对照"**（同映射、机制为零），否则 +5pp 级别的伪影会被当成机制；
2. 上表这种"净效应全负"的候选，**在模拟器阶段就该否决**，不要进跑批队列（省 52 分钟/次）。

**下一嫌疑点**（方向调整）：既然"谁重复出现"由序列结构而非权重决定，那么真正该动的是
**"按什么维度组织对端"**（同地点 / 同职业 / 同关系），而不是"给现状对端加权"。这条要与 `place` 打通才有生活质感，
而当前 `_participants` **连 `place` 都不读**（D2.2 诊断 §0 已证实）——那才是更可能的真缺口。
