# D2.9 实现方案离线验证：**`轮转 + agent 起点 offset` 分布极均匀（极差 1.5pp）**

> 日期：2026-10-25 02:58。纯离线复算，用 D2.8 B:42 的**真实旁白序列**（按 agent 计数推进），验证执行方的实现方案。

## 1. 执行方的方案（我复核采纳）

```
skel_offset(agent_id) = int(sha256(agent_id)[:8],16) % 5          # 每个 agent 的轮转起点
skel_idx(narration_ordinal, offset) = (narration_ordinal + offset) % 5
```

**它比我的建议多走了一步**：我只提议"按旁白序号轮转"，但**若所有 agent 都从 0 起轮转，每个 agent 的第一条旁白都会落 `skel 0`**（"把"字骨架）⇒ 16 个 agent ⇒ `skel 0` 被系统性抬高。执行方加了 `agent_id` 哈希起点，把这个偏置消掉了 —— **这是我没预见到的细节，采纳**。

## 2. 离线复算（用真实旁白序列，n=141 条带 `from` 的旁白）

| `skel_idx` | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| 条数 | 28 | 28 | 29 | 29 | 27 |
| 占比 | **19.9%** | **19.9%** | **20.6%** | **20.6%** | **19.1%** |

**极差 = 1.5pp**（对比：原 `sha256(tid|turn|skel)%5` 的极差 **8.1pp**）。

⇒ **`20±3pp` 的 mock 容差现在真的可用**（5 类全部落在 19.1–20.6%）。
⇒ 判据 `骨构 ≤20%` 也不会再被 `skel 0` 顶破（它现在是 19.9%）。

## 3. 各 agent 的轮转起点（可复算）

`P001:2 / P002:3 / P003:3 / P004:0 / P005:0 / P006:1 / P007:1 / P008:3 / P009:0 / P010:0 / P011:4 / P012:3 / P013:1 / P014:1 / P015:1 / P016:0`
（`sha256(agent_id) % 5`，与 `para_on` 的 `sha256(tid|turn)` **无共同输入** ⇒ 两变量构造上独立）

## 4. 结论

- **方案成立，且优于原预登记写法**：分布均匀性从 8.1pp 极差改善到 1.5pp，`±3pp` 容差可用；
