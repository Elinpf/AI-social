# D2.1-A2 诊断：**"对未回对端发起"在量产日志里占多少**（跑批前先量，避免白跑 50 分钟）

> 日期：2026-10-24。工具：`tools/d21/a2_incidence.py`（新增，可复算）。
> 目的：A2 代码已落分支（`913ac4d`，`HITT_NO_INIT_UNREPLIED`，默认关）但**无预登记、未跑批**。
> 在写预登记、花一次 50 分钟跑批之前，先用**已有日志**量出 A2 会拦掉多少条发起。

## 0. 复算命令

```bash
python3 tools/d21/a2_incidence.py \
  --log OFF=v2/evidence/run_d12c_off_n16r60_seed42/run.jsonl \
  --log D12I_on=.worktrees/d12i-aligned/v2/evidence/run_d12i_aligned_n16r60_seed42/run.jsonl \
  --out-json v2/evidence/d21_a2_incidence.json
```

## 1. 读数（两臂完全相同）

| 量（口径后缀见 §2） | OFF（T0 基线） | D12-I ON |
|---|---|---|
| `n_msgs_total`（MSG 三类） | 510 | 510 |
| 进分析的条数（有 `from` 且有序号） | **455** | **455** |
| `n_init_with_to`（`turn_index==0` 且有 `to`） | **114** | **114** |
| `n_init_owed_any`（对方找过我、我没回过，此后仍发起） | **30** | **30** |
| **`init_owed_rate_any`** | **26.32%** | **26.32%** |
| `n_init_owed_thread`（其中**同一条 thread** 内欠回复） | **2** | **3** |
| **`init_owed_rate_thread`** | **1.75%** | **2.63%** |
| `init_owed_rate_last_only`（弱口径） | 26.32% | 26.32% |

## 2. 口径（并列，不互相替代）

- **`455` 不是 `510`**：510 条 MSG 中 **55 条 `payload.from` 为空**（单人 PUBLIC 旁白，无人称主语）⇒ 不进"谁对谁发起"的分析。**两个数都保留**，不要用一个替代另一个。
- `_any`：只要**历史上**对方曾向本人发过消息、且本人此后未回过对方，即便那是另一条 thread，也算"欠"。
- `_thread`：**严格**——那条未回的消息必须在**当前这条 thread** 内。A2 代码按**对端**判，不按 thread ⇒ **A2 实际生效口径是 `_any`**，`_thread` 仅作对照。
- `_last_only`：弱口径，本数集上与 `_any` 恰好同值（30/114），**不可据此认为两口径等价**（其它语料可分叉）。

## 3. 结论（三条，均可复算）

1. **A2 有可测空间**：`init_owed_rate_any = 26.32%`（30/114 条发起）——约**四分之一**的新线程是开给"曾找过我、我没回"的人。
2. **但 A2 的语义前提在小镇语境里很弱**：这 30 条里**只有 2–3 条**（1.75%–2.63%）是**同一段对话没接**；其余 **27–28 条是跨线程**的"欠回复"。
   ⇒ 开 A2 会让居民**不再对老熟人开新话头**，这**未必更生活化**（现实里"昨天没接他话、今天见面照样打招呼"很常见）。**这是开跑前就必须写进预登记的失败模式**。
3. **该量是结构决定量，不随措辞/采样变**：两臂 30/114 完全一致（`_thread` 差 1 条）。
   ⇒ A2 一旦生效，**必然改结构**（拦掉 30 条发起 ≈ 30 条 thread 开头）
   ⇒ **"结构不变"不能作 A2 的闸，必须反过来把结构变化本身列为观测量**，并同时给「线程数下降 / 消息总数下降 / 回复闭环率上升」三个数。

## 4. 对下一步的含义

- 若跑 A2：预登记必须**同时**写死
  ① 主判据用哪个"闭环"量（如 `reply_closure_rate`，且与 `_any/_thread` 两口径并列）；
  ② **允许结构变化**，但要给出上限（如 `n_threads` 降 ≤15%），超限 ⇒ 判「作废（非单变量）」；
  ③ 明写"沉默 vs 生活化"不可区分 ⇒ 判定层只判闭环量，**归因层不得写"更生活化"**。
- **更值得先做的是对端选择本身**（`_initiate` 选谁）：26.32% 说明对端选择**几乎不看对话状态**，这才是"生活气息"的真嫌疑点；A2 只是在事后拦，不是选得更好。
