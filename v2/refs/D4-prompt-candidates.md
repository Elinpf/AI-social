## 0. 现状（v0，逐字）

`code/life/agent.py:769-772`
```python
def _dialogue_prompt(self, tid: str, parts: list) -> str:
    others = ", ".join(p for p in parts if p != self.agent_id) or "(独自)"
    return (self.persona.compressed_profile(self._current_goal())
            + f"\n场景：{tid}；对象：{others}。请用一句话自然地说点什么。")
```
**四个结构性问题**（不是措辞好坏，而是**给模型的输入根本不够**）：
1. `场景` 是模板 ID（`gift`/`whisper`/`combat_training`…）——**居民不懂"模板 ID"**；
2. `对象` 是 `P0xx` 编号——**居民不喊编号**（D3：34.35%）；
3. **没有**地点、时段、手上在做什么、对方刚说了什么、关系亲疏；
4. 指令 `请用一句话自然地说点什么` —— 一句话 + 无语境 ⇒ 模型只能拿**旁白**补语境（D3：63.91%）与**寒暄套话**开场（10.87%）。

## 1. v1 目标形态（合成版，逐条对应 C 编号）

```
{persona.compressed_profile(current_goal)}
此刻：青溪镇·{place}，第{day}天{slot_cn}。你手上正在：{activity_cn}。
场合：{scene_cn}。在场：{others_with_names}。
{称呼提示行}
{关系提示行}
{对方刚说行（仅当有上一句时）}
请你开口说话，要求：
- 只写你嘴里说出来的话：不要动作、神态、心理描写，不要括号旁白，不要引号，不要用第三人称说你自己。
- 第一句直接切入你此刻关心的事，不要用「哎」「哎哟」「哎呀」加称呼开场寒暄。
- 说 1～3 句，像过日子的人：带上具体的物、数或由头；可以留半句给对方接。
- {称呼可用：…；不要用编号称呼人。}
- 不要提现代商品、金融产品、网络词汇（镇上没有这些东西）。
```

## 2. 关键设计取舍（写清理由，便于核验方判断"这是设计不是调参"）

### 2.1 场景 ID → 中文场景短语（映射表要冻结）
模板 ID 对模型是噪声。建议**纯函数映射**（不新增 config 键，避免动指纹），置于提示词装配旁：
```
gift→"送东西给对方"          whisper→"压低声音说句私房话"
mentorship→"带一带新手"       combat_training→"一起练把式"
scarce_buy→"缺料，想找人凑一凑"  savings→"盘算攒钱"
polite_reject→"婉拒对方"      counter_propose→"还个价/换个法子"
rel_maintain→"维持老交情"     skill_practice→"手上的活计"
job_choice→"琢磨营生"          select_location→"挑地方"
contest→"比试"                ice_break→"搭话认识一下"
academic_collab→"合计个题目"   group_proposal→"当众提个议"
power_conflict→"起了争执"      rel_accept→"应下交情"
未登记 → 原样输出，并记一次 WARN（不静默）
```
**风险**：映射表写错会系统性跑偏 ⇒ 落地前用 v0 语料人工核一遍（27 个模板，成本低）；表随脚本落盘给 sha。

### 2.2 称呼与称谓分层（C5/C6，依赖 D2 名字表 + 关系值）
- **名字主干**：`display_name.split("·")[-1]`（「青溪镇·老周」→「老周」）；重名 ⇒ 加职业限定（`打铁的铁头`）。
- **称谓三档（用 `familiarity`，t300 实测 p50=19 / p90=35）**：
  | 档 | 条件 | 称呼形态 | 例 |
  |---|---|---|---|
  | 生 | `familiarity < 10` | 职业敬称 | 「石师傅」「周先生」「桂婶子」 |
  | 识 | 10 ≤ f < 30 | 直呼主干 | 「老石」「秀娘」 |
  | 熟 | `f ≥ 30` 或 `affinity ≥ 20` | 亲昵 | 「石哥」「婶子」 |
- **关键取舍**：**把"该用哪个称呼"算好后再喂给模型**（一行 `可用称呼：阿禾/小禾`），而不是让模型自己推断关系——模型推断会编出不存在的亲疏（属于新的不自然）。这样 C6 是"确定性算称呼、模型只负责说得自然"。
- 若 D2 未暴露关系值 ⇒ **只做两档**（生/识），并在报告里标"亲昵档缺失（降级）"。

### 2.3 「对方刚说」只放**一句原文**，不做摘要（C9）
- 放原文：可核验（能在 run.jsonl 里找到那条 MSG）、无摘要漂移。
- 只放一句：控 token；多句会诱导模型复述（L-7 已 64.78%）。
- **绝不**把整段历史塞进 prompt（成本 + 复述风险）。

### 2.4 负例清单要短且硬，长负例会反噬
- 只禁 4 类：旁白/第三人称自述、寒暄套话起句、编号称呼、现代词汇。
- **不写**"要自然""要生动""要有感情"这类空指令——它们不改变分布，只会占预算（T362 已验证成本 +3% 主要来自指令变长）。

### 2.5 「1～3 句」而不是"多轮"
- 多轮归属 D2（leader 明确边界）；D4 只负责"这一轮内部说好"。
- 上限 3 句 = 给模型留追问空间，又防止单条变成小作文（当前 max 179 字已偏长）。

## 4. 失败预案（事前写清，避免事后找补）

| 现象 | 判定 | 处置 |
|---|---|---|
| L-2 降到 ≈0，但 L-1 p50 掉到 <20 | 模型被"1～3 句"压成短句 | 加"具体由头"正向锚点，再测一次；仍不行回退该条 |
| L-8 没到 0 | 名字表未生效或模型仍用编号 | 先查 `peer_names` 是否真进 prompt（打 prompt 落盘核对），**代码问题不硬凑提示词** |
| 承接率上升但 judge 认为"答非所问" | 应答了但是错接 | **冲突保留**（leader 红线）：读数上去了不算成功，写明冲突 |
| 消息条数大幅下降（分母差 >30%） | 模型开始"懒得说" | 该指标不可比，回退或改指令；E-1 必须报 |
| 世界观越界升高 | 具体性锚点诱导了现代细节 | 收紧 C8 负例；仍升则回退 C4 |

## 6. 「生活气息」扩展（2026-10-20 用户指令升级后新增，候选 C12–C17）

> 背景：用户把北极星改成「让 AI 小镇更有生活气息」——流畅自然只是基础。判断标准一句话：**看这些对话，像不像真的有人在过日子**。
> 我的边界不变：**多轮与线程归属归 D2**；我只负责「这一轮内部怎么说 + 怎么把'过日子'的上下文喂进去」。

| 编号 | 候选提示词内容 | 对应"生活气息"维度 | 依赖 |
|---|---|---|---|
| **C12** | **日常节律**：「现在是{slot_cn}，{slot_mood}」——清晨赶早、晌午歇脚、傍晚收摊、夜里串门；要求说出**这个时段该干的事** | 日常节律 | 只需要 `slot`（已有） |
| **C13** | **习惯与偏好**：从 persona 的 `speech_style`/`background`/`goal_tendencies` 派生一句「你的老习惯：{habit}」，要求对话里**偶尔带出**（不是每次） | 习惯与偏好 | persona（已有），需派生纯函数 |
| **C14** | **跨天记忆引用**：从 `memory.summary_for_prompt()`（`life/memory.py:573`）取 2–3 条**高重要性、跨天**记忆，写成「你记得：{…}」，要求"可以顺口提一句昨天/前天的事" | 记忆延续 | life 记忆层（已有接口），需 D2 允许我读 world view |
| **C15** | **闲话/第三方转述**：「可以提一嘴别人最近的事（谁家…），但不确定就别编」+ 限制"只许转述**你真看见/听见过**的事件（给出可引用的事件摘要）" | 闲话与八卦 | 需 `visible_events` 摘要（D2 上下文装配） |
| **C16** | **情绪呼应**：「你此刻心情：{mood}；如果对方上一句让你不舒服/高兴，可以直接反应出来」 | 情绪呼应 | 需 mood（`PERSONA_DRIFT`/needs 已有）+ 上一句（D2） |
| **C17** | **不完美的口语**：允许「说到一半改口、留半句、答非所问一句」，禁止每句都圆满总结（反"总结腔"） | 闲聊真实感 | 纯提示词 |

**反面（防"假生活气息"）**——必须在提示词里禁掉：
- 把"生活气息"写成**景物描写**（「夕阳把青石板染成金色」）⇒ 那是旁白，直接顶掉 L-2 的改善；
- 每句都塞"昨天/记得"⇒ 变成套路（可用 L-6/L-7 去重指标反查）；
- 编造未发生的事件（谁家结婚了）⇒ **世界观污染**，比"干巴巴"更糟。
  ⇒ 因此 C15 必须**只允许转述给出的事件摘要**，**绝不**要求模型自由发挥八卦。

**落地优先级（在不加跑批成本的前提下）**：C12/C17（纯提示词，先做）→ C13（persona 派生）→ C14（记忆，需 D2 上下文）→ C15/C16（需 D2 事件/上一句）。
**新增指标需求（转 eval-researcher）**：跨天记忆引用率、习惯重复率、第三方转述率、情绪呼应率——我这边可先用 `run.jsonl` 的消息文本做**关键词代理**（"昨天/上回/前天/记得/上次" 命中率 + 人名提及率），标 proxy，正式定义以 D5 续版为准。
