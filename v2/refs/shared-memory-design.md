## 0. 定位（一句话）与差异化机会
**公共记忆池（PMP, Public Memory Pool）= 从权威账本派生的、"谁在何时知道了什么/说了什么"的可溯源投影**，承载小镇的"传闻与公共事态"，驱动社会事件涌现——**但绝不承载"社会结局"**。
> **差异化**：米哈游自曝的四通病（乱泄密/传旧闻/信息矛盾/来源丢失），恰好是我方**确定性日志 + 来源可追溯 + 引文溯源**的强项。**这不是补坑，是用我们的地基做出别人做不到的"可信公共记忆"。**

## 1. 载体与写入规则（必须回答 #1）

### 1.1 硬区分：世界事实 vs 角色主观认知（`【设计】`，核心）
| 维度 | **世界事实（objective）** | **角色主观认知（subjective）** |
|---|---|---|
| 谁产生 | **只有中央裁决器**（arbiter 校验后的事件） | **只有 Agent 自己**（感知/推理/转述） |
| 存哪 | PMP 的 `world_fact` 条目 | **各 Agent 私有记忆**（T205 EM/SM），**默认不进 PMP** |
| 进 PMP 的条件 | 事件 `visibility=global/public` 且可锚 `event_seq` | **仅当该 Agent 主动"发布/告诉别人"**（一次社交行为）→ 才成为 PMP 的 `testimony` 条目 |
| 是否"真" | 引擎保证唯一真值 | **不主张真假**，只记录"谁在何时据何来源说了什么" |

> **一句话**：**PMP = 世界事实的镜像 + 角色间传播的原话档案；不是"社会共识"的存储。**

### 1.2 PMP 条目类型（`【设计】`）
| 类型 | 来源 | 例子 | 关键字段 |
|---|---|---|---|
| `world_fact` | arbiter 事件（global 可见） | `AGENT_DIED`、`MSG_PUBLIC`（公告原文）、市场化清算、`gate` 外来物资、`TIME_MARK` | `source_event_seq`（必填） |
| `testimony` | Agent 的 `INTENT.SOCIAL`（发布/转述） | "C 说：我亲眼看见 A 推了 B" | `claimer`、`source_event_seq` 或 `source_pub_id`、`claim_type` |
| `correction` | 对既有条目的更正 | "D 澄清：其实是 B 先动的手" | `supersedes`（指向被更正条目） |
- **不设 `opinion_aggregate` 类型**：任何"全镇认为…/名声 X"**不得**作为 PMP 条目（属社会结局，见 §2；只能作观测层只读指标）。

### 1.3 写入规则（`【设计】`）
```
W1 只有 arbiter 产出的、visibility ∈ {global, public} 的事件可自动成为 world_fact 条目。
W2 Agent 不得直接写 world_fact；只能经 INTENT.SOCIAL 产生 testimony 条目（带 author + 来源）。
W3 每条 PMP 条目必须携带 provenance（source_event_seq 或 source_pub_id），否则拒收。
W4 append-only：只在末尾追加；更正走新的 correction 条目（supersedes），绝不改写旧条目。
W5 可见性门控：DM/私密内容不进 PMP；除非当事人主动发布（此时仍标 testimony + 作者）。
W6 时间/顺序：写入在回合内缓冲，由内核按既有阶段顺序提交（具体约束见 §6 两版）。
```
- **与 P7（意图/事实分离）一致**：Agent 侧永远只能"提意图"，事实由裁决器落定（`06` L-2）。

## 2. 合规判定（必须回答 #2，最重要）

### 2.1 总则：公共记忆属于「环境」，不属于「结局」（`【设计】`）
把红线「**只给环境，不给结局**」（`story-and-event-engine §1.3.1`）映射到公共记忆：
> **PMP 只能承载「发生了什么 / 谁在何时说了什么」；不得承载「社会应该怎么看、谁赢谁输、谁是坏人、大家是否一致认为」这类由系统直接给定的社会结论。**

**一句话判据（可操作）**：
> **这条内容能锚到 `event_seq`（事实），或能锚到「某主体某时刻的原话/主张」吗？**
> 能 → 合规（`world_fact` / `testimony`）。**只能靠系统"替大家下结论"才能写出 → 越线（社会结局）。**

**判定总则（三选一）**：
1. 可锚定**客观事件** → `world_fact` ✅
2. 可归因到**具体主体的发言/转述**（含作者与时间） → `testimony` ✅
3. 既非事件、也无法归因到任何主体发言（即"系统替社会下的结论"） → ❌ **越线，拒收**。

> **⚠️ 口径注记（红线 A vs A′，防止"同名不同义"）**：本节总则基于 **红线 A（"只给环境，不给结局"）**。该红线**已放宽为 A′** —— 允许**世界 AI 导演产生宏观群体事件、可介入**，附**三条保底**：(a) 每次介入都是**显式事件**（带 `directed`）；(b) 有**独立开关与剂量**（可消融）；(c) **可对未来下情境、不得改写已发生的事实**。
> **对"公共记忆"这一层的判定总则不变**——因为它约束的是 **NPC 之间的信息流转**（谁在何时知道了/说了什么），**不是世界侧的介入**。凡**跨层引用**本总则时，**须注明依据的是 A′**，避免与旧 A 口径混用。

### 2.2 边界测试集（`【设计】`，逐例）
| 内容 | 类型判定 | 结论 | 理由 |
|---|---|---|---|
| 「A 打了 B」 | world_fact | ✅ | 可锚事件 |
| 「A 给 B 转了 10 元」 | world_fact | ✅ | `TRANSFER` event |
| 「市场粮价涨到 3 元」 | world_fact | ✅ | 撮合结果事件 |
| 「C 说：我听说 A 打了 B」 | testimony（作者=C，来源=某 pub/事件） | ✅ | 是"谁说了什么" |
| 「C 转述 D 的话：…」 | testimony（链 C←D←…） | ✅ | 保留传播链 |
| 「**全镇都认为 A 是坏人**」 | 社会结局 | ❌ | 系统替社会下结论 |
| 「**A 的名声 = −50**」 | 社会结局 | ❌（只可作观测指标，不回写 PMP） | 系统给定评价 |
| 「**大家决定集体不理 A**」 | 社会结局 | ❌（除非由 Agent 自主行为产生的事件流） | 预存=越线 |
| 「据传粮价要涨」（某人预测） | testimony | ✅ | 谁说的 |
| 「**系统宣布：B 被大家排挤**」 | 社会结局 | ❌ | 指定社会结果 |
| 「系统制造：镇上粮仓起火（事态）」 | 环境事态 | ✅ | EF-6/EF-7 允许"抛出事态、不指定人" |
| 「系统指定：让 C 去说服 D」 | 社会议程/结局 | ❌ | EF-7 已裁决禁止（指定参与者/话题即越线） |
- **红线自检**：若某机制**直接 emit 社会结果**（`RELATION_CHANGE`/`NORM_ADOPTED`/`GROUP_*` 等结果）或把它**预存进 PMP**，一律 ❌（对齐 `story-and-event-engine §1.3.1/1.3.2`）。
- **"社会共识/名声/派系"的正规出口**：① **观测层只读指标**（T9：传播链、分歧度、话题热度），② **Agent 自主行为产生的真实事件流**（如投票产生的 `NORM_ADOPTED`）。**两者都不回写为 PMP 事实。**

### 2.3 待讨论（不替用户选）
- 是否允许 PMP 存在"由观测层计算、但标注为**派生指标**（非事实）"的只读条目？——**默认不允许进 PMP**（避免指标被当成事实回流），标 `【待讨论】`。

## 3. 来源可追溯（必须回答 #3）

### 3.1 条目 schema（`【设计】`）
```jsonc
{
  "pub_id": "PM-000123",
  "kind": "world_fact | testimony | correction",
  "claim_type": "fact | quote | hearsay",       // 转述措辞可作 hedge
  "topic": "conflict|market|health|...",
  "entity_refs": ["P003","P007"],                // 涉及主体（检索/索引）
  "place": "plaza", "day": 3, "slot": "evening", "round": 39,
  "claimer": "P007",                             // testimony 的发言人；world_fact 为 "SYSTEM"
  "body_ref": "side://pub/PM-000123.txt",        // 正文入侧存储
  "source_event_seq": 45678,                      // world_fact 必填：锚定权威事件
  "source_pub_id": "PM-000120",                   // 转述时指向被转述条目
  "provenance_chain": ["PM-000123","PM-000120","PM-000101"],  // 完整传播链（回指 seed）
  "visibility": "public | group:<gid> | place:<pid>",
  "supersedes": null,
  "hash": "sha256:..."                            // 条目内容哈希（防篡改/审计）
}
```

### 3.2 溯源规则（`【设计】`）
- **R1 每条必锚**：`world_fact` 必带 `source_event_seq`；`testimony` 必带 `source_pub_id` 或 `source_event_seq`。
- **R2 链完整**：转发时新建条目并把 `source_pub_id` 指向被转述条目 → `provenance_chain` 可回溯到最初 seed 条目。
- **R3 校验器**：`orphan_pub_count == 0`（无来源条目数）；`chain_reachable_ratio == 1.0`（每条都能回到 seed）。可复算、逐位一致。
- **R4 不可篡改**：条目 append-only + `hash`；与账本同一审计纪律（`06`/`08` 哈希链思路）。

## 4. 四个通病逐一对策（必须回答 #4）

| 通病（米哈游自曝） | 根因 | **我方对策（`【设计】`）** | 确定性/可观测判据 |
|---|---|---|---|
| **① 乱泄密** | 共享池无可见性 | **可见性门控**：每条目带 `visibility`；检索先按 agent 的可见集过滤（复用内核 `PERCEPTION_SCOPE`/`visible_events`，**不用 LLM 判可见性**）；DM 不入池除非当事人主动发布 | `leak_rate`（越权命中/总命中）== 0 |
| **② 传旧闻** | 无时效、无"新进展"覆盖 | **时效衰减 + 覆盖**：条目带 `R_ttl`（定点保留度，随 slot 衰减）；检索按新旧加权；"新进展"以 `correction`/新事件 `supersedes` 旧闻；过期条目移出 hot 索引、转 cold 归档 | `stale_hit_rate`（过期条目被当"当前"命中的比例）≤ θ_stale |
| **③ 信息矛盾** | 多方各说各话 | **分层消解**：<br>• fact↔fact：**不可能矛盾**（都能锚唯一 `event_seq`，引擎保证唯一真值）→ 冲突即 bug 报警；<br>• testimony↔testimony：**不强行统一**，**并存 + 标注作者/时间/来源**（这正是"传八卦"的真实性）；<br>• testimony↔fact：标 `contradicts_event_seq`，**不删**，供观测"谣言/失真" | `contradiction_unresolved`（并存数）、`rumor_rate`（与事实相悖的 testimony 占比）——**只观测，不消解为"社会真相"** |
| **④ 来源丢失** | 转述不记出处 | **来源可追溯**（§3）：`provenance_chain` 必填 + 校验器 | `orphan_pub_count == 0`、`chain_reachable_ratio == 1.0` |

> **与红线一致**：③ 中"不强行统一为单一社会真相"**正是**「不给结局」的体现——系统只保证"每条发言可溯源"，**是否形成共识由 Agent 自己涌现**。

## 5. 规模化管理（必须回答 #5，合并弱缺口 ③）

### 5.1 规模量级（`【设计】`，估算 `【未验证】`）
- **PMP 条目/周** ≈ 全局可见事件数（`MSG_PUBLIC` + `AGENT_DIED` + `gate` 外来 + 市场摘要 + 传播条目）。传播条目随人口超线性（与 `scale-50 §2` 的 `importance` 指数同源），**是主要增长项**。
- **关系矩阵** N=50：50×50=2500 有向边 × 3 维（T205 §6）→ **可忽略**；检索按每 agent Top-K（K=5）。
- **结论**：关系矩阵不是瓶颈；**PMP 条目数与检索注入 token 才是**（同 `judge` 超线性风险）。

### 5.2 索引与分区（`【设计】`）
```
主索引：pub_id（全序）
二级索引（确定性）：topic / entity_refs / place / round 窗口
hot/cold 分层：hot = 最近 W_hot 回合（默认 1 周=84）；cold = 归档（压缩 + 摘要）
分区：按 topic 或 place 分区，检索只扫相关分区 → 复杂度 O(命中分区条目数) 而非 O(全池)
检索：确定性打分（新近度/entity 匹配/来源可信度/话题热度），全序 tie-break
```
- **可见性先过滤、再打分**：避免越权信息进入候选（通病①）。

### 5.3 token 成本控制（`【设计】`）
- PMP 检索 = **只读，不调 LLM**；注入 prompt 只取 `top_k_pub`（默认 **5**）条目的**摘要 + 来源一行**（≤ `M_pub` token，默认 300）。
- **去重**：同 `source_event_seq`/同话题的转述合并展示（保留作者列表），避免刷屏。
- **规模上限**：hot 层条目上限 `CAP_hot`（默认 500/镇），超出按（新近度、来源可信度、热度）降级到 cold。

## 6. 与内核的代价 —— **必须两版选项（不替用户选）**（必须回答 #6）

**冲突本质**：PMP 是**共享状态**。现有内核纪律是「**回合内缓冲 + P6 唯一 append + 重放 `fold(apply_event)` 逐位一致**」。共享池与它如何共存，取决于 **Fork B（是否保留逐位可复现）**——`【事实】`用户本轮表述："**可靠回溯不是必须的，首要是有趣**"（`scale-50 §7` 亦记录该表述）。

### 版本 α：**不放开逐位可复现（保留 `replay_parity`）**
- **做法**：PMP 是**确定性投影**。所有写入走 `INTENT.SOCIAL/PUBLISH` → arbiter 校验 → 回合内缓冲 → **P6 一次性 append 入账本**；检索为**回合快照上的纯函数**，命中结果落 `PM_RETRIEVE` 事件。
- **代价**：① 每条 PMP 写入进账本 → 日志体积增大（随传播条目超线性，需压缩/归档）；② 更强的顺序/全序要求，传播写入必须纳入阶段序列；③ 需要一条"公共池派生器"（可从日志重建）。
- **收益**：完整可复算、可消融证伪（能判断"是自然涌现还是存进去的"）、可审计；四通病天然可解（来源=`event_seq`）。
- **50+ agent 负担**：无新增 LLM 调用；日志/存储增量可控（压缩后小，量级参考 `08 §5.1`）。**负担得起。**

### 版本 β：**放开逐位可复现（用户"可靠回溯不是必须"）**
- **做法**：PMP 作为**弱一致的共享可变存储**（账本外），允许即时更新、甚至让 LLM 直接写"公共记忆摘要"；**不做** P6 串行与全序；重放**只保证"事件可审计"，不保证逐位**。
- **代价**：① 丢失 `replay_parity`/`state_hash` 门禁 → **无法消融证伪**；② 来源可追溯退化为 best-effort（可能 `orphan`）；③ 与观测层"确定性重算"冲突（T9 指标须可复算）→ **PMP 相关观测指标可能被迫降级**；④ 与 A/B 门禁、`SYSTEM_ERROR=0` 等既有验收口径需重新定义。
- **收益**：引擎集成简单（无需入账本/P6），可支持更"实时/更活"的共享（更接近米哈游"活的世界"），可能更省日志与墙钟。
- **50+ agent 负担**：省日志、但可复算保证与消融能力下降（**非 token 成本问题，是"科学可验性"成本**）。`【未验证】`：弱一致下的传播统计是否仍稳健。

### 版本 γ（**中间选项，供参考，不替你选** `【待讨论】`）
- **事实锚走 α、叙述层走 β**：`world_fact` + `testimony` 的来源链**仍入账本**（保可追溯），仅"公共池摘要/热榜"等**叙述层**弱一致。介于两版之间——**保留"来源可追溯"这一差异化强项**，同时降低账本压力。
- 标注：**本条不构成推荐，仅列为选项**，最终由用户/Fork B 定。

> **给决策者的代价对照**（不替选）：`α` = 强可验、贵一点日志；`β` = 省事、丢"可消融证伪"；`γ` = 折中、实现更复杂。

## 10. 结论速览
1. **载体**：PMP = 账本派生的可溯源投影；硬区分 **世界事实（arbiter，进池）** vs **角色主观认知（私有，仅在主动发布时以 testimony 进池）**。

5. **规模**：关系矩阵非瓶颈；PMP 条目与注入 token 才是——用索引/分区/hot-cold/top_k 控住。
