## 0. 结论（先给答案）

> **能做，且判定环节是确定性的；但只能做"提示级"，不能进闸门。**

分三句说清：

1. **判定环节确定**：给定「操作前值 / 操作后值」两个**同量纲**数，判其相等没有歧义 ⇒ 这一步可写成确定性规则。
2. **提取环节不确定**：难点全在"**从散文里认出这一对**"。实测关键词命中 **76 处**，其中 **73 处（96.1%）** 在 4 行窗口内都含 ≥2 个数字，但绝大多数与"过滤"无关（时间戳、sha 前缀、无关计数）⇒ **朴素实现（有两数即比较）不可用**。
3. **强制"两数都写"会把噪声放大**：加结构化约束后只剩 **10/76（13.2%）** 行有「数→数」邻接，其余 **86.8%** 会落进第三态"无法判定"。⇒ 若把"必须两数都在"做成硬闸门，**近九成声称会被判"缺值"**，规则会被无视（`check_definitions.sh` 精确率 10–20% 的教训）。

## 1. 一次实测（读只读扫，非脚本、非跑批）

**语料**：`v2/evidence/**/*.md` + `v2/refs/**/*.md` + `reports/**/*.md`（当前工作区快照）。
**关键词**：`去重后｜剔除后｜过滤后｜筛后｜筛选后｜清洗后｜排除后｜去掉重复后｜修剪后`。

| 量 | 值 | 说明 |
|---|---|---|
| 关键词命中行 | **76** | 声称"做了某步清洗"的位置 |
| 窗口（本行 + 后 3 行）内 ≥2 个数字 | **73 / 76 = 96.1%** | ⇒ **"有两数"这个条件几乎恒真，不能当判据** |
| 窗口内出现「数 → 数」邻接结构 | **10 / 76 = 13.2%** | 用 `→ ｜->｜⇒｜得｜变成｜降为｜升为` 连接 |
| 人工抽看这 10 条，属"真前/后值对"的 | **约 2–3 条**（见 §2） | 其余是时间戳（`22:41`）、sha 片段（`4:89`）、行号误配 |

⇒ **朴素路径精确率极低；结构化路径精确率约 20–30%（n=10，只能算量级印象，不是校准值）。**

## 2. 两个**真实**可用的夹具（正例，均已在库）

### 正例 1（作者已标注空操作 —— 目标形态）
`reports/CYCLE-45-20261101.md:32`（照抄）：

```text
#   → 0（本报告的全部提交都只触及「本报告 + 证据目录」⇒ 排除后为空；该 0 不随提交次数变化）
```

⇒ 这里同时具备「前值 → 后值（0）」+「**排除后为空**」+「该 0 不随…变化」三层信息。**这是规则要求的样子，应作为 fixture 的首条正例。**

### 正例 2（作者用「仍」字暗示空操作）
`v2/evidence/d9z-lang-baseline-d9t-on-by-linguist.md:14`（照抄）：

```text
| MSG 条数 | **191**（`MSG_DM` 167 + `MSG_PUBLIC` 24；按 `msg_uid` 去重后仍 191，无重复）
```

⇒ 前后值都是 **191**，且用「**仍**」标出"没变"。**「去重后仍 N」应被视为作者已自标空操作**，检查器只做一致性核对，不再要求补写。

### 负例（误报来源，须进 fixture）
- **时间戳被当数对**：`reports/CYCLE-35-20261031.md:97` 的 `22:41` 命中「数:数」结构，与清洗无关；
- **sha 前缀被当数对**：`reports/CYCLE-34-20261030.md:287` 的 `4:89` 同理；
- **排除代码块 / 引用块 / 表格外的行号段**：否则会把 `L1:2` 之类的定位符算成数。

## 3. 假阳性风险（按危险程度排）

| # | 风险 | 后果 | 缓解（须写进实现，否则不可用） |
|---|---|---|---|
| R-1 | **"有两个数"≠"是同一对象的前后值"** | 96.1% 命中都会误报 | 必须要求**结构化连接子**（`→ ⇒ 得 仍 变成`）+ **同量纲** |
| R-2 | 时间戳 / 行号 / sha 片段被解析为数对 | 假阳性 | 数字前后**必须带量纲词**（条/行/字节/B/词/%/个），裸数字不算 |
| R-3 | 表格列错位（`\|` 分隔） | 取到相邻列的数 | 按 `\|` 先切胞，只在**同一胞内或同句**取对 |
| R-4 | 百分比与计数混比（`84.48%` vs `147/174`） | 假"空操作" | 量纲严格匹配；分子分母式不参与比较 |
| R-5 | 语料含英文/代码块/围栏 | 误报 | 跳过 ``` 围栏、HTML 注释、URL |
| R-6 | **"本来就没有"被当成"冒充"** | 把诚实件判成违规 | 输出用中性词「**本批为空操作**」，不用"错误/造假"；且只提示 |
| R-7 | 第三态占 86.8% | 噪声吞掉真信号 | **只在命中关键词的同一行内**给 UNJUDGEABLE 提示，不外扩到邻行 |

## 4. 最小实现思路（**不写完整脚本，不改现有脚本**）

**形态**：新增独立脚本（放哪由 Leader 定）；**不并入 `check_definitions.sh`**——它已有 §11/§12 两段逻辑，混进去会让它的 10–20% 精确率进一步失守。

```
输入：单个 .md 文件
输出：三类计数 + 逐行提示；默认 rc=0（REPORT_ONLY）
```

**步骤（4 步，全部确定性，无模型判断）**

1. **清洗行**：丢弃 ``` 围栏内、`<!-- -->` 内、URL、以及 `#` 注释行；按 `|` 切成"胞"，保留胞号。
2. **定位声称**：胞内含 `(去重|剔除|过滤|筛|筛选|清洗|排除|修剪)后` ⇒ 记一个 hit；**若同胞含「仍」⇒ 标 `AUTHOR_MARKED`**。
3. **取对**（只在本胞 + 同句内）：
   - 正则：`(?P<b>\d[\d,]*(?:\.\d+)?)\s*(?P<u1>条|行|字节|B|词|个|%|)?\s*(?:→|->|⇒|得|变成|降为|升为|仍|后为|减少到|剩)\s*(?P<a>\d[\d,]*(?:\.\d+)?)\s*(?P<u2>条|行|字节|B|词|个|%)?`
   - 接受条件：`u1` 与 `u2` **同量纲**（或一方缺省但另一方有量纲，取有量纲者）；否则丢弃。
4. **三态输出（不许砍成两态）**：
   - **`NOOP-CONFIRMED`**：取到对且 `b == a` ⇒ 提示「本批该步为空操作，请在件内写明」；
   - **`NOOP-NONEMPTY`**：取到对且 `b != a` ⇒ 通过；
   - **`NOOP-UNJUDGEABLE`**：**没取到合法对** ⇒ 提示「声称清洗但未给同量纲前后值」，**既不判空操作，也不判通过**。

**自检夹具（`--selftest` 建议形态，仿 `check_definitions.sh`）**
- 正例 1：§2 正例 1 那一行 ⇒ 期望 `NOOP-CONFIRMED`；
- 正例 2：「去重后仍 191」同句含 191 ⇒ 期望 `AUTHOR_MARKED` + `NOOP-CONFIRMED`；
- 负例 1：`22:41` 时间戳 ⇒ 期望 `NOOP-UNJUDGEABLE`（**不得** CONFIRMED）；
- 负例 2：`37 候选 → 收 22` ⇒ 期望 `NOOP-NONEMPTY`；
- 负例 3：`191 条` 与 `3,827 B` 同窗口 ⇒ 期望 `NOOP-UNJUDGEABLE`（量纲不同不配）。

**自检门槛**：五个夹具**全中**才算可用；**任一条期望不符即不得上任何报告**。

## 5. 正面回答 Leader 的那一问（"只写一个数"怎么办）

> 是要求两个数都写，还是抓不到就报"无法判定"？

**答：条文上要求"两数都写"（作者义务）；检查器上抓不到就报 `NOOP-UNJUDGEABLE`（提示，不阻塞）。**

理由三条：

1. **写进条文**才能让"空操作"在**源头**被标出（作者知道自己做了什么），这是唯一真正省事的做法；
2. **不设阻塞**，因为 `UNJUDGEABLE` 会占约 **86.8%**（§1），阻塞等于让全库停摆，规则会被绕过；
3. **不得把"只有一个数"判成空操作**：只写「去重后 191」而不写原始的，**是"没有可核形式"，不是"空操作"** —— 二者性质不同（同 `_proposed-noop-rule.md` §4 的反例边界）。把前者打成后者，会激励"干脆不写去重"。

**附带一条低成本改良**：把「**仍**」纳入关键词（`去重后仍 N`）。实测作者已有自发用法（正例 2），**顺着已有习惯定规则比新造格式更可能被采纳**。

## 6. 建议的落地节奏

| 阶段 | 动作 | 判据 |
|---|---|---|
| ① | 只做 `REPORT_ONLY`，在近期 5–10 份新件上跑 | 看 `CONFIRMED / NONEMPTY / UNJUDGEABLE` 三态真实比例 |
| ② | 用真实失败案例扩 fixture（至少 3 正 3 负） | 精确率像人一样可复算 |
| ③ | 再议是否 `--strict` | 与 `check_citations` / `check_definitions` 同一路径：**先有失败案例再收严** |

**本件不给"何时该收严"的阈值** —— 无校准数据前给阈值 = 拍脑袋。
