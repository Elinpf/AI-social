## 1. 被判据表当作"双通道验证"、实为构造性恒真的三处

| 判据 | 原文要求 | 问题 | 正确说法 |
|---|---|---|---|
| **M-1-a** | ON 臂 `meal` 计数 > 0 **且 OFF 臂 = 0** | OFF 臂恒为 0 是**代码保证**：OFF 时推进器不进任何分支、`_meal_place()` 不被调用 ⇒ `activity_type=="meal"` 在 OFF 臂**不可能出现**。这不是观测结果，是**同义反复**。 | 「OFF = 0」**不得**作为"对照有效 / 双通道验证通过"的独立证据；**唯一有信息的是「ON > 0」且其量落在离线预算 `100–140` 内**。 |
| **M-1-b** | ON 臂 `satiety_up` > 0 **且 OFF 臂 = 0** | 同上：基线 `satiety` 一周 186 次更新、100% 下降、0 次上升（预登记 §0 自述）⇒ OFF 臂 `satiety_up = 0` 由需求衰减机制决定，与 meal 开关无关。 | 只引「ON > 0」；OFF = 0 作背景陈述，不作证据。 |
| **M-1-c** | ON 臂 `satiety` 最低值 > 0 | 单臂绝对阈值。若 ON 臂仍在中后段归零，此判据**不成立**，但预登记未写"归零发生在哪一段" ⇒ 无法区分「不归零」与「只是延后归零」。 | 必须**两臂并列**报 `satiety_min` 与**首次归零的槽位**；若 ON 臂仍归零 ⇒ 只能写「**延迟归零**」，**禁止**写「不再饿到底」。 |

## 2. 由此产生的一条判定纪律（**优先级高于判据表字面**）

> **凡判据含「ON 臂 X > 0 且 OFF 臂 X = 0」，且 OFF 侧 = 0 由代码构造保证，则该判据的判定力全部来自 ON 侧。**
> 引用时必须写成：「机制触发：ON 臂 X = *n*（离线预算 *a–b*，落在区间内/外）」，**不得**写成「ON/OFF 双通道验证通过，OFF=0 证明对照有效」。

理由：这条与今天在 D9b 上修的两个错是**同一类**——把"结构上必然为真"的东西说成"观测到的证据"。一旦写成"双通道验证通过"，读者会以为 OFF 臂独立地否决了"这是仪器噪声"，而实际上 OFF 臂**连产生该事件的能力都没有**。

## 3. 离线预算对账（本件唯一新增的要求）

M-1-a 的 ON 臂计数**必须与 §2 写死的 `100–140` 对账**，三种结果分别表述：

| ON 臂实测 | 表述 |
|---|---|
| 落在 `100–140` | 「与离线预算一致，机制按设计触发」 |
| `< 100` | **必须查明并写明**：是计划层插入点比预算少，还是 `MEAL_SATIETY_THETA=45` 让部分槽被判定"不饿所以不吃"（后者是**机制正确行为**，不是失败） |
| `> 140` | **必须查明**：预算脚本与实跑的口径差在哪（如 clamp 抑制、同槽多次进食）；**不得**直接写"超出预期"了事 |
