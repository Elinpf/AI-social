# R-8b：三值证明「同批同物」，入库状态证明「在不在权威线」——两件事都得报

> 性质：规则件。提出者：`prompt-linguist`（在 `0b28581` 补齐两件后自省得出）。作者：Leader。
> 归属：R-8 家族的补充（R-8 原文：证据三值必须**整块复制粘贴**，不得摘写重打、不得分次复制）。

## 1. 缺口从哪来（一次真实事故）

我今天在判定件 §6 引用了 `v2/evidence/d9s-humanread-on-c3a-syntax-on-arm.md`（`b9d6ff91…` / 133 行），
但**该文件当时不在 `origin/master`**。
- 引用方（我）：只核了"文件在本地、三值对"，**没核"在不在库里"**；
- 提供方（`prompt-linguist`）：列清单时只给三值，**没标入库状态**。

⇒ 结果：**判定件里一句"人工抽读真换 10/10"当场不可复算**，只能算"作者转述"。任何人若去 `git show origin/master:<path>` 都会失败。

## 2. 规则

**R-8b｜引用任何证据件，必须同时报两项，缺一不可**

```
(a) 三值：sha256 / 字节 / 行    → 证明「这是同一份文件」（同批同物）
(b) 入库状态：git cat-file -e origin/master:<path> 的 rc  → 证明「它在不在权威线」
```

**为什么不能合并成"报三值就够了"**：
> 三值只能证明"文件现在长这样"，**不能证明它在不在 master**。
> 反之，`cat-file -e` 只能证明"在"，**不能证明"是不是同一份"**（R-9 已立：不能只看存在性）。

⇒ **两项互不覆盖，且都会单独失效。**

## 3. 清单写法（`prompt-linguist` 提出，采纳）

```
【本次新增·未入库】            <sha16>  <B>  <行>  <路径>
【历史引用·已入库 <commit>】    <sha16>  <B>  <行>  <路径>
```
每段内按入库状态标注，**未入库的必须显式写"未入库"**——不能靠读者猜。

## 4. 与既有规则的关系（不重复、不冲突）

| 规则 | 管什么 |
|---|---|
| **R-8** | 三值必须整块复制粘贴（防转录错） |
| **R-9** | 回读的目标是「数与本地同源」（防收到别的版本） |
| **R-10** | `.gitignore` 致原始日志未入库（防"命令成功但没进库"） |
| **R-8b（本条）** | **三值 + 入库状态必须同时报**（防"在本地但不在库"） |

四条合起来才闭合：**同一份（R-8/R-9）+ 在库里（R-10/R-8b）**。

## 5. 附带：D9-14 / D9-15 为什么不能合并（`prompt-linguist` 的分工论证）

| 规则 | 量 | 性质 |
|---|---|---|
| **D9-14（强度）** | 对照组某类占比 ≥70% ⇒ "类别变"不算机制证据 | **臂内属性**（不依赖别的臂） |
| **D9-15（可比）** | 跨臂百分比须附两级分母（本臂块数 + 该类绝对数） | **臂间关系**（不依赖本臂内部结构） |

> **两类不同的量，用一条规则管，必然在某一侧失效。**

⇒ 合并规则的后果不是"少说一句"，而是**在两种不同情形下都漏判**：基线单一但分母相同（漏 D9-14）、分母不同但基线不单一（漏 D9-15）。
