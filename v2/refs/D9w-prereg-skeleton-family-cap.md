## 1. 三门如何关（前置件的三问，逐条作答）

### 门一：族怎么切 = 参照系本身
- **切法写死：片段**前 **6 个字符**（含标点；不归一化、不剔停用词），与 `d9t-obs` 完全同口径 ⇒ **两件数字可直接并列**。

### 门一之附：`F_impl` 枚举（比"48"这个设定值更重要）

`F_impl` 必须是**能一条命令数出来的**，例如：
```bash
# 出口数 × 骨架模板数（实现/词表里可枚举的那两组清单）
python3 - <<'EOF'
import re,pathlib
src=pathlib.Path('code/life/agent.py').read_text()
print('n_openings =', len(re.findall(r'^\s*[①-⑧]', src, re.M)) or 'CANNOT-ENUMERATE')
EOF
```
> **若 `F_impl` 无法从实现中枚举**，则 `G8/G9` 只能写"以设定值 `F=48` 为基准，**换实现即失效**"——**不得**再称"外生"。

### 门二：`N` 必须外生
**不采用"同一族 ≤N 次"的绝对条数**（`N` 无法外生且对片段规模敏感）。改用**两条无量纲判据**：

| 判据 | 形式 | 外生推导（**不得由 53.85% 反推**） |
|---|---|---|
| **G8 主** | 骨架族 **top1 占比 ≤ `4 / F_impl`** | `F_impl` = **实现里可枚举**的"出口 × 骨架模板"总数（**必须附枚举命令**，见 §1.1）。均匀生成器的期望 top1 ≈ `1/F_impl`（实测模拟 `F=48` 时 top1 均值 **4.63%**、`F=64` 时 **3.91%**）⇒ **4 倍松弛**，仍为理论期望的整数倍 |
| **G9 护栏** | **`distinct / F_impl ≥ 0.85`** | 与 `G8` **同基准**。模拟：`F=48`、`n=208` 时均匀生成器 `distinct/n` 均值仅 **0.228** ⇒ 若按 `distinct/n` 判，**连理想生成器都过不了**（v1 的错，已改） |

> **同时声明**：两条阈值**均与被测臂现状无关**（D9t 现状 top1 = 6.90%（全臂）/ 53.85%（子集），**都不参与阈值推导**）。
> **`F_impl` 若无法枚举** ⇒ 本判据**不得冻结**（退回"设定值 48"必须明写"换实现即失效"）。

### 门三：与 `max_k` / `dupMax` 的关系（谁退役）

## 7. ⚠ v2 自检发现的阻断（2026-10-31 21:4x）：本件判据**目前不具分辨力**

按 `research-writer` 的要求去枚举 `F_impl`，实测结果**推翻了 v2 的锚点**：

```
实现侧枚举（cef1c58）：OPENINGS_MENU 有 8 个出口、共 17 个示例骨架
D9t 现状实测（v2/evidence/d9t-on_n16r24_s42，208 片段，前 6 字骨架）：
  distinct = 149      top1 = '凿子敲下去，' ×8 = 3.85%      Hill N1 = 88.29
```

**两个致命问题**：

1. **`F_impl` 不是族空间的上界**：实际观测到 **149 个不同骨架**，远大于 17 ⇒ `distinct / F_impl ≥ 0.85` 这种判据**恒真**（149/17 > 1），**无意义**。
   ⇒ 原因是**骨架空间是开放的**（模型自由生成），`OPENINGS_MENU` 只约束"出口"，不约束"骨架"。
2. **全臂 `top1` 已是 3.85%**：若 `G8` 用 5% 或 `4/F_impl`（=23.5%），**D9t 现状就已通过** ⇒ **`G8` 对"要改进的臂"零分辨力**。

**⇒ 结论：`d9t-obs` 里那个 53.85% 是"新出口子集内部（7/13）"的局部塌陷，不是全臂属性。**
**全臂骨架集中度本来就不高（Hill N1 88.29），所以"全臂骨架族上限"这条路没有头部空间。**
