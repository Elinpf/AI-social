## 0. 总则（所有工具共用）

**T-0.1 只读优先**：工具**默认只读** `EventLog` / 侧存储（经 `code/obs/reader.py`），不得回写世界（对应 `affects_state=false`）。
**T-0.2 来源可追溯**：界面上每一条事实/数字/关系边都必须能**点回具体 `seq`**（对接 `code/obs/census.py` 的事件溯源）。
**T-0.3 口径确定性**：所有聚合数字复用 `code/obs/*` 的确定性口径，**工具不另立算法**（避免"看板与报告对不上"）。
**T-0.4 红线**：**世界观/编年史/叙事**类工具只呈现**已发生**的事；**不得**提供"改结局/调分支/替 Agent 决定社会结果"的能力（`v2/refs/story-and-event-engine.md` §1.3.1）。**配置/沙盒**类工具只改**环境与机制开关**，不改**社会规则本身**。
**T-0.5 不新增不可复现环节**：工具产出（如导出的配置、编辑后的叙事）若进入世界，须是**确定性可复算**的输入（配置）或**只读旁路产物**（叙事）。

## 1. 世界观编年史可视化工具（**P0**）

> deck 对应：`[img-26]`「世界观与编年史生成工具」（deck 标"主力工具"）。
> deck 原文目标：*"将零散的设定和角色列表，自动整理成**编年史大纲、可视化关系网与事件时间线**，并为每个角色生成**可直接接入记忆系统的 Prompt**"*。

### 1.1 目标与用户
- **用户**：研发/设计（写世界观）、观察者（看"这个世界发生过什么"）。
- **价值**：把我们的**确定性事件日志**变成**可读的编年史 + 关系网 + 时间线**，并**自动产出角色 prompt 素材**——直接吃我们的强项（日志 + 来源可追溯）。

### 1.2 功能需求（可执行条目）
| # | 需求 | 输入 | 输出 | 验收 |
|---|---|---|---|---|
| W-1 | **事件时间线视图**：按周/日/回合铺开全部事件 | `obs/reader.py` 读 `EventLog`（schema `v1.1/08`） | 可缩放时间轴，节点=事件 | 任选一节点 → 展开原始 `seq`+payload |
| W-2 | **编年史大纲生成**：按时间聚合出"分章大事记" | `obs/census.py` 的事件分类 + `narrative` 选片 | 大纲（章节/条目，纯事实） | 每条含 `source_event_seqs[]`，无编造（对标 `story_quality` 硬门） |
| W-3 | **可视化关系网**：人物/组织/群组的关系图 | `obs/emergence.py`/`metrics_social.py` 关系图 + `RELATION_CHANGE/GROUP_*` | 可交互图（节点=Agent/Group，边=关系/沟通） | 边可点回事件；时间窗可切（累计/回放） |
| W-4 | **角色记忆 Prompt 生成**：为每个角色导出"可直接接入记忆系统"的素材 | `life/persona.py` 的 persona + 该角色的 `MEMORY_WRITE`/`RELATION_*` 子集 | 每角色一份素材包（身份段 + 关键记忆摘要） | 导出物**可被 life 层加载**（格式对齐），且不含未发生事实 |
| W-5 | **世界观设定视图**：呈现 `worldview`/地图/场所/编年史起点 | 世界配置 + `locations` | 设定页 | 只读；改动需走配置流程（不给"一键改世界"） |
| W-6 | **溯源跳转**：任一界面元素 → 事件详情（seq/payload/participants） | `census.py` | 详情侧栏 | 溯源可达，`seq` 真实存在 |

### 1.3 验收（工具级）
- **V-1 可溯源**：界面每条事实/数字/边，均能跳回真实 `seq`（抽样 100%）。
- **V-2 口径一致**：工具显示的聚合数字与 `code/obs/*` 报告**逐位一致**。
- **V-3 只读**：工具运行**不产生任何世界写事件**（`affects_state==false`）。
- **V-4 无编造**：编年史大纲的每条断言均带 ≥1 锚点（对标 `v1.1/17` H-1）。

### 1.4 依赖 / 优先级
- **依赖**：`obs/reader.py`、`obs/census.py`、`obs/emergence.py`、`narrative/weights.py`、`v1.1/08` 事件 schema、`v1.1/17` 叙事层。
- **优先级 P0**：**直接吃现有日志**、无新机制风险、与叙事机互补、能同时服务研发与"讲出来"。

## 2. NPC 配置工具（P1）

> deck 对应：`[img-25]`「通用 NPC UGC/PGC 配置工具（主力工具）」——*"像积木一样自由组合，无需编码即可配置"*。
> ⚠️ **口径已按 Leader 采用的定义**：**L1–L5 = 推理/算力档位，不是剧情重要性**（见 `v2/refs/mihoyo-deck-teardown.md` §3/§7 C-5）。

### 2.1 目标与用户
- **用户**：设计者（批量造角色）。
- **价值**：把"50+ 角色配置"从**手写 JSON** 变成**可视化、可组合、无需编码**，并绑定**推理档位**（降本）。

### 2.2 功能需求
| # | 需求 | 输入 | 输出 | 验收 |
|---|---|---|---|---|
| N-1 | **人设编辑器**：编辑 persona 全字段（大五/价值观/技能/背景/目标倾向/说话风格） | `life/persona.py` schema | 可视化表单 + 预览 | 导出物**通过 persona schema 校验** |
| N-2 | **推理档位选择（L1–L5）**：为每个 NPC 选"推理/算力档位"（非剧情重要性） | — | 档位字段 | 档位取值受限枚举；**不表达"谁更重要"** |
| N-3 | **积木式组合**：从模板/片段拼装角色（可复制/覆盖/继承） | 模板库 | 组合配置 | 组合结果可复算（同一输入→同一配置） |
| N-4 | **批量操作**：批量生成/复制/改档位 | — | 批量产物 | 支持 N=50 一键配置 |
| N-5 | **导出/导入**：导出为引擎可加载的 persona 配置 | — | 配置文件（**确定性、可版本化**） | 导入后引擎可加载；diff 可见 |
| N-6 | **校验**：字段完整性 + 与内核契约一致性 | 契约（`code/contracts`） | 校验报告 | 非法配置被拦，给出原因 |

### 2.3 验收
- **V-5** 导出配置**能被引擎加载**且**通过 schema/契约校验**。
- **V-6** 同一编辑操作序列 → **同一产物**（可复算）。
- **V-7** 档位字段**不携带"重要性/剧情权重"语义**（防红线）。

### 2.4 依赖 / 优先级
- **依赖**：`life/persona.py` schema、`code/contracts`、`frontend` 表单能力。
- **优先级 P1**（降本 + 50+ 刚需，但依赖 §3 档位设计先定）。

## 3. 自演化沙盒（P1）

> deck 对应：`[img-24]`「自演化沙盒（辅助工具）」。
> ⚠️ **红线约束**：**自演化只能自动调"环境参数 / 机制开关"**，**绝不自动改"社会规则/结局"**（`v2/refs/story-and-event-engine.md` 禁止清单 §1.3.2）。

### 3.1 目标与用户
- **用户**：研发（跑消融、扫参数、验证机制）。
- **价值**：把"改配置→重跑→比对"自动化，支撑**消融证伪**（`v2/00-roadmap.md` §0.3）。

### 3.2 功能需求
| # | 需求 | 输入 | 输出 | 验收 |
|---|---|---|---|---|
| S-1 | **参数扫描**：按网格/列表跑多组 `seed × config` | config + 参数域 | 多跑结果集 | 每组可复现（同 seed+config 一致） |
| S-2 | **机制开关矩阵**：对 EventForge 等机制逐开关做消融 | forge 开关（`story-and-event-engine.md` M4） | A/B 对照结果 | 关闭某机制→对应事件发生率显著下降（E-2 口径） |
| S-3 | **结果比对**：多跑指标并排 + 差异高亮 | `obs/*` 指标 | 对比视图 | 差异可从日志复算 |
| S-4 | **自动裁决（实验级）**：判定"是否通过门禁" | 门禁口径（`obs/gate.py`） | 通过/不通过 | 判定为**确定性**，不含 LLM |
| S-5 | **红线守卫**：禁止任何"自动改社会规则"的配置项 | — | 白名单校验 | 越线配置被拒（`social_result_emits==0` 类断言） |
| S-6 | **成本账**：每次运行的 token/调用内联展示 | `obs` LLM 成本 | 成本面板 | 与 `obs` 口径一致 |

### 3.3 验收
- **V-8** 消融**可证伪**：机制开关能显著改变对应现象（E-2/E-4）。
- **V-9** 自动调参**只触及环境/机制层**，`V-5` 级断言 `social_result_emits==0`。
- **V-10** 所有跑批**可复算**（seed+config+engine_version 指纹）。

### 3.4 依赖 / 优先级
- **依赖**：内核运行入口、`obs/gate.py`、EventForge 开关设计。
- **优先级 P1**（支撑消融与自改进；但**须先有可复算的跑批入口**）。

## 4. 叙事编辑器（P2）

> deck 对应：`[img-24]`「叙事编辑器（辅助工具）」。
> ⚠️ **红线**：叙事层是**只读旁路**（`story-and-event-engine.md` §0.1）；编辑器**只能编辑"怎么讲"**，**不能编辑"发生了什么"**。

| E-1 | **叙事稿编辑**：编辑 Storyteller 产出的正文 | `NARRATIVE`（`v1.1/17`） | 润色稿 | 编辑**不改变** `fact_event_seqs[]`/锚点 |
| E-2 | **多体裁/多视角切换**：编年史/周报/角色 POV | 模板（`v1.1/17` §4） | 多版 | 多版 `anchor_digest` **一致**（H-3） |

### 4.3 验收

- **V-12** 编辑**不回写世界**（只读层约束）。
- **V-13** 多版一致（`anchor_digest` 相同）。

### 4.4 依赖 / 优先级
