## 0. 为什么合并：一个「同名不同义」隐患

两份文档**功能重叠、且依据的红线不同**：

| 文档 | 候选机制 | 写于哪条红线 | 风险 |
|---|---|---|---|
| T204 `story-and-event-engine.md` | `EF-1..EF-9` | **红线 A**（只给环境，不给结局） | 对同一批宏观机制给出**偏严**判定 |
| T210 `world-director-design.md` | `WD-1..WD-10` | **红线 A′**（允许世界导演产生宏观群体事件 + 三条保底） | 对同一批宏观机制给出**偏宽**判定 |

→ 若不合并，会出现「**同一机制在两份文档里判定不一致**」。本文件把它们**归并为一张机制表**，**所有判定统一到红线 A′**。

### 0.1 红线 A′（Leader 09:53 拍板口径，【已定】）

- **原红线 A**「只给环境，不给结局」→ **放宽为 A′**：**世界层（背景 / 宏观事件 / 情境）我们定，不只观察者**；**社会层（经济 / 制度 / 分工）只给「定义的手段」，可定义、也可不被定义、可自行涌现**。
- **三条保底不变（A′ 的宪法）**：
  - **(a) 显式事件**：每次介入都落 `directed=true` 的可审计事件（不得隐形手）；
  - **(b) 可消融**：每机制有独立开关 + 剂量（可关掉做对照）；
  - **(c) 不改过去**：可对未来下情境，**不得改写已发生的事实**。
- **一句话**：**可以「导演未来」，不可以「篡改过去」，也不能「隐形出手」。**

## 1. 分工定义（本合并的第一件事）

| 角色 | 定位 | 回答的问题 | 产物 |
|---|---|---|---|
| **世界 AI 导演（World Director）** | **调度者 / 策略** | **何时**、下**什么指令**、多大**剂量** | `WORLD_DIRECTIVE`（意图） |
| **事件制造机（EventForge）** | **手段库** | **有哪些可用机制**、各自**合规前提**是什么 | `wd_mechanisms.json`（机制目录，数据化 config） |

- **导演**调用**机制库**中的机制；**机制库**只提供「手段 + 合规前提 + 开关 + 剂量域」，**不含策略**。
- **两者都不直接写账本**：产出经**确定性内核**校验（三条保底）后封装为 `WORLD_GROUP_EVENT`（事实）。
- **边界不变**：导演只给「情境」，个体 Agent 仍**自主决策**（判定总则见 T210 §1.2；本表复用不重述）。

### 2.1 关于 `kind` 枚举（**取代** T210 §4.1 的**临时**枚举）

`WORLD_GROUP_EVENT.kind` 最终枚举（14）：`season, festival, opportunity, public_works, supply_shock, scarcity, tension, incident, disaster, epidemic, visitor, edict, agenda, mass_event`。

- **WM-08（冲突门槛）与 WM-16（人格）不产生 `kind`**：前者是**条件**（只在 Agent 自主意图下派生 `CONFLICT_STARTED`），后者是**初始配置**。
- 与 `GROUP_CREATED.kind ∈ {chat, guild, …}`（群组类型）**枚举互不重叠**（见 T210 §4.3）。
- ⚠️ 本枚举**比** T210 交 `sim-engine-stats-architect` 的临时枚举多 4 项（`opportunity, scarcity, incident, agenda`）——登记前需**以此为准**（尚未登记，无返工）。

### 2.2 三条保底 → 统一可审计口径 + 验收判据

| 保底 | 统一可审计口径（纯 D，可复算） | 验收判据 |
|---|---|---|
| **(a) 显式事件** | 每条 `WORLD_GROUP_EVENT` 都有 `directive_ref` 且指向 `directed=true` 的 `WORLD_DIRECTIVE` | ① 全覆盖；② `count(改变宏观情境但无 directed 的事件) == 0` |
| **(b) 可消融** | 每机制一开关（表内`开关`列）+ 剂量；剂量=0 ≡ 关闭 | 关机制 → 其 `WORLD_GROUP_EVENT(kind=…)` 计数显著下降（置换检验 p≤0.05） |
| **(c) 不改过去** | `effective_from_round ≥ issued_round`；违者记 `WORLD_DIRECTIVE_REJECTED` | 无 `rewrites_past` 存活；【Fork B 口径】见 §5 |
| **统一审计** | 一条 `actor="DIRECTOR"`（或 `SYSTEM`+`directed=true`）即可捞全部介入 | 可由日志**独立复算**「这是导演干的」 |

## 4. 保留的亮点（跨两文档，必须继承）

1. **`directed` origin 优先级高于 `induced`**：`origin 判定优先级：directed > induced > rescue > spontaneous`（T204 §3.1 / T210 §5.1）。
2. **`Q-9 directed_mislabel == 0` 作为发布硬门**：凡 `origin="directed"` 的原子，叙述**必须显式表述为「世界侧介入/导演安排」**，**不得**说成"自发"；`NARRATIVE.source_event_seqs[]` 必含 `WORLD_DIRECTIVE` 的 seq。**这是保底 (a) 在叙事侧的落地，也是"作者化不退化成剧本冒充涌现"的良心所在。**
