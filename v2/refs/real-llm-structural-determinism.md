# 真 LLM 臂：**结构确定、文本随机** —— 由此推出「样本数」与「mock↔真」两条纪律

> 立件：Leader（team-leader）｜2026-10-29
> 由来：`dialogue-core-dev` 报「`run_d9_a1` 与 `run_d1_f6off` 完全一致，疑为同臂、不得当 2 个样本」。**后半对、前半错**（见 §2）。本件把两种情况分清。

⇒ **两次独立跑：文本全不同，结构量全同。**

## 2. 双方各对一半

| 说法 | 判定 | 理由 |
|---|---|---|
| 「**不得当 2 个独立样本**」 | ✅ **对** | 结构维度上两者提供**同一份信息**（同配置同 seed ⇒ 结构确定性），合并计数会虚增样本量 |
| 「数值全同，**疑为同臂**」 | ❌ **错** | 行数、字节、sha 全不同，**686 条 MSG 文本逐条不同** ⇒ 是两次独立跑，不是同一次跑、也不是复制 |

**准确表述**：「两个 **run**，一份**结构信息**」——不是「一个 run」。

## 3. 由此立的纪律

### 3.1 样本数怎么数
- **结构维度**：同配置同 seed 的多个真 LLM run，**只算 1 份**。要增加结构信息，**必须改配置或 seed**，重跑同配置无效。
- **文本维度**：每次 run 都是**独立的一份文本样本**。要增加文本多样性（如评估措辞丰富度、做人工读样本），**重跑同配置是有效且必要的**。
- ⇒ 报"我们有几个样本"时**必须写是哪个维度**；裸写"3 个样本"不合格。

### 3.2 mock ↔ 真 LLM 的关系（加固 `mock-vs-real-llm-lag-divergence.md`）
- 同臂对照已证：`mock_d9b_rw4_treat`（mock）`lag=2` 占 **1.06%**，`run_d9_a1`（真，同配置除 provider）占 **31.88%** ⇒ 差约 30 倍。
- 既然 `lag` 在真 LLM 内部是**结构量**（两 run 全同），那么 **provider 就是一个结构参数**，`mock` 与 `openai_compat` 是**两种不同的结构**，不是"同一结构的不同噪声实现"。
- ⇒ **不得**把 mock 与真 LLM 的差异解释为"mock 样本少/波动大"；它是结构差异。
- ⇒ 也**不得**因为"两真 LLM run 结构全同"就认为"结构稳"，那只说明**同 provider 内**稳。
