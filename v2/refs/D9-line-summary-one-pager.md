## ① 这条线问的是什么

**问的是一个具体问题：agent 回话的"时机"能不能被调？** 具体到可测量形式：
一次回复与它回复的那条消息之间，隔了几个回合（记为 `lag`）。
若 `lag` 能变大，对话就可能出现"隔几拍才接"的形态；若不能，则"立刻接"是结构性宿命。

`lag = 子消息 round − 父消息 round`；分母 = `reply_to` 非空的条数（= MSG 总数 − 发起数）。

## ② 证明了什么

### ②-A 结构层（可以放心引用的四条）

| # | 结论 | 证据件（sha8 / commit） | **它不能说明什么** |
|---|---|---|---|
| A1 | **`lag = 0`（同回合接话）在当前架构下不可能**：同组内 `turn_index` 全同值（mock 43/43 组、真 LLM 27/27 组），即后发言者**看不见**先发言者的同回合消息；旁证 `reply_to` 指向同回合 = **0/663（mock）、0/480（真 LLM）** | `v2/evidence/d9-same-round-invisibility-turn-proof.md`（`590a9684` / `640f152`） | 不能说明"模型不想同回合回复"——它说明的是**可见性时序**，不是意图 |
| A2 | **一切"回复时机"类参数只能在 `lag ≥ 1` 的区间内起作用**：窗口 `reply_window_rounds` 2→4 **零行为差异**（197,771 条事件逐条同，差异仅 `config_digest` 1 行 + hash 链 84 行） | `v2/evidence/d9b_reply_window_on_A1_base_result.md`（`6b85740a` / `79f9aeb`） | 不能说明"窗口参数无用"——它说明的是**窗口不是瓶颈** |
| A3 | **改"挑选顺序"能改行为，但改不动上界**：`recent_first→oldest_first` 后 `lag=2` 占比 1.06%→36.93%、p50 1→3、单发 139→109、≥3 轮 +7.37pp；但 **`lag ≥ 3` 两臂均为 0** | `v2/evidence/d9c_reply_pick_order_result.md`（`52ab0413` / `284c152`）；独立复算 `d9c_reply_pick_order_recalc_by_verifier.md`（`c7ed6b29` / `0ac16a7`） | 不能说明"顺序无用"——顺序明显改变了行为；也**不能**说明"真 LLM 下 `lag≥3` 也必为 0"（见 ③-3） |
| A4 | **`lag_turn` 与 `lag_round` 必须分列**：两臂 `lag_round` 上界同为 2，但 `lag_turn` 上界 **1→2 随顺序变化** | 同上（`52ab0413` / `284c152`） | 不能写"上界由结构决定"——那会漏掉 `lag_turn` 的可动性 |

**②-A 的一句话概括**：**同回合看不见 ⇒ `lag` 最小为 1；引擎折叠时机决定上界，参数只能在 {1,2} 里重新分配。** 若要 `lag ≥ 3`，必须动引擎的消息折叠时序，属"改坐标系"。

### ②-B 文本层（只有一条，且是纪律不是结论）

| # | 结论 | 证据件 | **它不能说明什么** |
|---|---|---|---|
| B1 | **`lag` 分布是"行为形态"，不是"结构量"**：同配置的 mock 臂 `lag={1:656,2:7}`（`lag=2` 占 1.06%）vs 真 LLM 臂 `{1:327,2:153}`（占 **31.88%**），**差约 30 倍**；而同臂内的结构量（MSG、回复、`lag=0` 为 0）一致 | `v2/refs/mock-vs-real-llm-lag-divergence.md`（`96bb8ca5` / `ea7a21b`） | mock 数**不能**用来估计真 LLM 的回复延迟分布；只有 mock 数时必须标「mock，不代表真 LLM」 |
| B2 | **真 LLM：结构确定、文本随机**。同配置同 seed 的两个真 run：**686 条 MSG 文本逐条不同**（逐行差异 185,825 行），但 MSG/回复/`lag` 三项全同 ⇒ "**两个 run、一份结构信息**" | `v2/refs/real-llm-structural-determinism.md`（`509edca2` / `8e8aafd`） | 不能说明"结构稳"——只说明**同 provider 内**稳；**provider 是结构参数**，mock 与 `openai_compat` 是两种结构，不是同一结构的不同噪声 |

**②-B 的一句话概括**：**结构层可用 mock 判（省时省钱），文本层与时间分布必须真 LLM。** 报样本数必须写维度：结构维度同配置同 seed 只算 1 份；文本维度每次 run 都算 1 份。

## ③ 什么是不可判的、为什么

| # | 不可判项 | 为什么不可判 |
|---|---|---|
| 1 | **`lag ≥ 3` 能否出现（真 LLM 下）** | 本批 `lag≥3 = 0` **只在 mock 上成立**；真 LLM 臂的 `lag` 形态已是 mock 的 30 倍差异（见 B1）⇒ 外推无依据。要回答必须新跑真 LLM 臂 |
| 2 | **"回复变慢是否让对话读起来更好"** | ①mock 臂**没有真实语言生成**（body 是模板文本），人工读样本这一验收项在 mock 上**不可能执行**（预登记 §5-2 的设计缺陷）；②即便有真 LLM，本线只测"时机"，未测措辞/内容/"迟到的补白" |
| 3 | **"是不是根本没有积压"** | `starved_inbound` 口径作废（原式把发起消息算进"未回入站"：H0 的 372 = 139 未回发起 + 233 未回回复）；按 `participants` 重算得 289/251，但 PUBLIC 91/86 条无对端被跳过、"按消息计 vs 按对端计"未定 ⇒ **未定型，不得引用** |
| 4 | **D9c 的判定本身** | 预登记四档（E/L/T/I）**全不命中** ⇒ 只能判「不可判（判据未覆盖）」；缺的一档是"主判据未达线但次级结构量显著变动"，需新预登记后另测，**不得回改本次判定** |

**为什么这些"不可判"值得单独写**：它们不是"暂时没算"，而是**结论方向已被证伪或被口径缺陷阻断**。把它们写成"待办"会让人以为再算一次就有答案。

## ④ 对下一步的建议（两条，配套使用）

**建议 1（本线内）：不要在"回复时机"上继续投入；要动就得先出只读可行性与代价规格。**
**建议 2（本线外，更上位）：D9 参数线结项，主力转语言层。**
依据 `v2/evidence/d9-direction-mismatch-observation.md`（`43bc728d` / `6652244`）：**参数线三方向全空**（窗口 A2 / 顺序 A3 / 选择权 预筛否），
而真 LLM 对话的**内容层已相当可用**（该件引了两段原文，如老石「带徒弟……是好事。我这儿，没人来。」、金先生「差一点活了，差一点也死了」）
⇒ **"时机"与"内容"是两件几乎无关的事**，参数线边际收益接近零。

> **它不能说明什么**：内容层"可用"是**定性举例**，不是量化评估（无 judge 分、无人工量表、无双盲）；也不说明"语言层一定好做"，只说明"参数线已到顶"。

理由（三条，按重要性）：
1. **瓶颈不在参数层**：窗口（A2）与顺序（A3）都已证"改不动上界"；`lag ≥ 3` 需要改引擎的**消息折叠时序**（同回合可见性），那是改 `round` 语义的坐标系；
2. **代价不对称**：一旦改坐标系，**现有全部读数失去可比性**（R 值、`lag` 分布、≥3 轮占比、全部历史臂对照），而当前最值钱的是"一批可比历史臂 + 一套已校准口径"；
3. **语言层还没验**：措辞、内容、迟到补白、误会与和解——这些在本线上**一次都没测过**；先换尺子等于把尺子全扔。

**本节作废（2026-10-29 17:37）**：曾以为下一嫌疑点是"选择权"（`code/life/agent.py` 的 `to = partners[0]`，agent 无选择权）。
经只读预筛否决（`v2/evidence/d9d-initiate-peer-diversity-prescreen.md`，`bb550b5e` / `f0ee80c`）：
**16/16 全员参与发起**（无哑巴）；有对端的发起 183 条（另 83 条纯 global 无对端概念）；
**不同 `(发起人,对端)` 对 176 / 理论上限 240 ⇒ 使用率 73.3%**；每 agent 独特对端数**中位 12–13**、11/16 的 agent ≥10、2 个用满 15 人；
**单对端最大占比 mean 0.189**（最高者 0.29）。
⇒ `to = partners[0]` 的"固定性"**被每-slot 模板的多样性抵消**，分布已接近自然社交的分散度 ⇒ **对端选择不是瓶颈，该方向不开实验、不写预登记**。
**三个参数方向（窗口 A2 / 顺序 A3 / 选择权 预筛否决）至此全部关闭。**

> **它不能说明什么**：预筛只说明"对端分布不集中"，**不**说明"agent 若有了选择权会产生更好的关系网络"——那是未测的假设，不能由本预筛反推。
