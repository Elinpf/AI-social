## 4. jev 候选枚举决策法的机制拆解与迁移评估

### 4.1 机制拆解（把"自由生成"换成"受限判别"）
```
传统：LLM → 自由生成 JSON 动作      （慢、贵、易 JSON 解析失败、可能生成非法动作）
jev 法：
  [1] 引擎枚举：由世界状态 + 规则 确定性算出**合法候选动作集** C = {c1..cn}
  [2] 判别调用：把 (state, C) 交给判别模型
  [3] 类型化返回：choice=ci + probability p + confidence c
  [4] 引擎执行：校验 ci ∈ C 后落到世界状态；低置信度 → 退规则/人工
```
**关键点**：**合法性由引擎保证，模型只做"选哪个"**；输出是**类型化离散值**，**不需要解析自然语言 JSON**。

### 4.2 迁移条件
| 条件 | 我们是否具备 | 说明 |
|---|---|---|
| **确定性候选生成器** | ✅ 基本具备 | 我们的**中央裁决器**已在"只接受合法 op"；只需反向暴露"**为某 Agent 枚举当前合法动作集**"（类似 precondition 求解） |
| **类型化判别模型** | ⚠️ 需接入或自建 | 接 **jev API**（最简）；或自建（logit-masking/NLI 复现）；或用普通 LLM 出 `choice`（但会失去"输出免费/毫秒/校准"优势） |
| **候选集可枚举且有限** | ✅ | 我们的动作空间本就离散、有界（回合制） |
| **置信度阈值回退** | ✅ 契合 | 与我们"T2→T1→T0 降级""低置信转规则"设计一致 |
| **冻结与可重放** | ✅ 契合 | 把 `(候选集, 选择, 概率, 置信度)` 一并写入 `LLM_CALL/LLM_JUDGMENT` 日志即可复现 |

**结论**：**迁移条件基本满足**；主要工作量在①实现"为每个 Agent 枚举合法动作"的候选生成器；②接入/自建判别模型；③把判别结果纳入冻结日志。**与我方"引擎唯一真值 + LLM 只出意图"边界天然同构。**

### 4.3 对 token 成本的影响（估算）
设：每回合每 Agent 需要一次"下一步做什么"决策；上下文输入 `I` token。
- **自由生成方案**：输入 `I` + 输出 `O_gen`（含 JSON/推理，经验 **数百～数千 token**）。
- **jev 候选枚举方案**：输入 `I + L`（`L`=候选列表 token，**有界、通常几十 token**）+ 输出 **≈0**（jev 输出免费且单次前向）。
- **净影响**：
  - **输出 token 成本 → ~0**（这是最大节省项；若长时程高频决策，节省随"Agent 数 × 回合数"线性放大）；
  - **输入 token 略增**（候选列表 `L`），但当 `L << O_gen` 时总成本下降；
  - **延迟**：单次前向 70–500ms vs 自回归 2–5s → **每决策延迟降一个量级**。
- **保守公式**（每次决策成本变化）：
  `Δcost ≈ price_in·L − price_out·O_gen + price_out·0`
  当 `price_out` 显著（自回归输出按 token 计费而 jev 输出免费）时，**Δcost 为负（省钱）**。
- ⚠️ **风险**：候选数 `n` 大时 `L` 上升；**应限制候选集大小**（如 top-k 合法动作）。**数字为量级估算，非实测【推断】**。

## 5. 可迁移点 top-5（每条一句话说明迁移价值）

1. **引擎枚举合法候选 + 模型受限选择（jev 模式）** →**直接填进我们"LLM 只出意图"的边界**，消灭自由 JSON 幻觉与非法动作，且输出 token 成本趋零。
2. **类型化输出原语 `choice/score/noul` + 校准置信度** → 把"下一步做什么/要不要/打分"统一为**可判定的类型化接口**，并支持**低置信度回退规则**（与我们分层降级一致）。
3. **单次前向 + KV 前缀共享（候选共享上下文）** → 在"同一状态评估多个候选"时，**边际延迟近零**，适合我们每回合高频的候选判别。
4. **公共记忆/共享记忆（"活的世界"雏形）+ 其工程通病清单** → 直接对应我们**涌现观测层**要观测的"信息传播/事件涌现"，且其"泄密/传旧闻/矛盾/来源丢失"正是我们**确定性日志 + 来源可追溯**要解决的问题。
5. **一个学生模型 + 多教师蒸馏承载多角色** → 为"50+ 角色各不相同"提供**低成本模型路线**（避免每角色一模型），可作为我们模型层的成本优化备选。
