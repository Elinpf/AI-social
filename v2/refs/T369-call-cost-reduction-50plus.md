## 0. 结论速览

1. **【事实】墙的形态不是"模型慢"，是"调用次数 + 零缓存尾巴"**（T350）：N=50×12 真 LLM 跑满（rc=0），但 **43,798 次调用 / 833 s·回合⁻¹**；**调用/回合对 N 强超线性（63.7×，拟合指数 ≈4.5）**，比 O(N²) 更陡。
2. **【事实】成本构成被"缓存"劈成两半**：`importance` 占 **95.6% 调用但 97% 命中缓存**（便宜，21.5 tok/调用）；**`judge` 仅 3.4% 调用却 0% 缓存 + thinking（贵）⇒ 真 token 尾巴**。
3. **【建议】削减应打两处（结构性、非调参）**：① **调用次数**（`importance` 合并/批量/降触发——省的是"每次调用的开销与墙钟"，非 token）；② **零缓存尾巴**（`judge` 判别式化/降频/去重——省的是真 token）。
4. **【建议】三条结构性杠杆**（已有前置）：**读路径增量聚合**（T295/T312/T319/T328/T338 已成）、**共享不可变源**（T268）、**分时/双时钟唤醒**（T265/D9+M4）——把"按人×回合全量付费"改成"按事件付费 + 错峰"。
5. **【建议】代价**：这些改动**多数属"改读路径/触发"，少数改判定来源** ⇒ 需与 **`T300`/`T355` epoch** 对齐、单变量消融、**保住可重建/可审计**。

## 1. 调用构成拆解（**【事实】**，T350 §3.1/§3.2）

| purpose | 调用 | 占比 | 缓存命中 | tok/调用 | 性质 |
|---|---:|---:|---:|---:|---|
| **importance** | **41,877** | **95.6%** | **97.0%** | ~低（被摊薄） | **次数主项，但便宜** |
| **judge** | **1,499** | 3.4% | **0.0%** | 高（thinking） | **真成本尾巴** |
| reflect | 272 | 0.6% | 0% | — | 到期触发 |
| dialogue | 100 | 0.2% | 0% | — | — |
| plan | 50 | 0.1% | 0% | — | 每周 |
| **合计** | **43,798** | — | **92.7%** | **21.5** | — |

- **【事实】per-round 非平稳**：调用**挤在每"3 回合段"首回合**（r1/r4/r7/r10），且逐段放大（2,884→2,287→**11,761→26,545**）⇒ **事件触发型随社会累积放大**（非平稳）。
- **【事实】与 N=20 对照**：调用/回合 **63.7×**（N 仅 2.5×）、per-agent-回合 **25.5×**、token/回合 **≈10×**（因 importance 缓存摊薄）。⚠️ 口径：N=20 热缓存/84 回合 vs N=50 冷缓存/12 回合，**不可直接比 per-round**。

## 1.5 ★ 靶心：`judge` 为何零缓存 / 能否缓存·批量·判别式化 / 降多少（Leader 点名先答）

**【事实】缓存键口径**（`code/freeze/llm_client.py:225-247` `make_cache_key` + `:70-78`）：
`cache_key = digest{ cache_schema, kind=purpose, engine_version, prompt_hash, model, tier, params }`，
其中 `prompt_hash = hash(system + user + params)`（**含整段 prompt，且含 `thinking`**）。⇒ **只有"完全相同的 prompt"才命中**。

- **【事实】`judge` 零缓存的根因**：judge 的 prompt 是**成对关系判定**（parties + 关系值 + 事件上下文），**每次几乎唯一** ⇒ `cache_key` 唯一 ⇒ **无重复 ⇒ 0% 命中**。对照：`importance` 的 prompt ≈ **观察文本**，**跨 agent/回合重复**（共享源）⇒ **97% 命中**。→ **不是"忘了开缓存"，是"输入天然不重复、缓存救不了"**。
- **能否缓存？【建议】有限、且要靠"改输入形态"**：仅当 `(dim, 上下文)` **完全重现**才命中；judge 上下文随关系演化 ⇒ 天然低效。可行提升：① **prompt 规范化/缩短**（剔无关字段，提高重复率）；② **走 M2b 受限选择**后，输入可标准化为"**候选枚举 + 固定 rubric 前缀**" ⇒ 重复率↑（且输出 tok↓）。
- **能否批量？【建议】可，且是"调用数/墙钟"杠杆**：同回合多对判定**合并为一次请求**（本地拼批，或 provider batch —— **【未验证】**）。**降调用数，不改 token 量级**。
- **判别式化降多少？【外推】`judge` token ≤0.2×**（依据 `T212`：一致率 0.9902、**成本降一个量级**）；须过**校准门**（ECE；校准差则退化为"受限选择 + 规则回退"）。
- **为何它随 N 成对增长**：judge 是**成对关系判定**，对数 `C(N,2)` ⇒ 超线性；**且零缓存 ⇒ 直接进成本**。这正是 `T350` 里"调用/回合 ×63.7（N×2.5）"的机理之一。
- **⇒ 结论（靶心）**：**`judge` 的靶子 = ① 输出 tok（判别式化）② 调用数（批量）——"让判定更便宜"，不是"少判定"。**

## 2. 削减项（**【建议】**；目标=结构性削减，非调参）

> 每股：**针对的构成项 → 机制 → 预期削减【外推】 → 语义/观测代价 → 验证 → 前置/参考**。

### L1 ★ 调用次数：`importance` 合并 / 批量 / 跨 agent 去重
- **针对**：95.6% 的调用次数。
- **机制**：同一回合内，对**同一源事件**的 `importance` 打分**合并**（不同 agent 观察同一 `RELATION_CHANGE`/`PLACE_*` → 一次打分，或按"同文本"去重）；同 agent 同回合多条 → **批量一次**（若 provider 支持 batch，否则本地合并成一次请求）。**触发门槛收紧**（仅显著事件，已经是现状方向）。
- **预期**：**调用数 ↓**（粗估 1.5–5×；【外推】，因 importance 已 97% 命中缓存 → **省的是每次调用开销 + 墙钟，不是 token**）。
- **代价**：**判定语义须不变**（合并后判定结果须与逐条逐条等价，或明确记录"合并"事件）；**可重建**（合并规则确定性、落日志）。
- **验证**：**逐条等价**（合并版 `importance` 序列 == 逐条版）+ 单变量开/关对照。
- **前置**：重要性触发/去重当前在 life（`_observe`）；M2b 已把 importance 判別式化可选（T213/T222）。

### L2 ★ 真 token 尾巴：`judge` 治理（M2b 判别式化 + 降触发率 + 去重/缓存）
- **针对**：3.4% 调用 / **0% 缓存 / thinking 贵** = **真成本尾巴**。
- **机制**：① **判別式化**（候选枚举 + 类型化打分，输出 ≤ 几十 tok，替代长 CoT）——T212 实测一致率 0.9902、成本降一个量级；② **降触发率/合并同类判定**；③ **去重/缓存**（同输入同判定）。
- **预期**：`judge` **token ≤0.2×**（【外推】，依据 T212/T213）；总 token 显著↓。
- **代价**：**改判定来源（生成→受限选择）** ⇒ **须校准门**（T212：一致率 + ECE；置信度回退证据不足则不启）；**`LLM_JUDGMENT` 冻结事件语义不变**（仍落日志、可重建）。
- **验证**：同 seed 对照 + **一致率/校准度** + 冻结可重建。

### L3 事件触发型超线性的**结构性**削减（读路径 / 扇出）
- **针对**：调用随"事件/关系对/记忆"累积放大（指数 3.5–4.5）。
- **机制**：**共享不可变源 + 指针**（T268，已成）、**读路径增量聚合**（T295/T312/T319/T328/T338，已成）、**感知范围收窄**（visibility scoping；T264/T266/T330/T331b）—— 让"谁看得到什么"更局部，**降低 importance/judge 的触发扇出**。
- **预期**：**削减扇出**（与人口/关系对相关；【外推】不给定点）。
- **代价**：**改读路径**（非存储）⇒ 按今日判据**显式标注**；**感知收窄会改"看到什么"⇒ 属改语义**，须单变量消融 + epoch。
- **验证**：**消费点被读三档证据**（HIT / FALLBACK / 静默回退可观测，范式见 T351/T345/T338）+ 逐条等价。

### L4 模型分级（tier）
- **针对**：非判据类 `reflect`/`describe`/`narrate` 与靠后的 `judge` 维度。
- **机制**：`reflect/describe/narrate` 下沉便宜档；`judge` **只对高价值维度**保留 T2 thinking（米哈游 L1–L5 智能分级）。
- **预期**：单次成本 ↓≥30%（【外推】，T203 §4.3）。
- **代价**：质量须冒烟对照；不改判定结构。

### L5 分时 / 双时钟唤醒（D9 / M4）
- **针对**：墙钟（LLM-IO 受限）+ 尖峰。
- **机制**：`T265` 唤醒集 + `M4` 并发错峰 → **只为本回合真正发生的事付费** + 平滑 QPS。
- **预期**：**墙钟 ↓（并发）/ 尖峰 ↓**；**调用次数↓有限**（T350 非平稳：段首爆发恰是"有事发生"，唤醒恒真）——**别指望它省调用**（T263 已证）。
- **代价**：默认 off；与 epoch 对齐。

### L6 provider 层（**未验证**）
- 前缀缓存（T350 已 92.7% 命中）、batch API、并发上界 —— **【未验证】** provider 是否支持；可能带来 wall/token 双重收益。**标【待定】、须 T208 类探测**。

## 4. 对世界语义与观测性的代价（**必须保住可重建、可审计**）

- **判据（今日口径）**：**①日志还能不能解释世界？②同 sha 只变一个开关时消融还比不比得了？**
- **能保住的**：所有 L1–L5 的机制都应实现为**确定性、可落日志/可重建**（合并规则、聚合表、判別式输出 = `LLM_JUDGMENT` 冻结事件）。
- **需显式标注的**：**L3 感知收窄 / L2 判別式化 / L1 降触发** = **改"读法/触发/判定来源"**（非"只改存储"）⇒ **单变量消融 + epoch 归属 + 交用户知悉**。
- **可审计**：合并/去重必须**不隐藏判定事实**（要么等价、要么落"合并"事件）；静默回退（缓存/降级）**必须可观测**（`DEGRADE`/`degraded=true`）。

## 5. 验证方法（**【建议】**）

1. **同 seed 单变量开/关对照**（每杠杆独立开关；默认 off；同 sha 只翻一个）。
2. **消费点被读三档证据**（防 inert；范式：`HIT`（派生态被真读到）/ `FALLBACK`（回退全扫）/ **静默回退可观测**；参考 T351/T338/T345）。
3. **逐条等价**（凡聚合/合并/端口化：`聚合结果 == 全表扫` 逐条，参考 T295/T312）。
4. **判別式质量门**（L2）：一致率 + **ECE 校准**（T212；校准差则不启置信度回退）。
5. **与 T350 对齐**：**用 release 正式数（sha `10428f24`）**，勿用初步数；本方案所有"当前值"均引 T350。
6. **epoch**：与 `T300`/`T355` 重冻对齐（改判定来源的 L2 起新 epoch；纯读路径的 L3 随现 epoch）。

## 6. 优先级（**【建议】**）

1. **L2（judge 尾巴）** —— **真 token** 杠杆最大、最值钱。
2. **L1（importance 次数）** —— 次数/墙钟杠杆。
3. **L3（扇出结构）** —— 治本（超线性根因），但**动语义**、需 epoch。
4. **L4/L5** —— 补充（成本/墙钟）。
5. **L6** —— 待探测。
