## 1. D2.7 到底栽在哪（决定本臂怎么改）

| D2.7 的观察 | 失效原因 |
|---|---|
| `paren_rate` 0% → **100%** | 指令说"**可用**"，模型执行成"**必需**" ⇒ **过冲**，且不符合生活质感（真人不是每句都做动作） |
| `len_p50_excl` 40 → **26 字（−35%）** | **总输出预算没变**，旁白是从台词里抠的 ⇒ **替换而非伴随** |

⇒ 本臂针对性改两处：**①把"可用"改成确定性的"按比例可用"；②给台词一个显式下限**。

## 2. 改动（两处收尾指令 + 一段确定性开关，均在措辞层）

### 2.1 概率性旁白（确定性，不用随机数）

两处收尾指令改为**条件式**，条件由 agent 侧计算后拼进提示词（不改任何 config/结构）：

```
para_on = (int(sha256(f"{thread_id}|{turn}")[:8],16) % 3 == 0)     # ≈ 1/3 的话带动作
```

- `para_on == True`  ⇒ 收尾指令写：「**这句开头先用一个括号写一个具体的动作或神态**（不超过 15 字），再写台词。」
- `para_on == False` ⇒ 收尾指令写：「**这句只写台词，不要写任何动作/神态/心理描写。**」

**为什么用哈希而不是随机数**：项目纪律要求计划/生成**确定性可复现**（同 seed 同输入 ⇒ 同输出）；
哈希保证"三分之一"这个比例是**稳定的、可复算的**，且单测可验证（同一 `thread_id|turn` 恒定同值）。

### 2.2 台词长度配额

两处收尾指令**共同**追加一句：
> 「台词本身不少于 30 字、不超过 80 字，要像真人随口说的话。」

（当前 C 臂 `len_p50_excl = 40`，30 字是**下限而非目标**，不要求变长。）

### 2.3 保留不变（一字不改）

「不要解释也不要总结」「用口语短句，别反复用同一句口头禅」、`_l7_struct_line` 结构提示、
上下文装配（`history_turns=3`、`max_thread_chars=240`）、配额（`max_messages_per_slot=2`）、
线程参数（`max_turns=6` 等）**全部不动**。零 config 改动。

## 4. 判据（跑前写死；**P 用区间与连续口径，不用"越高越好"**）

| # | 指标 | 达标线 | 未达档位 |

| **M1 机制生效** | `paren_rate` | **落在 [25%, 45%]**（≈1/3，**过高也算未达**：>45% ⇒ 仍过冲）；且旁白 `p50 ≤ 20 字` | **机制未生效（比例失控）** |
| **P1（主）台词不许变短** | `len_p50_excl` | **≥ C 的 100%**（即 ≥40.0，允许 ≥40） | **无效（台词仍被挤短）** ⇒ 直接判作废档 |
| **P2（主）具体性** | `P1_count_mean`（**连续口径**，`d12c_metrics.DETAIL` 词表计数均值） | 相对 C **↑ ≥ 10%**（≥3.51） | **无效（只是加花架子）** |

| **Q3** | `F-2_content_drift`（=F-2′） | 相对 C **降 ≤ 2.0pp** | **无效（内容漂移）** |
| **S** | `n_threads`、`n_msgs_total` | 相对 C **±10%** | **作废（非单变量）** |
| **代价** | `llm_calls` | ≤ +10% | 破只记录 |

> **P1 为"一票否决式"前置**：若台词变短，即使 P2 涨了也**直接判「无效（台词仍被挤短）」**，

**判定合成**：M1 过 + P1 过 + P2 过 + Q1/Q2/Q3 过 + S 过 ⇒ **有效**。
