## 2. 目标 1：时间区间口径（**【建议】 + 给 08 的口径清单，不替 08 定**）

### 2.1 核心：回合外保留、tick 内加"微时刻"

```
现状：事件只有 round（整数 tick）；同 tick 内靠 seq 定序，但语义上是"原子快照"。
B：  world_micro_time  μt = round * U + sub     (U = 每回合微时刻数，整数)
     事件携【可选】区间 span = {start:(round,sub), end:(round,sub)}
       - 瞬时事件：start == end（默认，向后兼容，不填即 (round,0)）
       - 跨 tick 事件：end.round > start.round ⇒ "进行中"跨结算拍
     round 仍是【结算拍】（代谢/税/计息/守恒/观测切片 = 每回合一次，不变）；
     μt 只用于【排序/重叠/先后/进行中】，不改变结算频率。
```

- **用"世界时刻"还是"回合内相对偏序"？** → **【建议】两者兼得**：**对外/对格价**用 `μt`（世界微时，全序、可与 round 互转）；**tick 内**等价于相对偏序。避免"绝对墙钟"。
- **跨 tick 区间与结算拍共存**：区间**在每回合的结算里只结算"本回合那一片"**（见 §3）；`end.round>start.round` 的事件在**未结束回合**是"进行中"（§4）。
- **`U` 取值**：**【建议】默认 `U=SLOTS_PER_DAY*ROUNDS_PER_SLOT`? 否** —— 直接用**每回合微时刻数 `U`（建议 6，可调 1–12）**，与 slot 解耦；`U=1` 退化为现状（原子）。

### 2.2 【待定】给 08 的口径清单（**不替 08 定**）

1. **区间字段**：在既有事件**加可选字段**（不新增类型，遵 T8 原则）：`span.start_round/start_sub/end_round/end_sub`（缺省=瞬时 `(round,0)`）。
2. **哪些事件带区间**：移动（MOVE/ARRIVED）、活动（ACTIVITY_*）、会话（MSG_*）、要约（OFFER_*）、再扩展？（**先最小集**：移动+活动）。
3. **`U` 语义**：`rounds*U+sub` 全序；`sub` 值域 `[0,U)`；是否允许 `end` 落在**未来 round**（进行中）。
4. **`seq` 与 `μt` 的关系**：`seq` 仍**全局唯一事实序**（红线）；`μt` 是**语义时间**；排序键 `(round, sub, seq)`（或 `(μt, seq)`）须在 08 写死。
5. **默认值/向后兼容**：无 `span` 的旧事件 = 瞬时；**旧日志可读**（不得强制迁移）。
6. **时间模型版本戳**：日志带 `time_model`（如 `"atomic"` / `"interval-U6"`），用于**分界线**（§7）。
7. **TURN_SEAL**：是否记 `time_model`/`U`（建议：是，只增可选字段）。

> **★ 已落（T8）**：以上 7 项 T8 已落 **08 §5.10**（commit `6cf176e`）：区间字段可选 `span`、最小事件集（移动+活动）、`U` 默认 6 可调 1–12（`U=1` 退化原子）、**事实序=`seq` / 语义时间序=`(start_μt, agent_id, seq)` 二者并存不可混用**、无 `span` 兼容、`TURN_SEAL` 加可选 `time_model`+`U`、轻索引增可选 `start_sub`。**本文引用 08，单一真源在 T8**。

### 2.3 `U=6` 的取值理由（Leader 要求写进 08 口径，**【建议】**）

- **分辨率 vs 日志体积**：`U` 每翻一倍，**区间事件的排序分辨率**翻倍，但**字段值域与"同回合内可区分的先后段数"**也翻倍；`U` 过大 ⇒ 语义上"同一回合内被切得太细"、且**排序/切片计算量上升**（`O(事件数·log)` 仍可控，但多余片段增多）。
- **实际动作粒度**：移动/活动的最小可感时长以**时段（=3 回合）**为量级；`U=6` 给出"每回合 6 个微时刻" ⇒ **一次移动（0–3 回合）与一次会话往复**都能落在整数微时刻上，**不必更细**。
- **退化与控制**：`U=1` = 现状（原子）；**`U=6` 是"够用且不虚增"的折中**，并**可调 1–12** 供标定。
- **【未验证】**：`U` 对日志体积/排序开销的实测影响，**须在期①的对照里量**（见 §5 验收）。

## 3. 目标 2：仲裁如何变（**【建议】**）

- **现状**：**一次性原子结算**——相位内按 `seq` 全序折叠；对"过程"无概念。
- **B**：把动作建模为**区间**，每回合 P4 ARBITRATE **按 `μt` 排序、按区间重叠结算本回合切片**。

### 3.1 判定规则（**【建议】**，交 08/kernel 复核）

| 规则 | 内容 |
|---|---|
| **排序** | 键 `= (start_μt, agent_id, seq)`，**全序**（确定性） |
| **独占资源** | **同一 agent 不得有重叠的"独占动作"**（移动/劳作=独占；参照 SKYCity R1「一个 agent 同时最多一个进行中行动」）→ 重叠 = **确定性拒绝**；⚠️ **拒绝必须"可解释"**：落 **`INTENT_REJECTED`（带 `intent_class` + `reason` + 冲突区间）**，**禁静默丢**（否则日志解释不了世界，违两问①） |
| **跨 agent 交错** | **允许**交错（不同 agent 区间可重叠）；**互不影响**除非共享资源（同场所容量、市场撮合） |
| **先后/因果** | "**回应在发起之后**" ⇒ `reply.start_μt ≥ original.end_μt`（或 `≥ start`，口径 08 定）；用于对话/谈判**跨回合**可判定 |
| **抢占/中断** | 高优先动作区间**覆盖**进行中低优先动作 ⇒ **`ACTIVITY_INTERRUPTED` 真正发生**（现 0 次） |
| **结算切片** | 跨回合区间在**每回合末**结算"归本回合的比例/离散片"；**守恒仍每回合校验** |

### 3.2 与"回合缓冲 + P6 唯一 append"的关系（**【建议】**）

- **保留**：ADR-08 整回合缓冲 + **P6 唯一 append + 守恒回滚**。
- **新增（加法）**：区间/`μt` **只作为事件字段与排序依据**；**不并行乱序 append**（`seq` 全序红线不变）。
- **间距**：tick 内"分片结算"是**同一回合缓冲内的确定性切片**，不引入新 append 点。

### 3.3 ⚠️ 【待定】切片结算与"日志唯一记录"（kernel-dev `d87309ed` 点 2，**必答**）

- **问题**：**逐回合切片结算若不发事件**，则"本回合结算了多少"**不是日志事实** → 可能违反**纪律①（日志仍是唯一记录）**。
- **【建议·判定规则】**：**看切片是否有"独立事实"**：
  - **若切片是"已记录区间 + round"的纯函数**（如"本回合占了该活动 1/3"、纯派生的中间量）→ **可由日志推导 ⇒ 满足纪律①**（无需新事件；"进行中"=可重建派生）。
  - **若切片含独立事实**（如"本回合消耗了某资源/产生了某结果"，非区间可推）→ **必须发事件**（要么新类型、要么**扩 `ACTIVITY_*` 加性字段**）→ **交 08 定**。

## 7. 分界线怎么划（**【建议】**，必答）

- **历史基线不可直接比较** ⇒ **在日志/`TURN_SEAL` 埋"时间模型版本戳"**：`time_model ∈ {"atomic"(B 前), "interval-U6"(B 后)}`（+`U`）。
- **规则**：
  1. **跨分界线的 run 不得混入同一曲线**（同 §7 口径）；
  2. **消融对照必须在同一 `time_model` 内**（同 sha 只变一个开关）；
  3. B 前产物标 `atomic`，B 后标 `interval-*`；**重冻基线**从此分两套。
- 这与 T236（重冻）、T281（`segment.enabled`）**同族**：**每次动语义/结构都要一个可识别的"版本戳"**。

## 8. 区间化状态可否重建（**【建议】**，必答；与 T276/T285/T262）

- **能**：
  - **区间是事件字段** ⇒ `replay = reduce(apply_event, 日志)` **天然折叠**；"进行中"= 由日志**可重建派生**（同 T281 §「可重建派生集合」）。
  - **T276 续跑**：续跑读"最后一段 + 轻索引"重建视图；区间/`μt` 随事件保存 ⇒ **续跑不丢时间语义**。
  - **T285/T262（账本分段）**：段文件保存**含 `span` 的 record**；轻索引字段可含 `start_round`（**是否含 sub 交 08**，见 §2.2-2）；**段边界仍按回合**（T8 §5.9）——**与"跨 tick 区间"不冲突**（区间是事件属性，不跨段）。
  - **`state_hash`**：区间/进行中**不进 `state_hash`**（派生），故 **`state_hash` 只在"启用了行为改动（②③）"时变**；① 不变。
- ⚠️ **待定**：轻索引是否需要 `sub` 字段（影响回读精度）——交 T8/kernel。

## 9. 两问的可执行回答（必答）

**问① 日志还能不能解释这个世界？**
- **能**（**前提**：区间/排序/切片规则**确定且写进 08**）。具体：区间在事件里；"进行中"是**可重建派生**（不入真相源）；排序键 `(start_μt, agent_id, seq)` 全序；结算切片确定性 ⇒ **任意时刻状态 = 日志的确定性函数**。
- **反例边界**：若允许**非确定性抢占**或**依赖墙钟**，则不能——**故明令禁止**。

**问② 同 sha 只变一个开关，消融还比不比得了？**
- **能**（**前提**：三期**各有独立开关**、默认 off；同 sha 只翻一个）。三期开关：`time.interval.enabled` / `time.ongoing.enabled` / `time.interleave.enabled`。
- ⚠️ **但"B 前 vs B 后"不可直接比** —— 那是**两个 sha/两个 `time_model`**，用 §7 分界线隔离。

## 10. 一页第一期最小切片（**08 口径**）

```

【最小改动】
```
