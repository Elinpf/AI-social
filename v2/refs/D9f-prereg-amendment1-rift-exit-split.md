# D9f 预登记 · amendment 1：「rift 不在台账」必须拆三档 —— 淡忘不是和解

> 由来：`prompt-linguist` 读实现时发现（**不是措辞问题，是判读口径的漏洞**，我采纳）

## 1. 问题：`dialogue_repair.py` 有**两个出口**，都让 rift 从台账消失

```
code/life/dialogue_repair.py（sha256:2f75386f0cdf）
:189-196   ② 和解：has_repair(body) ⇒ rifts.pop()               ← 出口一：修复词命中
:197-200   prune(rifts, params, round_no)：
               · max_age_rounds 超龄 ⇒ 淡忘
               · max_open 上限 ⇒ 挤出（最早的）
                                                                  ← 出口二：淡忘 / 挤出
```

⇒ **「rift 不在台账」有三种成因**，而从**终态**看它们一模一样：

| 档 | 台账终态 | 含义 | 是不是"和解" |
|---|---|---|---|
| **c1** | 仍有未了结 rift | 冲突还在 | 否（但可核） |
| **c2** | rift 不在，**且无 `dialogue_repair`** | **淡忘** 或 **被 `max_open` 挤出** | **不是** |
| **c3** | rift 不在，且**无法区分** | 词表未覆盖该措辞（可能真和解了没被识别）／确实没和解 | **不可判** |

## 2. 为什么这条必须在跑批前写死

**`c2` 是最容易被读成"和解了"的一类——账没了，但没人道歉。**

若 D9F 把 `c2` 计入"修复闭环"，就会得出"DR 机制提高了和解率"的结论，而真相是**张力没有被化解，只是被时间冲掉**。那会**把一个降低生活气息的机制误当成功**：居民之间的不愉快不再有下文，而是到点自动消失——这恰恰是"机器感"最重的形态之一。

## 3. 由此对 D9F 追加的必报量（**未列入原预登记 §2，本件补**）

| # | 量 | 为什么必报 |
|---|---|---|
| 10 | **`prune` 命中数**（超龄淡忘 / `max_open` 挤出，**分开数**） | `c2` 的两个成因，缺一个就无法判定 c2 的构成 |
| 11 | **三档分类计数** `c1 / c2 / c3` | 判定"闭环"的唯一合法入口 |
| 12 | `has_repair` 命中条数（修复词触发 `pop` 的次数） | 这才是 c 的**真正**"和解"出口 |

## 4. 判读口径（写死，与原预登记 §5 五级并用）

- **L3「闭环走到」= 出现 `dialogue_repair`（含 `rift_id`）**；
- **`c2`（淡忘/挤出）不得计入 L3**，必须单列并报 §3 的量 10；
- 若 `prune` 命中数 > 0 且 `dialogue_repair` = 0 ⇒ 只能写「**rift 因淡忘/挤出而消失，无和解证据**」；
- **禁止**把"rift 数下降"直接写成"和解增加"。

## 5.1 `c2` 的成因判定路径：**允许"受校验的重放"（选 A）**

`_prune` 是**静默的**（`dialogue_repair.py:199-215`，不产生事件、不留日志）⇒ `c2` 的成因（淡忘 / 挤出）**无法从日志直接判出**。两条路已裁：

> **选 (A) 允许重放，但必须带自校验；校验不过即退回 (B) 记 CANNOT-VERIFY。**

**执行条件（缺一不可）**：
1. **只重放 `ingest_one` / `prune` 这条只读逻辑**，不重跑世界、不调 LLM、不改 `code/`；
2. **同 params**（`window_msgs=8 / max_open=3 / max_age_rounds=84 / context_max_age_rounds=24`）；
3. **同输入事件序**（按 `seq` 升序喂）；
4. **强制自校验**：重放出的 rift 状态序列，必须与日志中 `dialogue_rift` 字段（`open` 数、`with`、`threads`）**逐条对上**；
   - **任一处对不上 ⇒ 重放不可信，`c2` 整档退回 `CANNOT-VERIFY`（方案 B），不得局部采信**；
5. 退出原因分为四类并**分类计数**：`word-pop`（修复词，= 真和解）/ `age-prune`（超龄淡忘）/ `max_open-evict`（被挤出）/ `still-open`。

**为什么值得做这步（repro 的实测支持）**：
```
max_age_rounds = 84，而本臂 rounds = 84  ⇒ age-prune 几乎不触发
max_open = 3                             ⇒ 第 4 条以后的旧账会被静默挤掉
```
⇒ `c2` 的主体**大概是 `max_open-evict`，不是"淡忘"**。若走方案 B（整档不可判），D9F 里"账消失了"的读数会**大量落在不可判**，等于白跑这一臂；而重放能把它们分出来，且成本近零（无 LLM）。

**但重放本身必须被怀疑**：它是"用另一套实现复现同一状态"，一旦与日志不一致，说明我对 `ingest/prune` 的理解是错的——那时**宁可不可判，也不要一个自洽的错答案**。
