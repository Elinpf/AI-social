## 0. 结论速览

1. **【事实】当前呈现层"消费时间"的方式**：整条时间轴**只有"回合"一个粒度**——`main.js` 每 `speed` ms 推进一个回合、`town.js` 对该回合状态做一次**点到点补间**（时长∝显示距离，固定速度）。**没有任何地方消费"事件时长"**（因为世界层现在也不给）。
2. **【建议】总原则**：世界层给了 `span` 之后，呈现层**只做"把已记录区间翻译成画面"，绝不替世界补时长**（延续今日红线：**不让画面替世界撒谎**）。
3. **【建议】六问答案见 §2**；其中**最有约束力的是 Q6（不该编造什么）**。
4. **【建议】分期**：呈现端按 T286 三期**跟随**，每期只加"能消费的"（无字段时逐位不变、可回退）。
5. **【待定】**：播放时钟是否从"按回合"升级为"按 μt"（涉及 `main.js`/`review.html`，**须保持默认行为不变**）。

## 1. 【事实】现状：呈现层现在怎么消费"时间"（给文件:行）

## 2. 六问：答案

### Q1 移动跨 N 回合：**匀速演满**还是**每回合一段拼接**？如何与结算拍对齐？

- **【建议】匀速演满（单条补间贯穿区间），不要"每回合一段拼接"。**
  - 理由：现状 `renderState` **每回合重设 `target`** 且 `tick()` 带**惯性 + 速度上限**（`town.js` tick）：若按回合切段，接缝处会因 retarget/惯性产生**一次抖动/顿挫**（正是要避免的"每回合接缝一跳"）。
  - 世界给 `span={start,end}` 后：`target` 改为**按区间进度 `lerp(起点,终点, progress(μt))` 连续更新**，renderer 速度 = `路径长 / 区间时长`（或维持 `VMAX` 但**取消每回合 retarget**，只在区间端点换点）。
- **【建议】与"回合结算拍"对齐**：**回合仍是结算拍**（T286 §2.1）；但**画面时钟改为可落在回合内（μt）**——播放推进仍是"回合"，只是回合内以 `U` 个微时刻细分成画面时间。
  - 方式 A（改动小，shell 侧）：**保留按回合推进**，把每回合的 `speed` ms **再细分**为 `U` 段推进画面时钟。
  - 方式 B（更彻底）：`main.js` 播放时钟从"离散回合"换成"连续 μt"，回合边界仅触发结算相关刷新（`renderFacts`/审计）。
  - **【待定】**A/B 由 frontend-dev 定（默认行为必须不变，见 Q5）。
- **【事实】现状无 span ⇒ 本条在给字段前**无法实施（保持现状补间）。

### Q2 「进行中」怎么表现，且不喧宾夺主？

- **【建议】最小侵入、复用既有语言，不新增常驻装饰**（今日已证"装饰越多越像贴图"，先层次后细节）：
  - **default 视图**：只在**场所层**一处**低频、弱对比**的"进行中"提示（复用现有夜光 dither / 接地影手法，统一调色板），**不逐 agent 叠加**。
  - **info / 选中视图**：才显示**头顶进度**（进度条/环形，由 `span` 的 `start→end` 派生；**必须可由日志重建**，不入真相源）。
  - 场所气泡：**仅在有"进行中"时才出现**，且合并同类（一个场所一条），避免铺满。
- **【待定】**：由谁触发头顶进度（常驻 vs 仅 selected）——建议**仅 selected**，符合"不喧宾夺主"。
- **【事实】** T286 §4：进行中=**可重建派生**（不新事件、不入 `state_hash`）⇒ 呈现端**只能消费派生视图**，不得自己维护"进行中"状态。

### Q3 对话 / 劳作有"持续"后，「在谈 / 在做」如何可感？

- **【建议】用 `span` + 关联字段做"进行中"的轻表现**：
  - **对话**：若日志带 `thread_id/reply_to`（T286 期③），仅在进行中画一条**两人之间的弱对比连线/相向小气泡**（像素虚线 + 抖动，统一调色板）；**无 thread 字段时不画**。
  - **劳作**：`ACTIVITY_*` 带 `span` 时，该场所的 agent 演**劳作姿态/步态**（复用 `tick()` 的行走/步态机制），或场所轻标。
- **【事实】** 现状：`MSG_*` **无线程**、`ACTIVITY` **只有起止两端点无进行中事件**（T284）⇒ **现在无法表现**，等世界层字段。

### Q4 瞬时事件（成交 / 交换）怎么"不一闪而过"？

- **【建议】不为瞬时事件编造"世界时长"；只做"呈现层的一次性强调"**：
  - 复用**已有一致语言**：审计台事件流 + 顶部走马条 `renderEvticker()`（`main.js:238`）**已**把瞬时事件呈现且**可回看**（事实）。
  - 画面内：**一次性高亮/闪记**（图标徽章 + dither 闪光），**其"停留"是 UI 行为、不是世界事实**（关键红线，见 Q6）。
- **【事实】** `MARKET_TRADE/TRANSFER` payload **无时长**（T284 分类表）⇒ 缺省=瞬时，呈现层**不得**把它演成"持续 N"。

### Q5 回放对齐：时间轴怎么改才不把"时长"压掉（且不破坏盲测台）？

- **【事实】** 盲测台每片段固定 `speed=150`（`review.html:116`）⇒ 即使世界给了时长，**按回合切**也会把跨回合区间压掉。
- **【建议】默认行为不变、只增可选开关**（严格不破坏 T275）：
  - **不改** `?log=` / `?rounds=` / `/__gitstamp` 语义（硬约束）。
  - **新增可选** `?tclock=round|mu`（默认 `round`＝现状）；`mu` 时播放按 **μt** 推进（Q1 方式 B），回合边界仅触发结算刷新。
  - 或**在 `index.html` 消费端**做 **speed ms 内细分 `U` 段**（方式 A，`review.html` 完全不用改）。
  - **5 片段与 5 维度不动**；`speed` 仍可传；`/__gitstamp` 不动。
- **【待定】** 是否给 `review.html` 增"时长感"提示（如片段标注 `time_model`）——建议**只读展示、不改判据**。

### Q6 ★ 渲染**不该编造**什么（红线清单，最高约束力）

> 原则：**画面只翻译"日志里已记录的"，不替世界补时长、不补过程、不补因果。**

1. **不编造"世界时长"**：无 `span`（或缺省=瞬时）的事件，**不得被演成"持续 X"**。（今日红线：画面不替世界撒谎。）
2. **不编造"进行中"**：世界层未暴露 `current_activity` / 无未结束区间时，**不显示"进行中"**（含头顶进度、场所气泡）。
3. **不编造"中间位置"**：日志无中间位置时**不假造轨迹**。现状 `tick()` 的点到点补间是**显示插值**（须明确标注为"显示层"）；**只有世界给了 `span`，才按其区间演**。
4. **不编造"先后 / 因果"**：同回合多事件**无 `μt`** 时，**不排序为"谁先谁后"**（不画"A 在 B 之前发生"）。
5. **不编造"关系 / 线程"**：无 `thread_id/reply_to` 时**不画"谁在接谁"**的连接。
6. **不因时长改变结算 / 锁死推进**：呈现端**不得**用"时长"去阻塞回合推进、或改变任何结算节拍（结算拍是世界层的）。
7. **不把"一次性强调"当世界事实**：瞬时事件的高亮停留是 **UI**，不得写回、不得当作事件时长。

## 3. 对 T286 第二 / 三期的**最小需求**（世界层要暴露什么，供呈现端消费）

> 呈现端**只需要"已记录的区间与关联"**；以下是**最小字段集**（对齐 T286 §2.2 / 08 §5.10 单一真源）。

**期②（进行中可感知）——呈现端需要：**
- **可选 `span`**：事件携 `{start_round,start_sub,end_round,end_sub}`（缺省=瞬时 `(round,0)`）。
- **移动**：`PLACE_MOVE/ARRIVED` 的 `span` **按 `topology.travel_ticks` 真实生效**（`end.round>start.round`）——呈现端据此演"走过去占 N 回合"。
- **活动**：`ACTIVITY_STARTED` 携 `span`（含 `end`）⇒ 派生出"进行中"。
- **`WorldView.current_activity`**（self + 同场所他人，按 `PERCEPTION_SCOPE` 过滤）——**供 Q2 的"进行中"表现**。
- **`time_model` / `U` 版本戳**（TURN_SEAL 可选字段）——供呈现端**分界线**与 Q1 的 μt 换算。

**期③（交错 / 先后）——呈现端需要：**
- **`MSG_*` 携 `thread_id/reply_to` + `span`**——供 Q3 的"在谈"表现与 Q6-5 的"可画连接"。
- **跨回合 pending offer 的 `span`**——供"谈判进行中"表现。

**【已定】（08 §5.10(g)，单一真源在 T8）】**：轻索引**增可选 `start_sub`**（**仅区间事件**；供回读/排序精度；`U` 由 `time_model` 版本确定；**默认原子不占**）。
→ **呈现端可依赖**：当 `time_model` 为 `interval-U<U>` **且** 该事件带 `span` 时，轻索引提供 `start_sub`；否则视为瞬时（无 `sub`）。**故"回合内先后"的可视化精度有据可依，不再是待定。**
