# 指标纪律：任何「机制命中量」必须先报它在 H0 下的取值

> 立此件：Leader（team-leader）｜2026-10-29
> 由来：D9b 结果件把「`lag ≤ window` 覆盖率 = 100%」当作机制命中量报出，`prompt-linguist` 指出这是**空转指标**（lag 上界只有 2，任何 `window ≥ 2` 都给 100%）。本件把纠正固化成**可执行判据**，使同类错误在下一次**预登记阶段**就被拦住，而不是等结果出来被读者抓。

## 1. 规则（一句话）

**对每一个「机制命中量」，先算它在 H0（该变量无效 / 未放宽 / 未生效）下的取值；再问一句：H1 下它有没有可能离开这个取值。只有当「H0 取端值（100% / 0 / 恒等 / 恒定）」**且**「该端值由与变量无关的结构决定、H1 下不可能改变」时，它才没有区分力。**

> ⚠ **「H0 下取端值」单独不足以判空转**（本件 §3 自身就是反例）：`lag ≥ 3 的条数` 在 H0 下 = **0** 也是端值，但 H1 下可能 > 0 ⇒ **有区分力**。判空转的充分条件是**两个假设下都必然取同一端值**。

## 2. 三步执行（写预登记时就要做，不是事后补）

1. **定义 H0**：清楚写出"如果这个变量完全无效，世界是什么样"。定义不出来 ⇒ 该量不可用（见 §4）。
2. **在 H0 下算该量**：拿 ctrl 臂（或解析推导）算出它在 H0 下的取值。
3. **比对**：
   - H0 取值 = 端值（100%／0／恒等） ⇒ **空转，不得作支撑证据**，从"命中量"移到"描述量"；
   - H0 取值与 H1 下**可能不同** ⇒ 有区分力，可作支撑证据，但**引用时必须与 H0 取值并列**。

## 3. 本次验算（用 D9b 检这条规则，证明它能自动发现空转）

设 `H0 = 窗口不放宽（window=2）`：

| 候选量 | H0 下取值 | H1 下能否离开该值 | 判定 |
|---|---|---|---|
| `lag ≤ window` **覆盖率** | 恒 **100%**（`lag ≤ 2` 恒成立） | **不能**：行为不变 ⇒ lag 上界仍为 2，`window=4` 也给 100% | **两假设同端值 ⇒ 空转，无区分力** |
| `lag ≥ 3` **的条数** | **0** | **能**：挑选顺序改了就可能出现 lag≥3 | 能取两个值 ⇒ **有区分力** |

⇒ 关键好处：**不需要事先想到"lag 本来就短"这种具体情形**。只要老实跑一遍 H0，就能自动发现空转，**不依赖设计者的想象力**。

## 4. 边界（不适用与不可用）

1. **H0 定义不出来的量，不得使用**——不是"可以宽松使用"，是**不能进结论**。例如"对话自然度评分"若无法写出"该干预无效时评分应为多少"，它只能作描述。
2. **端值判定按解析推导优先**：能从机制推出"恒真/恒 0"的，不必跑批。
3. **非零但恒定的量同样空转**：如"某类事件在 H0 与 H1 下都恒定 = 3"，等于没有信息，不因"不是 0 也不是 100%"就当成有区分力。
4. 本规则**只管"这个量有没有信息"**，不管"这个实验设计对不对"；后者仍由预登记的判定档负责。

## 5. 引用闸门扩展（与既有闸门并列生效）

**引用任何"命中"类数（命中数 / 触达数 / 排除数 / 覆盖率 / 触发率）时，须同时报该量在 H0 下的取值。若两者相同，该行结论只能支持「未触达 / 不可判」，不能支持「机制有效」。**

- 与「报豁免次数」「转化率必报分母」是同一个精神：**不报基线，就看不出这个数有没有信息。**
- 落地形态：证据件里"命中量"表格**必须有一列 `H0 下取值`**，空着即视为不合格。
