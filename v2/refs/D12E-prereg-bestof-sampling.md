## 0. 为什么必须换层（**两轮实验直接指出来**）

1. **D12-C**（提示词加"具体物/第三方"两行）：P1 **+10.20pp**、P2 **+16.08pp**，但 `L-7` **+20.98pp**（44.12%→65.10%）⇒ 具体物被**同一批骨架**承载；
2. **D12-D**（提示词再加"换新物/换开头"两行）：`L-7` **只降 0.59pp**（65.10%→64.51%）⇒ **未过 5pp 闸**；而旁白砍掉 **16.07pp**，**删掉旁白后重算的 `L-7` 反而升 0.99pp** ⇒ **模板句从旁白搬进正文，撞车总量不变**。

⇒ **提示词层已到边界**：模型会照做"内容"（槽里填什么），但不照做"骨架"（怎么组织）。再往指令里加约束，只会换来"看起来按要求了"。
⇒ 既有两条机制也已被击穿：`code/life/anti_repeat.py`（事后重试，R12 实测 `retries=88=collisions=88`，重试率 17.25%）、`code/life/l7_structural.py`（开口/收束轮转，A5 抽检 #7 仍三次复用同一骨架）。
⇒ **本臂换机制：不再"求"模型别重复，而是"选"出一条不重复的。**

## 1. 设计（**机制层 · 采样择优 · 确定性选优**）

新增 env **`LIFE_PROMPT_D12E_BESTOF`**（**默认 1 = 关闭，行为与现树逐字节一致**；`3` = 开启三采样择优）。

**开启时（`=3`）**，对**每一处对话生成**（`_dialogue_prompt` / `_reply_prompt` 的调用点，**仅对话生成**，`judge` / `importance` / `plan` / `reflect` 一律不受影响）：

1. 用**同一个 prompt** 连采 **M = 3** 次（温度等参数不变，靠采样随机性）；
2. 对每条候选算「与**该 agent 可见的最近 N = 16 条台词**」的 **8-gram 交集条数**（shingle 集合沿用 D5 `normalize_body` + 8-gram，**不自创口径**；最近台词取材复用 `l7_structural.recent_bodies(wv, agent_id)`，**replay 安全、无状态**）；
3. **确定性选优**：取交集数**最小**的那条；**平局取第 1 条**（保证 replay 可复现）；
4. 落盘 `ctx.d12e = {"m":3, "scores":[a,b,c], "picked":i}`（additive，进日志不进 `state_hash`）。

### 1.1 ⚠ 实现前提：**缓存键必须含采样序号**（否则三采一优会退化成"取同一条的三份拷贝"）

已核对实现（`code/freeze/llm_client.py::make_cache_key`，2026-10-23 10:40）：

```python
return digest({"cache_schema", "kind", "engine_version", "prompt_hash", "model", "tier", "params"})
# 命中逻辑：hit = self.store.get_response(cache_key)  ← 命中原样返回，不调模型
```

⇒ **同一个 prompt + 同 params ⇒ 同一个 `cache_key` ⇒ 第 2、3 次直接命中缓存、返回同一条文本**。
⇒ 若不处理，**M=3 的三个候选完全相同**，`scores` 三项相等、`picked` 恒为 0 ⇒ **择优机制形同不存在**，`L-7` 自然也不会动。这正是"开关未生效"的第六种形态，必须在代码里堵死。

**规定（实现者必须照做）**：
1. 每次采样把 **`sample_index = 0/1/2` 并入 `params`**（→ 进 `cache_key`），使三次调用是三次真实请求；
2. `sample_index` 必须由**确定性输入**派生（直接取 k 即可），**禁止随机数** —— 否则 `FREEZE_MODE=replay` 时重算出的 `cache_key` 与日志里的不匹配，会触发"重放模式缓存未命中（禁止真实调用）"，直接毁掉 replay；
### 1.2 三个"看起来一样"的东西必须分清（否则会做错实现）

| 名字 | 由什么决定 | D12-E 开启后会不会变 | 与判据/接线的关系 |
|---|---|---|---|
| **`prompt` 文本**（`_dialogue_prompt` / `_reply_prompt` 渲染结果） | 提示词函数 + 世界状态 | **不变**（D12-E 只加采样与选择，**一个字都不改提示词**） | ⇒ `prompt_fn_sha256` **必须仍等于 T1 的 `effc14db…`** |
| **`params`**（模型参数 dict） | 调用方传入 | **变**：三次分别为 `{…, "sample_index": 0/1/2}` | ⇒ 进 `cache_key`，使三次是三次真实请求 |
| **`prompt_hash`**（`_prompt_hash(system, user, params, messages)`） | 含 `params` | **会变**（3 个值） | 只影响 `LLM_CALL` 日志字段，**不影响任何判据**；`prompt_hash ≠ prompt_fn_sha256` |

**因此**：
- **正确做法**：`sample_index` 只进 **`params`**，**绝不写进 prompt 文本**；
- **不可取**：把采样序号/种子"写进 prompt 尾部改变 prompt_hash"——那会**同时改掉 `prompt_fn_sha256`**，等于**偷改提示词**，直接违反本臂的接线证明（sha 必须等于 T1），整臂作废；
- **也不用**换 `cache_dir`：`cache_dir` 变化会破坏"同一 store 内 replay"的既有契约，而 `params` 加键是最小改动。

3. 上述两条本身也构成**接线证明**：`LLM_CALL` 中对话 purpose 的 `cached` 必须为 **false**，且三条候选的 `cache_key` **两两不同**（跑后从日志核）。

**与既有机制的区别（必须写进报告，防止被当成"又一个 anti_repeat"）**：
| 机制 | 触发时机 | 选择方式 | 已知效果 |
|---|---|---|---|
| `anti_repeat`（既有） | 生成后撞车才重试 | 盲目重试 1 次 | R12：`retries=collisions=88`，**无效** |
| `l7_structural`（既有） | 生成前给开口/收束模板 | 无选择 | A5 #7：**仍复用同一骨架** |
| **D12-E（本臂）** | 生成时**采 M=3** | **按 8-gram 交集确定性择优** | 未知（本预登记要测） |

### 1.3 必须落盘的审计字段（**跑前定死，出数方按字段判，不按归组猜**）

`ctx.d12e` 至少包含：

| 字段 | 值 | 用途 |
|---|---|---|
| `m` | `3` | 接线闸 M1（命中率须 = 100%） |
| `sample_index` | `0/1/2` | 证明三个候选来自三次采样 |
| `scores` | `[a,b,c]`（与近期 16 条台词的 8-gram 交集条数） | 接线闸 M2（"非第 1 条被选中"比例 ≥20%） |
| `picked` | `0/1/2` | 选中哪条 |
| **`group`** | **`f"{thread_id}:{turn_index}:{round}:{from}"`（确定性派生）** | **出数方据此把三条候选归成一组**；**禁止用落盘后才有的 `msg_uid`**、**禁止随机** |

**纪律**：若 `group` 缺失，出数方**不得**回退到 `(thread_id, turn_index, from, round)` 归组"补救"（群聊同轮多人、同轮同人连发时会混组，产生假 PASS），而应**报"接线字段缺失"并按「机制未生效」处理**。

## 9. 边界

1. 单 seed / 单规模 / 单树；**本臂只改"采样与选择"，不改提示词**（sha 必须等于 T1）；
2. `L-7` 是 8-gram 撞车代理、`F-2` 是 char-bigram Jaccard 代理，**都不等于"读起来重复/接不接得上"**；
3. 本臂引入 **3× 对话调用成本**，若有效也只是"在 M=3 下有效"，**不证明 M=1 时模型自己会换说法**；
4. **不得**写"对话更自然了"——本臂无人类评证据；`judge` 与系统同源，只能作旁证；
5. 判据与阈值**同时冻结**；要改须新开预登记并说明前一份为何作废。
