## 1. 追认实现口径变更：哈希 → **轮转 + agent 起点**

预登记 §2 原写 `skel_idx = sha256(tid|turn|skel) % 5`。**该式在旁白集合（n=160）上把 `skel 0`（"把"骨架）派到 26.2%**，
而判据 D1 要求 `把N往/在P一V 骨架 ≤20%` ⇒ **机制层在跑之前就注定过不了**。

**改用**（已在 `c5b4459` 实现并单测）：
```
skel_offset(agent_id) = int(sha256(agent_id)[:8],16) % 5
skel_idx(narration_ordinal, offset) = (narration_ordinal + offset) % 5
```
- 实测分布：n=160 → 20.00/20.63/18.12/20.63/20.63（极差 2.5pp）；n=384 → 极差 **0.21pp**；
- `skel_offset` 只读 `agent_id`，与 `para_on` 的 `sha256(tid|turn)` **无共同输入** ⇒ 两变量构造上独立（比"用不同盐"更干净）；
- **`para_on` 比例、台词长度、其余提示词段落一律未动**（mock 已逐字验：`para=False` 与 D2.8 逐字相同）。

## 2. 修 D1 的一条阈值：`骨构 ≤20%` → **`骨架 ≤25%`**

**问题**：5 类均匀的**理论值就是 20%**。要求"`骨架 ≤20%`"等于要求**任一骨架不得高于理论值**，
即**不允许任何统计波动**——真跑只要 `skel0 = 20.6%` 就会判「骨架未多样化」，而它其实**完全均匀**。

mock 已实测 `skel0 ∈ [20.00%, 20.63%]` ⇒ **该线在真跑中必然被打穿，且打穿不说明机制失败。**

**修正**：`把N往/在P一V 骨架占比` 的达标线改为 **≤25%**（= 均匀值 20% + 5pp 容差，与本项目其他"漂移带"口径一致）。
**同时保留**：
- `把 开头 ≤25%`（不变，现状 66–69% ⇒ 有 40pp 余量，不受此问题影响）；
- **`骨架 TOP1 ≤30%`（不变，作为主判据）** —— 它才是"是否集中"的真正判据，容差天然更宽。

**这不是放宽判据**：改动的只是一条**在数学上不可能稳定通过**的线；
真正约束"骨架是否多样化"的 `TOP1 ≤30%` 与 `把 开头 ≤25%` **一字未改**。
