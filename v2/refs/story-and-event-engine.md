## 0. 总纲：先把「主动制造」与「观察并叙述」分清（本文件的第一原则）

### 0.1 两类能力的边界（一张图）

```
                       ┌────────────────────────────────────────────────┐
                       │  确定性世界（EventLog = 唯一真值，可重放）          │
                       └───────▲──────────────────────────────┬──────────┘
     【主动制造】写世界          │                              │      【观察并叙述】只读
                       ┌───────┴───────────┐         ┌────────▼─────────────────┐
                       │  事件制造机          │         │  故事叙述机               │
                       │  EventForge         │         │  Storyteller             │
                       │  给「条件/机会/压力」 │         │  读日志 → 选片 → 成文      │
                       │  产出确定性世界事件    │         │  产出 NARRATIVE(只读)     │
                       │  （经裁决器落账本）    │         │  affects_state=false      │
                       └────────────────────┘         └──────────────────────────┘
```

- **主动制造（EventForge）= 写世界**：产物是**确定性的世界事件/环境条件**，经中央裁决器落账本。它**只能设定「环境里有什么机会/什么压力」**，**不得**直接产出「社会结果」（关系/契约/制度/胜负）。
- **观察并叙述（Storyteller）= 只读**：产物是 `NARRATIVE{affects_state=false}` 文本，**绝不回写世界、不进评估指标、不进训练信号**（17 §0.2 H-2）。
- **一句话铁律**：**制造机决定「世界里可能发生什么」，叙述机决定「把已经发生的讲成什么故事」。** 二者**不在同一层、不共用写入路径**，**不得混为一谈**（本文件每一节都标注它属哪一类）。

### 0.2 继承约束：逐条对齐既有红线（**必须逐条声明**）

| 红线（来源） | 精确含义 | 对 **EventForge** 的约束 | 对 **Storyteller** 的约束 |
|---|---|---|---|
| **不替 AI 设计经济/社会**（`v2/00 §0.1`） | A 物理层只给底座与工具；价格/工资/雇佣/借贷/税收/制度由 B 层 Agent 自己涌现 | 机制**只提供环境条件与可用机会**（供给侧/日历/稀缺/冲击）；**绝不写死**价格/工资/税率/制度，**绝不指定**谁与谁结盟/冲突 | 只朗读日志中**已发生**的事；不替任何人「决定」关系或制度 |

# Part I · 事件制造机（EventForge）——**主动制造**

> **本模块回答**：什么样的机制能**主动制造事件**（而非只等它发生）？**每条机制必须声明它是否违背「不预设经济 / 不替他们设计社会」的红线。**

## 1.1 功能边界（**一句话**）

EventForge 是**A 物理层的一个子模块**：它按配置与种子，确定性地**制造「环境条件、可利用机会、外部压力」**，使事件**更可能发生**；**它绝不制造「社会结果」**（谁跟谁结盟、谁赢、什么价格、什么制度）。

**它能做**：日历节律、机会（稀缺/用工/场地/物资）投放、外部冲击（天气/事故/外来访客）、客观冲突门槛（stakes 出现）。
**它绝不能做**：写死价格/工资/税率；指定对手/胜负/盟友；代写规范条款；直接 emit 关系/契约/制度类**结果**事件。

## 1.2 设计原则（三条）

1. **制造机会 ≠ 制造结果**：forge 只调「机会的存在与可见度」，**用不用、谁用、结果如何**全部交给 Agent 的自主决策（`INTENT`）与确定性结算。
2. **确定性可复现**：forge 的调度与分支**全部由 `(seed, config, round)` 决定**（日历 + RNG 流），**LLM 不参与**；同 `(seed, config)` 的事件序列一致，`replay(log)` 逐位一致。
3. **可开关、可消融**：**每个机制一个独立开关**，用于「去掉机制 → 事件显著减少」的消融证伪（`v2/00 §0.3`）；**写死常量不算涌现**（因此不设「必然发生」的硬脚本，只设概率/条件）。

## 1.3 候选机制清单（**每条声明红线合规性**）

### 1.3.1 红线判定总则（一句话可判）

> **forge 给的是「环境与工具」（机会、稀缺、压力、日历、冲击），不是「社会结局」（关系、价格、胜负、制度、组织）。**
> 凡是**直接 emit 社会结果事件**（`RELATION_CHANGE` / `OFFER_*` / `CONTRACT_*` / `NORM_ADOPTED` / `GROUP_*` / `RANKING_EMITTED` 结果）的机制，一律 **❌ 违背**——这些必须**由 Agent 的自主行为产生**。

### 1.3.2 禁止清单（NON-GOALS，**明确不做**）

1. **不写死**价格 / 工资 / 税率 / 是否铸币（B 层事务）。
2. **不指定**结盟、冲突、雇佣、借贷的**对象与胜负**。
3. **不代写**规范条款、提案结论、组织章程。
4. **不脚本化**「谁死谁富谁上位」的剧情结局。
5. **不做不可消融**的硬脚本（否则「假涌现」，`v2/00 §0.3`）。
6. **不引入**任何形式的「为了有故事而强行制造社会关系」。

## 1.5 验收判据（EventForge）

# Part II · 故事叙述机（Storyteller）——**观察并叙述**

> **本模块回答**：如何从确定性/可审计的事件日志里**长出故事**？管线 = **选角 → 冲突识别 → 节拍 → 成文**，并支持**多视角 / 多体裁**。基线见 `v1.1/17`，此处**工程化 + 模块化**。

## 2.1 功能边界（**一句话**）

Storyteller **只读** `EventLog`（+ 冻结判定 `LLM_JUDGMENT` 只读回），确定性地产出「值得讲什么」（选片）与「怎么讲」（文本）；**绝不回写世界、不进评估/训练信号**。

## 2.2 五段管线（**D 决定讲什么 → N 决定怎么讲**）

```
extract_atoms(log) ──► select_scenes(atoms, drama) ──► detect_conflict(scene)
      │                        │                              │
   [D] 事实抽取             [D] 戏剧性选片                  [D] 冲突/代价/转折识别
      ▼                        ▼                              ▼
   StoryAtom[]            scored Scene[]                   StoryBeats（节拍骨架）
                                                              │
                                        render(beats, style, pov, budget) ──► NARRATIVE
                                                              │        [N] 成文（句级锚点）
                                              qc(narrative, atoms) ──► story_quality [D] 质检
```

| 段 | 模块 | 做什么 | 确定性来源 | 复用 |
|---|---|---|---|---|
| **① 选角** | M5-Select | 从 `CAST` 原子 + 戏剧性**影响面**选出「主角/配角/群像」 | `c_impact`（17 §2.1）、`cast[]` | 17 §1 |
| **② 冲突识别** | M5-Select | 扫描场景内 `c_conflict/c_turn/c_plunge/c_ruin` 命中，标注「张力点」 | 17 §2.1 九子维 | 17 §2 |
| **③ 节拍** | M5-Select | 按**起承转合**把原子排成 beat 骨架：`setup→escalation→turn→resolution→aftermath` | 原子时间序 + `when.seq` | 新增 |
| **④ 成文** | M6-Render | 多视角/多体裁渲染，**句级锚点** | LLM（N 类），步①的事实践包为唯一世界知识 | 17 §3、§4 |
| **⑤ 质检** | M6-Render / M7 | 硬事实校验 + 锚点覆盖 + 故事质量自检 | 纯 D 校验器 | 17 §3.3、本文件 §4 |

### 2.2.1 节拍模板（④ 的骨架，**新增**）

| 节拍 | 取材（从日志） | 作用 |
|---|---|---|
| `setup` | 场景首个 `CAST`/`ACTION` 原子 + 时间地点 | 交代「谁、在哪、想干嘛」 |
| `escalation` | `c_conflict↑` / `c_plunge` 之前的行动原子 | 累积张力 |
| `turn` | `c_turn` 命中原子（符号翻转）或 `c_plunge` | 转折点 |
| `resolution` | `OUTCOME` 原子（胜负/死亡/采纳/成交） | 结算 |
| `aftermath` | 后续 `RELATION_DELTA` / `NEED_UPDATE` / 次周余波 | 代价与回响 |

> **纪律**：beat 骨架**由 D 从原子生成**（确定性、可复算）；LLM 只**按骨架填充**叙述，**不得**增删事实现（17 §3.3）。

## 2.3 多视角 / 多体裁产出矩阵

> 体裁 = 17 §4 的四类模板；视角 = 全知 / 角色 POV。

| 体裁 \ 视角 | 全知（omniscient） | 角色 POV（受限） |
|---|---|---|
| **编年史 chronicle** | 全镇按周分章大事记 | 某角色的「编年长卷」 |
| **每周纪事 weekly_gazette** | 「青溪周报」头条+简讯 | 某角色的「本周手记」 |
| **角色视角 character_pov** | —（此格即 POV 主档） | 第一人称日记体（**严格受限**，见 17 §4.3） |
| **重大事件特写 feature** | 单场景多视角拼贴 | 当事者视角的特写 |

- **POV 可见性**：严格用 `v1.2/03-pov-visibility-check.md` 的 `visible_events(agent)`（亲历）/ `heard_events(agent)`（听说，须 `refs`）二分；缺 `refs` 的转述一律按「听说（未核实）」处理 `spec=true`。
- **多版一致性**：同一 `fact_event_seqs` 的四体裁共用一个 `anchor_digest`（确定性），**版本差异只允许在措辞/视角/顺序/详略**，**不得在事实内容**（金额/胜负/死亡/关系数值/时间地点）——这就是 **H-3 红利**（17 §0.2、§5）。

## 2.4 模块拆分（**可独立交付**）

| 子模块 | 功能边界 | 交付物 | 依赖 |
|---|---|---|---|
| **ST-Select** | 抽取 + 选片 + 节拍 | `narrative_selection`（scored scenes + beat 骨架，纯 D 侧产物） | 17 §1–§2、`weights.py` |
| **ST-Render** | 渲染 + 锚点 + 硬事实校验 | `NARRATIVE{fact_event_seqs[],body_ref,affects_state=false}` + `anchor_map` + 侧存储正文 | 17 §3–§4、`08 §1.2`、POV 可见性 |
| **ST-Registry** | 体裁/视角注册表 + 模板 | `templates/`（四体裁提示词骨架） | 17 §4 |
| **ST-QC** | 质检（见 §4） | `story_quality` 侧产物 | 本文件 §4 |

## 2.5 验收判据（Storyteller）

| # | 判据 | 口径 | 复核 |
|---|---|---|---|
| **S-1** | **事实可追溯（H-1）** | 每个 `StoryAtom.anchors[]` 非空且均为日志真实 `seq`；渲染后**每个断言句**映射 ≥1 anchor；`NARRATIVE.source_event_seqs[] ⊆ 已发生事件` | `validate_narrative(narr, log) == ok` |
| **S-2** | **只读不污染（H-2）** | `affects_state==false`；`metrics()` 忽略 `NARRATIVE`；报告头 `narrative_reads_in_decision==0` | 硬校验 |
| **S-3** | **多风格重述（H-3）** | 同 `fact_event_seqs` 多版 `anchor_digest` **逐位一致** | 规范哈希比对 |
| **S-4** | **防幻觉** | 硬事实（金额/死亡/胜负/关系数值/时间地点）**逐字**匹配 `evidence[]`；`inferred=true` 句必须 `spec=true`；违规 → 重渲染一次 → 再失败回退纯模板句 | `story_quality.hard_fact_violations==0` |
| **S-5** | **可复算** | `extract_atoms` / `compute_drama` 两次调用**逐位一致**；`llm_calls==0`（仅渲染一步调 LLM） | 规范 JSON + `round(...,6)` |
| **S-6** | **来源标签诚实** | `induced` 场景**不得**叙述为「小镇自发」；`frozen_llm` 判定句标注 `(LLM 判定, 已冻结)` | `story_quality.origin_mislabel==0` |

# Part III · 「什么叫一个精彩故事」的可验收判据（M7 Quality-Bar）

> **本模块回答**：给「故事质量」一个**可复算或可人工验收**的口径。**关键纪律**：质量判据属**叙事层自检**，**不进**世界判定、**不进** A/B 门禁（守 H-2）；判据本身**不得依赖 LLM 判定**。

## 3.1 可复算判据（`story_quality`，纯 D）

| # | 判据 | 可复算口径 | 通过线 |
|---|---|---|---|
| **Q-1** | **含真实事件** | `assertions_with_anchor / assertions_total`（断言句锚点覆盖率） | **== 1.0**（硬门） |
| **Q-2** | **有冲突或张力** | 场景 `max(c_conflict, c_plunge, c_ruin) ≥ θ_drama` | ≥ 阈值 |
| **Q-3** | **有转折** | `c_turn ≥ θ_turn` 或场景含 ≥1 转折原子（符号翻转） | bool |
| **Q-4** | **有代价** | 场景含 ≥1 代价型 `OUTCOME`（损失/死亡/关系下降/资源再分配） | bool |
| **Q-5** | **有关系变化** | 场景含 ≥1 `RELATION_DELTA` | bool |
| **Q-6** | **无编造** | `hard_fact_violations == 0` 且 `inferred` 句均 `spec=true` | **== 0**（硬门） |
| **Q-7** | **多版事实一致** | 同场景多版 `anchor_digest` 一致 | bool |
| **Q-8** | **来源诚实** | `origin_mislabel == 0`（不把 induced 说成 spontaneous） | **== 0**（硬门） |

```
story_quality(scene) = {
  hard_gate:   Q-1 ∧ Q-6 ∧ Q-8,                     # 硬门，不过则该故事不发布
  richness:    (Q-2 + Q-3 + Q-4 + Q-5 + Q-7) / 5,   # 故事「厚度」连续分，用于排序/选题
  passed:      hard_gate ∧ richness ≥ τ_rich        # τ_rich 为可调阈值【待标定】
}
```

- **可复算**：Q-1/Q-6/Q-7/Q-8 全为**纯 D 校验器**；Q-2~Q-5 复用 17 §2.1 的戏剧性子维（已在 `weights.py` 落盘）。两次计算逐位一致。
- **用途**：① **发布门禁**（硬门不过的故事不投放前端）；② **选题排序**（`richness` 高者优先）；③ **人工验收的自动化底稿**。
- **纪律**：`story_quality` 是**叙事层侧产物**，**不进** `metrics.*`、**不进** A/B 门禁、**不进**训练信号；**不得**用 LLM 打分（否则违反「判定不依赖 LLM」）。

## 3.2 人工验收 rubric（人读，5 维 × 0–2 分）

| 维 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| **可读性** | 语义混乱 | 通顺但有赘述 | 流畅、有节奏 |
| **代入感** | 像流水账 | 有角色轮廓 | 能感到「在场」 |
| **因果清晰** | 只见事件不见因果 | 部分可推 | 因→果链清楚 |
| **钩子/悬念** | 无 | 有一点 | 想读下去 |
| **情绪起伏** | 平 | 有小波动 | 有明显高潮 |

- **发布线**：5 维合计 **≥ 7/10** 且无 0 分项。
- **诚实声明**：rubric 是**人审**，仅供抽样评估与调优提示词；**不作为**自动门禁（避免主观判断污染）。

## 3.3 与「不得编造」的关系（**回扣任务要求**）

任务明列：**是否有可溯源的真实事件 / 不得编造日志里没有的事实**。
→ 对应 **Q-1（锚点覆盖=1.0，硬门）** + **Q-6（硬事实零违规，硬门）** + **S-4**（17 §3.3 三层防幻觉）。**这是「精彩」的底线：不真实的故事一律不是好故事。**
