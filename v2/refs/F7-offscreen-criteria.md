## 0. 结论先行（只给事实与可比性判定，不给改善/恶化结论）

| 层级 | v0-anchor（`run_d2_before_n16_seed42`，187 条消息） | A0（`run_d2_after_n16_seed42`，686 条消息） | 可比性 |
|---|---|---|---|
| **P1 提及层**（主） | **2 / 2**（可判定消息仅 2 条；<30 不报百分比） | **81 / 108 = 75.00%**（CI 66.67–83.33%） | **不可比**：分母差 **98.1%** |

**统一口径后两臂仍然不可比**，差的不是算法，是**分母（可判定提及的消息数）**：2 vs 108（差 98.1%），
根本原因是 v0-anchor 侧**几乎不产生可判定的第三方提及**（详见 §5.2 三条结构事实）。
因此：**在 A0/v0 之间对 F-7 报任何百分比、任何"变好/变坏"都是不成立的**；

同时本卡给出的一项可复用判定：**旧读数的 `1.07%` 与 `15.6%` 不是同一把尺子的两个值，而是两个不可解释的数**

## 2. 匹配规则（怎么算"提及"）

### 2.1 正则与切分（原文）

```python
# 主干名：名单内 20 个主干名逐个做子串匹配（无分词、无边界符）
#         名字长度 2–3 字，全部互相不成子串（脚本运行时已校验，如「石头」不含「老石」）
# 裸 ID：P + 3 位数字，后瞻防 4 位（与 tools/d5/dialogue_metrics.py::AGENT_ID_RE 完全一致）
AGENT_ID_RE = re.compile(r"P\d{3}(?!\d)")

# 旁白：中英文括号整段，P1 先剔除再匹配。不设长度上限
#      （旧口径 PAREN_ANY_RE 限 120 字符，超长旁白会漏剔 —— 旧口径的一处已知缺口）
PAREN_NARRATION_RE = re.compile(r"(?:（[^）]*）|\([^)]*\))")

# 称呼层 P2：token 后紧跟呼语标点，或前 ≤6 字以呼语引导词结尾
VOC_PUNCT   = set("，,、！!？?啊呀呢吧——…~～")
VOC_CALL_RE = re.compile(r"(?:喂|哎|嘿|嗨|哟|唉)[，,、]?\s*$")
```

### 2.2 逐项裁定（本卡定死，不许事后放宽）

| 情形 | 是否计入 | 依据 |
|---|---|---|
| 主干名（`老周`、`桂婶`…） | **计入** | 名单内、非发言人自己 |
| **裸 ID**（`P009`、`P016`） | **计入**（P1 起） | v0-anchor 正文直接写 `喂，P009——`；不计裸 ID ⇒ v0 被机械判成"0 提及"，这正是旧口径 1.07% 的成因 |
| 发言人自己的名字/ID | 不计入 | 自称不是越界 |
| DM 收件人（`payload.to`） | **不计入**（P1 主判据） | 点名对收件人说话 ≠ 越界；其不在场是 DM 通道属性，不是叙事错误。此轴在变体表里两种都算过（§5.3） |
| 旁白（括号内）提及 | **不计入**（P1 主判据） | 旁白是第三人称描述，写"巧儿蹲在废料堆边"不等于人物当面对不在场者说话。两口径都算过（§4） |
| **别名 / 昵称变体**（`桂婶儿`、`兰姐儿`、`老周叔`） | **不计入** | `personas.json` 无 alias 字段；硬造别名 = 引入不可复算的主观判断。**这是本卡的已知低估方向**（只会少算，不会多算） |
| 称呼变体（`喂，X` / `X啊` / `X，你说`） | 提及层**都算**；称呼层（P2）**单独一层** | P2 = 只保留称呼型，用于更接近"对不在场者说话"的代理；**P1、P2 不得相加或互相代入** |
| 未登录词（名单外的人名，如"金先生"以外的陌生称呼） | **不计入分母也不计入分子** | 无法核验在场性；若计入分子就变成"猜" |
| 间接指代（"他""那位师傅"） | **不计入** | 需要共指消解，超出零成本脚本能力；列入 §6 局限（低估方向） |

### 2.3 「越界」判定式

```
在场性：place(agent, t) = 该居民在消息 seq 之前最后一条 PLACE_ARRIVED/PLACE_MOVE 的 place
        （point-in-time；无任何位置事件 ⇒ 不可判定，剔除出分母）
越界：payload.place(发言者) 存在 且 place(被提及者, t) ≠ payload.place(发言者)
per-message 命中：一条消息中 ≥1 个被提及者越界 ⇒ 该消息记 1
per-mention 命中：按被提及者逐个计
```

> 旧口径用「同一 round 内最后一条位置事件」，会取到消息**之后**的位置（时序倒错）；
> P1 改为 point-in-time，这是两臂统一、且与"当时在不在场"语义一致的关键一处。

## 3. 分母定义（187 / 686 / per-message / per-mention）

| 分母 | 定义 | 本卡地位 | 两臂值 |
|---|---|---|---|
| **可判定提及消息数**（主） | 至少含 1 个「非收件人、非自己、名单内、可查到位置」的提及的消息 | **P1 主分母** | v0 = **2**；A0 = **108** |
| 可判定提及数（per-mention） | 上述消息中逐个被提及者（去掉不可判定） | P1 副分母（同时报） | v0 = **2**；A0 = **142** |
| 全部消息数（per-message，旧口径分母） | `MSG_DM + MSG_PUBLIC + MSG_GROUP` 全量 | **降级为对照列，禁止单独引用** | v0 = 187；A0 = 686 |

**为什么不用 187 / 686 作主分母**：这两个数衡量的是"这一刻说了多少话"，而 F-7 只在**出现他人指称**的消息上
才有定义。用全量消息做分母，会把"这一臂根本不叫人名字"混同为"这一臂不越界"——v0-anchor 的
`1.07% = 2/187` 正是这个混同：187 条里只有 58 条有他人指称，其中只有 2 条可判定。
`n_msgs` 差（187 vs 686 = 3.67 倍）本身来自两臂 thread schema 不同（legacy vs explicit），不是 F-7 的自变量，
把它当分母等于把"发言机制改动"记在"越界编造"账上。

**per-message 与 per-mention 都报、不相加**：一条消息可能提及多人，per-message 记 1、per-mention 记 N；
两者回答不同问题（"多少条消息出问题" vs "多少个指称出问题"），混加会产生超 100% 的数。

## 4. 旁白隔离（两种口径都算，差异写清）

### 4.1 定义

- `narration=exclude`（P1）：先用 `PAREN_NARRATION_RE` 删掉括号整段，再在剩余正文里匹配。
- `narration=include`：原样 `body` 匹配（旧口径行为）。

### 4.2 两臂实测差异

| 臂 | 旁白剔除（P1） | 旁白计入 | 差异 |
|---|---|---|---|
| v0-anchor | 2 / 2 | 2 / 2 | **无差异**（v0 仅 2 条可判定样本，命中均出自括号外正文） |
| A0 | 81 / 108 | 85 / 114 | **+4 条命中、+6 条分母** ⇒ 旁白贡献 4/85 ≈ 4.7% 的命中 |

结论（事实）：旁白**不是** A0 越界读数的主要来源（4/85），但**必须剔除**——否则"旁白里描述一个走开的人"
会被当成"对不在场者说话"。P2 称呼层同样两算：A0 `exclude` 56/79 vs `include` 57/80（差 1 条）。

### 4.3 `1.07%` 与 `15.6%` 到底是什么（旧口径解剖）

| 读数 | 分子/分母 | 旧口径内部状态 | 为什么不可解释 |
|---|---|---|---|
| v0-anchor `F-7a = 1.07%`（`d5_metrics_v0anchor.md`） | 2 / 187 | 不可判定位置查询 = **0** | 分子 2 条来自 2 条可判定消息；分母却是 187 条消息。**两个单位混用** |
| A0 `F-7a = 15.60%`（`d5_metrics_a0.md`） | 107 / 686 | 不可判定位置查询 = **487**（远大于可判定提及数） | 分子只在"恰好同 round 有位置事件"的极小子集里取值，分母是全部 686 条。**两个单位混用 + 位置时序可用性随臂漂移** |

`f7_offscreen_mention.py` 内置 `legacy_compat` 块逐位复现这两条旧读数（2/187、107/686，含 487 次不可判定），
所以"旧数不是算错，是口径不可解释"这一点是**可复算的**，不是推测。

### 5.2 为什么仍不可比（三条结构事实，均来自读数 JSON 的 `units`）

| 臂 | 总消息 | DM | PUBLIC | GROUP | 含他人指称的消息（DM / PUBLIC / GROUP） |
|---|---|---|---|---|---|
| v0-anchor | 187 | 132 | 48 | 7 | 58（58 / **0** / **0**） |
| A0 | 686 | 497 | 63 | 126 | 398（305 / **0** / 93） |

1. **两臂的公开（MSG_PUBLIC）消息里，他人指称都是 0 条**（48 条 vs 63 条全是自言自语/旁白）。
   ⇒ "当众对不在场者说话"这一最贴近"编造"的场景，**两臂都没有样本**（P1 公开+群聊口径：v0 = 0/0，A0 = 67/93）。
2. **v0-anchor 的 58 条指称全在 DM，且 56 条是"点名收件人"**（`喂，P009——`），剔除收件人后只剩 2 条第三方提及。
   ⇒ v0 的第三方提及面 = 2 条，任何百分比都建在这 2 条上。
3. **DM 量本身差 3.8 倍**（132 vs 497）、GROUP 差 18 倍（7 vs 126），因为两臂 thread schema 不同
   （legacy vs explicit）。这是发言机制的自变量，不是 F-7 的自变量。

⇒ **判定：不可比（分母差 98.1%）。** 差在哪：可判定提及消息数 2 vs 108；
再往上一层，差在"v0 只有 2 条第三方提及、A0 有 398 条含他人指称消息"。

## 6. 已知局限（只往"低估"方向偏，逐条可复核）

1. **无别名扩展**：`桂婶儿`、`兰姐儿`、`老周叔` 等变体不算提及 ⇒ 分子偏小。
2. **无共指消解**：`他`、`那位师傅` 不算提及 ⇒ 分子偏小。
3. **名单固定 20 人**：若 run 内有 20 人之外的合成居民，其提及不计入 ⇒ 分子偏小（两臂同规则，不制造不对称）。
4. **P2 是正则启发式**，不是人工标注：`X，你说` 判为称呼，`说起 X 就……` 判为非称呼。故 P2 只能作方向代理，
   **不得**写成"越界编造率"；若需硬结论，须另开人工标注任务（本任务零 LLM 零人力预算）。
5. **在场性用"最后一条位置事件"外推**：agent 停在原地时无新事件，本卡认为其仍在原地（合理，但属假设）；
   `SLEEP_STARTED`（睡觉）未单独排除 ⇒ 睡前位置仍算"在场"，属低估/高估混合项，未在本轮量化，列下轮。
6. **旁白正则不设长度上限**：能覆盖超长旁白，但若正文出现不成对的半括号，会删到行尾（当前两臂未出现）。
