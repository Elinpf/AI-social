# D12-H 预登记 · **run 内真配对**：同一上下文下 ON/OFF 各 3 采、只比候选级配对差

> 立此存照：**2026-10-23 21:45（v2，已采纳 eval 的 5 条核算）**，在任何 D12-H 代码改动与跑批之前。
> 依据：`v2/evidence/d12g_result.md`、`v2/evidence/d12g_pairing_feasibility.md`（跨 run 配对只压缩 14%）、`v2/refs/batch-hosting-runbook.md` §3.107–§3.109。
> **v1 → v2 的五条修正见 §7**，其中 ① 改变了判据、② 削掉了归因越界、③ 新增中途停手条件。

## 0. 为什么要这个设计

前六臂的教训：**单步效应测不出来**（D12-F vs E 的 −3.33pp、D12-G vs T4 的 −3.92pp，**CI 均含 0**）；**放大轮次不行**（改变测量场景）；**跨 run 配对也不行**（同 slot 逐字相同仅 2.74%，压缩 14%）。
⇒ 唯一能抵掉共模噪声的是**同一条消息、同一上下文下同时出 ON 与 OFF 的候选**。

## 1. 设计（一个 run、60 轮不变）

对**每一处对话生成**，**采 6 次**，两组**各自 3 选 1**：

| 组 | 3 条候选的 prompt | `sample_index` | 是否落库 |
|---|---|---|---|
| **ON** | **全部 = T1 + 「开口先叫对方一声，别用你上一句或对方上一句的前四个字。」** | 0 / 1 / 2 | **是**（落选中那条） |
| **OFF** | **全部 = T1 基础 prompt（逐字节）** | 3 / 4 / 5 | **否**（只用于配对） |

- **只开一个结构位**（"开头约束"）⇒ ON/OFF 唯一差别是**这一行提示词**；
- 两组各自按「与最近 16 条台词的 8-gram 交集最小」择优（平局取组内最小 index）；
- **`pair_delta` = `off.scores[off.picked] − on.scores[on.picked]`**（>0 ⇒ ON 组选出的候选交集更小）。

**落库字段**（每条消息 6 份候选元数据，约 2.7MB 总量）：
`ctx.d12h = {m:6, group, on:{picked, scores[3], cand_shingle_hashes[3]}, off:{picked, scores[3], cand_shingle_hashes[3]}, pair_delta, resampled}`

## 2. 判据（**判据只能建立在"候选级配对差"上**）

> **① 的硬约束**：OFF 组 3 条候选**永不落库**，而 `L-7` 的 dup 是**全局 shingle 索引**（与他人重合才计）⇒ **OFF 组没有 `L-7` 读数**。
> ⇒ **本臂判定只用 `pair_delta`；禁止用 `L-7`（任何口径）解释配对差**。`L-7` 只能作为「ON 语料的总量读数」单列，且**不得**与 T5 的 48.63% 作"配对效果"的换算（同场景可比，但那是另一件事）。

| # | 判据 | 阈值 |
|---|---|---|
| **1（主）** | **`pair_delta` 均值** | **> 0 且配对 CI 不含 0**（CI 用 **slot 级配对重采样** B=2000/seed42；另报线程级，两者不得互代） |
| 2（次级） | `pair_delta > 0` 的占比 | ≥55%（只作次级） |
| 3（机制闸） | `ctx.d12h` 六采齐 `m=6` 命中率 | = 100% |
| 4（机制闸） | ON/OFF 两组**各自** argmin 命中 | 各 = 100% |
| 5（代价闸） | **`L-3` 含括号块率**（按**落库 body**，OFF 组不参与） | **≥55%** |
| 6（效果层，仅记录） | `L-7` norm8/raw8、`P1`、`F-2'`、`L-15 strong`（均为 ON 语料） | 沿用 T5 阈值，**只报点估计，明写"本设计不判效果显著性"** |

## 3. 中途停手条件（新增，因 ③ 的预警）

`eval` 用 T5 估出：**391/510 = 76.7% 的消息三候选同分**（`scores` 全 0）⇒ 配对差在这些条上**恒为 0**；**非全同分只有 119/510 = 23.3%**。
⇒ 预登记写死：
1. **预期有效配对（`pair_delta ≠ 0`）占比 ≈23%**；
2. **跑到 1/3（约 20 轮）时必须实测该占比**：**若 <20%，立即停跑并判"本设计对 −4pp 级效应无分辨力"**（不进入效果判定，不出无效/有效结论）；
3. 若实测 ≥20%，继续跑完，但**报告必须给出有效配对条数**，并按该条数说明 CI 的现实半宽。

## 4. 反事实

| 观察到 | 判定词 |
|---|---|
| 判据 1 达标（`pair_delta` >0 且 CI 不含 0）+ `L-3 ≥55%` | **有效** |
| 判据 1 达标但 `L-3 <55%` | **无效（靠砍旁白换重复）** |
| 判据 1 的 CI 含 0（且有效配对数 ≥20%） | **机制未生效** |
| 有效配对数 <20%（§3） | **不出判定**，只报"本设计无分辨力" |
| 机制闸（3/4）任一未达 | **机制未生效（接线问题）** |

## 5. 落盘要求

1. **shingle hash 列表 6 份**（ON 3 + OFF 3），每份为**排序后的 blake2b-8B hash 列表**；**不要集合 sha**（摘要算不出交集）；
2. **`scores` 窗口写死**：`recent_bodies(wv)` 取**该 agent 可见**的最近 **16 条**（按 `(round, seq)` 倒序）、`normalize_body` 后 **8-gram**、交集**条数**（非比率）；
3. **候选 sha 重复**：组内若出现 sha 重复 ⇒ **重采该候选**（上限 2 次），记 `ctx.d12h.resampled`。

## 6. 成本与边界

| 项 | T5 | **D12-H** |
|---|---|---|
| `dialogue calls` | 1,530 | **≈3,060（6×510）** |
| 总 `calls` | 3,898 | **≈5,428** |
| tokens | 831,809 | **≈1.16M** |
| 墙钟 | 49 分钟 | **预计 75–110 分钟** |
| rounds | 60 | **60（不变）** |

**边界**：单 seed / 单规模 / 单树；**OFF 组是"关掉开头约束、其余全开"的新臂，本项目从未跑过 ⇒ 与 T1（单采，无 best-of-3）及任何既有臂均不可互译**；无人类评证据；不得写"更自然"；`pair_delta` 是**候选级交集差**，不等于"读起来更不重复"。
