# D12-F 预登记 · 候选结构多样化（在 D12-E 上补"可分性"这一步）

> 立此存照：**2026-10-23 14:30，在任何 D12-F 代码改动与跑批之前**。判据、阈值、反事实**先写死**。
> 依据：`v2/evidence/d12e_leader_terminal_check.md`（D12-E 终态：机制生效但差 0.78pp）、`v2/evidence/d12e_candidate_separability_analysis.md`（0 次 LLM 的离线否证）。

## 0. 为什么做这一步（数据直接指出）

D12-E 已经证明：
- **择优逻辑 100% 正确**（非全同分样本中 `picked==argmin` **79/79**）；
- **机制生效**（M1 `510/510`、M3 PASS）；
- `L-7` norm8 **65.10% → 55.88%（−9.22pp）**，**差 0.78pp** 未达 55.10%；
- `L-6` 完全重复 **9.61% → 0.78%（降 8.8 倍）**、`P1` 99.02%、`F-2` 73.61%、`L-15 strong` 4.12% 全守。

**唯一的瓶颈是「候选可分性」只有 15.9%**：85% 的样本三候选 `scores` 完全相同（多为全 0），择优无从发力。离线分析已否证"换比对范围"（同线程前文会让可分性 18.8%→7.6%）⇒ **只能从候选侧制造差异**。

## 1. 设计（**只改"给候选配什么 prompt"，不改择优逻辑**）

新增 env **`LIFE_PROMPT_D12F_DIVERSE`**（**默认 `1` = 关闭**；`3` = 开启），在 D12-E（`LIFE_PROMPT_D12E_BESTOF=3`）之上叠加：

| 候选 k | prompt | 说明 |
|---|---|---|
| **k=0** | **= T1 的 prompt（逐字节相同）** | **这是本臂的接线锚**：候选 0 必须与 T1 完全一致 |
| k=1 | T1 prompt **+** `"\n开口先叫对方一声，别用你上一句或对方上一句的前四个字。"` | 制造"称呼起头"的结构差异 |
| k=2 | T1 prompt **+** `"\n开口先讲一句你眼下正在做的小事，再说对方。"` | 制造"动作起头"的结构差异 |

**择优规则与 D12-E 完全相同**（与"最近 16 条广义台词"的 8-gram 交集最小者；平局取 k 最小）。`ctx.d12f = {"m":3, "picked":k, "scores":[…], "group":…}`。

> 为什么这样设计：候选 0 = T1 行为 ⇒ 若"选中候选 0"占多数，结果自然回落到 T1 水平，**不会比 T1 更差**；只有候选 1/2 在结构上真的不同、且交集更小时才会被选走。这是**风险可控**的加法。

## 2. 接线证明（**与本臂强绑定，跑前必须过**）

| # | 要求 |
|---|---|
| 1 | **候选 0 的 `prompt_fn_sha256` 必须逐字 = T1 的 `effc14dbffdb6865…`**（证明"候选 0 就是 T1"） |
| 2 | 候选 1、候选 2 的 prompt 渲染 sha **必须互不相同、且都 ≠ 候选 0** |
| 3 | 三次 `cache_key` 两两不同、`cached=false`（沿用 D12-E 的 `sample_index` 机制，`sample_index` 仍只进 `params`） |
| 4 | `ctx.d12f.picked` 有分布；**非全同分样本 argmin 命中 = 100%**（沿用 M3） |

## 3. 机制闸（**先判；未过只能写"机制未生效"**）

| 闸 | 阈值 | 理由 |
|---|---|---|
| **M1** `ctx.d12f.m=3` 命中率 | **= 100%** | 接线 |
| **M3** 非全同分样本中 `picked==argmin` | **= 100%** | 择优逻辑正确性 |
| **M4（本臂新增）** **候选可分性**（非全同分样本占比） | **≥ 25%**（D12-E 实测 15.9%） | **多样化必须真的提高可分性**，否则等于没做 |

> **M4 不达 ⇒ 「机制未生效」**：因为这说明"结构提示"没有让候选产生足够差异，问题仍在候选侧，而不是择优侧。

## 5. 反事实（跑前写死）

在 **M1/M3/M4 全过** 的前提下：
| 观察到 | 判定词（5 档之一） |
|---|---|
| `L-7` 双口径达阈值 且 四条代价闸守住 | **有效** |

| M1/M3/M4 任一未达 | **机制未生效** |

## 6. 代价与执行

- **对话调用 ×3**（同 D12-E）：约 1,530 次；**prompt 变长**（候选 1/2 各多一行）⇒ token 略增；
- 墙钟预期 **70–90 分钟**（D12-E 因 44.9% 缓存命中只用了 32 分钟；本臂**新 prompt** 会大量 miss 缓存，**按 70–90 分钟估**）；
- 规模 **n=16 × 60，seed 42**；**只跑一臂**（T4），基线 = T1（`run_d12c_on_n16r60_seed42`）；
- **必须用全新 cache 省不了钱**：候选 1/2 的 prompt 是新的 ⇒ 首次必 miss，这是预期的。

## 7. 边界

1. 单 seed / 单规模 / 单树；本臂改的是**候选 prompt**（不是择优规则）；
2. `L-15`、`F-2` **无 bootstrap 带** ⇒ 点估计阈值，报告须写"未做显著性检验"；
3. **不得**写"对话更自然"；无人类评证据；
4. 若 M4（可分性 ≥25%）达标但 `L-7` 仍不达 ⇒ 说明**"选中最优候选"这件事本身的天花板不高**，下一轮应转而考虑"增加候选数 M=5"或"换评判口径（不只 8-gram 交集）"——这一点也先写死，防止事后找理由。
