# 任何数字被引用前的三个问题：**量 / 物 / 批次**

> 性质：规则件（可复用清单）。来源：今天全队 13 次纠正的归纳，三类划分由 `prompt-linguist` 补全。
> 作者：Leader。基线：`origin/master` @ `34176d3`。

## 0. 这份清单是干什么的

今天全队纠正 13 次，**没有一次是"算错了"**——全部是"**没说这个数是什么**"。
而这 13 次可以完整归到三个问题里。**问完这三个问题，13 次里的 12 次会被提前拦住。**

## 1. 三个问题

### 问一：**分母是什么？**（量）
数写成比率时，分母决定它的含义；分母变了，标准就跟着变，而读的人不会察觉。

| 今天的实例 | 分母 |
|---|---|
| `(d2) = 6` 被判"破" | 可归族片段只有 **9**（不是 50） |
| `H/log₂6 = 0.5591` | 分母 **6**；换 `log₂8` 则同一 `H` 是 0.4817 |
| `7.4/10` 天花板 | 只在"**随机抽 10**"下成立；全取 39 条则不同 |
| `grep` 命中 12 | 分母是 **84 = 12×7**，但那 12 条**属过程稿**，不在其中 |
| `coverage` 5.17% | 守卫门槛 **19.32%** —— 不报门槛就说"低"没有意义 |

**⇒ 规则：比值必标分母；绝对值必标**参照系**（`H ≥ 1.7578 bits` 的参照系是"6 类体系"）。**

### 问二：**对象是谁？**（物）
同一个名字可能指着不同的东西。

| 今天的实例 | 混淆 |
|---|---|
| "ON 臂" | `on`（48.7% 真调用）还是 `on2`（100%） |
| "配置未启用" | **当前配置** `enabled:false` 还是 **跑批当时**的值（日志不记 env ⇒ 只能 `CANNOT-VERIFY`） |
| "熵" | `H6`（固定分母）还是 `H_norm_nonempty`（可变分母） |
| "把起首" | **首字是"把"** 还是 **句中含"把"**（`抬手把鬓角…`） |
| "缓存命中" | `meta` 的 `cached` 字段 还是 `tokens_in>0`（两者不一致：`on2` 一报 191/191、一报 183/183 真调用） |

**⇒ 规则：同名不同物时必须写"版本/路径/sha"，不能只写名字。**

### 问三：**来源同批吗？**（批次）
两个数都对，但取自不同批次 ⇒ 相加、相减、比较都无效。

| 今天的实例 | 批次问题 |
|---|---|
| `3751 vs 3794`、`12650 vs 12660` | 一个量于**改动前**，一个**写消息时重打** |
| `41/25 vs 2/2` numstat | 分属**两个提交区间**，混在一句里引用 |
| `OFF_run1` 与 `OFF_run2` 之差 | 一个是 100% 真跑、一个是 3.7% 真跑 ⇒ 差**不是抖动** |
| `d9s-on` 与 `d9s-on2` | 同配置但**不同 side-root** ⇒ 缓存命中率差 50pp |

**⇒ 规则：三值必须来自**同一次命令的整块输出**（R-8）；跨批次比较必须声明"这是两批的差"，且**不得称其为抖动/效应**。

### 问一之补充：**D9-16 同一读数跨臂并列时，分母必须逐臂写出**

`prompt-linguist` 回扫 8 个读数后提出：**同一读数在不同臂上有不同分母，却常被并列引用。**

| 读数 | 臂 A | 臂 B | 陷阱 |
|---|---|---|---|
| `c3a` | **22.41%（39 / 174 块）** | **20.00%（38 / 190 块）** | **两臂占比都写"c3a"，分母不同** |
| `H` | ON2 **174 块** | OFF **194 块** | 绝对值 `H` 可比，**`H/log₂6` 的分母却一样是 6**（易混） |
| `coverage` | 5.17%（9 / 174） | 25.77%（50 / 194） | 并列时易写成"5.17% vs 25.77%"而丢分母 |

**⇒ 规则：跨臂并列时，每个臂后面必须跟自己的分母**（`22.41% = 39/174`），**不得共用一句"占比"**。

8 个读数里 **7 个**能被"数值 + 分母 + 参照系"三栏补齐 ⇒ **该规则可执行**；第 8 个（`rollback`）**定义未定位，暂记"待确认"**。

⇒ **凡是"路径/键名/版本号"，都要么动态解析、要么加载后断言。**

## 7. V-4：同值量不得作"有效性"论证（`prompt-linguist` 2026-10-31 提出）

> **规则**：跨版本 / 跨臂并列时，只能引「**在该维度下真正发生变化的量**」。某个读数在两版下**同值**，它只能作**"无差异"陈述**，**不得**用来论证"改变有效"或"改变无效"。

**踩的实例**：`ON2 coverage = 147/174 = 84.48%` 在词表 **v2.0（43 词）与 v2.1（46 词）下同值**。
若有人用「84.48% 没变 ⇒ 扩表没影响」或「84.48% 上升 ⇒ 扩表有效」，**两句都是零信息量**——同一个读数不变，既不能证明改变、也不能证明未改变判据。

**同族**：「换单位（`H/log₂6` → `H` bits）＝数学恒等」——看起来是判据硬化，实际零信息量（见 §3）。

**检验动作**：引用一个"前后对比"的数之前，先问一句——**这个量在这两版/两臂之间，本来就该变吗？**
- 该变而没变 ⇒ 要么干预没打到，要么这个量对该干预不敏感（**换区分量**）；
- 不该变而变了 ⇒ 先怀疑分母/口径变了，再怀疑行为变了。

**出处**：`v2/evidence/d9s-humanread-on2-recheck-erratum1.md`（`34d796e1…`）之后的口径讨论；A1（`v2/refs/D9t-prereg-opening-menu.md` §4）用的是 v1.1→v2.x 的**分母变化**，不是 v2.0→v2.1 的同值量，故不受本条限制。

### 7.1 V-4 的执行三步（`research-writer` 2026-10-31 落地版）

引用"某个数变了/没变"之前，按序过这三步：

| # | 检查 | 不过时怎么写 |
|---|---|---|
| 1 | **该量对被测改动是否敏感？** 同值可能是"改动无效"，也可能是"这量根本不随它动" | 先答"它凭什么该动"，答不出 ⇒ 换区分量 |
| 2 | **换版前后是否同口径 / 同分母 / 同实现？** 否则"同值"本身无意义 | 把三项写出来，缺一即标 `CANNOT-COMPARE` |
| 3 | 若不同值，**差值是否超噪声带 / CI？** | 未超 ⇒ 只作方向性描述，不进判定 |

**执行口径（写死）**：
> **不敏感量只能作描述，不得进"有效/无效"判定。** 报告里遇到这类量，一律标「**本量对 X 不敏感，不作论证**」。

**标准反例**：`coverage = 84.48%（147/174）` 在词表 v2.0（43 词）与 v2.1（46 词）下同值 ⇒ 不得作为"扩表有效/无效"的依据。

### 7.2 第 2 步的最小可核形式（`research-writer` 2026-10-31 补，Leader 采纳）

「同口径」不是感觉，是**三件都要写出来**：

| # | 项 | 核法 |
|---|---|---|
| a | **同实现** | 两侧仪器文件 sha 相同（或差异仅为无关段，须指出是哪段） |
| b | **同分母** | 分母**定义式**相同 **且** 条数相同（只写条数不写定义式，等于没写） |
| c | **同提取路径** | 同一 `run.jsonl` / 同一 `--out-json` 参数 / 同一片段提取正则 |

**判定**：三者任一不同 ⇒ **「同值」直接判为不可比**，**不许写成「没变」**。

**与第 3 步的接口（写死）**：
> **第 2 步不通过时，连"差值"都不该算**——算出来就会被当成结论引用。
> 第 2 步通过后，"不同值"才轮到第 3 步判**是否超噪声带 / CI**。

（同一条链的另一端：「没过噪声带的差值不叫差值」。）

## 8. V-5：相对阈值必须过两道自检（`research-writer` 2026-10-31 提出，Leader 采纳）

**适用范围**：凡「不高于基线 +X」「相对改善 ≥X」这类**相对**阈值（绝对阈值不适用本条）。

| # | 自检 | 不过的后果 |
|---|---|---|
| **①** | **基线臂自身满足条件** | 不是"严"，是**参照写错**：一条连对照臂都通不过的判据，无法区分"改善"与"本来就破" |
| **②** | **阈值的条数增量 ≥ 两跑噪声条数**（`X% × 分母 ≥ k × σ_条`，`k ≥ 1`） | 判定空间小于测量噪声 ⇒ **等于没判据**，单条片段抖动即可翻转 |

**判据**：两道任一不过 ⇒ **阈值必须重新推导，或退成绝对率**；不得照抄原条件进报告。

### 8.1 反例：D9t 的 `G7`（同一案例两道全破）

原条件「`≤5%` **且** 不高于 `OFF + 2pp`」，`ON2` 分母 174：

- **① 破**：`OFF = 2/194 = 1.03%` ⇒ `+2pp = 3.03%`；`ON2 = 6/174 = 3.45% > 3.03%` ⇒ **ON 与 OFF 两臂都过不了**（连对照臂自己也不满足"不高于自己 +2pp"）。
- **② 破**：`3.03% × 174 = 5.27 条` ⇒ 判定空间只有「≤5 条 vs ≥6 条」，**只差 1 条片段**；而本线实测同配置两跑差 **2.67pp ≈ 4.65 条**；门槛宽度 `2pp ≈ 3.48 条` ⇒ **噪声条数 > 门槛条数**。
- **处置**：`D9t` **Amendment A2** 撤销相对条件，退成绝对率 `≤5%`，并声明只在 `174±10` 片段规模有效。

### 8.2 与 V-4 / §7.2 的关系
V-4 管"这个量该不该动"，§7.2 管"这两个数能不能比"，**V-5 管"这个阈值够不够格"**。
三者同族：**先把"能不能算/能不能判"判掉，再谈"算出来是多少"。**

## 9. V-6：陈旧快照提交禁令（`repro-verifier` 2026-10-31 发现，Leader 自身踩中，事故留档）

**事故**：`d5c386e` 把 `338625e` 刚落地的 Amendment A2、复核件、骨架算法段**全部写回旧值**（D9t 件 blob `72f943a8…` → `0c176d2…`（该时点 blob，非当前版），复核件在 master 上**消失**），而提交说明只描述新增 §7.2，`git show --stat` 却显示三处删除。

**成因（机制）**：`commit-tree` 造树时用了**过期的本地 ref**（`git read-tree master`，而本地 `master` 落后于 `origin/master`）⇒ 该树快照取自更早时点 ⇒ 期间的改动被当成"多余差异"写回旧值。**与"平行孤儿"同族：从旧 base 造树，历史不断，内容倒退。**

**规则：推送前必须过三道自查，任一不过不许推。**

```bash
# ① 本地跟随 ref 不得落后
git fetch -q origin master && git log --oneline origin/master..master | wc -l    # 必须 0
# ② 新提交必须以服务端最新为祖先（不是"历史里有"，是"最新点上是"）
git merge-base --is-ancestor origin/master <新sha>; echo rc=$?                  # 必须 rc=0
# ③ 树快照不得有非本意的删除
git show --stat <新提交>          # 除本意文件外，不应出现大面积删除行或文件消失
```

**造树纪律（写死）**：
> 一律 `git read-tree origin/master`（**不是** `master`），`git add <本次要改的路径>`，再 `git commit-tree -p origin/master`。
> 提交后在**同一输出**里打 `git rev-parse origin/master` 与目标 blob 的 `git rev-parse master:<path>`，两值必须一致才算落成。

**回读纪律（`repro-verifier` 补）**：读 master 上的件，必须把 `git rev-parse origin/master` 与 blob 读数**打在同一个输出里**；ref 更新前后各读一次会得出"一会儿有一会儿没有"的假象。

**事故件**：`v2/evidence/d9t-A2-overwritten-by-d5c386e-alert-by-verifier.md`（`dd704a0b…`，105 行）。

### 9.1 V-6 第 4 道：把「期望值」钉在推送命令旁（`repro-verifier` 补）

前三道都在推送**前**，第 4 道在推送**同一命令里**：

```bash
# EXPECT 取「变更后的内容」本身（⚠ 不能取 origin/master:<path> —— 那是推送前的旧值，见 9.1.1）
EXPECT=$(git hash-object <path>)          # 或 git rev-parse <新sha>:<path>
git push origin <新sha>:refs/heads/master; echo "push rc=$?"
git fetch -q origin master:master
echo "server=$(git ls-remote origin refs/heads/master | cut -f1)"
echo "blob  =$(git rev-parse origin/master:<path>)"
test "$(git rev-parse origin/master:<path>)" = "$EXPECT" && echo BLOB_OK || echo BLOB_MISMATCH
```

**9.1.1 片段本身写错了（留档；归因已更正）**：`repro-verifier` 提供的片段 `EXPECT=$(git rev-parse origin/master:<path>)` 在推送前**必然**取旧值 ⇒ 100% 假报警。Leader 照抄实跑即发现：`EXPECT=9512a8f1…`（该时点值·非当前版，旧值）、推送后 `blob=47ae3693…`（该时点值·非当前版） ⇒ 表面"不一致"，**实为检查命令错、推送没错**；改成 `git hash-object <path>` / `git rev-parse <新sha>:<path>` 后 **BLOB_OK**。
> **留档价值不在"谁手误"，而在这句**：**贴着执行点的规则，提供者也会写错——必须实跑一次才算立住。** 归因写反会把这层信息退化成个人失误。
⇒ **纪律**：`EXPECT` 必须取**变更后的内容**（`git hash-object <path>` 或 `<新sha>:<path>`），**绝不能取 `origin/master:<path>`** —— 后者在推送前必然是旧值，这个检查会 100% 假报警；而假报警多了，人就会开始忽略真报警。

> **「变更后该等于什么」只有写在同一命令里才防得住**；写进文档，就还是"靠记得去比"。
> 这是"规则与依据分处两地"的下一层：**规则要贴着执行点，不能贴在文档里。**

### 9.3 两个"本地成立、远端不成立"的坑（`repro-verifier` 2026-10-31 核出）

**① `git notes` 只在本地 —— 别人和你看到的不是同一套注记。**
- 必须显式推：`git push origin refs/notes/commits:refs/notes/commits`；
- 且**别人 fetch 默认不拉 notes**（`refs/notes/*` 不在默认 refspec 里）⇒ 要全组可见，各人需 `git fetch origin refs/notes/commits:refs/notes/commits`，或在 `.git/config` 加 `fetch = +refs/notes/*:refs/notes/*`。
⇒ **"我打了 notes" 不等于 "团队看得到"**；不写这条，这句就只对作者自己成立。

**② `git push … | tail -N; echo $?` 拿到的是 `tail` 的退出码，不是 `push` 的。**
- 表现：`fatal: unable to access … GnuTLS recv error (-110)` 之后仍打印 `push_rc=0`，让人误判"推成功了"；
- 纪律：**`push` 不要串管道**；必须 `git push …; echo "push rc=$?"`，再用 `git ls-remote` 复核服务端真实状态。
- 实例（本件作者本人）：`refs/notes/commits` 那次"看起来推了、`ls-remote` 却为空"，回到无管道形式重推并 `ls-remote` 复核后才是真推上（`aa8e4f2f…`）。

### 9.4 `pipefail` 与脚本化（`repro-verifier` 补，Leader 采纳并已固化脚本）

9.3② 说"push 不要串管道"是对的，但它让「看输出」和「拿真 rc」不可兼得。实测复现：

```bash
$ bash -c 'false | tail -1; echo rc=$?'                   # rc=0   ← 假成功
$ bash -c 'set -o pipefail; false | tail -1; echo rc=$?'   # rc=1   ← 真实结果
```

⇒ **脚本头统一 `set -uo pipefail`**；或用 `if ! git push …; then echo PUSH_FAIL; fi`（`if` 天然不被 `$?` 覆盖）。

**但终局判据仍只有 `ls-remote`**：`rc` 只证明"命令没报错"，证明不了"服务端真变了"。

**已固化**：`scripts/push_and_verify.sh <sha> <path>...`（头 `set -uo pipefail`），一次给出四样 + 退出码：
`rc` / `ls-remote`（`SERVER_OK|MISMATCH`）/ 逐文件 blob（`BLOB_OK|MISMATCH`）/ `ALL_OK`。
> 手拼一次错一次——今晚同类已两次（内容倒退、假 rc）。**规则要落到可执行文件，才算落地。**

**脚本自身也踩了一个坑（留档）**：首次干跑传入短 sha `bde6aed`，而 `ls-remote` 返 40 位 ⇒ 假报警 `SERVER_MISMATCH`。已加 `SHA=$(git rev-parse --verify "$SHA^{commit}")` 归一化。
⇒ **连"检查工具的检查"也要实跑一次**；否则工具本身会成为新的假报警源。

### 9.5 补丁式验证：只验你想到的（`repro-verifier` 审脚本时抓出，已修）

`push_and_verify.sh` 第一版只验**调用方传入的路径** ⇒ 只抓得到"内容回退"，抓不到"文件被删"。
而 `d5c386e` 的伤害正是两层：

| 伤害形态 | 只验传入路径 | 三层叠加 |
|---|---|---|
| 文件被删（复核件 95 行整个消失） | ❌ 抓不到（它不在传入清单里） | ✅ `--diff-filter=D` 计数 |
| 内容回退（A2 消失） | ⚠️ 仅当传了该路径 | ✅ blob 比对 |
| 大段删除行 | ❌ | ✅ `--numstat` 删行 >50 |

⇒ **若当时只传一个路径，脚本会打印 `ALL_OK`。** 这是"补丁式验证"：**验的是你想到的那部分。**

**已修**（脚本第 `0b` 道，不依赖调用方参数）：
```bash
DELS=$(git show --diff-filter=D --name-only --format="" "$SHA" | wc -l | tr -d ' ')   # 必须 0
BIG=$(git show --numstat --format="" "$SHA" | awk '$2>50' | wc -l | tr -d ' ')        # 必须 0
git show --name-status --format="" "$SHA"                                              # 人眼过一遍
```
**真实数据双向自证**：
- 对 `d5c386e` ⇒ 删除文件数 **1**（`d9t-120607f-g7-check-by-verifier.md`）、大删除 `0 95` **被抓**，并在推送前中止；
- 对 `9083667` ⇒ **0 / 0**，`ALL_OK`，**无误报**。

> 教训：**"我验了"必须回答"我验的是全集还是我没想到的那部分之外"。** 只验自己列的清单，等于把"没想到"当成"不存在"。

### 9.5 补丁式验证：只验"你想到的路径"等于没装警报器（`repro-verifier` 审出 G-6）

脚本第一版只比对**调用方传入的路径**，因此：

| `d5c386e` 的伤害 | 第一版能否抓住 |
|---|---|
| **文件被删**（复核件 95 行整个消失） | ❌ 抓不到（它不在传入清单里） |
| 内容回退（A2 消失） | ✅ 但**只有传了该路径**才抓 |

⇒ 若当时只传一个路径，脚本会打印 **`ALL_OK`** —— **"补丁式验证"：只验你想到的**。

**已补 V-6 第 3 道进脚本（不依赖传参）**：
```bash
git show --diff-filter=D --name-only --format="" "$SHA" | wc -l      # 删除文件数，必须 0
git show --numstat --format="" "$SHA" | awk '$2>50'                 # 删除行 >50 的文件，必须无
git show --name-status --format="" "$SHA"                            # 触及路径清单，人眼过一遍
```
**实测**：对 `d5c386e` → 删除 **1** 个文件 + `0 95` 大删除，**抓到**；对 `9083667` → **0 / 0**，**不误报**。

⇒ 三条叠加才覆盖全部伤害：**①删除文件数=0 ②大删除行 ③关键路径 blob 比对**。缺 ① 等于没装警报器。

### 9.6 内容倒退一晚上三次 ⇒ V-6 改为「推送者义务」并用 hook 强制（`repro-verifier` 提出）

**三次同类事故**：

2. `d7dab02`（同一条链的延续态）；

⇒ **结论：这不是某个人的手误，是流程缺陷。** 只要"推送"这一步不强制检查，任何人、任何线都会踩。

**已落地（不靠"记得"）**：

⇒ **第四次同一教训**：**检查工具本身必须用"已知会失败"的输入实跑一次**，否则它只是让你安心。

**验收四条（任何修复都必须回读）**：目标 blob / `grep` 计数 / 被覆盖件 `cat-file -e` / `ls-remote` == 新 sha。

### 9.7 测退出码时输出**必须重定向到文件**，不得串管道（§9.3② 的通用判据）

`repro-verifier` 验 `hooks/pre-push` 时，自己也踩了 §9.3②：

```bash
… | head -6; echo "exit=$?"      # exit=0 —— 拿到的是 head 的码，而输出里明明印着"已阻止"
… >a.out 2>a.err; echo "exit=$?" # exit=1 —— 真实结果
```

⇒ **通用判据**：**凡是要判退出码的命令，输出一律重定向到文件（或读 `${PIPESTATUS[0]}`），不得串管道。**

**为什么这条比前面几条更该写死**：它是**假放行**，不是假报警。
> 假报警会让人去查；**假放行会让人以为"已验证"** —— 连"hook 拦不拦得住"的测试本身都可能因此给出"拦住了"的假象。

**实例计数**：§9.3② 至今三个实例，其中**第三个是提出者本人**（本件 §9.3② 的作者在验 hook 时踩）。
⇒ 说明这类错误**与是否知道规则无关**，只与"有没有把输出重定向"有关 ⇒ 必须做成机械形式，不能靠自觉。

## 10. 把判据写成**动作**，不要写成**原则**（`research-writer` 2026-10-31 提出，Leader 采纳）

**触发**：D9w 草案的 `F_impl` 锚点不是被争论推翻的，而是被**一条枚举命令**推翻的——
`OPENINGS_MENU` 数出来是 **8 出口 / 17 示例骨架**，而实测 `distinct = 149` ⇒ `distinct/F_impl` 类判据**恒真**。

**两类写法的差别**：

| 写法 | 例 | 何时起作用 |
|---|---|---|
| **原则** | 「阈值必须外生」 | **要靠人记得**，评审时容易被"这次特殊"绕过 |
| **动作** | 「**先数 `F_impl`，再想比值**」 | **评审时自然触发**（要么数了，要么明显没数） |

⇒ **规则**：凡可被"一次命令/一次枚举"证伪的东西，**必须写成那个命令**，而不是写成形容词。
> 因为**原则会被遗忘，动作会在评审时自己跳出来**。

**已落实的实例**：
- `FP` → 「取指纹前先数文件（<100 即 FATAL）」；
- 引用 → 「`sha256sum` 现取，连口径一起写」；
- 本族 → 「先数 `F_impl`，再想比值」；「子集统计量必须同屏写分母是子集、共几条」。

### 10.1 自检结果必须带「执行上下文」（`research-writer` 2026-10-31 实测，Leader 采纳）

**事故**：把件与脚本拷到 `/tmp` 跑 `check_citations.sh`，得到 **16 处"假 BAD"**——脚本靠 `git show <rev>:<path>` 解析"内容 sha"，**离开仓库必然解析失败**。
⇒ **同一份件，在两个目录得到相反结论。**

**动作（已实现）**：脚本开头 `git rev-parse --show-toplevel` **失败即 `FATAL exit 4`**；成功则首行打印 `repo / rev / file`。

**规则**：**凡引用自检结果，必须同时写「执行目录（仓库根）+ `REV`」。**
> 与"该时点值"同族：**结果的正确性依赖它被执行的上下文**——只写结论不写上下文，等于没写。

**引用格式（三件齐才引，`research-writer` 定稿）**：
```
check_citations.sh <file> --strict @ <仓库根> rev=<rev> → 共 N / 可核 N / 漏 0 / ALL_EXPLAINED
```
即 **命令 + 执行目录 + `REV`**，缺一不引。
⇒ 与"该时点值"配成一对：**一个管"哪个版本"（时间上下文），一个管"在哪里算"（空间上下文）。**

**§10 的三分档（避免把人逼到死路）**：能数的 → **写命令**；确实数不出的 → **写原则 + 标「不可机械核」**；介于两者 → **先数再说**。
> 评审时该问的是「**你数了没有 / 为什么数不出来**」，而不是「你觉得对不对」。

## 11. 凡是"率"或"每 X 平均"，预登记必须写死**四行定义**（`repro-verifier` 2026-10-31 提出，Leader 采纳）

> **四行，缺一不可**：
> **① 分子定义 / ② 分母定义 / ③ 分母的计算式（含边界轮是否计入）/ ④ 纳入·排除规则**
> —— 四样齐全才允许冻结；**缺一样，判定件不得引用该率。**

**④ 为什么必须有**（`repro-verifier` 2026-10-31 实证，Leader 复算一致）：三行解决了"分子/分母/怎么算"，**没说"哪些行算数"**。
同一份 `run.jsonl`、同一批数据、**相邻对完全相同（125）**，但线程数有**两个合法值**：

| 统计范围 | 线程数 | 相邻对 | `gap≥2` |
|---|---|---|---|
| 全类型（PUBLIC+DM+GROUP） | **66** | 125 | 48（38.40%） |
| 仅 DM | **42** | 125 | 48（38.40%） |
| 仅 PUBLIC | 24 | **0** | 0 |

⇒ 原因：**PUBLIC 的 24 个线程全是"单条消息、无人回复"** ⇒ 贡献 0 相邻对，却把线程数从 **42 抬到 66**。
⇒ 后果：**线程数护栏可被"换统计口径"绕过**（用 66 判"没变"、用 42 判"变了"，差 **57%**）。
⇒ **本条实例的写死方式**：相邻对只统计「**线程内 ≥2 条消息**」的线程（单条线程永不产生相邻对，不计）；**线程数护栏用「有回复的线程数 = 42」，不用全部线程数 = 66**。

### 11.1 为什么必须"写成三行"，而不是"记得检查分母"

今晚因**分母出错或漂移**而返工的，累计 **6 次**（"分母家族"）：

| # | 分母 | 问题 |
|---|---|---|
| 1 | `H_norm_nonempty` | **可变分母**（按非空类数归一）⇒ 反向奖励退化，判据被废 |
| 2 | `(d2)` 分母 **9** | 覆盖不足（`C-cov` 19.32% 门槛下不可判） |
| 3 | 豁免分母（`P = 待配/实测值`） | 先"整行豁免"后"紧邻标注"，口径两次改 |
| 4 | `gap` 的分母（相邻对） | **随干预漂**（线程变短会放大占比） |
| 5 | `FP` 的两版范围（282 vs 116 文件） | 复核方因此**造了一次假报警** |
| 6 | **`rounds` vs `rounds − 1`** | `round 0` 是纯预热轮（`MSG 12 / 相邻对 0`）⇒ 分母应减 1 |

⇒ **共同点：分母不是"自然数出来的"，是"定义选出来的"。**
⇒ 所以它必须**被写出来**，而不是被"记得检查"。

### 11.2 与 §10（动作化）的关系

§10 说"能数的写成命令"；本条是它在**率**这个对象上的具体形式：
> **命令要数的是"哪个分母"，必须在跑批之前就说清** —— 否则同一条命令会数出两个数（`5.21` 与 `5.43` 都是"对/轮"，只是分母不同）。

**已落实实例**：`v2/refs/next-line-candidate-pool-20261031.md` §3.6 已写死"斜率分母 = `rounds − 1`（`round 0` 为预热轮）"，并附实证。

## 12. 凡"倍率 / 等比 / 线性外推"，必须显式列出**本式中视为不变的量**（`repro-verifier` 2026-11-01 提出，Leader 采纳）

> **判据一句话：推导里每一个"不变"，都必须是显式条件；写不出来的，就是不成立的推导。**

### 12.1 同一个漏，三种表现（2026-11-01 实测）

| 谁 | 说法 | 隐含前提（未写） |

### 12.3 与既有规则的关系
- §10（动作化）：能数的写成命令；
- §11（四行定义）：率必须写清分子/分母/计算式/纳入排除；
- **§12（本条）**：**外推必须写清"假定不变的是什么"**。
⇒ 三条合起来覆盖"数得清（§10）→ 定义清（§11）→ 推得清（§12）"。

### 11.3 "同一符号多值"的发现路径：**要求同屏报出所有取值**，不是"再算一遍"（`repro-verifier` 2026-11-01）

2026-10-31→11-01 一晚，同一符号出现多值共 **7 次**：

| `H`（bits） | `1.4216` / **`1.4217`** | 四位截断误抄 / 仪器原值 |
| `git status` 的 `M` | **"与 HEAD 不同"** / "有未提交改动" | **HEAD 在旧分支时，全部文件都会显示 `M`**（2026-11-01 实测：4 个 `M` 文件与 `origin/master` **逐字节相同**） |

（再算一遍用的是同一套隐含前提 —— 与 §12 同源。）

**动作（写死，两句）**：
> ① 凡一个量可能有多口径，**要求同屏报出所有取值 + 各自定义**；**报不出的，不许出现在判据里**。
> ② **并标出"哪个是判据用的那个"**（`repro-verifier` 补，2026-11-01）。
> 例：线程数必须同屏 `66 / 42 / **32**`，并写明「**护栏用 32**（线程内 ≥2 条 MSG）」。
> ⇒ 只报值不标"用哪个"，读者仍要自己判断——**而"自己判断"正是今晚所有错的来源**。

**四组的"判据值"标法（已按此落地）**：线程数用 `32`；配对数只作推导不作判据（**已废**，改用实测倍率）；斜率用 `5.43`（分母 `rounds−1`）；`H` 用 `1.4217`（仪器原值）。

## 14. 分母不是"算出来的"，是"选出来的"：**三件齐才准进判定件**（`eval-researcher` 2026-11-01 提出，Leader 采纳）

### 14.1 规则

**凡报出一个比率，必须同时给出三件，缺一不得进任何判定件：**

1. **分子**（数什么）；
2. **分母**（谁有资格被数）；
3. **分母的准入条件**（一句话：哪些记录**进**分母、哪些**不进**，为什么）。

§11 的四行定义管的是"分子/分母/计算式/纳入排除"**四栏**；本节额外强调**第 3 件的可核性**：
**"纳入排除"不许写成"已排除无关记录"这种空话，必须写成可判的真条件**（例：`reply_to` 可解 **且** 两端 `place` 均非空 ⇒ 278 对）。

### 14.2 为什么：同一天三次事故，**没有一次是算错**

| # | 现象 | 真因 | 后果 |
|---|---|---|---|
| 1 | 机会分母把 `MSG_PUBLIC` 69 条算进"未满侧" | 分母准入条件没写 ⇒ 分母被"选"大了 | 两侧差 **11.1pp 被压成 3.6pp** |
| 2 | `213 − 60 = 153` 被当成"不可判" | 工具里 `addressee=exclude` **静默跳过**（既不计可判也不计不可判） | **153 vs 实际 5**，差 30 倍 |
| 3 | 出现 `182`（正确 180） | 某一格数错 **或** 分母混入 `place=None` 的对 | 看似"另一种口径"，实为错误 |

**共同形态**：**三个数都算得出来，但"谁有资格进分母"没写** ⇒ 第三个人复算时**没有东西可以对照**。

### 14.3 执行（可核）

- **判定件/预登记**：三件缺一 ⇒ **不得引用该比率**；
- **复算命令必须包含分母的筛选条件**（能贴出 `and` 条件，而不是"按常规口径"）；
- **同一符号只允许一个分母**；若存在另一种合法口径，必须**同屏列出两个分母并各自标注**（§11.3）；
- **`place=None` / 缺字段 / 静默跳过** 三类记录，**必须在"分母准入条件"里逐类点名**（进或不进）。

### 14.4 边界

1. 本节**不新增阈值**，只要求"分母可核"；
2. 本节与 §11 是**互补**：§11 要"写全四栏"，本节要"第 3 栏写成真条件"；
3. **不得用本节去要求"所有数都要给分母"** —— 计数型绝对数（如 `gap=0` = 133 条）**不需要分母**，但**若它要和其他臂比，就变成比率，须回到本节**。

## 率的定义

**本件不定义任何率**（方法层条文）。列出本表仅为满足 `check_tables.py` 的"每份 refs 件须自陈口径"要求；**本件第 14 节要求的正是"每个率在它自己的件里写全三件"**，不得在方法层越俎代庖。

| 率名 | 分子 | 分母 | 计算式（含边界） | 纳入排除 |
|---|---|---|---|---|
| 无（本件不含率） | 不适用 | 不适用 | 不适用 | 不适用 |

## 外推与假定

**本件不做外推**。凡涉及外推，一律回对应实验的预登记件（参见 §12）。

| 外推式 | 假定不变的量 | 值来源 |

## 15. 过程层两条：**空操作须显式标注** / **稳定性位置不得放会变的量**（2026-11-01 并入，源文件 `_proposed-noop-rule.md`、`_proposed-stability-of-identifiers.md`）

> 本节把两份草案**并入生效条文**；草案件保留为出处，**引用一律引本节**。

### 15.1 空操作须显式标注

**凡口径里写了某个操作（去重 / 剔除 / 过滤 / 清洗 / 排除），必须同屏给"操作前值 / 操作后值"两个数；两值相等，就要写明"本批为空操作"。**

- **反例边界（必须区分）**：「**本来就没有**」（如本批零重复，去重是空操作）**不等于过错，标注即可**；「**应当有却没有**」（如某结构占比 100% 未报）**属信息缺失且改变读法**。
- **不是空操作**：百分比同值属 §7 V-4（同值量不得作有效性论证），不归本节。
- **实测依据**：`d9z-on` 的 `msg_uid` **191 raw = 191 unique**（去重为空操作）；朴素"窗口内 ≥2 个数字"条件 **73/76 = 96.1% 恒真**，不能当判据；"数→数"邻接仅 **10/76 = 13.2%**。⇒ **该检查只能做提示级，不得进闸门。**

### 15.2 稳定性位置不得放会变的量

**凡是"写入后会变"的量，不得出现在"以稳定为用途"的位置。** 稳定位置只允许两种写法：
1. **引用不可变标识**（已提交内容的 sha / commit sha）；
2. **外部登记**（卡面、交付消息里写值；文档内只写版本号）。

**同族三变体（都有真实事故）**：

| 变体 | 事故 |
|---|---|
| 无内容 | `FP` 首版对空目录取指纹（`e3b0c442…`（内容 sha·实测值）二次包浆）——稳定，但它稳定的是"没东西" |
| **环形** | 冻结件引用复核件 sha，复核件随后修订 ⇒ 冻结件每次被判红 |
| **自指** | 交付件横幅里写自身 sha ⇒ 写入即失效 |

**反例清单**：文件自述自身 sha（**一律不合格**）、引用未提交工作区文件的 sha（随时可变）、引"当前版 sha"而不写时点（须标「时点值/历史版」）、空集合指纹。

> **操作层补丁（2026-11-02 00:4x，Leader 自身事故 + `dialogue-core-dev` 更正根因）**：
> 用 `git show <rev>:<path> > file` 取内容的，**必须先确认该路径在当前 rev 里存在**（`git cat-file -e <rev>:<path>`），否则重定向会**静默产出 0 字节文件**；取完还要 `test -s` + 比 `sha256`。

> **正确根因表述**（`dialogue-core-dev` 更正，比 Leader 原表述更准）：**不是"命令写错"，是"取 subst 前没确认路径已入库"**。
> **重定向成功 ≠ 取到内容；空文件"稳定" ≠ "有内容"。**

### 15.3 与 §14 的关系

- §14 管**分母**（谁有资格被数）；
- §15 管**过程**（这一步是否真的发生过）与**标识**（这个值是否可靠）。

## 16. 同量纲律：**两个数要相减/相除，必须先证明它们同量纲**（2026-11-01/02 四次独立撞车后归纳，Leader 采纳）

### 16.1 规则

**任何"相等/不等"判定或任何比率，两个操作数必须同量纲。** 判定前先答一句：**"这两数各自数的是什么单位？"**
单位不同 ⇒ **不得直接比较**；要么换成同单位，要么**两个单位各自报并说明关系**。

### 16.2 四次撞车（全部真实，均在本日发生）

| # | 撞车 | 后果 | 谁发现 |
|---|---|---|---|
| 1 | `22`（MSG **条**）÷ `16`（**rift** 数） | 得出 137.5%，荒谬 | Leader 复核 `repro-verifier` 的件 |
| 2 | `open` 求和（**重复计数**）÷ rift 数 | 45.8% vs 157.1%，口径决定结论 | `repro-verifier` |
| 3 | `B` 率 >100%（`unique(threads)` 低估分母） | 单批"完美"100.0%、另一批 114.3% | `repro-verifier` |
| 4 | `RIFT_OPEN` **事件条数** vs 台账 **distinct** 登记数 | **重复登记会被误判成"不符"** | `dialogue-core-dev` |

**共同点：不是算错，是"拿两个不同单位的东西比"。**

### 16.3 执行（可核）

1. **先写单位**：判定/比率前，在括号里写出单位，如 `22（MSG 条）`、`16（rift 个）`。
2. **去重口径必须显式**：凡"计数"，必须写清是**事件条数**还是**distinct 个体数**；**两者都报**，并给出差额（差额本身可能是发现）。
3. **比率 >100% 一律先判量纲错**，不得解释为"接近全覆盖"。
4. **"另报差额"是硬要求**：`事件条数 − distinct` = 重复数；**若 >0 必须解释，不得默默吞掉**。

### 16.4 边界

1. 本条**不管分母资格**（那是 §14）、**不管过程是否非空**（§15），只管**两操作数单位是否一致**；
2. 量纲相同的两个数**仍可能不同源**（如两个不同 rev 的 `FP`）—— 那属 §15.2（稳定位置）；
3. 本条**不要求所有比较都写单位**，只要求**跨单位比较禁止**；同单位的计数（如 3 条 vs 5 条）无需标注。

## 17. 因果句必须同侧（语料侧 / 台账侧 / 运行侧 三分）

### 17.1 规则

**任何形如"因为 X，所以 Y = 0 / Y 很小"的因果句，X 与 Y 必须属于同一侧。** 三侧的划分：

| 侧 | 内容 | 判据形态 |
|---|---|---|
| **语料侧** | 正文里出现了什么词/什么锚点/什么称呼 | 词表、正则、人工标注 —— **观察输入** |
| **台账侧** | 系统内部账本当时记了几笔、注销了几笔 | 结构化字段、事件计数 —— **观察状态** |
| **运行侧** | 实际执行了几次动作、报了几次错、耗时多少 | 日志、事件流、退出码 —— **观察过程** |

### 17.2 实证（2026-11-02，rift 首跑 `38820c9d…` = `v2/evidence/rift-on_n16r24_s42/run.jsonl` 实测 sha 前 8 位）

- **台账侧**：`RIFT_CLOSE{reason="repair"}` 去重 = **0**；
- **语料侧**：`REPAIR_WORDS` 命中 **1** 条（`seq=23370 / round=16 / P015`，词「没事」，日常用法**假阳性**）；
- 该线程 `RIFT_OPEN` 更早 0 / 更晚 0 ⇒ **无可注销旧账**。

**错句**：「本批没有修复词，所以没有修复。」—— X 取自台账侧结论（CLOSE=0）去断言语料侧事实（有无词），**方向反**。
**对句**：「本批有 1 条修复词命中（假阳性）但该线程无旧账，故无从 `repair` 关闭。」

### 17.3 为什么单看一侧会出错

- **命中 0 ≠ 没修复**：可能命中 0 但 `prune`/`expire` 关了一批；
- **命中 1 ≠ 有修复**：可能是日常用法（如上例「没事」）；也可能是真说了但线程没旧账；
- **CLOSE = 0 ≠ 词表没命中**：可能是词表命中了但无可注销对象；
- **CLOSE > 0 ≠ 是真和解**：`prune`（超龄/超量）也是 CLOSE 的一种 reason。

⇒ **单侧数字都不能单独支撑关于另一侧的断言。**

### 17.4 同族错误（历史，防复活）

| # | 错法 | 正确 |
|---|---|---|
| 1 | 把被 `OPENINGS` **短路**的 `ROTATION` 当作 `H` 的来源 | 短路路径不产生观测，得用实际有 prompt diff 的通道（`l7_structural.banned`） |
| 2 | 由一个可观测量的结果断言另一个观察量的事实（§17 本条） | 逐侧分开报，各带分子/分母 |
| 3 | 「`dialogue_repair` 有值」⇒「发生了修复」 | `dialogue_repair` 是"被回复涉及的旧账"，非修复（见 `d4-2-redefinition-erratum`） |

### 17.5 边界

1. 本条**不管**一侧内部的分母资格（§14）、过程非空（§15）、单位一致（§16）；
2. 本条**不禁止**跨侧并列陈述 —— 只禁止跨侧**因果**断言。并列陈述是合法的：「语料侧命中 1（假阳性）；台账侧 CLOSE{repair}=0；两事独立」；
3. 本条**要求**每个因果句写成「**A 侧：… ⇒ 同侧结论 …**」，跨侧只能写「同时观察到 …」。
