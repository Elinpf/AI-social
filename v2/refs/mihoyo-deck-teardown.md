## 1. 类脑 NPC 决策架构（逐层拆开）

### 1.1 deck 原文事实（`[img-18]`，标题"#1 自研类脑 NPC 决策架构"）
- 定位：*"让 NPC 具备主动行为能力"*。
- 核心能力原文要点：
  - *"NPC 不只是被动响应。Agent 架构让它能感知环境、自主决策、发起行为"*；
  - **「我们没有沿用工程化的 Sense-Plan-Act 范式，而是从脑认知与行为科学中寻找蓝本」**；
  - **管线**：*"外界信号经**事件感知层**输入，由 **PFC 决策中枢**判断，驱动**行为模式层切换**，最终由**行动执行层**落地"*；
  - 目的：*"越贴近人脑的组织方式，角色越能摆脱'脚本感'，向真正的'活人感'逼近"*。
- 配合 `[img-14][img-17]`：决策层用的具体模型是 **PFC 决策 + ECN 行为模型**（T202 已核实的同源演讲：PFC=想什么、ECN=怎么做）。

### 1.2 四层逐一拆解
| 层（deck） | 做什么 | 与我们哪一层对应 |
|---|---|---|
| **事件感知层** | 把外界信号（环境/他人/玩家）整理成输入 | ≈ 我们 life 层的 `perceive` / observation 构建 |
| **PFC 决策中枢** | 目标拆分 / 道德判断 / 后果推演 / 风险评估 → 拍板 | ≈ 我们「**LLM 出意图**」（T2 决策） |
| **行为模式层切换** | 决定"用哪种行为模式"再去做 | ⚠️ 我们**没有**等价物（我们直接从意图到裁决） |
| **行动执行层** | 把决定落地为动作 | ≈ 我们「**确定性裁决器**」执行 intent |

### 1.3 「它把我方『LLM 只出意图 + 确定性引擎』拿走了哪一部分？」
- **它拿走的，其实是同一条边界**：**决策（脑）与执行（引擎）分离**——`PFC 决策中枢`≈ 我们的"LLM 只出意图"，`行动执行层`≈ 我们的"确定性引擎执行"。**这不是被拿走，而是与我方同源**（T200 SKYCity 也印证同一分野）。
- **它多做的**：把"决策层"内部**显式拆成 PFC（想什么）+ ECN（怎么做）+ 行为模式层（用哪套模式）**，为的是**拟人化（活人感）**，**不是**为了"确定性可复现"。
- **我们该不该拿回来？**
  - ❌ **PFC / ECN 不整体拿回**：它是**拟人化手段**，会引入更多 LLM 环节（↑成本、↑不可复现面），**与我方"可审计、可重放"目标不匹配**。
  - ✅ **只值得拿回「行为模式层切换」这一件**：把"当前处于哪种行为模式（如 工作/社交/休息/求生）"做成**一个廉价的门控**，**模式决定走哪条子策略与模型档位**——这与 SKYCity 的"Agent 默认休眠 + 事件驱动唤醒"、与我们 T2/T1/T0 分层同源，是**降本**而非拟人化。
- **一句话**：**他们的架构证明"决策与执行分离"是行业共识，我方无需改动；可拿走的是"行为模式门控"这个降本件，不必拿走整套类脑拟人化。**

## 2. 超类人记忆五重能力（`[img-19]`）

### 2.1 deck 原文五重能力（逐条）
| # | 能力（deck 原文） | 释义 |
|---|---|---|
| 1 | **脑认知记忆** | *"有编码、遗忘、联想与重构，而不只是存储"* |
| 2 | **跨角色记忆** | *"经历在 NPC 之间流转共享，成为剧情涌现的养料"* |
| 3 | **超长期记忆** | *"突破上下文窗口的限制，跨越漫长时间线，角色依然完整"* |
| 4 | **超多人记忆** | *"同时维系与众多玩家、众多角色的关系脉络，互不干扰"* |
| 5 | **跨平台记忆** | *"人格与经历不被单一场景锁定，随玩家切换场景而延续"* |

并给出总目标：*"让 NPC 从'能对话的程序'，成为真正能在游戏世界中自主生存的角色"* `[img-19]`。

### 2.2 逐条对照：我方现状 vs SKYCity 三层记忆
| 能力 | 我方现状（v1.1/v2） | SKYCity（T200） | 判定 |
|---|---|---|---|
| 1 脑认知记忆（编码/遗忘/联想/重构） | 有记忆流 + 反思；**无"遗忘/重构"**（只增不减） | 有 working 剪枝；**episodic/semantic 永不删、无衰减** | ❌ **真缺**：两家都缺"真遗忘/重构" |
| 2 跨角色记忆（互相流转共享） | 有**传播/关系**（观测层读日志），**无"共享记忆池"** | episodic **只记当事方、绝不记他人秘密**（刻意不共享） | ⚠️ **部分缺**：我方有传播、无公共记忆 |
| 3 超长期记忆（突破上下文窗口） | ✅ 有（长期记忆 + 文件系统式 + 冻结） | ✅ 有（三层 + 反思） | ✅ 方向已有 |
| 4 超多人记忆（多关系脉络互不干扰） | 有 50-Agent 关系矩阵，**规模受限、检索 O(n)** | 关系表；**检索全表扫描、无 embedding**（50+ 线性变慢） | ⚠️ **规模缺**：需 embedding/分区 |
| 5 跨平台记忆（人格不绑单场景） | 单小镇，**无跨平台** | 单世界 | ❌ **不适用/暂缺**（我方当前单小镇） |

### 2.3 结论：我们**真缺**的是什么
1. **遗忘与重构**（能力 1）：我方与 SKYCity 都只增不减 → **要做真衰减/归档**（决策与观测都要"记得住重点、淡忘次要"）。
2. **跨角色公共记忆**（能力 2）：正对 T202 里米哈游自己说的"**公共记忆像传八卦、让信息带动社会诞生传说/事件**"——**与我方"涌现观测层"要观测的对象重合**。但注意：**这是"写世界"还是"只读观测"要分清**（见 §7 冲突）。
3. **超多人关系管理**（能力 4）：50+ 规模下关系检索必须有 embedding/分区（SKYCity 已在 50+ 线性变慢）。

## 3. NPC L1–L5 智能等级（最直接的降本手段）

### 3.1 deck 原文（`[img-25]`，"通用 NPC UGC/PGC 配置工具"）
- 解决痛点：*"搭建一个 NPC 需要反复填写分散的配置项，智能程度越高，手工成本越高"*。
- 核心能力：*"从 0 到 1 搭一个完整角色，人设、故事背景、**智能等级**自由设定"*；
- **「我们将 NPC 分为 L1–L5 五个智能等级，最高级别 L5 具备多模态学习、具身智能与自主创造能力，类似《西部世界》中的 Host」**；
- *"基于此开发了一套通用 NPC 框架，像积木一样自由组合，无需编码即可配置——也为未来 UGC AI 生态搭建了基础"*。

### 3.2 「用分级降本」对 50+ 的具体做法（我方落法）
> 核心洞察：**不是所有 Agent 都需要满血**。分级把"每回合 × 全员 × T2"的爆炸成本，压成"分级 × 事件驱动"。

| 等级 | 适用 | 模型档位 | 决策频率 | 记忆/反思 | 相当于 |
|---|---|---|---|---|---|
| **L5 主角级** | 少数关键 Agent（如实验焦点角色） | **T2（大模型/thinking）** | 每回合 | 全量记忆 + 频繁反思 | 我们现在**所有** Agent 的待遇 |
| **L4 重要级** | 有剧情线角色 | T2/T1 混合 | 事件驱动 + 低频轮询 | 全量记忆 + 周期反思 | — |
| **L3 常驻级** | 多数社会成员 | **T1（判别式/小模型）** | 事件驱动 | 摘要记忆 | — |
| **L2 背景级** | 群演 | **T0（规则/效用）** | 仅被触发 | 关键事件记忆 | SKYCity 的"休眠 + 唤醒" |
| **L1 道具级** | 环境 NPC | 纯确定性 | 不决策 | 无 | — |

- **降本原理**：把当前"**全员每回合 T2**"改为"**金字塔**"——`总调用 ≈ L5×1 + L4×f + L3×f + T0 兜底`；T2 只留给少数。
- **对本项目 50+ 的直接收益**：**judge/importance 的 72.7% token 主要来自"全员高频判别"**；分级后**多数 Agent 降到 T1/T0**，**T2 调用数可数倍下降**。
- ⚠️ **代价/风险**：L1–L5 是**"作者化"预设**（预设哪些角色更重要）——与我们"给底座看涌现"有张力（见 §7），**但它可**降级为**纯工程旋钮**（按"是否需要复杂推理"而非"角色是否重要"分级），从而**不碰红线**。
- **结论**：**建议采纳，但重定义为"算力/推理档位"而非"剧情重要性等级"**——这是 §3 与 §7 的关键区分。

## 4. 奖励模型两种用法 → 迁移到我方 judge / importance

### 4.1 deck 原文（`[img-23]`，标题"Reward Model (RM) 应用场景与技术"）
- **场景一 · 在线打分（Best-of-N）**：*"用户输入(考虑) → Agent 模型生成 N 个候选 → **RM 打分（指令遵循/价值观/安全）** → 选择最优回复 → 生成给玩家"*。
- **场景二 · 线下辅助强化学习训练**：*"Candidate 候选注 → ①**Scalar-based RM**（输入一个标量值，输出单一打分结果，更加快捷） + ②**Rubric-based RM**（给定评测 rubric 标准，**逐项打分**：指令遵循 / 人设一致性 / 安全性…） → 强化学习训练（PPO/DPO/GRPO）→ Policy Model"*。
- 配合 `[img-22]`：*"Reward 层搭建基于 **rule 规则、scalar 信号和 rubric 生成式反馈的三层 Hybrid Reward 体系**"*。
- 配合 `[img-21]`：*"奖励模型在训练中充当质量的度量与锚点……**评估器的质量决定自我改进循环的上限**"*。

### 4.2 与 jev 的同族关系
- jev = **判别式单前向 + 类型化输出（choice/score/noul）+ 校准置信度**（见 `v2/refs/mihoyo-and-jev.md`）。
- **Scalar-based RM**（输出单一标量）= jev 的 **`score`**；**Rubric-based RM**（逐项打分）= 多次 **`score`/`noul`**；**Best-of-N 打分** = jev 的 **`choice`/`score` 排序**。
- **三者同族**：**用小模型判别（打分/分类），而不是用大模型生成**。

### 4.3 迁移到我方 `judge` / `importance` 的具体方案（P0 成本项）
| 现状 | 目标 | 做法 |
|---|---|---|
| `judge`：T2 thinking 大模型**生成**打分/推理（**占 72.7% token**） | **判别式单前向 + 类型化输出** | 把 judge 拆成 **Rubric 子项**（如"人设一致性/安全/逻辑"），每项一次 **`score` 或 `noul`** 判别调用；**输出 token≈0**、可冻结 |
| `importance`：大模型生成显著性 | **标量判别** | 一次 **`score`（0–9）** 调用（jev 的 importance 用法与 AI Town `calculateImportance` 同构） |
| 结果不可复现 | **冻结** | 把 `(rubric, 候选, 分数, 置信度)` 一并写入 `LLM_JUDGMENT` 日志；**重放读缓存、不重调** |

- **收益估算**：判别式**输出 token→0**，且**单前向 70–500ms**（vs 自回归 2–5s）；对"全员高频 judge"这一最大成本项是**数量级下降**。
- **实现路径（三选一）**：① 用**我们内网的小模型** + logit-masking/约束输出复现 jev 的"形"；② 训练一个**判别式 rubric RM**（见 §5）；③ 先用普通 LLM 出 `score`（保留结构化，但失去"输出免费/毫秒"优势）。
- ⚠️ **不碰红线**：这三个都是**度量/判别**层，**不写世界**，与"只给环境不给结局"不冲突。
- 佐证：`v2/refs/scale-50-efficiency.md` 记 **judge 占 72.7% token**；T202 §4.3 已给"候选枚举 + 类型化选择"对 token 的影响估算。

## 5. 一个模型驱动所有 NPC（`[img-17][img-20][img-21]`）→ 用户目标 #10

### 5.1 deck 原文
- `[img-17]`：能力模块 =「**通用 AI 角色模型**（#角色扮演模型# + #奖励模型#）」+「**AI 生态后训练框架**（#SFT→RLHF→DPO→OPD#）」。
- `[img-20]`：*"**自研角色扮演模型能同时驱动多个 AI NPC，保证低延迟、高拟真**"*。
- `[img-21]`：奖励模型作为"质量度量与锚点"。
- `[img-22]`：*"在 Reward 层搭建基于 rule/scalar/rubric 的**三层 Hybrid Reward 体系**，结合 OPD 等技术"*；*"RM 与 RL 的真正难点都不在算法，而在于**建模出'什么是好的 AI 角色表现'**"*。
- 同源演讲（T202）：**多教师在线蒸馏 → 一个学生模型承载所有 NPC 人设/能力**。

### 5.2 对应用户目标 #10（产出数据训练小模型）：我们需要做什么
1. **收集**：把确定性日志里的**高质量交互轨迹**（含冻结的 LLM 判定）导出为训练集（我们已有 append-only 日志 + 冻结层，**这是我们的独有优势**）。
2. **判别式小模型**：优先训**判别式 RM**（rubric/scalar，§4）——**用于 judge/importance 的廉价替代**，回报最快。
3. **角色小模型**：把"日常对话/常规决策"从 T2 大模型蒸馏到**一个小角色扮演模型**；大模型只处理 L5/L4 关键决策（配合 §3 分级）。
4. **闭环**：小模型 → 跑更多 Agent（50+ 同时驱动，如 deck 所述）→ 产出更多数据 → 再训。**且我们全程有可审计日志，比他们更可复现。**

> **一句话**：他们的"一个模型驱动所有 NPC"是**成本路径**，而**"用产出数据训小模型"（目标 #10）是我们可复现的优势的自然延伸**。

|---|---|---|---|---|
| **世界观编年史可视化工具** | 有 Storyteller（叙述机）+ 关系网指标 | **可视化关系网/事件时间线 + 角色记忆 Prompt 生成** | **P0（最高）** | **直接吃我们的日志/关系指标**；可自动化；与叙述机互补 |
| **NPC 配置工具** | 有 persona 配置（v1.1 M1） | **可视化、可组合、无需编码** | **P1** | 50+ 角色配置成本高；配合 §3 分级 |
| **自演化沙盒** | 有沙盒执行 + 消融（EventForge M4） | **"自演化"闭环（自动改配置/自改进）** | **P1** | 支撑消融证伪与自改进；**但要防越红线**（自演化若自动改社会规则=越线） |
| **叙事编辑器** | 有 Storyteller 渲染 | **人工编辑入口** | **P2** | 人工介入需求不确定；我方叙事**只读**，编辑属可选 |

> ⚠️ **自演化沙盒的越线风险**：若"自演化"允许系统**自动改社会规则/结局**，则**违反"只给环境不给结局"红线**；我方版本**必须限定为"只自动调环境参数与机制开关"**（可消融、可复算）。
