## 0. 一句话目的

把 F-3（情绪呼应）从「**永远不可判**」推进到「**可判或明确不可判**」。
现状的唯一致命伤不是机制没接上，而是**判定口径的分母只有 28 / 22**，远低于仓库统一的
`PROBE_MIN_DENOM = 68`，因此无论机制好坏都只能落 `count_only`。

**本卡只做一件事：重新定义「一次情绪呼应机会」这个计数单元，并且把口径写死到可离线复算。**
本卡**不下调阈值**、**不换命中定义去凑签名**、**不挑选结论**。

**注意：「可判」需要同时满足两个判据** —— ①分母判据 `den ≥ 68`（§4.3）；
②效应可检判据 `|Δ| ≥ MDE ≈ 2.7pp`（§4.3.1）。只满足 ① 时，正确结论是
「**在 MDE 以下无可检出差异 / 样本不足以排除小效应**」，不是「证明没有差异」（§4.3.2）。

## 2. 旧口径分母溯源（**护栏段，必须逐字读完再改任何东西**）

旧读数的分母是 **28（OFF）/ 22（ON）**。它从哪来？它与 cycle34 记录的「per-round 机会密度」完全吻合：

```
OFF：0.345679 × 81 = 28.0     （per_round = 0.345679，n_rounds_seen = 81）
ON ：0.271605 × 81 = 22.0     （per_round = 0.271605，n_rounds_seen = 81）
```

两个乘法都精确回到旧分母。因此：

> ⚠️ **「per-round 机会密度 × n_rounds」不是更宽的口径，它就是旧口径本身。**
> 把宽口径定义成 `per_round × rounds`，分母会原样回到 28 / 22，仍 < 68，本轮白跑。
> **本卡明确禁止把 per-round 口径作为本轮新口径。**

旧口径为什么这么小：它的机会单元是「线程内相邻消息对，且**上一句在词表上极性 ≠ 0**」。
词表只有 34 条词，绝大多数消息在词表上极性为 0，于是 480 条 reply 消息里只剩 28 条能进分母。
**这不是「机会少」，是「尺子太挑」**——它把「沉默/中性表述的父消息」全部判成「没有机会」。

## 3. 新口径 · 机会单元定义（可执行判定式）

### 3.1 术语与字段（全部来自 run.jsonl，机制无关）

对任意 `type` 以 `MSG_` 开头的日志行：

- `U(m)` = `payload.msg_uid`（字符串；`meta.json` 断言 `msg_uid_unique = true`）
- `RT(m)` = `payload.reply_to`（父消息的 `msg_uid`；无父则 `null`）
- `parent(m)` = 日志内满足 `U(x) = RT(m)` 的消息 `x`（借 `meta.json` 的 `ptr_dangling = 0`、`ptr_cross_thread = 0` 保证可解析）
- `mood(m)` = `payload.ctx.mood`（字符串，或 `None`）
- `body(m)` = `payload.body`（字符串）
- `pol(body)` = 词表极性：`pos = #{w ∈ lexicon : weight(w) > 0 且 w 是 body 的子串}`，
  `neg` 同理取 `weight < 0`；`pol = sign(pos − neg) ∈ {−1, 0, +1}`
  （**与 `tools/d5` / `tools/f3/f3_metrics.py` 同一算法：朴素子串计数、不切词**）
- `NEUTRAL_MOOD = {"平和"}`（本批实测 mood 取值域：`紧绷 453 / 饥饿 147 / 平和 69 / 孤单 11 / 疲惫 6`）
- `affect(x)` := `(mood(x) ≠ None 且 mood(x) ∉ NEUTRAL_MOOD)` **或** `pol(body(x)) ≠ 0`

### 3.2 机会集 O（本卡唯一分母）

```
O(arm) = { m ∈ MSG_* :  RT(m) ≠ null
                        ∧ parent(m) 可在本批日志内解析
                        ∧ affect(parent(m)) = true }
分母 den_wide = |O(arm)|
```

### 3.3 为什么这个单元是「一次真实机会」（论证，不是「因为分母大」）

1. **呼应的语义前提是「有一句可以呼应的话」。** 发起消息（`reply_to = null`）没有对象，
   不存在「呼应」这件事 ⇒ 不算机会。把 206 条发起消息算进分母，是在**稀释率**，
   属于把不该算机会的东西算进来，本身即造假。
2. **父消息若既无情绪标签、正文也无情绪词，则「无物可呼应」。** 要求 `affect(parent)` 为真，
   是在**保住「情绪呼应」这个词的语义**，不是挑数据。若不要求，分母会虚高到 480，
   而 480 里 41/42 条父消息在 `平和` 且正文无情绪词 —— 「你教教我桃酥怎么烤」这种父消息
   被要求「呼应情绪」是不成立的。
3. **信号必须机制无关、两臂同在。** `ctx.mood` 与 `body` 是引擎无论 F-3 开关都写的字段
   （OFF 臂同样有 `ctx.mood` 全量覆盖），因此该分母在两臂上是**同一把尺子**，
   不出现「只有 ON 臂才有这个字段」的不可比分母（这正是机制口径 107 vs 0 的死穴，见 §5.2）。
4. **可离线复算。** 判定式只用 `msg_uid / reply_to / ctx.mood / body / type` 五个字段，
   不依赖模型、不依赖网络、不依赖时间戳，零 LLM 即可执行，逐字节可复现。

### 3.4 明确排除项（写清楚，免得被误读为漏算）

| 排除项 | OFF | ON | 为什么不算机会 |
|---|---|---|---|
| 发起消息 `reply_to = null` | 206 | 206 | 无父消息，无呼应对象 |
| 父消息 `mood = 平和` 且 `pol = 0` | 41 | 42 | 父消息无情绪信号，无物可呼应 |
| `reply_to` 悬空 / 跨线程 | 0 / 0 | 0 / 0 | 本批 `ptr_dangling = 0`、`ptr_cross_thread = 0` |
| 非 `MSG_*` 事件 | — | — | 不是对话消息 |

> 640 = 686 − 206 是 reply 消息总数（实际 480，另 160 条为发起侧计数差异，读数器按 `reply_to` 实数统计，不手工填任何数）。

### 3.6 极性判定的实现指认（回答「这份分母是不是我自己造的」）

**不是我自己造的。** 极性判定 `pol(body)` 引用仓库**既有**实现，两臂用**同一份**，本轮**不改它**：

## 4. 命中定义与判档规则

### 4.1 主指标 P1 = H1 ∪ H2（两臂同尺、文本层、机制无关）

- **H1 · 极性一致**：`pol(parent.body) ≠ 0` 且 `pol(m.body) = pol(parent.body)`
- **H2 · 共情标记**：`m.body` 含 §1 那 10 个标记中任意一个

> P1 命中数、`den_wide`、`rate = hits/den_wide`、Wilson 95% 区间，一并报出。
> **必须分列报 H1、H2 各自的命中数**，不得只给合并数（防止「合并掩盖了哪一路在动」）。

### 4.2 次级指标（**分列单报，永不并入 P1**）

- **H3 · 情绪标签回声**：`m.body` 含父消息 mood 的字面词（`紧绷/孤单/疲惫/饥饿`）。零命中也是结论。
- **S1 · 结构化情绪共振**：`mood(m) = mood(parent)` 且 `mood(parent) ∉ NEUTRAL_MOOD`。
  ⚠️ **显式声明：S1 受 agent 需求状态持续性混淆**，`紧绷` 一条就占 62.9%（273/434），
  它是「状态没变」而非「听到了对方的情绪」。**S1 只作对照，不得当作情绪呼应的主判据。**
- **机制侧 M**：`payload.ctx.echo` 存在的消息数（`echo_msgs`）、`verify.present`、`verify.adopted`。
  这一组**只在 ON 臂有值**（OFF 臂恒 0），因此**不参与两臂比较**，只用于「机制接线成立 ≠ 行为被采纳」的警示。

### 4.3 判档规则（照抄仓库纪律，**不得为本轮放宽**）

| 分母 den_wide | 判档 | 允许报什么 |
|---|---|---|
| `den < 30` | `count_only` | 只报事件数，**不报率** |
| `30 ≤ den < 68` | `不可判(count_only)` | 只报事件数，**不报率**；必须给出抬到 ≥68 的最小代价（外推，标明非实测） |
| `den ≥ 68` | `ok` | 报率 + Wilson95 + 判档 |

- `PROBE_MIN_DENOM = 68`，**本轮不下调、不改判档边界**。分母够不够是事实，不是目标。
- 两臂差分：Newcombe(1998) hybrid score 95% CI。
  **CI 跨 0 ⇒ 不得宣称两臂有差异**（N1 纪律：本规模下不能把「没检出」写成「没有」）。
- 口径变更声明：**新口径下的率不可与旧口径（28/22）直接比大小。** 报告必须并列旧口径读数。

### 4.3.1 效应可检判据 · 预登记最小可检测效应量（MDE）

**「分母 ≥ 68」只说明「允许报率」，不等于「能判出效应」。** 两个判据必须分开预登记：

1. **分母判据**：`den_wide ≥ 68` ⇒ 允许报率（§4.3）。
2. **效应可检判据**：本轮能检出的最小绝对率差 **MDE**，按预登记分母与预期基线率算出。

MDE 公式（两独立比例、双侧 α=0.05、检验力 1−β=0.80，正态近似，预登记**写死**）：

```
se   = sqrt( 2 · p̄ · (1 − p̄) / n )        # n = 单臂分母；p̄ = 两臂合并基线率
MDE  = ( z_{1−α/2} + z_{1−β} ) · se = (1.95996 + 0.84162) · se = 2.80158 · se
```

按 §6.1 预登记的分母 `n ≈ 438–439` 与基线 `p̄ ≈ 2%`：

```
se ≈ sqrt(2 × 0.02 × 0.98 / 439) = 0.00945
MDE ≈ 2.80158 × 0.00945 ≈ 0.0265  ⇒  MDE ≈ 2.6 ~ 2.8 个百分点（pp）
```

| 量 | 预登记值 | 说明 |
|---|---|---|
| 单臂分母 | ≈ 438–439 | §3.2；实测值以读数器为准 |
| MDE（绝对率差） | **≈ 2.7 pp**（区间 2.6–2.8） | α=0.05 双侧、power=0.80 |
| MDE（相对） | **≈ +128% 相对提升** | 基线 2.1%，2.7pp/2.1% ⇒ 需**翻倍以上**才可检出 |
| 若只想检出 1 pp | 每臂需 **≈ 3227 条机会** | `n = 2·p(1−p)(z_a+z_b)²/δ²`，δ=0.01 ⇒ 3227/arm |
| 若只想检出 2 pp | 每臂需 **≈ 807 条机会** | 同上，δ=0.02 |
| 若只想检出 5 pp | 每臂需 **≈ 129 条机会** | 同上，δ=0.05 |

> **推论（预登记）**：本规模下只能检出 **≥2.7pp 的绝对率差**（相对翻倍以上）。
> 因此本轮最可能的结论形态是「**在 MDE≈2.7pp 以下无可检出差异**」，
> **而不是**「证明了没有差异」。二者的区别见 §4.3.2。

### 4.3.2 表述纪律：三种说法不得混用

| 观测 | 允许写的 | **禁止写的** |
|---|---|---|
| 分母 < 68 | 「不可判（count_only），本轮不报率」 | 任何比率、任何「无效」结论 |
| 分母 ≥ 68，两臂 Newcombe CI 跨 0，且 \|Δ\| < MDE | 「**在 MDE ≈ 2.7pp 以下无可检出差异**」+「**样本不足以排除小效应**」 | 「**证明没有差异**」「F-3 无效」「该线可关停」 |
| 分母 ≥ 68，CI 不跨 0 且 \|Δ\| ≥ MDE | 「在 α=0.05、power=0.80 下检出差异，方向 = X」+ 口径变更声明 | 「F-3 有效」这种不带口径与规模的断言 |

> 负面结论是对的，但必须精确。**「已证无差异」是一种会被下一轮拿去否掉整条线的错误归纳**，
> 本轮报告出现该表述即视为失败。

若隐瞒探性而假装「零窥视」，才是真正的预登记造假。

## 5.5 机制覆盖范围发现（独立成段，不得埋进附录）

探性检查中最重的一条事实：

> **两臂的结构化情绪共振率完全相同：`S1 = 348 / 434 = 80.18%`（OFF 与 ON 逐值一致）。**
> 逐值一致不是「巧合接近」，而是**逐值相同**。共振对分布两臂也同一份：
> `(紧绷→紧绷) 273`、`(饥饿→饥饿) 75`、`(饥饿→紧绷) 34`、`(紧绷→饥饿) 30`、`(紧绷→疲惫) 6`、
> `(紧绷→孤单) 4`、`(紧绷→平和) 4`、`(孤单→紧绷) 3`。

**这说明什么（机制覆盖范围的读法）：**

1. `ctx.mood` 由需求/状态（`NEED_UPDATE` 等）驱动并持续，**不由对话内容写回**。
   F-3 只改**措辞**（在回复里加一句情绪呼应），**没有改动 agent 的状态/kernel**。
   因此「情绪状态层」在两臂之间根本没有被触碰过 —— 这不是「没有效果」，是**机制的作用面本来就不覆盖状态层**。
2. 这也**顺带解释了**为什么文本层 P1 会大概率无可检出差异：**只改措辞、不改状态，
   而共情标记只有 10 个、情绪词表只有 34 条 ⇒ 措辞层能产生的可观测位移本来就极小**。
3. 因此 `S1` 两臂相同**不能**被解读为「情绪呼应没用」，只能被解读为
   「**用状态共振来测措辞层干预，量具与作用面错配**」。`S1` 在本卡里只作对照，不作主判据（§4.2）。

**下一轮方向（一句话，本轮不做）：** 若要让「情绪呼应」真正落到状态层，需要让 echo 结果
**写回** `mood` / kernel 状态（例如被安抚后 `紧绷` 下降），这属于改 `code/` 的行为，
必须**另开分支、另做跑批、另开口径卡**，不在 #t2 范围内。

## 7. 读数器契约（`tools/metrics/f3_echo_rate.py`）

- **只读** `run.jsonl`。零 LLM、零网络、零随机、零时间戳。
- 支持对**任意** arm 目录运行：`--log-dir <dir>`（读 `dir/run.jsonl`）。
- 必须同时输出：① 机器可读 JSON（`sort_keys=True`、`ensure_ascii=False`）；② 人读表格（markdown）。
- 必须内嵌：本卡 path + sha256、脚本自身 sha256、输入 log sha256、词表 sha256。
- 必须复算并输出 **旧口径读数**（§2 的相邻对口径）与 **新口径读数**并列。
- 同一卡 + 同一臂 ⇒ 两次运行输出**逐字节相同**（`cmp` 可证）。
- 不得修改 `code/life`、`orchestration`、`config`、`engine` 四个受保护目录下的任何文件。
